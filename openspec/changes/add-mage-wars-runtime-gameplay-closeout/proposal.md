# Change: 收口法师战争标准竞技场两派系流程

## Why
当前 Mage Wars 的运行时代码已经转向 4x3 标准竞技场，但 OpenSpec 和部分测试/文案仍把目标写成“学徒模式 / 2x3”。这会把教程用的简化地图误当成本轮产品目标，也会让后续实施偏向补全法术目录而不是先跑通真实流程。

## What Changes
- 将 Mage Wars 主 spec 和本提案口径改为“标准竞技场 + 默认两派系（兽王 / 女祭司）流程 MVP”。
- 保留现有预设法术书和素材配置中的 `apprentice` 资源名，但明确它们只是首批可验证资源来源，不代表教程学徒模式；正式入口默认只要求兽王 / 女祭司两派系跑通流程。
- 让正式入口使用标准竞技场部署：4x3 / 12 区域、兽王与女祭司从标准对角起始。
- 继续通过现有 DomainCore 命令、事件和响应窗口推进玩家真实交互：计划、部署、施法、移动、守卫、攻击和阶段推进。
- 只实现流程跑通所需的少数已配置卡牌能力；全量法术、自由构筑、教程和完整 AI 继续后置。
- 增加完成判断标准：收口时必须列出当前运行池、代表链覆盖、明确未覆盖项和截图清单；“流程跑通”不得外推到墙体 / 墙壁法术、视线、通行伤害或全卡表。

## Impact
- Affected specs: `mage-wars`
- Affected code:
  - `src/games/mage-wars/Board.tsx`
  - `src/games/mage-wars/domain/`
  - `src/games/mage-wars/data/`
  - `e2e/mage-wars/`
  - `public/locales/*/lobby.json`

## Scope Boundary

本 change 的完成口径是“可由两个玩家真实操作完成的标准竞技场兽王 / 女祭司两派系核心链”，不是教程学徒模式，也不是整套 Mage Wars 的全部内容。全 322 张法术、墙体 / 墙壁法术与墙体边界选择、视线阻挡、通行伤害、自由构筑、四人模式、豪华竞技场、扩展法师、完整 AI、教程、行动日志 UI 和撤回 UI 继续由后续 change 管理。
