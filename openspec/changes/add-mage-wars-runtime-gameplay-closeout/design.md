## Context

Mage Wars 当前已有纯函数领域层、标准竞技场资源和正式在线入口，但历史提案把本轮目标写成“学徒模式 / 2x3”。当前设计只把 `apprentice` 作为首批预设法师、法术书和素材配置的历史命名，不把它当作教程模式或地图目标；正式入口默认席位由 4x3 标准部署决定，当前只要求兽王 / 女祭司两派系流程闭环。foundation E2E 仍可验证渲染和布局；真实玩法完成度必须回到正式联机入口。

## Goals

- 让正式入口可以在 4x3 标准竞技场中从初始状态进入计划、部署、施法/目标、移动或守卫、攻击/骰子、伤害/状态和回合推进。
- 保留现有 DomainCore、GameConfigPackage、事件驱动 FX、响应窗口和隐藏信息边界。
- 用真实页面交互证明主链，不把测试夹具或截图当作玩法实现。

## Non-Goals

- 不在本 change 中录入或实现全 322 张法术。
- 不新增自由构筑、四人模式、豪华竞技场、扩展法师、完整 AI、教程、行动日志 UI 或撤回 UI。
- 不重做已经确定的 Board 视觉布局；只有为真实交互提供入口或修正错误文案时才做最小 UI 改动。

## Decisions

### Decision: 页面只负责选择，领域层负责裁决

法术书、竞技场区域、计划牌和行动来源由 Board 提供点击入口；费用、阶段、射程、目标合法性、行动标记、法力、弃牌和事件结果继续由 `validate`、`execute`、`reduce` 及现有系统负责。页面不能通过本地状态绕过领域校验。

### Decision: 场地直选优先

当当前状态已经能唯一确定来源或合法目标时，玩家直接点击场地中的卡牌、法师或区域完成选择；只有需要多个候选或响应窗口时才使用现有交互系统。页面不新增“确认使用”这类规则不存在的常驻按钮。

### Decision: E2E 从真实初始状态开始

核心 E2E 不调用 `__BG_TEST_HARNESS__` 的 `state.patch` 或等价核心状态注入。若需要可重复的骰子结果，只使用现有正式测试随机入口或领域层确定性测试 seam，并在 E2E 中仍由玩家点击驱动命令。

### Decision: 先收口最小可玩链

第一批只打通兽王 / 女祭司两派系的一条可重复链：进入标准竞技场 → 双方选择并计划法术 → 部署首批生物/法术 → 进入行动阶段 → 从场地选择来源/目标施法或攻击 → 观察骰子/伤害/状态 → 结束阶段并切换回合。其余已有领域能力用定向领域测试覆盖，不能假设 UI 已自动支持。

## Risks / Trade-offs

- 风险：现有 Board 的视觉结构包含大量布局验收约束。缓解：只添加真实交互语义和最少选择态，不用新面板替代场地与卡牌。
- 风险：响应窗口可能中断施法或攻击。缓解：第一条 E2E 选择不触发隐藏响应的基础法术和基础攻击，随后单独补响应窗口链。
- 风险：部分配置卡仍标记为 `requiresCodeSupport`。缓解：E2E 只选择已实现能力，并在测试矩阵中明确排除项。

## Completion Evidence

完成本 change 前必须同时具备：领域测试、正式入口真实点击 E2E、桌面与移动真实交互证据、隐藏信息检查、正式素材加载检查、法术 FX 触发证据和 OpenSpec 校验结果。两条状态注入布局测试只能作为视觉回归辅助证据。
