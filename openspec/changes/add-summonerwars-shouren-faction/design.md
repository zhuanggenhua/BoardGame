# Design: Summoner Wars Shouren Faction

## Context

冰苔兽人素材沿用莫古/灰烬的 `8088x1454`、`8x2` 图集合同，slot 0-10 有效、slot 11-15 为空白。静态接入可以复用现有派系目录和牌组工厂，但规则中存在三类新增结算语义：

1. “激励”要求看到攻击/技能掷骰结果后决定是否消耗充能重掷全部骰子，且选择前不得结算伤害。
2. “狂暴/原始狂怒”要求攻击后可选推拉自身，再获得一次额外攻击；“蛮力冲击”要求伤害后可选把目标向远离来源的方向推拉。
3. “冻结/无上荣耀”要求持续事件在存续期间改变目标或友方单位的可执行能力，并在事件离场后自动恢复，不把临时效果永久写入卡牌定义。

## Goals

- 保持攻击掷骰、重掷、最终命中与伤害的唯一权威结算路径。
- 所有等待玩家输入的步骤进入 `sys.interaction`，真人、AI 和服务端读取同一状态。
- 可选效果在存在合法候选时仍允许跳过，跳过不改变权威状态。
- 额外攻击沿用现有额外攻击额度，不递增普通攻击次数，也不形成无限递归。
- 持续事件通过运行时 resolver 派生效果，事件离场即自动失效。

## Decisions

### 1. 攻击掷骰采用可暂停结算

为 `SummonerWarsCore` 增加可序列化的 `pendingAttackRoll`，至少保存攻击者、目标、攻击类型、基础/有效战力、骰面、当前重掷次数和来源。`DECLARE_ATTACK` 在命中“激励”合法条件时只产生 `ATTACK_ROLL_PENDING` 事件并写入该状态，不产生 `UNIT_ATTACKED`、伤害或摧毁事件；`SummonerWarsInteractionSystem.afterEvents` 依据该事件创建选择。玩家通过专用 `RESOLVE_PENDING_ATTACK` 命令选择“重掷”或“保留”后，再从同一结算函数计算最终命中、伤害、摧毁与攻击后触发，并清空 `pendingAttackRoll`。

当前 `UNIT_ATTACKED` 事件已经代表领域伤害完成，`useGameEvents` 中的 `pendingAttackRef` 只是动画缓冲，不能作为规则真相源，也不能用于暂停伤害。待结算阶段必须使用新的领域事件；UI 让 `DiceResultOverlay` 读取 `pendingAttackRoll` / interaction 数据显示原骰面和“重掷全部 / 保留结果”操作。最终选择完成后才发射一次正式 `UNIT_ATTACKED`，避免重复日志、重复动画和重复伤害。

约束：

- “激励”只在当前玩家回合、友方单位位于格鲁纳克 3 格内、格鲁纳克有充能时出现。
- 选择重掷时先消费 1 充能，再重掷全部骰子；本次掷骰只允许一次激励选择，防止循环。
- 跳过时使用原骰面继续结算。
- `pendingAttackRoll` 存在时，除所属 interaction 响应和专用继续命令外，其他领域命令必须被拒绝。
- AI 必须能从 interaction descriptor 选择保留或重掷。

### 2. 攻击后推拉与额外攻击复用统一 interaction 链

“狂暴”“原始狂怒”和“蛮力冲击”都在最终攻击伤害落地后创建显式交互：

- 狂暴：先结算 1 颗能力骰；只有掷出特殊标记时才进入自身 1 格推拉选择，执行推拉后获得一次额外攻击。
- 原始狂怒：召唤师攻击相邻敌方卡牌后，进入自身 1-2 格推拉选择，执行推拉后获得一次额外攻击。
- 蛮力冲击：攻击确实对单位造成伤害后，只提供使目标远离攻击者的 1 格合法落点。

额外攻击使用来源标识记录，同一来源产生的额外攻击不得再次触发该来源形成无限链；其他明确允许“每次攻击后”触发的能力仍按卡面子句执行。

### 3. 持续事件只保存来源与目标身份

- “冻结”在 active event 上保存稳定目标单位身份。能力解析、移动验证、攻击验证、推拉候选和攻击目标候选统一查询冻结状态。
- “粗暴蛮力”和“无上荣耀”不修改单位卡 `abilities`；`getUnitAbilities` 与有效战力 resolver 根据 active event 动态授予能力/修正。
- 主动事件按现有回合开始清理链离场后，派生效果自动消失。

### 4. 冰霜单位按牌组符号判定

“刺骨冰霜”中的冰霜单位定义为带冰霜牌组符号 `droplet` 的友方单位。冰苔兽人新增另一枚派系牌组符号，ID 使用 `tundra`；格鲁纳克牌组符号为 `double_axe + tundra + droplet`。

### 5. 提示板旧译名不进入运行时名称

单卡是名称与规则的主真相源；提示板只负责起始配置。提示板“冰原斗士/寒霜萨满/为了荣耀”分别映射到单卡“冰苔斗士/冰霜萨满/无上荣耀”，运行时统一使用单卡名称。

## Risks

- 攻击结算从同步一步变为条件式暂停，可能影响既有攻击事件顺序；必须补旧派系攻击回归和事件序列断言。
- 额外攻击来源若缺少次数边界可能递归；必须覆盖狂暴/原始狂怒的单次来源上限和交互清理。
- 冻结若只在 UI 禁用会被 AI/命令绕过；必须在 validate/helper/resolver 三层使用同一判定。
