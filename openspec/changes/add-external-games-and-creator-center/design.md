## Context

本方案锁定对象为外链目录、站内试玩、个人中心的投稿/作品管理和作者认领。真相来源为本轮用户要求、当前源码、指定站点实际响应和下列官方产品文档。目标环境为当前 BoardGame 工作区的 Web 正式入口设计，先产出文字方案。验收以真实入口的行为、权限和双端 UI 为准；本轮没有运行时 PASS。

当前事实：
- `PlatformUploadWorkspace.tsx` 调用 `/ugc/submissions` 保存、上传封面、送审和列出本人记录。
- `GameSubmissionsService` 的 `ownerId` 当前筛选投稿人；`author` 只是文字，状态枚举虽包含 approved/rejected，但该服务未提供审核与公开启动链路。
- `PlatformProfile.tsx` 显示资料、对局历史和统计；时长显示“未记录”。`PlatformHomeSurface.tsx` 已有 `section=profile/upload/library`。
- `games.config.tsx` 合并正式游戏与 UGC 规则包；外链不是规则包，不能伪装成可建房的领域游戏。

## Information Architecture

保留现有发现、收藏库和账户导航。个人中心使用现有资料头与当前视觉体系，下方提供同源内容分区：

| 分区 | 用户任务与主动作 | 内容/状态 | 不承担的职责 |
| --- | --- | --- | --- |
| 概览 | 看自己玩过什么、继续游玩、修改头像昵称 | 现有对局历史；外链最近游玩和估算停留时长；现有资料编辑 | 不把外链停留伪装成胜负对局，不填假统计 |
| 我的投稿 | 看我提交过哪些游戏，继续编辑或送审 | 草稿、待审核、已收录、已驳回；名称、封面、更新时间、审核意见 | “我提交过”不表示“我拥有” |
| 我的作品 | 管理本人已获授权的游戏 | 全部本人可管理作品；编辑资料、预览、调整展示状态；空态可申请认领 | 不重复收藏库；非作者投稿不混入此列表 |
| 作者认证 | 申请/查看作者认领结果 | 目标游戏、主页链接、截图、控制权证据；待审核、驳回理由、已通过 | 认证标记不自动授权同名作者的所有游戏 |

- 默认概览；我的投稿、我的作品各自保留筛选、分页、滚动与返回位置。建议路由为 `?section=profile&tab=...`，值由统一导航 owner 解析。
- 现有上传捷径继续可用，进入同一编辑器；增加“来自我的投稿/作品”的返回上下文，不复制编辑页面。
- PC 以资料头加分区内容为骨架；手机保留相同信息层级，将分区导航收纳为可横向浏览的短标签，密集操作进入作品详情。具体尺寸待双端参考与当前基线对照后确定。
- 未登录保持登录入口；空、加载、失败、无权限、审核中都展示对应实际状态。登录取消不丢失原目标，上传失败保留可重试内容。
- 认证材料仅本人和审核管理员可读，不放进作者公开资料或公开游戏接口。

## Ownership and Publication

### 唯一责任和对象

| Owner | 对象/唯一写入口 | 消费者 |
| --- | --- | --- |
| 现有投稿服务 | 投稿人、草稿字段、审核状态；审核批准时创建或关联一个外链目录条目 | 我的投稿、编辑器、管理员审核 |
| 外链目录服务 | 稳定的外链游戏 ID、公开资料、关联投稿、嵌入检查结论及检查 URL/时间；管理者由认领只读投影 | 发现/收藏/详情/我的作品/启动入口 |
| 认领服务 | 目标外链游戏、申请人、公开作者主页、私有证据、审核人/时间/理由；已批准认领是管理权唯一写入来源，数据库唯一索引防止并发重复授权 | 作者认证、管理员审核、可追溯记录 |
| 时长服务 | 与账号、外链游戏关联的会话和已接受计时片段 | 本人游玩历史、汇总统计 |

不建立独立的“我上传的游戏”复制表。我的投稿查询投稿，作品列表查询已批准认领并关联外链目录。现有投稿 `ownerId` 保持“投稿人”语义，迁移时不自动提升为作者；公开目录返回的 `ownerUserId` 只读投影，不另存第二份权限状态。

首版公开作品与编辑字段复用一个字段合同和编辑器。非作者编辑投稿仍走审核；已认领管理者可以直接修改公开字段，不要求每次重新证明作者身份。URL 变化使旧嵌入检查失效；隐藏作品不删除历史、投稿或认领证据。公开条目的身份不随标题/URL变化，不替换同名的本站原生游戏。

### 认领流程

1. 登录用户从游戏详情“我是作者，申请认领”或作者认证分区选择目标游戏。
2. 提交作者主页 URL、主页截图及自己与该游戏关系的说明。系统生成有期限、绑定账号和目标游戏的随机验证短码。
3. 优先将短码临时放入可公开核对的作者主页简介/动态；截图可展示该内容。无法公开放码时，提交可证明当前管理控制权的后台截图，由管理员人工核对，不自动通过。
4. 管理员审核“申请账号控制该作者主页”和“该作者确实对应目标游戏”两件事。仅证明 B 站账号控制权不足以证明游戏归属。
5. 批准后授予该游戏站内管理权，作品进入“我的作品”。投稿记录保持原始提交人，原投稿人不能借旧投稿编辑继续改动已认领作品的公开内容。
6. 已有管理者时不能用新截图直接覆盖；转入有原管理者记录与双方材料的管理员争议处理，不执行自动转移。此站内权限不宣称转移作品的法律著作权。

普通公开主页截图容易被任何访客取得，因此只作为申请材料。审核通过的历史记录可支持本人“已认证作者”展示，但不因同名/同链接自动取得其他作品。重提申请保留审核轨迹；证据上传使用独立私有存储访问控制，不能沿用公开封面 URL。

## External Game Launch

- 外链作为独立目录类型接入现有发现/详情/收藏读模型；启动操作进入 `/external/:gameId`，不会调用原生建房、AI 或 UGC 规则执行服务。
- 从已审核目录读取 URL；浏览器路由不接受任意 URL 参数作为启动目标。只允许审核后的 http(s) 网址；公开正式入口优先 HTTPS，不能在 HTTPS 宿主内静默加载混合内容。
- 采用跨源 iframe，限制顶层跳转和未授权权限；不向外站发送本站 token、账号数据或原生桥能力。脚本、表单、存储/登录与弹窗需求在目标站实测后选择最少权限；禁止将本站同源页面当外站装入有脚本和同源权限的容器。
- 全屏目标是包含 iframe 与平台悬浮菜单的共同容器；不授予内部 iframe 独立全屏覆盖平台菜单的权限。若游戏依赖内部全屏按钮，需与作者配合或单独确认取舍，不能承诺两者同时无条件工作。
- 悬浮球只在试玩容器出现，展开提供全屏/退出全屏、结束并返回和问题反馈。复用现有悬浮操作的拖拽、触控和安全区经验；当前页面内只有一个正式试玩菜单，不重复挂载同职责悬浮球。
- iframe 的 load 事件不能证明游戏可玩。已知 DENY/CSP 拒绝时不尝试宣称就绪；未知加载状态提供说明、重试和外站打开，不自动弹出新窗口，也不以超时推断所有错误原因。
- 显式外站打开动作告知离开本站，结束本站会话；没有外站配合时不继续计算离站时间或承诺外站仍有本站悬浮球。
- 浏览器不支持全屏或拒绝请求时保留可用的窗口内铺满和明确反馈。需分别验证桌面、手机横竖屏，不能以桌面 API 成功覆盖手机。

## Time Measurement

第一版定义为“外链游戏容器前台停留时长（估算）”，不称为游戏有效操作时间。外站 iframe 内部点击、暂停、房间、胜负和离开页面后的行为均不可观测。

- 用户从平台启动外链页开始会话；容器可见且处于试玩页时累计，隐藏/切后台、结束、返回、卸载、显式外站打开时暂停或关闭。已知嵌入拒绝不累计。
- 服务端保存会话和累计片段，按已确认的有限窗口结算；分片重试不重复相加，掉线/崩溃不把最后心跳以后无限时间计入。多个标签页的重叠区间合并，不能翻倍累加。
- 访客可试玩并看本次估算，不悄悄补记到其他账号；账户切换终止原身份会话。读接口只能查本人数据，不能靠客户端指定任意 userId。
- 未接合作方协议时，加载失败和闲置仍可能影响估算精度，产品明确口径。实际开局/暂停/结束事件需要另行约定可信的跨源消息协议，不在首版假造。

## UI Contract and Evaluator

文字方案先审阅，批准后再实施。实施前补读当前真实页面基线和逐功能双端商业参考，不以这些文档代替图面。

三条影响画面的结论：投稿不等于作品管理，因此分区与按钮按权限分开；外链没有胜负记录，因此停留历史不能塞成对局结果；DENY 不是加载慢，因此详情应给可执行的外站打开而不是无限加载。

验收要覆盖：新用户无投稿/无作品、投稿各状态、认领各状态、有权/无权编辑、原投稿人被认领后访问、外站拒绝嵌入、容器全屏与菜单、加载失败、返回上下文、个人头像昵称/原对局历史保留。主内容、状态反馈与操作不重复，长标题/大量游戏可浏览；PC 首屏主次合格后再验手机滚动、触控、安全区与横屏。

## Migration and Execution Order

1. 批准本提案，补齐 UI 参考与当前基线；第一版保持当前首页视觉体系，不重新设计整个平台。
2. 扩展投稿审核并建立外链目录和按作品的管理权校验，保持既有投稿数据可读。
3. 接入个人分区、共享字段编辑器、私有认领材料与管理员审核。
4. 接入外链详情/启动页、全屏菜单、会话计量和本人历史；认领接口与公开编辑必须先完成权限验证再开放。
5. 将收录草稿通过正式录入路径写入测试环境；补封面/必要元数据，不猜人数时长，不写生产数据；用户没有真实作者认证材料时保持未认领。
6. 分别验证本站能力与指定外站。站点解除嵌入限制之前，指定站点 iframe 验收保持阻塞，不用本地测试页替代它。

## Risks and Open Questions

- 指定站点需作者修改嵌入策略，并验证外部登录、资源与尺寸适配；本站无法单方完成。
- 最小必要的封面、分类和玩家人数未确认，不能拿本站同名游戏数据补齐。
- 私有认证图存储与管理员审核 UI 需要真实生命周期，不可用公开封面接口或仅有表单代替完成。
- 当前用户请求是考虑作者认证与个人中心，具体审核门槛、直接编辑范围和分区结构以本提案审阅结果为准。
- 发布、通知作者/原提交人、团队协作及所有权争议裁决不因本提案自动获得执行授权。
