## Context
- 旧方案使用“服务器主源 + 对象存储回退”降低访问延迟，但这仍把对象存储保留在正式下载、灾备和验收路径里。
- 当前目标是彻底脱离对象存储在线链路：公开域名保持不变，线上下载、OTA、移动素材包和原生更新都只认服务器活动版本。
- 对象存储可以作为历史遗留对象存在，但不得作为当前发布成功、回滚成功、更新可用或清单可读的证据。
- 本变更同时承担防止静默失败的责任：源站失败、清单读取失败、跨域预检失败、哈希不一致都必须暴露为错误。

## Goals / Non-Goals
- Goals:
  - 公开素材 URL、前端资源基址和协作者命令名保持不变。
  - 服务器 `/home/admin/storage/assets/current` 是正式素材和发布包唯一线上真相源。
  - Worker 不绑定对象存储，不读取同 key 兜底对象，不把源站失败伪装成成功。
  - 发布脚本必须在公开域名回查本次对象，校验来源、大小、哈希和 CORS 预检后才报告成功。
  - OTA 客户端必须区分“没有更新”和“清单读取失败”，强更场景下清单读取失败必须阻塞并提示。
- Non-Goals:
  - 不删除历史对象存储内容。
  - 不建立对象存储灾备队列。
  - 不实现对象存储容量门禁或历史对象恢复演练。
  - 不使用对象存储作为服务器损坏后的自动重建来源。

## Decisions

### Decision: 服务器是唯一线上真相源
- 所有正式发布先写入服务器 staging，完成校验后原子切换 `current`。
- 发布脚本不得把对象存储可读、旧完整包可读或旧 manifest 可读当成本次发布成功。
- 服务器 release 至少保留当前版本和上一个已验证版本，用于低风险回滚。

### Decision: Worker 只代理服务器并显式失败
- `assets.easyboardgame.top` 的 `official/**` 请求进入 Worker。
- Worker 只允许 `GET`、`HEAD` 和 CORS `OPTIONS`。
- 服务器返回成功时，Worker 透传响应并标识 `X-Asset-Source: server`。
- 服务器连接失败、超时、返回 `404` 或 `5xx` 时，Worker 返回可观测错误并标识 `X-Asset-Source: server-error`。
- Worker 配置不得声明对象存储 bucket binding，运行时代码不得引用对象存储环境变量。

### Decision: 发布验收必须检查公开域名和 CORS 预检
- 普通素材、OTA bundle、`latest.json`、移动素材包 manifest、file-index 和原生更新包都必须从公开域名回查。
- JSON 清单必须校验正文大小和 SHA-256，二进制包必须校验大小和 SHA-256。
- 需要被移动端读取的清单必须执行 `OPTIONS` 预检，确认允许生产 Origin、请求方法和必要请求头。
- `X-Asset-Source: server-error`、非 2xx、预检失败、内容类型异常或哈希不一致都必须阻塞发布。

### Decision: 客户端不得静默吞掉更新链路错误
- Android OTA 检查必须区分三种结果：清单存在、清单不存在、清单读取错误。
- 只有 `404` 可以解释为“没有对应清单”；网络错误、跨域错误、超时、非 OK 响应、非 JSON 响应或 JSON 解析失败都属于清单读取错误。
- 强制更新时清单读取错误必须显示阻塞错误态；后台自动检查也必须至少给出可追踪提示，不能降级成“没有更新”。

### Decision: 旧对象存储清理不是当前发布链路的一部分
- 历史对象何时删除、如何隔离、是否保留恢复窗口，需要用户单独确认。
- 当前仓库中与对象存储上传、下载、同步、备份和容量门禁相关的脚本入口应退役或删除，避免被误用为正式发布入口。
- 如果后续需要做历史清理，必须新建只处理历史对象清理的 OpenSpec change，不得混入 OTA 或素材发布验收。

## Rollout Plan
1. 本地代码切换为服务器唯一源，并删除 Worker 对象存储绑定和读取逻辑。
2. 退役对象存储上传、下载、同步、备份和容量门禁脚本入口。
3. 更新 OTA、移动素材包、原生更新发布脚本，使发布后回查公开域名、大小、哈希和 CORS 预检。
4. 更新后台发布页 ready 状态，使其只依赖服务器资源发布入口。
5. 更新现行部署文档和 Android 发布 skill，明确失败必须显式暴露。
6. 部署无对象存储绑定的 Worker；部署前若缺少 Cloudflare 凭据，只能报告未上线，不得宣称线上完成。

## Rollback Plan
- 同一次发布失败：不切换服务器 `current`，继续保留上一个已验证 release。
- 新 release 出现问题：将服务器 `current` 切回上一个已验证 release。
- Worker 部署异常：回滚到上一个无对象存储绑定、只代理服务器的 Worker 版本。
- 不允许把“恢复对象存储回退链路”作为本变更完成态的默认回滚方案；如果确需临时恢复，必须明确标注为临时止血并单独确认。

## Acceptance Criteria
- 现有公开素材 URL 不变，正式对象由服务器活动版本返回。
- Worker 配置不包含对象存储 bucket binding，运行时代码不引用对象存储环境变量。
- 源站失败时返回可观测错误和 `X-Asset-Source: server-error`，不读取对象存储同 key 对象。
- OTA 发布后必须回查 bundle 和 `latest.json`，并校验 `latest.json` 的 CORS 预检、大小和 SHA-256。
- OTA 客户端清单读取失败必须显示错误，不得被当作“没有更新”。
- 后台发布页不再以对象存储配置作为 ready 门禁。
- 现行代码、脚本和当前文档不得保留对象存储回退、灾备队列、容量门禁或发布前置口径。
