# Design: 召唤师战争战术 AI 搜索策略

## Context
召唤师战争当前 AI 主体集中在 `src/games/summonerwars/ai.ts`。它已经接入公共 `createLookaheadLocalAiPolicy`，并通过 `buildSummonerWarsAiLegalActions` 枚举合法动作，再由多个 scorer、assignment、feature snapshot 与 `projectAction` 叠加分数。这个架构方向正确，但当前价值判断仍分散在动作类型和局部 metadata 中，阶段内多动作组合与派系策略表达不足。

## Goals
- 保持 `legalActions` 为唯一动作根集合，继续走 validate / execute / reduce / systems。
- 建立统一 `evaluateSummonerWarsBoardState()`，让召唤、移动、建造、攻击、技能、弃牌换魔力共用同一局面价值口径。
- 将动作投影统一改为动作后局面差值，减少分散硬编码权重。
- 在预算内搜索阶段内 2-3 步候选序列，优先覆盖短线战术组合。
- 引入派系策略 profile，影响评分但不改变规则合法性。
- 保持 AI trace 可解释，能说明基础分、局面差值、序列收益与派系权重来源。

## Non-Goals
- 不实现完整 MCTS。
- 不实现 Minimax 全局对抗搜索。
- 不引入神经网络、强化学习或远程大模型实时落子。
- 不读取对手隐藏手牌、真实牌堆顺序或任何超出 `playerView` 的信息。
- 不修改召唤师战争正式规则和 UI 主流程。

## Decisions

### 1. 统一局面价值函数先落地
`evaluateSummonerWarsBoardState(state, playerId, options)` 作为单一价值入口，返回总分和 breakdown。首批维度：

- 召唤师安全：召唤师剩余生命、可被攻击路径、直接威胁伤害、挡路单位。
- 威胁与击杀：可确认击杀、敌方召唤师压力、冠军/普通单位/建筑价值。
- 魔力经济：手牌保留价值、弃牌换魔力收益、可召唤曲线、魔力上限浪费。
- 位置与控制：中心控制、前线推进、己方/敌方城门附近站位、通路阻断。
- 节奏：本阶段剩余动作次数、已移动/已攻击单位、事件牌或技能带来的即时窗口。
- 派系偏好：由 profile 提供加权项，不直接写入基础规则。

### 2. `projectAction` 改为前后差值
动作投影应先用当前局面价值作为 baseline，再对候选动作做安全模拟，得到动作后局面价值，最终使用差值回灌 lookahead 分数。

如果某动作不能安全投影，必须保守降级为现有 scorer 结果，不能为了投影绕过合法动作或真实领域执行链。

### 3. 阶段内序列搜索只做短线组合
阶段内搜索以当前合法动作为根，每次执行一个候选动作后重新生成当前状态下的合法动作，最多展开 2-3 步。默认只搜索高价值动作类型：

- 技能 / 事件牌
- 召唤
- 移动
- 建造关键城门/阻挡建筑
- 攻击
- 弃牌换魔力
- 阶段结束仅在无明显可兑现动作时进入候选

搜索必须有时间预算、候选数量上限和深度上限。搜索结果进入同一 trace，不另建第二套解释协议。

### 4. 派系策略通过 profile 注入
每个阵营提供 `SummonerWarsFactionAiProfile`，只影响权重和解释，不改变命令合法性。首批方向：

- 亡灵：复活、弃牌堆利用、牺牲低价值单位、持续施压。
- 冰霜：建筑/冰墙、位置控制、阻断路径、保护召唤师。
- 哥布林：低费铺场、前压、围攻、快速击杀窗口。
- 圣骑：保护召唤师、治疗/护盾、稳健推进。
- 蛮族：高强度单位、冲锋、强化后攻击。
- 诡术：换位、控制、关键目标扰乱。

### 5. MCTS 只保留扩展位
本 change 只设计出未来 MCTS 能复用的边界：局面价值函数、动作投影、合法动作根集合、trace、预算和可见信息约束。完整 MCTS 需要更强的状态沙盒、随机性采样和对手回应模型，因此保留为后续独立 change。

## Risks / Trade-offs
- 阶段内搜索可能放大状态模拟成本；通过 shortlist、深度上限和时间预算控制。
- 局面价值函数如果权重过强，可能压过特殊技能语义；通过 scorer contribution 和 profile trace 暴露调试。
- 派系 profile 过早复杂化会增加维护成本；首版只做少量权重，不为每张牌写专属策略。
- 投影如果触发系统副作用会污染真实对局；必须在实现中确认只使用安全模拟或纯投影 helper。

## Validation Plan
- 新增局面价值函数单测，覆盖召唤师安全、击杀、魔力、中心控制、城门/前线。
- 新增动作后差值测试，证明同一动作在不同局势下分数能合理反转。
- 新增阶段内序列搜索测试，覆盖技能→攻击、移动→攻击、召唤→阻挡/推进。
- 新增派系策略测试，证明同一候选在不同阵营 profile 下排序变化可解释。
- 保持现有召唤师战争 AI 交互链、准备阶段、目标型技能和防卡死测试通过。

## Future Extension
- 可在后续独立 change 中基于本次抽出的价值函数和安全投影扩展 MCTS。
- MCTS 若实施，必须先证明状态复制、随机采样、隐藏信息边界、沙盒执行和 trace 成本可控。
