## ADDED Requirements

### Requirement: 托管网页游戏使用平台房间
系统 SHALL 为声明房间 SDK 协议的已收录网页包提供平台建房、发现房间、入座和开局。游戏通过同一协议读取房间标识、座位和昵称，连接自己的对局。

#### Scenario: 刚收录或已经收录的网页包
- **WHEN** 玩家打开携带房间 SDK 的已发布网页游戏详情
- **THEN** 已适配的游戏显示「创建房间」，点击后打开易桌游的建房界面

#### Scenario: 房主配置游戏开发者声明的选项
- **WHEN** 声明使用托管 v1 的游戏在入口旁提供 SDK 房间配置文件
- **THEN** 建房弹窗使用该声明的人数和配置选项。平台校验并保存房主的选择，在房主及访客进入游戏时通过 SDK 提供同一份配置

#### Scenario: 游戏未声明可选人数
- **WHEN** 游戏没有通过 SDK 声明多个可选人数
- **THEN** 建房界面省略人数控件，房间按已有默认容量创建

#### Scenario: 易桌游管理外部游戏的房间密码
- **WHEN** 房主在平台建房时填写密码，访客从房间列表或邀请链接加入
- **THEN** 平台验证密码，验证通过后才允许访客入座并加载游戏，密码留在平台端

#### Scenario: 好友通过邀请加入并开局
- **WHEN** 房主在易桌游建房，访客在易桌游游戏详情找到该房间并加入
- **THEN** 访客无需登录即可入座，房主在平台房间开局后双方进入同一局

#### Scenario: 直接在游戏里等待入座
- **WHEN** 房主建房或游客入座，房间尚未开局
- **THEN** 平台即刻呈现游戏并提供房间状态和操作，玩家可以在同一游戏页面等开局

#### Scenario: 开发者使用平台托管 v1
- **WHEN** 网页包声明使用平台托管的 v1 SDK，平台发布兼容的 SDK 更新
- **THEN** 新打开的游戏房间使用更新后的平台 SDK，已打开的对局继续使用页面载入时的 SDK，开发者无需重传网页包

#### Scenario: 房间固定资源版本
- **WHEN** 房间创建后游戏上传了更新
- **THEN** 该房间继续使用创建时的入口。参与者只接收发给自己的对局连接信令
