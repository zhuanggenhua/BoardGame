## Context
七大恨当前存在两套彼此纠缠的区域语义：

- 印刷地图语义：来自原图上的闭合边界和地区名，例如 `喀喇沁部`、`土默特部`、`察哈尔部`
- 运行时逻辑语义：服务规则和初始配置的逻辑区，例如 `辽西`、`宁远`、`蓟镇`

现状把两者压在同一套 `region-mask-regions.json` / `region-graph.json` / runtime region id 上，导致：

- devtool 无法把“自动填充后的闭合区”直接当成正式真相
- 逻辑层通过名称覆盖和借位 id 侵入地图真相
- 一旦地图上存在独立闭合命名区但逻辑层没有独立承载，正式区就会被吞并

## Goals / Non-Goals
- Goals:
  - 让印刷闭合区成为 devtool 正式结果的单一真相来源
  - 让运行时逻辑区通过显式映射依附于印刷闭合区，而不是反向污染它
  - 保留现有 `qidahen` 规则逻辑可逐步迁移，而不是一次性重写全盘玩法
- Non-Goals:
  - 本次不要求立刻重做所有七大恨玩法平衡
  - 本次不要求立刻消除所有历史逻辑区抽象，只要求先把地图真相层分出来

## Decisions
- Decision: 新增“印刷正式区”层作为物理地图真相。
  - Why: 用户要求正式区域必须直接来源于自动填充后的闭合块；当前只有单独分层才能保证这一点。

- Decision: 运行时逻辑区通过显式映射引用一个或多个印刷正式区。
  - Why: 现有逻辑区已经存在 `辽西`、`宁远`、`蓟镇` 这类非原图印刷名，短期内不可能全部删除；显式映射能先解耦，再逐步迁移。

- Decision: devtool 的审计结果必须能区分“地图真相缺失”和“逻辑映射缺失”。
  - Why: 当前视觉上看似是漏填颜色，实际根因可能是正式区缺失，也可能是逻辑区借位，混在一起会继续误判。

## Risks / Trade-offs
- 风险：印刷区数量上升后，运行时邻接、移动代价和初始布置可能需要重新声明。
  - Mitigation: 先引入映射层，允许旧逻辑区继续消费聚合结果，再逐步细化。

- 风险：已有测试大量直接绑定 `city-region-*`。
  - Mitigation: 先收敛哪些 id 是印刷区 id，哪些是逻辑区 id，再分批迁移测试断言。

## Migration Plan
1. 先定义印刷正式区表与逻辑区映射表
2. 让 devtool 只围绕印刷正式区工作
3. 让运行时读取印刷区后再派生逻辑区
4. 逐步修复受影响的名称、邻接和玩法测试

## Open Questions

- 现有逻辑区里哪些应该维持聚合，哪些应直接回归为一对一印刷区
