## Context
本次重构承接当前工作区已经完成的地图 Scene/HUD 分层和局内阵营确认，不修改地图边界、卡牌数据、战斗数值或阵营规则。真实流程证据来自当前工作目录在 `http://127.0.0.1:4273` 的三人房流程，覆盖创建房间、剧本、阵营、人物与军备、首次行动、突袭、支付、战斗和战后选择。

## Goals
- 玩家在每次提交前都能回答：正在选什么、当前选了什么、确认后发生什么、如何取消。
- 同一时刻只有一个主交互焦点，选择态不保留无关行动入口。
- 地图对象继续作为地图选择的正式点击载体。
- 手机横屏关键控件保持可读、可点，不依赖整层 HUD 缩放。

## Non-Goals
- 不修改《七大恨》规则、卡牌归属、军备可选范围或战斗结果。
- 不重绘地图、卡牌素材和完整视觉风格。
- 不复制第二套 `MobileBoard`，不修改其他游戏的共享牌桌布局。

## Design Declaration

### Spec
- 目标用户：首次进入《七大恨》的三人在线玩家，以及手机横屏玩家。
- 主路径：创建房间 -> 选择剧本 -> 选择阵营 -> 完成私有前置 -> 执行首次行动 -> 突袭与战后处理。
- 必须覆盖：可选择、已暂选、已提交、等待他人、不可选、取消、目标切换、结算后恢复。

### Domain
- `候选` 是客户端尚未提交的草稿，不改变领域状态。
- `已确认` 才发送现有领域命令；服务端领域状态仍是唯一正式结果。
- 地图目标必须使用现有合法候选和区域真相源，不新增旁路按钮列表替代地图点击。

### Design
- 延续“明末地图墨框 UI”的 `mapInk / mapPanel / mapGold / cinnabar` 语法。
- 候选态与已确认态不能只靠颜色区分；同时使用短状态和边框层级。
- 常驻主 UI 不放规则说明正文，只显示对象、数值、短状态和单步动作。

### Components
- 开局使用同一套“候选卡 + 详情预览 + 底部确认栏”。
- 地图选择使用对象高亮和固定决策栏，决策栏只承载当前对象、后果摘要、取消和确认。
- 战后选择先选处理方式，再选数量/退路，禁止一次平铺所有笛卡尔组合。
- 手机横屏复用原组件，通过壳层布局模式和局部尺寸令牌重排，不复制业务组件。

### Craft
- 单一主焦点；等待态不伪装成可操作态。
- 不用重复说明文案弥补交互层级。
- 卡牌必须有稳定放大入口，移动端不依赖 hover。
- 动效遵守 `prefers-reduced-motion`。

### Template
- 桌面：地图 Scene 全屏，HUD 保持现有固定槽位；临时决策只占右侧决策槽和底部手牌槽。
- 手机横屏：地图保持等比并可平移；顶栏、当前决策、手牌与主按钮按真实视口定位，关键操作不进入整体缩放层。
- 开局全屏页：标题/进度固定可见，候选区内部滚动，确认栏固定在可视区域底部。

## Decisions
- Decision: 开局候选使用客户端草稿，确认时复用现有命令。
  - Why: 可以消除误触，不改变领域事件和联机真相源。
- Decision: 地图选择继续点击地区本体，确认栏只提交当前地区。
  - Why: 保持地图是正式交互载体，同时让高代价动作可核对、可取消。
- Decision: 临时聚焦保存进入选择前的视口，退出该选择状态时恢复。
  - Why: 避免固定恢复到某个默认倍率，也保留玩家进入前的视角。
- Decision: 手机 HUD 不再对整个 `1920x1080` 容器做比例缩放。
  - Why: 整层缩放会同步缩小文字与触控热区，无法满足真实 CSS 像素下的可用性。

## Evaluator
- 任务清晰度：第一眼能识别当前对象和唯一下一步。
- 状态合同：候选、确认、等待、取消和结算后状态互不混淆。
- 布局完整性：桌面与手机均无裁切、重叠、纯色边块或异常留白。
- 人体工学：手机关键操作热区至少 `44x44 CSS px`。
- 回归合同：规则结果和合法候选不因 UI 重构改变。
- 通过门槛：真实桌面与手机截图审计至少 `90/100`，且没有硬失败项。

## Risks / Trade-offs
- 客户端草稿可能在联机状态变化后失效。
  - Mitigation: 每次渲染按最新合法候选校验，失效时清空草稿并要求重新选择。
- 手机局部重排可能影响桌面固定构图。
  - Mitigation: 以壳层 `data-layout-mode` 隔离移动令牌，桌面尺寸和锚点保持不变。
- 战后分层会改变 E2E 的点击顺序。
  - Mitigation: 保留最终领域 choice id，只改变 UI 如何选择该 id。

## Migration Plan
1. 先落开局草稿确认和突袭目标摘要，保持现有领域命令。
2. 再收口地图选择、地图视口恢复和战后分层。
3. 最后切换手机 HUD 布局并补双端截图/E2E。
