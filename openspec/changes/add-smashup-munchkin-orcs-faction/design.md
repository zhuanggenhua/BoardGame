# Design: 萌奇金兽人派系

## 真相源与对象边界

- 规则真相源：`evidence/smashup/munchkin-new-faction-flow-audit-2026-08-01.md` 中的兽人 C1-C6 子句，以及用户指定素材目录中的兽人卡图 / 基地图。
- 静态 owner：`src/games/smashup/data/factions/munchkin.ts`；本 change 只补能力标签和运行时消费，不另造卡牌目录。
- 能力 owner：优先新增 `src/games/smashup/abilities/munchkin_orcs.ts`；统一力量修正、保护和基地计分扩展分别落到已有 shared authoring owner，避免把跨派系合同塞进兽人文件。

## 实现决策

1. 标准持续力量使用 `ongoingModifiers` 的统一 authoring surface；剑王只给同控制者的其他仆从加力，且自身不受该来源加成。
2. 需要玩家选择的能力使用现有 Smash Up ability runtime 的 prompt / sequence 合同；不能新增 raw `queueInteraction + continuationContext` 作为默认续链。
3. `呆瓜兽人`、`太难了`、`洗手间` 与 `坑洞` 的“行动影响保护”必须复用 protection / affect 过滤合同；保护范围必须带上控制者、宿主基地和本次牌打出来源，不能用全局布尔值。
4. `给我！` 必须先锁定附着行动，再摧毁原宿主，最后由玩家手动选择己方新宿主；附着行动不得因为原宿主摧毁而提前进入弃牌堆。
5. `躺下！`、`狗堆`、`愤怒的掠夺者` 的计分前响应必须沿现有 response-window / before-scoring 入口接入，不能新增平行响应壳层。
6. `要塞` 的前三名 VP 奖励与 `坑洞` 的基地保护分别落在基地计分和保护 owner；并列、少于三名玩家和无合法候选必须有显式领域负向测试。

## 交互与验收矩阵

| 对象组 | 关键玩家决定 | 最小真实证据 |
| --- | --- | --- |
| 剑王 / 呆瓜兽人 | 无额外按钮；读取持续效果结果 | 同基地己方 / 对手 / 自身对照截图与最终力量 / protection 状态 |
| 粉碎者 | 手动点击天赋入口 | 天赋按钮存在、点击后无状态变化且使用标记正确 |
| 重击者 / 死亡之息 | 手动选择合法目标；单候选仍停住 | 目标本体高亮、结算后摧毁或回牌库底 |
| 躺下！ / 愤怒的掠夺者 / 狗堆 | 计分前手动选择响应、目标或跳过 | before-scoring 真实响应窗口和结算后状态 |
| 挤碎 | 先选基地、再选玩家、再选随从 | 三段选择态均显示真实候选本体 |
| 给我！ | 先选附着行动、再选己方宿主 | 原宿主消失、行动转移且不进弃牌堆 |
| 洗手间 / 太难了 / 坑洞 | 每次保护是否发动由玩家决定 | 他人打牌触发保护选择与未保护对照 |
| 要塞 | 计分门槛与前三名奖励 | 总力量不足 / 达标、并列与最终 VP 对照 |

## 风险与回退

- 共享保护合同若无法表达“本次牌影响但不影响其它来源”，先补共享合同及测试，再实现兽人卡牌；不以局部过滤代替正式规则。
- 计分前响应若与现有响应排序冲突，先锁当前 response-window 归属和来源事件，再继续实现；不绕过响应窗口直接发事件。
- 目标选择截图若被源卡特写、重复上下文卡或其它 HUD 遮挡，重构承载或重拍；不以内部 interaction option 证明视觉完成。
