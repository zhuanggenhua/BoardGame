## Context
《七大恨》的地图与 HUD 都以 `1920x1080` 固定舞台为父节点。宽屏下使用额外地图图片填充舞台外侧，但中心交互地图仍属于固定舞台，两个地图实例不能共享缩放、平移和裁切位置。开局状态则在剧本结算时直接按 `playerIds` 顺序写入各阵营的 `playerId`。

## Goals
- 地图 Scene 覆盖真实 viewport，宽屏不出现固定舞台硬边或纯色边块。
- HUD 保持现有设计尺寸与安全区，不随 Scene 的 `cover` 裁切。
- 玩家在局内明确确认自己的阵营，之后所有私有前置和手牌都使用同一个阵营归属。
- 不改地图区域数据、地图命中坐标和战斗规则。

## Non-Goals
- 不重做《七大恨》地图素材、卡牌美术或完整 HUD 视觉风格。
- 不修改其他游戏的牌桌壳层。
- 不把本轮扩展为任意人数、观战席或热座模式重做。

## Decisions
- Decision: Scene 使用 cover 缩放，HUD 使用 contain 缩放，两者共享内部 `1920x1080` 设计尺寸但拥有独立父层。
  - Why: 地图可以裁掉非关键边缘并铺满真实 viewport，HUD 则必须完整可见；同一缩放公式无法同时满足这两个要求。
- Decision: 交互地图只渲染一个实例，不再使用额外地图图片补固定舞台外侧。
  - Why: 两个地图实例无法可靠共享平移、缩放和点击坐标，必然产生拼接边或视觉错位。
- Decision: 阵营确认只在局内剧本选择模式启用，直接领域测试和既有非投票 setup 继续保留默认座位映射。
  - Why: 这样修正正式联机开局，同时避免把大量规则测试改造成联机 setup 测试。
- Decision: 每个玩家可在阵营确认阶段修改自己的选择，直到所有玩家都占用唯一合法阵营；最后一个有效选择提交后统一完成归属并进入人物/军备前置。
  - Why: 不需要额外房主确认，也不会出现两个玩家同时持有同一阵营。

## Risks / Trade-offs
- Scene 使用 cover 后，在超宽视口会裁掉地图上下边缘。
  - Mitigation: 交互地图保留缩放和平移能力；HUD 独立完整显示，E2E 覆盖主目标区域点击。
- 阵营选择会改变现有联机 E2E 的固定座位假设。
  - Mitigation: E2E 显式完成三席位阵营选择，再验证各自前置和手牌视角。

## Migration Plan
1. 先引入独立牌桌壳层并保持现有地图命中逻辑。
2. 增加阵营确认领域状态、命令和 UI。
3. 更新联机 setup 与宽屏/突袭 E2E。
4. 运行定向领域测试、ESLint 和 E2E。
