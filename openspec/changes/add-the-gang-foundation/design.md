# Design: 纸牌帮 The Gang 基础版接入

## Context
纸牌帮 The Gang 是合作类德州扑克排序游戏。基础版支持 3-6 人，每局由 3-5 次“抢劫”组成；每次抢劫有 4 轮，对应玩家逐轮用不同颜色的筹码表达自己当前牌力排序。第 4 轮红色筹码排序与真实牌力一致则本次抢劫成功，否则失败。累计 3 次成功获胜，累计 3 次失败失败。

## Goals
- 建立 `the-gang` 独立游戏目录和可生成 manifest 的最小实现。
- 首期只实现基础版 3-6 人玩法，不把扩展规则混入本体。
- 用项目现有 DomainCore + GameEngine 模式实现确定性状态流。
- Board 页面展示可玩的基础流程：玩家手牌、公共牌、筹码池、抢劫结果、游戏胜负。
- 资源链路先接入缩略图与候选资源登记，不直接引用未压缩原图。

## Non-Goals
- 不实现 7-10 人扩展、exit chips、0/7/8 星扩展筹码。
- 不实现挑战卡、专家卡、Joker、工具牌、Dealer 变体和 4 种扑克变体。
- 不新增共享引擎系统；若发现可复用缺口，只记录为候选抽取项。
- 不新增首页外的测试捷径或产品入口。
- 不把空的 `dom.txt` 当作布局真相源。

## Core Model
- `players`: 每名玩家的手牌、每轮已选筹码、摊牌可见状态。
- `deck`: 标准 52 张扑克牌洗牌序列。
- `communityCards`: 公共牌，Round 2 翻 3 张，Round 3/4 各翻 1 张。
- `heist`: 当前第几次抢劫、成功次数、失败次数。
- `round`: 1-4，对应白/黄/橙/红筹码。
- `chipPool`: 当前轮可选筹码，基础版为 1 到玩家数星。
- `phase`: `chip-selection`、`showdown`、`game-over`。

## Commands
- `TAKE_CHIP`: 当前轮玩家选择一个当前无人持有的筹码，可在本轮内更换。
- `END_ROUND`: 所有玩家都有当前轮筹码后推进到下一轮，翻对应公共牌。
- `REVEAL_SHOWDOWN`: 第 4 轮后公开玩家手牌并判定本次抢劫。
- `START_NEXT_HEIST`: 抢劫未达到 3 成功/3 失败时，重新洗牌进入下一次抢劫。

## Scoring
摊牌时，每名玩家用自己的 2 张底牌加 5 张公共牌组成最佳 5 张德州扑克牌型。按真实牌力从弱到强排序后，与红色筹码从低星到高星排序对比；若所有玩家的相对顺序不冲突，则抢劫成功。真实平手允许不同星级筹码同时视为正确。

## UI Direction
- 采用横向牌桌布局，中央展示公共牌与当前轮筹码池。
- 玩家区域围绕牌桌分布；本地玩家显示底牌，其它玩家默认隐藏到底牌背面，摊牌后公开。
- 常驻文字只保留对象名、数值、短状态和按钮文案；规则说明放到帮助/规则面板，不常驻堆在主 UI。

## Additional Capability Matrix
| Capability | 本轮状态 | 理由 |
| --- | --- | --- |
| action-log | 本轮明确跳过 | 首期先完成基础可玩闭环；后续可补抢劫与筹码选择记录 |
| undo-system | 本轮明确跳过 | 筹码可更换已覆盖基础修正需求；撤销栈后续单独评估 |
| game-ai-system | 仅保留底层接口，UI 暂不交付 | 基础版需要多人判断，首期先保证本地热座与在线真人流程 |
| tutorial-engine | 本轮明确跳过 | 规则文档先落地，教程作为后续 change |
| debug-config | 仅保留底层接口，UI 暂不交付 | 可通过测试直接覆盖领域流程 |

## Candidate Shared Extractions
- 扑克牌牌型评估器未来可服务其它扑克类游戏，但本轮先放在 `src/games/the-gang/domain/` 内。
- 可交换筹码选择交互未来可能抽成通用 ranking interaction，但本轮先做游戏内命令。

## Risks
- PDF 文本抽取含图文混排噪声，规则合同必须引用已定位的基础版段落，不从乱码标题推导规则。
- 外部图片素材数量较多且文件名不语义化，首期只接入明确可用的缩略图/牌桌素材，其它资源保留候选清单。
- 3-6 人在线信息隐藏必须通过 `playerView` 验证，避免把真实平台聊天协作之外的隐藏手牌泄露给其他玩家。
