## ADDED Requirements

### Requirement: 《七大恨》正式主循环 MUST 按规则书暴露同层一级动作
《七大恨》正式局 SHALL 让玩家在回合主循环中按规则书语义处理：`手牌上限弃牌 -> 转动轮盘 -> 执行一次手牌行动及轮盘行动`，且手牌行动内部的 `执行事件 / 升级军备 / 势力行动` 必须作为并列一级入口成立，而不是被地区预选或抽象替代入口长期取代。

#### Scenario: 正式开局先完成公共推进再进入一级动作
- **GIVEN** 玩家从《七大恨》正式开局进入首回合
- **WHEN** 页面进入主循环
- **THEN** 玩家先处理手牌上限与轮盘推进
- **AND** 在进入具体地图目标或支付步骤前，页面先暴露同层一级动作语义
- **AND** 一级动作不得被“先选地区”取代为默认主入口

#### Scenario: 手牌行动内部的三种并列入口都能成立
- **GIVEN** 当前回合允许玩家执行一次手牌行动
- **WHEN** 玩家查看正式局可选的手牌行动
- **THEN** 系统必须能区分 `执行事件`、`升级军备`、`势力行动`
- **AND** 这三类入口必须落在真实可操作对象上
- **AND** 不得长期依赖“只有势力行动是真入口，其它两类只在教程或少量特殊牌上偶尔可用”的状态收口

### Requirement: 《七大恨》正式手牌 MUST 具备最小规则级身份
《七大恨》正式局的初始手牌与摸牌结果 SHALL 在运行时具备最小可追的规则级身份，至少能支持系统稳定判断该牌属于事件、军备、战术、银两或其它规则对象；不得长期以大量 `unknown` 预览壳承担正式手牌主入口。

#### Scenario: 正式开局手牌不再大面积是 unknown 壳
- **GIVEN** 玩家进入《七大恨》正式开局
- **WHEN** 系统生成各势力初始手牌
- **THEN** 正式手牌对象必须带有足以支持规则入口的类型信息
- **AND** 系统能稳定判断哪些牌可以直接作为事件或军备入口
- **AND** 不得把“显示了牌背/切片预览”视为正式规则对象已建立

#### Scenario: 正式摸牌后仍保持可追身份
- **GIVEN** 某势力在正式局中后续获得新手牌
- **WHEN** 该牌加入玩家手牌区
- **THEN** 新手牌必须延续同一套规则级身份合同
- **AND** 后续事件、军备、支付与教程链不得因为新摸牌回退成无身份壳

### Requirement: 《七大恨》地区状态 MUST 拆分默认聚焦与正式决策语义
《七大恨》正式局 SHALL 将默认聚焦、已锁来源、当前目标和展示锚点作为独立语义处理；系统不得继续依赖单一地区状态同时承担这些职责，也不得在后续 builder 中互相反写。

#### Scenario: 地图切换观察焦点不会改写已锁来源
- **GIVEN** 玩家已经进入某个需要来源区与目标区的正式步骤
- **AND** 该步骤的来源区已经锁定
- **WHEN** 玩家在地图上切换当前观察焦点或浏览其它候选区
- **THEN** 系统只更新当前焦点或展示锚点
- **AND** 不得反写该步骤已锁定的来源区

#### Scenario: 默认高亮不会冒充正式已确认目标
- **GIVEN** 某个正式步骤存在默认高亮候选区
- **WHEN** 玩家尚未明确点击确认该目标
- **THEN** 默认高亮只表示便捷聚焦或候选提示
- **AND** 页面文案、摘要和后续逻辑不得把它表述成玩家已经决定的正式来源区或目标区

### Requirement: 《七大恨》联机正式局 MUST 保持当前座位控制权
《七大恨》正式局 SHALL 始终按当前进入页面的座位显示私有手牌与可操作对象；正式教程或联机页面不得允许当前用户切换到其他势力视角替其执行一级动作、支付或地图目标。

#### Scenario: 联机页面不会替下一势力代操作
- **GIVEN** 一个《七大恨》联机房间中存在多个不同势力
- **WHEN** 当前回合控制权切换到下一势力
- **THEN** 非当前势力玩家的页面仍保持自己的私有视图
- **AND** 不得直接暴露对下一势力私有手牌、支付区或一级动作的控制权

#### Scenario: 教程示范也不破坏联机控制权心智
- **GIVEN** 玩家正在观看或体验《七大恨》教程
- **WHEN** 教程涉及多势力顺序推进
- **THEN** 教程必须明确哪些步骤是系统推进、哪些对象才是玩家当前能点的真实入口
- **AND** 不得把“切到别的势力继续执行”描述成玩家通用操作规则
