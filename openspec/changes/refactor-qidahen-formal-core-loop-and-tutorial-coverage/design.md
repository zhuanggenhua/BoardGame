## Context

《七大恨》当前已经完成三类重要收口：

1. 联机局内剧本介绍、投票、前置与私有视角隔离；
2. 正式棋盘的一级/二级交互壳、轮盘 CTA、支付/弃牌槽位与“视觉已表达就不要重复写”的常驻 UI 约束；
3. 一批真实教程截图与 closeout E2E。

但运行态审计已经证明，当前仍不能把《七大恨》判成“新游戏收工”。真缺口不是文案，而是正式规则入口和教程规则覆盖：

- 正式局大多数手牌仍是低保真对象，不能稳定承接规则书口径的 `执行事件 / 升级军备`
- `selectedRegionId` 仍承担多重职责，持续把正式心智推向“先选地区，再做动作”
- 教程虽然已有多章和多条截图链，但仍缺少对若干关键规则面的真实章节覆盖

## Goals / Non-Goals

- Goals:
  - 让正式局主循环回到规则书口径，而不是长期依赖抽象按钮和默认地区聚焦
  - 让正式手牌对象具备最小可追的规则级身份
  - 让教程从正式开局带玩家走完一个完整主循环，并补齐关键规则面的真实证据
  - 让“联机视角隔离”和“教程覆盖完整”同时成立，而不是只在 hotseat 演示单人链路
- Non-Goals:
  - 本轮不重做整套七大恨美术风格
  - 本轮不凭空发明规则书不存在的简化入口
  - 本轮不把“已有少量 seam 可跑通”包装成“正式局完整实现”

## Decisions

- Decision: 正式局必须先补手牌对象真相，再补规则书级手牌入口
  - Why: 如果正式开局大多数手牌仍是 `unknown`，那么任何“从手牌直接打出事件/军备”的 UI 只是局部 seam，不是稳定规则入口。

- Decision: 地区状态必须拆语义，不能继续依赖单一 `selectedRegionId`
  - Why: 目前它同时承担默认聚焦、来源区、目标区和展示主语，任何教程或文案都会被这层建模再次带偏。

- Decision: 教程必须从正式开局出发，而不是绕到特制残局或只演示一条按钮链
  - Why: 用户要的是“看得出一个游戏怎么运作”的基本端到端，不是局部功能样例。

- Decision: 教程章节允许分章，但必须按规则心智分章，不得把同一主循环拆成前后重复教学
  - Why: 轮盘、手牌行动、地图目标和战斗结算本来就有明确层级；章节结构应该贴规则层，不贴当前实现偶然分支。

- Decision: 联机控制权边界继续保持严格
  - Why: 《七大恨》是联机游戏。教程和正式 UI 都不能再出现“当前页面可以切去替别人执行回合”的错误暗示。

## Risks / Trade-offs

- 如果先补教程、不补正式手牌对象真相，教程很容易再次写成“抽象按钮链”，但正式局仍不可依赖。
- 如果只拆文案、不拆地区状态语义，`selectedRegionId` 仍会在 builder 和 follow-up 层把玩家心智拖回“地区先行”。
- 如果为了快速补证据继续依赖隐藏续章，主章节会继续和真实规则覆盖脱节。
- 如果为了教程稳定性引入 tutorial-only 入口或默认代打，会再次破坏联机控制权边界。

## Migration Plan

1. 先冻结 OpenSpec 边界，明确这轮不是壳层修饰，而是正式规则和教程覆盖补齐。
2. 审核正式手牌对象真相源，决定哪些牌类能立即建立正式映射，哪些需要继续补素材/规则目录。
3. 拆地区状态语义，回写 selection/dispatch/follow-up builder。
4. 重构教程章节与文案，再补 E2E 和截图证据。
5. 回写运行态审计文档，确保缺口列表与当前实现同步。

## Open Questions
