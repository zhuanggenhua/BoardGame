# Change: 收口新增游戏架构与既有技术债

## Why

扩大范围静态审计已确认共享动作提交、归档、环境依赖、交互描述、规则时序、存档与主入口职责存在可被新游戏复制的问题。用户已批准统一整改方案，并于 2026-10-23 明确要求“全部重构吧”。本 change 记录该已批准范围的实施，不另建审批环节。

## What Changes

- 完成审计整改包 R1–R7，保留现有规则、玩家交互和公共入口。
- 游戏客户端注册与服务端规则装配分离；共享描述只保存数据，运行行为在客户端显式注入。
- 交互结果与触发链使用明确的领域事件 / 正式后处理 owner。
- 存档接收、版本、迁移、保留与保存反馈由正式数据 / session owner 承担。
- 拆分诡屋规则入口、七大恨 Board 多职责，并消除已确认的运行时依赖环。
- 补齐静态依赖门禁与最小参考说明。

## Impact

涉及 game-registry、interaction-system、共享 transport、代表游戏 domain / UI 和质量脚本。UGC 已放弃，不在实施范围。第三方、SDK、插件与导入包源代码保持只读。

首轮按用户当时约束只做静态验证。用户随后明确允许测试，并于 2026-10-26 要求完成剩余四项和静默验收；当前范围包含类型门禁、构建、框架/代表游戏回归、临时本地服务和无头浏览器验证。未覆盖的生产容量目标独立记录。
