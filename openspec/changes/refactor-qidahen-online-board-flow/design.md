## Context
《七大恨》已经具备领域层的剧本人物/军备待决命令，也已经有本地入口专用的 `QidahenPregameScenarioGate`。但联机 runtime 之前没有“剧本介绍 + 投票 + 前置”的局内 setup seam，建房阶段会直接写入剧本结果，正式棋盘只剩“阻断提示”而没有对应操作 UI。另一方面，领域层缺少稳定的 viewer 语义兜底，导致正式棋盘曾按当前行动势力渲染底部手牌，在联机或观战语义下会泄露私有信息并制造“切到别人的视角”假象。

## Goals
- 让《七大恨》在线房间通过同一套“局内剧本介绍与投票 → 局内前置 → 正式牌桌”流程进入首回合。
- 让《七大恨》本地与既有领域测试继续保留可控入口，不因联机流程改造而被迫全部改成投票起手。
- 让正式牌桌按当前座位展示私有信息与可操作对象，不再跟着当前行动势力切换。
- 让一级行动、二级行动和地图点击拥有明确主次，用户能一眼看出当前唯一下一步。
- 让首回合攻城/派兵等高风险分支能以端到端证据证明可继续推进。

## Non-Goals
- 本轮不重做《七大恨》地图素材、区域工具或全部美术风格。
- 本轮不引入新的房间外快捷入口或额外测试专用产品按钮。

## Decisions
- Decision: 在线房间先进入“剧本介绍 + 投票”局内层，投票结算后再进入人物/军备前置。
  - Why: 剧本本体并不只是一个房间参数，它还承担介绍阅读、候选对比和全员裁定职责。把最终结果提前写死在建房页，会让联机缺少真实公共决策入口。
- Decision: 复用“局内 setup 壳层”而不是继续把剧本待决留在正式棋盘内联提示。
  - Why: setup 与正式牌桌是两种不同语义；前者是开局配置，后者是回合操作。继续混在同一 HUD 只会造成阻塞和遮挡。
- Decision: 通过显式房间模式标记控制“是否启用局内剧本投票”，而不改掉领域层默认 setup 入口。
  - Why: 联机流程要进入投票态，但既有 direct setup、规则测试和本地场景不能被一刀切破坏。显式房间标记能让联机走新口径，同时保留老入口的稳定性。
- Decision: `playerView` 负责裁掉非当前座位的私有手牌，正式棋盘再按 `playerID` 决定底部手牌与按钮归属。
  - Why: 只改 UI 不足以防止联机泄露；必须先把权威状态裁到 seat view，再让 UI 用同一语义展示。
- Decision: 当当前 viewer 解析不到 seat / faction 时，不再回退成“当前行动势力”的私有视图。
  - Why: 这种 fallback 本质上就是本地同屏思路，会把联机页面错误切到别人的手牌与私有候选。
- Decision: 一级行动只负责“选择当前主动作”，二级交互只在动作锁定后出现；地图点击仅在当前二级交互明确需要地图目标时开放。
  - Why: 这能把“当前主交互对象”“固定槽位”“让位顺序”锁成单一来源，避免用户从地图、按钮、手牌三处同时猜。
- Decision: 房间创建阶段不再承接《七大恨》剧本本体和剧本细项选择；建房页只写入“局内投票模式”标记。
  - Why: 用户要验证的是联机对局流程，不是建房表单；剧本介绍、投票和剧本细项都只有在进入 match 后才与座位/势力归属同屏成立。

## Risks / Trade-offs
- 把剧本本体与剧本细项都移出建房弹窗后，联机房间首次进入会多出“介绍/投票 → 前置”两段 setup。
  - Mitigation: 这两段都在局内一次性完成；投票结算后只保留该剧本真正需要的前置项，不再重复。
- `playerView` 会改变现有测试和 AI 可见状态。
  - Mitigation: 保持领域真相不变，只在 seat view 裁剪私有手牌；AI 仍通过自己的 seat view 决策。
- 行动壳重排可能影响已有按钮 test id。
  - Mitigation: 复用现有测试 id 家族，并为一级/二级壳新增稳定 test id。

## Migration Plan
1. 先补 OpenSpec 与流程规则。
2. 实现 `playerView` 与正式棋盘视角切换。
3. 把《七大恨》局内“剧本介绍 + 投票”壳层接到 online runtime，并移除建房表单里的剧本本体/细项入口。
4. 重构一级/二级行动壳与地图可点击门禁。
5. 回跑定向测试与 E2E，补截图证据。

## Open Questions
- 无。本轮正式口径就是“剧本介绍、投票、人物前置、军备前置全部在局内完成”；建房阶段只负责房间级模式参数。
