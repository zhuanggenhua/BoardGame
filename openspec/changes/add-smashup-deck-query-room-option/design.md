## Context

这个需求同时跨越了：

- 大杀四方房间 setup 配置与运行时读法
- 游戏内牌库查看 UI 权限控制
- 大厅房间广播 payload
- 房间卡片的扩展摘要展示

当前大厅广播只透出 `roomName / owner / password / players` 等基础字段，不适合直接把完整 `setupData` 原样暴露给前端房间列表。

## Goals

- 为大杀四方增加一个默认关闭的 `余牌查询` 房规项，并将其并入现有扩展多选组。
- 让牌库查看能力完全服从该房间选项。
- 在大厅安全地展示“已开启扩展”摘要。
- 保持房间卡片摘要可读，扩展 tag 直接显示完整展示名。

## Non-Goals

- 不把所有房间 setup 选项都搬到大厅卡片。
- 不重做大厅房间卡片整体视觉结构。
- 不扩展到其他游戏的牌库查看权限模型。

## Decisions

- Decision: `余牌查询` 作为大杀四方独有 setup 字段进入 manifest，而不是塞进通用 lobby 逻辑。
  - Why: 这是 SmashUp 专属规则开关，不属于跨游戏通用能力。

- Decision: `余牌查询` 与 `泰坦`、`DIY` 共用同一个多选组，而不是单独渲染成第二个字段。
  - Why: 最新交互口径要求它和现有 SmashUp 扩展入口放在一起，避免用户在创建房间时面对两处分散配置。

- Decision: Lobby 只广播“公开 setup 摘要”而不是完整 `setupData`。
  - Why: `setupData` 里可能带 `ownerKey / password / guestId / AI seatControllers` 等不该进入房间卡片的数据。

- Decision: 房间扩展摘要只展示“已开启扩展”，不展示 `余牌查询`。
  - Why: 用户明确要的是“已开启扩展”的加入前提示，房间规则开关和扩展包不是同一类信息。

- Decision: 扩展 tag 在展示层直接使用完整展示名。
  - Why: 最新需求明确取消字数限制，房间列表应优先保留完整扩展信息。

- Decision: `余牌查询` 关闭时，牌库区仍显示剩余数量，但不能打开剩余牌详情面板。
  - Why: 最新产品口径只限制“查询详情”能力，不影响牌堆数量这一层公开信息。

- Decision: `余牌查询` 开启时，对手视角下的牌库区也按当前视角玩家的数据工作。
  - Why: 对手视角本质上是在查看另一位玩家的公开牌区，开启查询后应能连带查看该视角玩家的余牌信息。

## Risks / Trade-offs

- 房间广播新增公开摘要字段后，前后端类型需要同步，旧测试可能依赖 `LobbyMatch` 形状。
- 完整扩展名可能让极端长标签占用更多卡片宽度，若后续扩展名继续增长，再评估专用短标签字段或布局压缩方案。

## Validation Plan

- 对 setup 解析补单测，确保默认关闭与显式开启都能透传到大杀四方运行时。
- 对 lobby payload/房间卡片补单测，确保只暴露公开摘要且 tag 显示完整展示名。
- 跑大杀四方 E2E，覆盖：
  - `余牌查询` 关闭时仍显示剩余数量，且点击牌库不出现查看面板
  - `余牌查询` 开启时可查看剩余牌详情
  - `余牌查询` 开启时切到对手视角也能查看对应牌库
  - 房间卡片显示完整扩展 tag
