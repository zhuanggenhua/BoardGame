## ADDED Requirements

### Requirement: 系统必须采用引擎式页面内场景编辑模型
系统 MUST 将 UI authoring 建模为“真实页面内编辑”的引擎式场景编辑能力，而不是停留在 YAML 文本调试原型。

#### Scenario: 首页 V2 进入作者模式
- **GIVEN** 首页 V2 已接入 UI scene runtime
- **WHEN** 作者通过显式入口进入 `?author=1`
- **THEN** 系统 MUST 在真实页面中开启场景编辑能力
- **AND** MUST 允许作者直接操作页面上的真实 UI 节点

### Requirement: 作者模型必须区分场景文档、编辑会话态和 YAML 真源
系统 MUST 将作者模型拆分为 `Scene Document`、`Editor Session` 和 `YAML Source` 三层，不得让高频交互直接以 YAML 文本作为唯一状态源。

#### Scenario: 拖拽节点时不直接依赖 YAML 文本
- **GIVEN** 作者正在页面中拖拽一个节点
- **WHEN** 指针持续移动
- **THEN** 系统 MUST 先更新编辑会话态中的实时预览结果
- **AND** MUST NOT 要求每一帧都先回写 YAML 文本才能更新页面

#### Scenario: 保存时将场景文档序列化为 YAML
- **GIVEN** 作者已完成一轮布局编辑
- **WHEN** 作者执行保存
- **THEN** 系统 MUST 从场景文档生成 YAML 持久化结果
- **AND** MUST 保持 YAML 作为长期真源

### Requirement: 编辑态与正式态必须复用同一内容渲染器
系统 MUST 让编辑态与正式显示态复用同一套内容渲染器，避免两套实现产生偏差。

#### Scenario: 编辑态中的节点排版与正式态一致
- **GIVEN** 某个节点在正式页面中已经通过 scene runtime 渲染
- **WHEN** 页面切换到作者模式
- **THEN** 系统 MUST 复用同一内容渲染结果
- **AND** MUST 仅额外叠加作者辅助层

### Requirement: 拖拽与缩放必须具备跟手体验
系统 MUST 让拖拽、缩放和位置调整具备接近游戏引擎或成熟低代码平台的跟手体验。

#### Scenario: 拖拽节点时实时跟随指针
- **GIVEN** 作者选中了一个可移动节点
- **WHEN** 作者按下并拖动该节点
- **THEN** 节点的实时预览位置 MUST 按指针移动连续更新
- **AND** MUST 不出现“必须等待 YAML 重算后才移动”的卡顿式交互

#### Scenario: 缩放节点时实时更新预览框
- **GIVEN** 作者拖动节点缩放手柄
- **WHEN** 指针持续移动
- **THEN** 系统 MUST 实时更新节点预览尺寸
- **AND** MUST 在提交点写回最终文档结果

### Requirement: 缩放控制柄与修饰键必须符合专业编辑器习惯
系统 MUST 为单节点与多选组提供清晰的缩放控制柄，并支持常见修饰键交互，以降低作者迁移成本。

#### Scenario: 选中节点后显示 8 向缩放控制柄
- **GIVEN** 作者选中了一个可调整尺寸的节点
- **WHEN** 选框显示在画布上
- **THEN** 系统 MUST 提供角点与边中点共 8 个缩放控制柄

#### Scenario: 使用修饰键调整缩放行为
- **GIVEN** 作者正在拖动缩放控制柄
- **WHEN** 作者按住 `Shift` 或 `Alt`
- **THEN** 系统 MUST 支持锁定宽高比或以中心点缩放等专业编辑器常见行为

### Requirement: 跟手交互必须使用统一交互热路径
系统 MUST 通过统一的交互热路径处理拖拽、缩放、吸附和容器命中，而不是让不同面板分别改文档。

#### Scenario: 拖拽时命中容器并显示高亮
- **GIVEN** 作者正在拖动一个节点
- **WHEN** 指针移动到某个可接收子节点的容器区域
- **THEN** 系统 MUST 在统一交互层识别该容器命中
- **AND** MUST 显示容器高亮或插入反馈

#### Scenario: 拖拽时显示吸附线
- **GIVEN** 页面中存在可吸附的边界或参考线
- **WHEN** 节点接近吸附位置
- **THEN** 系统 MUST 显示对应吸附线
- **AND** MUST 让实时预览结果应用该吸附

### Requirement: 系统必须支持多选与组边界框
系统 MUST 允许作者通过画布框选或追加选择形成多选，并以统一组边界框承载后续批量操作。

#### Scenario: 框选多个节点
- **GIVEN** 画布上存在多个可选节点
- **WHEN** 作者通过拖拽选区框住多个节点
- **THEN** 系统 MUST 一次性选中这些节点
- **AND** MUST 显示多选组边界框

#### Scenario: 通过组边界框批量移动或缩放
- **GIVEN** 当前有多个节点处于选中状态
- **WHEN** 作者拖动组边界框或其控制柄
- **THEN** 系统 MUST 对整组选中节点执行批量移动或批量缩放

### Requirement: 多选批量排版必须支持主参考对象
系统 MUST 为多选批量排版提供主参考对象，以支持接近 Figma / Penpot 的批量对齐、分布与统一尺寸行为。

#### Scenario: 在多选中切换主参考对象
- **GIVEN** 当前有多个节点处于选中状态
- **WHEN** 作者再次点击其中一个已选中节点或通过等价入口指定主参考对象
- **THEN** 系统 MUST 将该节点标记为主参考对象
- **AND** MUST 在画布或面板中提供可见反馈

#### Scenario: 以主参考对象执行批量排版
- **GIVEN** 当前有多个节点处于选中状态且已存在主参考对象
- **WHEN** 作者执行左对齐、顶对齐、垂直分布、同宽或同尺寸等批量排版操作
- **THEN** 系统 MUST 按主参考对象或等价专业编辑器规则计算结果
- **AND** MUST 将结果写回结构化场景文档

### Requirement: 键盘编辑命令必须覆盖微调与常用清理动作
系统 MUST 让作者在不离开画布的情况下，通过键盘完成微调、删除、撤销、重做和取消选择等高频动作。

#### Scenario: 使用方向键微调节点
- **GIVEN** 当前至少有一个节点处于选中状态
- **WHEN** 作者按下方向键或 `Shift + 方向键`
- **THEN** 系统 MUST 支持小步长与大步长位移微调

#### Scenario: 使用删除与撤销重做命令
- **GIVEN** 当前至少有一个节点处于选中状态或最近刚执行过一次编辑命令
- **WHEN** 作者按下 `Delete`、撤销快捷键、重做快捷键或 `Esc`
- **THEN** 系统 MUST 支持删除、撤销、重做或取消当前选择
- **AND** MUST 保持画布与辅助面板状态同步

### Requirement: 场景必须建模为正式节点树
系统 MUST 将 scene 建模为正式节点树，而不是仅维护一组区域矩形。

#### Scenario: 页面元素以树结构组织
- **GIVEN** 某个页面包含标题区、按钮区、详情区和装饰元素
- **WHEN** 系统描述该页面
- **THEN** 系统 MUST 使用父子节点树表达这些结构
- **AND** 每个节点 MUST 拥有稳定的 `id` 和父级关系

### Requirement: 容器必须是一等节点能力
系统 MUST 将容器作为正式节点能力，支持子节点挂载、重排和布局计算。

#### Scenario: 将一个标题和两个按钮放入容器
- **GIVEN** 作者需要将多个元素组织成一个可重排区域
- **WHEN** 作者创建容器节点并放入子节点
- **THEN** 系统 MUST 允许该容器拥有子节点
- **AND** MUST 允许子节点在容器内调整顺序与布局

### Requirement: 第一阶段至少支持自由容器、纵向容器、横向容器和网格容器
系统 MUST 在第一阶段提供最小可用容器集合，以支撑首页 V2 和后续图片化页面。

#### Scenario: 创建自由容器
- **GIVEN** 作者需要放置可自由定位的书签或装饰元素
- **WHEN** 作者选择容器类型
- **THEN** 系统 MUST 提供自由容器

#### Scenario: 创建纵向或横向容器
- **GIVEN** 作者需要组织标题、按钮组或条目列表
- **WHEN** 作者选择容器类型
- **THEN** 系统 MUST 提供纵向容器和横向容器

#### Scenario: 创建网格容器
- **GIVEN** 作者需要组织宫格入口或卡片区域
- **WHEN** 作者选择容器类型
- **THEN** 系统 MUST 提供网格容器

### Requirement: 容器必须支持基础布局属性
系统 MUST 让容器至少支持 padding、gap、align、justify、clip 和子项顺序。

#### Scenario: 编辑容器内边距和间距
- **GIVEN** 作者选中了一个容器节点
- **WHEN** 作者在属性面板中修改容器布局属性
- **THEN** 系统 MUST 支持修改 padding 与 gap
- **AND** MUST 将结果应用到该容器的真实排版

### Requirement: 系统必须支持节点重挂载与容器内重排
系统 MUST 支持将节点从一个父级移动到另一个父级，并支持同容器内排序调整。

#### Scenario: 将节点拖入另一个容器
- **GIVEN** 页面中存在两个可接收子节点的容器
- **WHEN** 作者将某个节点拖入另一个容器
- **THEN** 系统 MUST 更新该节点的父级关系
- **AND** MUST 保持该节点的结构化文档可保存

#### Scenario: 调整容器内顺序
- **GIVEN** 某个容器已有多个子节点
- **WHEN** 作者调整这些子节点顺序
- **THEN** 系统 MUST 保存新的排序结果

### Requirement: 容器拖放必须提供可预判的插入反馈
系统 MUST 在容器拖放过程中提供 inside 高亮、插入条或插入槽位等反馈，帮助作者预判最终落点。

#### Scenario: 拖入容器主体时显示 inside 提示
- **GIVEN** 作者正在拖动一个节点
- **WHEN** 指针进入可接收子节点的容器主体区域
- **THEN** 系统 MUST 显示容器 inside 高亮或等价反馈

#### Scenario: 在流式容器中显示插入条
- **GIVEN** 作者正在拖动一个节点经过纵向或横向容器
- **WHEN** 当前落点对应某个子节点前后插入位置
- **THEN** 系统 MUST 显示插入条或插入槽位
- **AND** 在释放后 MUST 按该位置完成重排或重挂载

### Requirement: 系统必须提供层级树
系统 MUST 在作者模式中提供层级树，以便作者查看、选择、展开和定位场景节点。

#### Scenario: 通过层级树选择节点
- **GIVEN** 作者模式已开启
- **WHEN** 作者点击层级树中的某个节点
- **THEN** 系统 MUST 选中对应真实页面节点
- **AND** MUST 在页面中显示该节点选框

### Requirement: 系统必须提供属性面板
系统 MUST 在作者模式中提供属性面板，用于编辑布局、外观、资源和交互属性。

#### Scenario: 在属性面板中修改节点布局
- **GIVEN** 作者选中了一个节点
- **WHEN** 作者在属性面板中修改位置、尺寸或容器属性
- **THEN** 系统 MUST 更新该节点场景文档
- **AND** 页面 MUST 反映最新结果

#### Scenario: 在属性面板中执行多选批量排版
- **GIVEN** 作者当前选中了多个节点
- **WHEN** 作者在属性面板中执行对齐、分布或统一尺寸
- **THEN** 系统 MUST 允许在同一批量编辑区完成这些操作
- **AND** MUST 在属性面板中展示当前主参考对象或等价批量编辑上下文

### Requirement: 作者辅助 UI 必须直接使用中文
系统 MUST 让作者模式中的辅助 UI 直接使用中文，不得以英文技术标签作为面向作者的默认文案。

#### Scenario: 打开作者模式面板
- **GIVEN** 作者进入作者模式
- **WHEN** 系统显示工具条、层级树、属性、资源和 YAML 面板
- **THEN** 这些面板标题、字段名、按钮和提示语 MUST 使用中文

#### Scenario: 节点类型在作者界面中显示中文标签
- **GIVEN** 系统内部仍以英文 ID 表示节点类型
- **WHEN** 作者在界面中查看节点类型或插入菜单
- **THEN** 系统 MUST 显示中文标签

### Requirement: 作者模式必须提供中文工具条
系统 MUST 提供面向作者的中文工具条，承载模式切换和高频动作。

#### Scenario: 作者查看高频操作入口
- **GIVEN** 作者已进入页面编辑态
- **WHEN** 页面加载完成
- **THEN** 系统 MUST 提供中文工具条
- **AND** 工具条 MUST 能承载选择、移动、容器、资源、YAML、保存等作者动作

### Requirement: 作者辅助 UI 必须采用可收起抽屉并为工作区让位
系统 MUST 将图层、属性、资源、源码等辅助 UI 做成可收起抽屉或等价停靠面板，并在打开时为画布工作区让位。

#### Scenario: 打开侧边抽屉时画布工作区自动收缩
- **GIVEN** 作者模式已开启且左侧或右侧抽屉处于关闭状态
- **WHEN** 作者打开图层树或属性抽屉
- **THEN** 系统 MUST 调整工作区留白或画布容器尺寸
- **AND** MUST 避免抽屉直接压住可编辑内容

#### Scenario: 打开底部抽屉时仍可继续操作画布
- **GIVEN** 作者模式已开启
- **WHEN** 作者展开底部源码、资源或组件抽屉
- **THEN** 系统 MUST 为底部面板让位
- **AND** 画布剩余区域 MUST 继续保持可见和可操作

### Requirement: 作者模式必须提供资源面板
系统 MUST 在作者模式中提供正式资源面板，而不是要求作者只靠手写资源路径。

#### Scenario: 为节点选择图片资源
- **GIVEN** 作者选中了一个图片节点或使用皮肤的节点
- **WHEN** 作者打开资源面板
- **THEN** 系统 MUST 允许作者浏览可用资源并选择资源
- **AND** MUST 将选择结果回写为受控资源引用

### Requirement: 资源系统必须统一支持本地、服务器资源和上传后继续引用
系统 MUST 让 scene/skin 资源引用统一兼容本地资源、已发布到服务器资源主源 的资源以及新上传资源。

#### Scenario: 引用本地资源
- **GIVEN** 某张素材仅存在于本地
- **WHEN** 作者在 scene 或 skin 中引用该素材
- **THEN** 系统 MUST 能解析该资源并在本地开发环境中使用

#### Scenario: 引用已发布到服务器资源主源 的资源
- **GIVEN** 某张素材已经发布到服务器资源主源
- **WHEN** 作者在 scene 或 skin 中引用该素材
- **THEN** 系统 MUST 通过统一资源解析链路读取该资源

#### Scenario: 上传后继续沿用同一逻辑引用
- **GIVEN** 某张素材先在本地被引用，随后被发布到服务器资源主源
- **WHEN** 该 scene 再次被加载
- **THEN** 系统 MUST 允许继续使用同一逻辑资源引用
- **AND** MUST NOT 要求作者手工把 YAML 改成最终 CDN URL

### Requirement: 系统必须以 assetRef 作为首选逻辑资源引用
系统 MUST 将 `assetRef` 作为 scene 与 skin 的首选逻辑资源引用格式，并将其作为 AI 与人工协作默认写法。

#### Scenario: 在 YAML 中引用资源
- **GIVEN** 作者需要在 YAML 中为节点设置图片资源
- **WHEN** 作者编写 scene 或 skin
- **THEN** 系统 SHOULD 允许通过 `assetRef` 引用逻辑资源

### Requirement: 系统必须支持作者模式中的资源上传链路
系统 MUST 为作者模式提供上传链路，使新素材能进入统一资源体系。

#### Scenario: 上传新素材并用于当前页面
- **GIVEN** 作者需要为当前场景新增一张素材
- **WHEN** 作者在资源面板中上传该素材
- **THEN** 系统 MUST 将该素材纳入统一资源注册表
- **AND** MUST 允许作者立即在当前 scene 中引用它

### Requirement: YAML 仍然是长期真源
系统 MUST 继续使用 YAML 作为长期持久化真源，供 AI 和人工协作编辑。

#### Scenario: AI 修改场景结构
- **GIVEN** 用户要求 AI 继续修改某个场景
- **WHEN** AI 输出新的场景结构
- **THEN** 系统 MUST 允许 AI 修改 YAML 或结构化 patch
- **AND** MUST 让这些变更最终可回写为 YAML

### Requirement: YAML 面板必须是同步视图与协作出口，而不是高频交互核心
系统 MUST 将 YAML 面板定位为同步视图和协作出口，不得将其作为拖拽热路径中的唯一状态源。

#### Scenario: 拖拽后同步 YAML 面板
- **GIVEN** 作者在页面中完成一次拖拽
- **WHEN** 该拖拽提交到场景文档
- **THEN** 系统 MUST 将最新结果同步到 YAML 面板
- **AND** 该同步 MAY 采用节流或提交式更新

### Requirement: 系统必须支持命令式编辑提交
系统 MUST 以命令式提交承载作者变更，以支持稳定的文档更新和后续撤销/重做扩展。

#### Scenario: 移动节点生成结构化提交
- **GIVEN** 作者移动了一个节点
- **WHEN** 该操作提交到场景文档
- **THEN** 系统 MUST 以结构化命令或等价 mutation 更新文档
- **AND** MUST NOT 仅通过拼接 YAML 字符串完成核心变更

### Requirement: 场景节点必须继续受控白名单化
系统 MUST 将场景节点限制在受控白名单内，不得在第一阶段开放任意脚本或任意 JSX。

#### Scenario: 使用受控节点搭建页面
- **GIVEN** 作者需要搭建首页 V2 书页内容区
- **WHEN** 作者插入节点
- **THEN** 系统 MUST 提供受控节点类型
- **AND** MUST NOT 要求把任意 React 代码直接写入 YAML

### Requirement: 节点与字段必须具有作者侧中文元数据
系统 MUST 为作者模式中的节点与字段提供中文元数据，以驱动属性面板、插入菜单和提示文案。

#### Scenario: 属性面板渲染字段标签
- **GIVEN** 属性面板需要渲染节点字段
- **WHEN** 系统展示字段名和分组名
- **THEN** 系统 MUST 使用字段中文元数据渲染这些文案

### Requirement: 交互节点继续使用受控 actionId
系统 MUST 继续让交互节点使用受控 `actionId`，并由宿主页面完成实际行为绑定。

#### Scenario: 按钮触发宿主行为
- **GIVEN** 某个按钮用于切换首页页签
- **WHEN** 作者在场景中配置该按钮
- **THEN** 节点 MUST 通过 `actionId` 表达动作意图
- **AND** 宿主页面 MUST 提供对应 handler

### Requirement: 编辑态入口必须显式且受权限门禁控制
系统 MUST 通过 route、query 或等价显式入口进入编辑态，并在生产环境下进行权限校验。

#### Scenario: 开发环境通过 query 进入作者模式
- **GIVEN** 当前为开发环境
- **WHEN** 作者访问带 `author=1` 的页面
- **THEN** 系统 MAY 直接进入作者模式

#### Scenario: 生产环境校验权限
- **GIVEN** 当前为生产环境
- **WHEN** 用户试图访问作者模式
- **THEN** 系统 MUST 校验管理员、白名单或等价权限
- **AND** 未通过校验时 MUST 拒绝显示作者辅助 UI

### Requirement: 作者辅助层不得改变真实内容布局
系统 MUST 让选框、手柄、层级面板、属性面板、资源面板和 YAML 面板与正式内容布局解耦。

#### Scenario: 开启作者模式后真实页面排版保持不变
- **GIVEN** 页面已有正式内容布局
- **WHEN** 作者模式开启
- **THEN** 系统 MUST 保持真实内容节点的排版结果不变
- **AND** 仅通过 overlay、portal 或等价方式叠加作者辅助层

### Requirement: 编译与保存链路必须可定位错误
系统 MUST 让编译、校验、保存和资源解析错误具备清晰定位信息，便于人工和 AI 修复。

#### Scenario: 保存时容器字段非法
- **GIVEN** 某个容器字段配置不合法
- **WHEN** 系统执行编译或保存
- **THEN** 错误结果 MUST 包含文件、字段路径、错误代码和人类可读原因

#### Scenario: 资源解析失败
- **GIVEN** 某个 assetRef 无法解析
- **WHEN** 系统执行编译或保存
- **THEN** 错误结果 MUST 指向具体资源引用位置

### Requirement: 首页 V2 必须作为首个引擎式 adopter 完成迁移
系统 MUST 以首页 V2 作为首个 adopter，验证场景树、容器、中文辅助 UI 和资源作者链路。

#### Scenario: 首页 V2 使用新作者模式
- **GIVEN** 首页 V2 已接入新的场景编辑架构
- **WHEN** 作者进入 `?author=1`
- **THEN** 系统 MUST 提供场景树编辑、容器布局、中文辅助 UI 和资源编辑能力
- **AND** 正式态页面 MUST 与编辑态内容渲染保持一致
