## ADDED Requirements

### Requirement: 七大恨正式棋盘 MUST 提供固定交互槽位
《七大恨》正式棋盘 SHALL 将“右侧行动交互区”和“底部手牌交互区”作为固定槽位使用。承担推进、确认、选择、取消职责的 UI 不得因为说明块、状态块或瞬时面板出现而离开各自槽位。

#### Scenario: 轮盘与势力行动共存时仍保持固定槽位
- **GIVEN** 玩家已经进入《七大恨》正式棋盘
- **AND** 当前页面同时存在轮盘、行动按钮、手牌区和地图主视图
- **WHEN** 玩家进入轮盘推进、势力行动选择或手牌支付/弃牌步骤
- **THEN** 右侧行动交互区仍固定停留在右侧 rail
- **AND** 底部手牌交互区仍固定停留在底部手牌槽位
- **AND** 说明性内容不得把这两块真实可操作 UI 顶走、压窄或移出视口

### Requirement: 七大恨轮盘唯一下一步 MUST 提供明文 CTA
当《七大恨》当前合法推进步骤只剩轮盘动作时，系统 SHALL 在正式棋盘提供明文按钮或等价 CTA，直接告诉玩家“下一步点这里”，不得只依赖点击轮盘盘面本体。

#### Scenario: 只剩轮盘推进时显示明文按钮
- **GIVEN** 当前势力行动已经完成
- **AND** 当前没有剧本待决项、支付弃牌步骤或其他待选分支
- **AND** 当前仍存在可执行的轮盘推进选项
- **WHEN** 玩家查看正式棋盘
- **THEN** 右侧行动交互区显示轮盘推进 CTA
- **AND** CTA 文案直接表达这是“下一步”或“点击此处推进回合”

### Requirement: 七大恨消耗型手牌交互 MUST 先显式选择并允许取消
《七大恨》里任何需要弃牌、支付、手牌超限弃牌或同语义消耗型手牌交互 SHALL 先进入显式选择态，并通过底部手牌区承接；该状态必须同时提供动作名/成本、已选数量、确认入口，以及在语义允许时的取消入口。

#### Scenario: 势力行动支付先选牌再确认
- **GIVEN** 玩家点击一个需要弃牌支付成本的势力行动
- **WHEN** 系统进入支付步骤
- **THEN** 底部手牌交互区明确显示当前动作、所需成本与已选数量
- **AND** 玩家需要先点击手牌选择要弃掉的牌
- **AND** 系统提供确认执行入口
- **AND** 系统提供取消本次行动入口

#### Scenario: 手牌超限弃牌通过底部手牌区收口
- **GIVEN** 某势力在回合检查时超出手牌上限
- **WHEN** 系统进入弃牌步骤
- **THEN** 底部手牌交互区明确显示需弃数量与已选数量
- **AND** 玩家通过底部手牌区完成弃牌选择
- **AND** 系统仅在满足弃牌数量后允许确认提交

### Requirement: 七大恨关键交互证据截图 MUST 使用中文语义命名
《七大恨》正式棋盘的关键验收截图 SHALL 使用中文语义命名，至少表达当前阶段或页面、动作对象以及动作前/动作中/动作后状态，避免后续审查无法判断截图在证明什么。

#### Scenario: 弃牌选择截图可直接读懂步骤
- **GIVEN** 开发者为《七大恨》支付或弃牌流程生成验收截图
- **WHEN** 其他人查看截图文件名
- **THEN** 文件名中直接出现中文阶段与动作语义，例如“弃牌选择”“确认执行”或“手牌超限”
- **AND** 查看者无需依赖 test id、代码字段名或实现上下文猜测截图含义
