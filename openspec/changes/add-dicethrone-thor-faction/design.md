# 索尔实现边界与交互设计

## Owner裁定

本轮新增英雄内容owner `heroes/thor/` 与专属规则消费owner `domain/customActions/thor.ts`，扩展现有角色/骰子/Token registry；不新增平台系统或第二套结算状态。静态定义与本地化只消费录入合同。

锤子是正式同伴指示物，不是攻击伤害。优先使用既有Token持有关系表达位置；若当前选角合同允许多个索尔同时在场，必须在实现前改用能区分所属英雄的唯一位置状态。该前提不可按单测夹具猜测。

## 已确认交互模式

来源：雷神提示板/官方Q&A、现有DiceThrone `PassiveAbilityPanel`、进攻投掷结束Token选择、`CHOICE_REQUESTED`与奖励骰结算。完整原文与门槛见录入核对表。

| 玩家任务 | 第一入口/选择顺序 | 确认与结果/收口 |
| --- | --- | --- |
| 弃牌飞掷/召回锤子 | 既有主动动作栏；选择弃哪张真实手牌，飞掷时选择规则允许的敌人 | 正式选择提交后弃牌、移动指示物；飞掷立即结算独立伤害，召回获得驭电；不另加确认壳 |
| 技能要求锤子移动 | 技能原有入口；只有规则保留选择权时用既有choice | 无须弃牌；次数、可选跳过、逐次目标与附加规则分别消费；后续回原技能结算 |
| 破防 | 现有进攻投掷结束Token选择，可使用或跳过 | 支付1、显示正式奖励骰、4/5使本次攻击不可防御；可继续花费另一枚 |
| 驭电抽牌 | 既有主动动作栏，主要阶段且4枚可用；其它状态保持同一禁用入口 | 花费4、抽1、每回合一次；重置消费既有回合边界 |
| 奖励骰/任选骰重掷 | 现有骰区/奖励骰选择与确认 | 用同源骰面、真实随机和正式重掷授权；0颗/至多N的跳过路径按来源保留 |

外部发布范围仅索尔正式媒体的定向上传；不包含生产Web/服务端部署。
