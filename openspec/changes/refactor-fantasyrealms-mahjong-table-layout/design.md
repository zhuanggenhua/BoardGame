## Context
`fantasyrealms` 现有 Board 虽然已经换上正式卡图，但结构上仍是典型 Web 三栏页：状态栏、内容栏、说明栏互相抢面积。结果是首屏视觉焦点被多个盒子打散，玩家不是“坐在牌桌前”，而是在“看一页牌桌数据面板”。

当前用户已经进一步给出更强裁决：早先 `fr-ui-current-*` 虽然代表过一次收口方向，但其中仍保留底部常驻提示横条；当前正式方向应以前移后的 `fr-merge-pass2-opening / after-draw / after-select` 真实运行态为准。
因此这份 design 不再继续论证“麻将桌候选是否合理”，而是直接解释当前 `fr-merge-pass2` live 路线的结构原则：
- 无待处理对象时，先保留干净牌桌
- 有待处理对象时，只把当前这一步要处理的牌推到桌面中央
- 回合、局况、分数、确认动作都退到边缘物件
- 提示/分析不得再以底边常驻横条出现；若必须存在，只能是贴边短标签或临时态提示，不能替代牌桌本身
- 桌面 live 页面几乎不保留描述性说明文字；能用位置、数字、状态高亮表达的，不再写成解释块

## Goals / Non-Goals
- Goals:
  - 用 `fr-merge-pass2` 中央承接路线重建 `fantasyrealms` 桌面端主布局。
  - 让首屏阅读顺序回到“当前要处理的牌 → 下一步动作 → 边缘状态”。
  - 把 `fr-merge-pass2` live 路线正式翻正，并把旧候选降级为历史材料。
  - 把“PC 真实页先过，再做移动端”写入项目门禁。
- Non-Goals:
  - 不再继续维护第二套正式桌面候选。
  - 不做多套视觉风格比稿。
  - 不在本轮解决移动端细排或终局微交互。

## Reference Conclusions
基于当前已批准的 `fr-merge-pass2-*` 三张真图，这条路线的空间组织原则是：

1. 当前步骤优先
   - 当前真正要处理的牌必须居中。
   - 玩家不应先扫侧栏，再猜这一步到底该点什么。

2. 空态保持安静
   - 没有待处理对象时，牌桌可以留白。
   - 不需要为了“看起来完整”硬塞永久手牌带、空河或占位盒。

3. 角落承载状态，而非主区承载状态
   - 牌库余量、当前回合、玩家分数、终局阈值都应变成角落/边缘部件。
   - 这些信息要随时可读，但不能把主区切碎。

4. 提示区贴边，不替代牌桌
   - 对桌面进行页来说，解释块默认直接退场。
   - 只允许留下细提示轨、边缘短标签或终局复盘态的必要信息。

## Layout Decisions
### 1. 桌面端主构图
- 左侧：
  - `牌库物件`
- 顶部：
  - `回合 / 阶段 / 进度` 的极简状态轴
- 中央：
  - `当前这一步要处理的牌`
  - 包括待摸牌、待弃牌、公开候选或待确认对象
- 右侧：
  - `确认动作 + 分数摘要`
- 底部：
  - `默认留空，不再放当前正式方向的常驻提示横条`
- 终局附加：
  - `最终排名` 在终局时浮层化或中层展开
  - 不在进行中常驻占位

### 2. 信息权重
- 一级：当前步骤正在处理的牌
- 二级：回合状态、牌库余量、当前总分、确认动作
- 三级：终局说明、细分计分、历史复盘

### 3. 布局禁止项
- 禁止继续使用三栏等权布局。
- 禁止继续把旧麻将桌候选写成当前正式方向。
- 禁止继续让 `current` 与 `rework-v*` 同时冒充“当前桌面完成态”。
- 禁止把大块解释文案长期放在右栏。
- 禁止在桌面进行页常驻任何描述性说明块，包括规则说明、观察者说明、推演说明、长标签空态。
- 禁止让空态公开区成为最大的视觉盒子。
- 禁止在进行中常驻大终局面板或大计分纸。
- 禁止把牌库、回合、分数、公开区、手牌都渲染成同级厚方框。

## Sequencing Decision
实施顺序固定为两阶段：

1. `PC-first`
   - 先完成桌面端真实页
   - 先验证 opening / live discard / gameover 三个关键状态
   - 先清零阻塞级桌面端 UI bug

2. `Mobile-after-PC`
   - 仅当桌面端真实页达标后，才进入移动端适配
   - 如果用户明确要求“先做移动端”或“桌面端与移动端并行”，才允许打破这个顺序

## Risks / Trade-offs
- 当前步骤全部居中后，必须避免确认按钮和提示轨再次长成第二套大壳。
- 空态更干净之后，必须保证“下一步做什么”仍然一眼可懂。
- 终局态如果继续沿用进行中构图，信息会变挤；终局可能需要独立的浮层或局后复盘展开区。
