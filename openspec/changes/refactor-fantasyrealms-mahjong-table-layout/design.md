## Context
`fantasyrealms` 现有 Board 虽然已经换上正式卡图，但结构上仍是典型 Web 三栏页：状态栏、内容栏、说明栏互相抢面积。结果是首屏视觉焦点被多个盒子打散，玩家不是“坐在牌桌前”，而是在“看一页牌桌数据面板”。

用户要求的方向很明确：参考成熟麻将游戏，把这局牌重新组织成一张桌面。麻将类产品的共同点不是具体皮肤，而是稳定的信息层级：
- 自己的手牌永远占据最长、最连续、最低干扰的操作带
- 公共弃牌河永远是桌面中心
- 回合、局况、分数是边缘角标，不是中心模块
- 提示/分析只能贴边，不能替代牌桌本身
- 桌面 live 页面几乎不保留描述性说明文字；能用位置、数字、状态高亮表达的，不再写成解释块

## Goals / Non-Goals
- Goals:
  - 用麻将桌式构图重建 `fantasyrealms` 桌面端主布局。
  - 让首屏阅读顺序回到“手牌 → 弃牌河 → 回合/分数/焦点”。
  - 把设计阶段与实现阶段分开，先冻结方案，再开工。
  - 把“PC 真实页先过，再做移动端”写入项目门禁。
- Non-Goals:
  - 本轮不直接改 `Board.tsx` 运行布局。
  - 不做多套视觉风格比稿。
  - 不在本轮解决移动端细排或终局微交互。

## Reference Conclusions
基于成熟麻将产品的稳定布局规律，适用于 `fantasyrealms` 的不是“麻将视觉元素”，而是以下空间组织原则：

1. 主操作对象贴近玩家
   - 自己的牌必须作为底部连续操作带存在。
   - 玩家不应先扫侧栏，再回到牌。

2. 公共河放桌面中心
   - 中央区域用于承载“全员都在看”的公开信息。
   - 对 Fantasy Realms 来说，就是公开弃牌河，而不是右栏卡组或说明。

3. 角落承载状态，而非主区承载状态
   - 牌库余量、当前回合、玩家分数、终局阈值都应变成角落/边缘部件。
   - 这些信息要随时可读，但不能把主区切碎。

4. 提示区贴边，不替代牌桌
   - 对桌面进行页来说，焦点卡和策略提示默认直接退场。
   - 焦点推演、规则解释、观察者说明只允许保留在堆叠态、终局复盘或用户显式展开态。

## Layout Decisions
### 1. 桌面端主构图
- 顶部：
  - 左上 `牌库余量 + 回合/动作短标签`
  - 右上 `座位式分数条`
- 中央：
  - `公开弃牌河`
  - 默认按 2 行河式网格排布，优先表达“公开流动信息”
- 底部：
  - `当前玩家 7 张手牌操作带`
  - 必须成为最宽的连续区域
- 终局附加：
  - `最终排名` 在终局时浮层化或中层展开
  - 不在进行中常驻占位

### 2. 信息权重
- 一级：手牌、公开弃牌河
- 二级：回合状态、当前玩家、牌库余量、当前总分
- 三级：仅限非桌面进行页出现的焦点推演、终局说明、细分计分

### 3. 布局禁止项
- 禁止继续使用三栏等权布局。
- 禁止把大块解释文案长期放在右栏。
- 禁止在桌面进行页常驻任何描述性说明块，包括规则说明、观察者说明、推演说明、长标签空态。
- 禁止让空态公开区成为最大的视觉盒子。
- 禁止在进行中常驻大终局面板或大计分纸。
- 禁止把牌库、回合、分数、公开区、手牌都渲染成同级厚方框。

## Sequencing Decision
实施顺序固定为两阶段：

1. `PC-first`
   - 先完成桌面端真实页
   - 先验证 opening / live discard / gameover 三个关键状态
   - 先清零阻塞级桌面端 UI bug

2. `Mobile-after-PC`
   - 仅当桌面端真实页达标后，才进入移动端适配
   - 如果用户明确要求“先做移动端”或“桌面端与移动端并行”，才允许打破这个顺序

## Risks / Trade-offs
- 公开弃牌河从“横向行”改成“河式网格”后，需要重新校准 1 张、少张、满 10 张时的视觉密度。
- 焦点区缩回边角后，必须避免丢失当前已有的分数推演价值。
- 终局态如果继续沿用进行中构图，信息会变挤；终局可能需要独立的浮层或局后复盘展开区。
