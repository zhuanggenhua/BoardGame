# 法师战争

## Purpose

定义 Mage Wars 在标准竞技场下的当前可玩边界：默认两名法师（兽王与女祭司）使用规则书第 40 页标准起始法术书中的对应法术书，从正式入口完成计划、部署、施法、移动、守卫、攻击和阶段推进。配置包同时登记四本标准起始法术书（兽王、女祭司、邪术师、巫师）作为当前默认对象范围。这里不是教程学徒模式，也不以 2x3 地图作为当前目标。

## Requirements

### Requirement: 标准竞技场开局
系统 SHALL 提供两人标准竞技场正式开局，使用 4x3 / 12 区域竞技场、默认两名首批可验证法师（兽王与女祭司）和配置包中的标准起始法术书。

#### Scenario: 从正式入口创建标准竞技场对局
- **WHEN** 两名玩家从正式 Mage Wars 入口进入对局
- **THEN** 系统 MUST 创建两名玩家、十二个标准竞技场区域、兽王/女祭司默认席位和各自的规则书第 40 页标准起始法术书
- **AND** 默认两名法师的初始生命 MUST 为 24
- **AND** 双方起始位置和默认法师 MUST 来自配置包的标准竞技场部署，而不是 UI 临时常量或 2x3 教程地图

### Requirement: 配置包驱动静态事实
系统 SHALL 从严格 JSON 配置包提供首批法师、规则书第 40 页标准起始法术书、法术牌、标准竞技场区域、正式图集引用、骰子和 token 的静态事实。配置 ID 或素材合同中保留的 `apprentice` 名称只能表示 legacy/tutorial 资源命名或历史对照来源，不能把运行目标改写成教程学徒模式。

#### Scenario: 配置与运行时一致
- **WHEN** 运行时查询首批法师、标准起始法术书、法术牌或标准竞技场区域
- **THEN** 查询结果 MUST 能回到 `src/games/mage-wars/data/mage-wars.config.json`
- **AND** 当前运行时竞技场模式 MUST 为 `formal-4x3`
- **AND** 卡牌素材 MUST 使用正式 atlas/frame 引用
- **AND** 未实现的特殊效果 MUST 明确标记为代码能力缺口，不能仅凭卡面文字宣称可执行

### Requirement: 核心回合玩法
系统 SHALL 支持标准竞技场两人流程中的重置、聚魔、维持、计划、部署、快速施法、魔物行动和最终快速施法阶段，并通过领域命令与事件推进状态。

#### Scenario: 玩家完成一条核心行动链
- **WHEN** 当前玩家在正式页面选择法术、选择合法目标并施放
- **THEN** 页面 MUST 发出真实领域命令
- **AND** 领域层 MUST 校验阶段、行动标记、法力、射程和目标规则
- **AND** 页面 MUST 反映法力、计划牌、弃牌、场地对象或伤害状态的变化

#### Scenario: 玩家完成攻击链
- **WHEN** 当前玩家从合法行动来源选择攻击并选择合法目标
- **THEN** 系统 MUST 经过攻击声明、骰子/防御响应和伤害结算
- **AND** 攻击骰、效果骰、伤害和状态 token MUST 使用真实事件结果
- **AND** 回合结束后 MUST 进入下一合法阶段或下一玩家回合

### Requirement: 真实交互端到端覆盖
系统 SHALL 以正式入口和真实玩家交互作为 Mage Wars 流程可交付性的验收依据。

#### Scenario: 核心玩法 E2E 不注入核心状态
- **WHEN** 执行 Mage Wars 核心玩法 E2E
- **THEN** 测试 MUST 从正式入口创建或进入标准竞技场对局
- **AND** 测试 MUST 通过页面交互或正式命令入口完成双方计划、部署、施法/目标、移动或守卫、攻击/骰子、伤害/状态和阶段推进
- **AND** 测试 MUST NOT 使用测试 harness 直接 patch 核心游戏状态来代替上述玩法链

#### Scenario: 隐藏信息和正式素材保持有效
- **WHEN** 对手查看己方未揭示的计划牌或隐藏结界
- **THEN** 对手 MUST 只能看到规则允许的牌背/数量信息
- **AND** 验证 MUST 同时确认标准竞技场、法师牌、法术牌、骰子和 token 的正式资源确实加载

### Requirement: 能力扩展运行时
系统 SHALL 使用引擎能力注册表和执行器注册表承接 Mage Wars 法术能力与场上对象主动能力，保证后续扩展法师和派系时通过配置、能力定义和执行器增量接入，而不是为每个派系建立独立运行时。

#### Scenario: 法术能力目录与执行器保持同步
- **WHEN** 运行时加载标准起始法术能力目录
- **THEN** 每张标准起始法术 MUST 有稳定能力 ID、实现状态和 GameConfig-compatible ability catalog 条目
- **AND** 每个已登记法术能力 MUST 能通过 `AbilityExecutorRegistry` 按 `spell-cast` 标签找到执行入口
- **AND** 标记为需要代码支持的法术 MUST 保持显式缺口，不能静默冒充已完整实现

#### Scenario: 对象能力通过注册表分发
- **WHEN** 玩家使用场上对象、装备或法师相关主动能力
- **THEN** 验证层 MUST 通过对象能力定义和验证器确认阶段、来源、费用、目标和使用次数
- **AND** 执行层 MUST 通过对象能力执行器注册表生成领域事件
- **AND** 未注册对象能力 MUST 在验证阶段 fail-close，不能静默当成无效果成功

#### Scenario: 状态债务不形成第二套 buff 真相
- **WHEN** 当前能力继续使用历史状态字段，例如 `statusTokens`、`temporaryTraits` 或 `abilityUseRoundNumbers`
- **THEN** 系统 MUST 将其标记为后续 TagContainer / ModifierStack 迁移债务
- **AND** 当前实现 MUST NOT 同时维护一套并行 buff 真相源

### Requirement: 明确的未交付范围
系统 MUST 将尚未纳入本轮的内容标记为后续 change，不得把两名法师流程 MVP 误报为完整 Mage Wars。

#### Scenario: 完成状态汇报保持边界
- **WHEN** 当前实现只完成标准竞技场下兽王与女祭司两派系的标准起始流程和部分卡牌能力
- **THEN** 完成汇报 MUST 明确说明全 322 张法术、标准书内墙体牌的主黄金链整合、服务器资源发布、自由构筑、四人模式、豪华竞技场、扩展法师、完整 AI、教程、行动日志 UI 和撤回 UI 是否仍未交付；墙体对象级覆盖 MUST 按共享流程判等或对象直接证据说明，不能用未定义的完成门槛词挡进度
- **AND** 布局截图、静态单测或状态注入型 E2E MUST NOT 单独作为整款游戏完成证据

### Requirement: 完成覆盖矩阵
系统 MUST 在宣称 Mage Wars 两派系流程跑通前建立覆盖矩阵，区分当前运行池、代表链证据和明确未覆盖对象。

#### Scenario: 代表链不外推为全法术覆盖
- **WHEN** 汇报标准竞技场兽王 / 女祭司两派系流程覆盖
- **THEN** 汇报 MUST 列出当前运行时标准起始法术 / 对象池、每个被宣称对象族的代表 E2E、对应截图或测试证据，以及仍未覆盖的对象族
- **AND** 标准书内墙体牌已纳入配置对象池；墙体公共机制可在具备运行对象、合法目标 UI、领域状态、正式 runtime atlas/frame、浏览器 E2E 和截图证据后登记为局部覆盖；墙体牌数据默认信任当前录入基线，只有 Wiki、玩家反馈或用户指定新主真相源冲突时才退回复审；但墙体主黄金链整合、服务器资源发布、完整全卡表或任何未列入矩阵的法术族 MUST 保持 deferred；若某张墙体牌出现独有规则、入口差异、证据冲突或用户点名，才补该对象直接浏览器链
- **AND** 系统 MUST NOT 用生物、装备、结界、咒语、攻击或魔物代表链推断墙体玩法已经覆盖
