- 适用游戏：`dicethrone`

强制说明：

- 下文 `crops/ability-cards/*.webp` 只表示历史核对文件名，不自动等于正式资源或主真相源。

## 当前真实结论

1. 源图已直接证明武士存在复合物理升级牌：
   - `slot-22` = `肃穆之仪 II` + `庄严`
   - `slot-24` = `正宗 II` + `荣耀`
   - `slot-25` = `叶隐之心 II` + `羽翼剑道`
2. 这些下半区现在已收回到升级后基础技能内部的 `variants`，而不是独立手牌。
3. `slot-24 / 正宗 II` 已不再属于“升级差异待核定”。

5. `slot-23 / 武道 II` 的 `8 damage` 已由本地卡图 OCR 再次支撑，和当前实现一致。
6. 本轮逐格重看 `slot-00 ~ slot-17` 后，确认武士通用牌顺序与枪手相同，`SAMURAI_COMMON_ATLAS_INDEX` 必须使用反向映射；旧正向写法已判定为 bug 并修正。
7. 端到端已验证：武士复合升级牌在手牌预览里显示整张物理牌，升级后进入技能槽，不会再出现“只剩上半张”的运行时语义。

2. 历史 `hand-preview` / crops 脚本仍可继续清理，但那属于录入中间产物治理，不再影响正式运行时合同。
3. 后续若继续补图证，可把重点转到提示板 OCR 清晰度，而不是继续重复登记 `slot-22 / slot-24 / slot-25` 的复合语义。

## 当前运行时取图合同

不是把整套武士卡重新录一遍，而是把运行时取图收回到和老角色一致的 atlas 规格：

- 全部 `previewRef` 统一走 `previewRef.type = 'atlas'`
- atlas 使用 `ability-cards.webp`
- `slot-18 ~ slot-31` 直接作为武士专属卡运行时索引
- `slot-00 ~ slot-17` 也已按全量对图结果更新为反向通用牌映射，不再沿用默认公共 atlas 顺序
- `slot-22 / 24 / 25` 这类复合物理牌，在手牌预览中仍显示整张物理牌；下半区通过升级后基础技能内部的 `variants` 表达
- 升级卡的 `targetAbilityId` 统一命中基础技能 ID（如 `katana-slice / wakizashi / masamune`），即使 `newAbilityDef` 内部有多个 `variants`，也不会额外生成新的卡图索引
- 结论：
  - 索引已经更新，不再沿用旧 `hand-cards-atlas` 的 `0 ~ 13` 顺序
  - 需要改的是运行时取图映射与升级卡合同，不是把技能变体再拆成另一套卡牌对象

## 与老派系升级合同逐张对照

### 老派系基线

先确认老派系已经长期成立的升级合同：

- 升级卡永远替换一个`基础技能 ID`，不是替换某个 `variant`。
- 即使升级后的 `newAbilityDef` 内部带多个 `variants`，`newAbilityDef.id` 也仍然保持基础技能 ID。
- II / III 级共存时，是多张升级卡分别指向同一个基础技能，而不是给每个 `variant` 单独发一张牌。

可直接复查的老派系样例：

- `monk/card-thrust-punch-2 -> replaceAbility('fist-technique', FIST_TECHNIQUE_2, 2)`
- `monk/card-thrust-punch-3 -> replaceAbility('fist-technique', FIST_TECHNIQUE_3, 3)`
- `barbarian/upgrade-slap-2 -> replaceAbility('slap', SLAP_2, 2)`
- `paladin/upgrade-holy-defense-2 -> replaceAbility('holy-defense', HOLY_DEFENSE_2, 2)`
- `paladin/upgrade-righteous-combat-3 -> replaceAbility('righteous-combat', RIGHTEOUS_COMBAT_3, 3)`

结论：

- 武士这轮和老派系保持同一条`升级卡 -> 基础技能`合同，没有“因为技能里有多个变体就拆出多张升级卡/多张预览卡”的例外。
- 武士需要继续守住的是`atlas 索引映射`与`基础技能命名合同`，不是去把 `variants` 误当成新的卡牌对象。
