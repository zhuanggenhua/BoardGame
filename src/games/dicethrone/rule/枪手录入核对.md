## Addendum（2026-05-17）：Bounty 生命周期与可移除性分离

- 旧口径中“持续到游戏结束 / 不会自动移除”只描述生命周期：`Bounty` 不会因为触发加伤/给 CP 自动消耗，也不会在阶段末自然清理。
- 该口径不能继续外推为“不可被移除状态效果移除”。`Bounty` 是负面 token，当前定义为 `passiveTrigger.removable: true`，可被 `Bye Bye` 等移除状态链路移除。
- 相关失效证据已回写到 `evidence/dicethrone/dicethrone-gunslinger-audit-2026-04-11.md` 与 `evidence/dicethrone/dicethrone-paladin-blessing-removable-fix.md`；真实手牌复现与修复证据见 `evidence/dicethrone-bye-bye-bounty-repro-e2e.md`。

## Addendum（2026-05-17）：Loaded 重掷例外的结构落点

- `Fill'Em With Lead` 与 `Quick Draw II` 的“花费 Loaded 后可重掷该奖励骰一次”不再只靠 `handleLoadedUse()` 内的 `sourceAbilityId` / `quickDrawLevel` 隐式判断承接。
- 当前结构落点为 `AbilityDef.tokenBonusDieReroll` / `AbilityVariantDef.tokenBonusDieReroll`：`Fill'Em With Lead` 是来源技能级 hook，`Quick Draw II` 是 `scope: allTokenUses` 的全局 Loaded 使用 hook。
- 行为回归仍以 `cross-hero.test.ts` 的 Loaded 链路为准；结构合同由 `gunslinger-loaded-contract.test.ts` 固定。`Quick Draw II` 与 `Fill'Em With Lead` 的 Loaded 可重掷单骰特写已有真实 UI 截图链；Spin the Chamber、Eat My Lead 与 The Law 单选收口也已有截图链。`mark-the-target` 的 UI 证据缺口仍以审计文档 D47 为准，不能据此写成枪手全量 UI 已补。

## Addendum（2026-03-31）：当前真实残余收敛

- 旧“专属卡图仅登记图片，未正式逐卡录入”的说法已经过期。
- 当前枪手专属卡组、升级卡与攻击修正卡都已接入运行时代码；`fill-em-with-lead` 的装填重掷逻辑也已有代码和定向回归覆盖。
- `Loaded / 装填弹药` 的最终时机现已裁定：通用 token 保持“攻击掷骰阶段结束后加伤”，具体技能或攻击修正牌若显式写“花费 Loaded 后重掷该骰”，则按具体文本建立例外。
- 因此，枪手线当前不再把 `Loaded` 时机冲突保留为角色级 residual。
