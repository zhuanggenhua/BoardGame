# 奖励骰测试合同

本文件记录项目当前的 Dice Throne 奖励骰测试合同，不代表官方规则原文。

## 奖励骰和临时结算测试

DiceThrone 的奖励骰必须和普通进攻骰、防御骰分开审查。奖励骰测试至少覆盖：

- 投掷后到普通确认前，不得提前改变最终 HP、伤害、资源、Token、状态或阶段。
- 改骰 / 重掷后，确认结算必须读取最终骰面，而不是初始骰面快照。
- 确认后 pending、当前交互和父攻击 / 防御流程必须按规则收口；第二次确认不得重复结算、重复扣血或再次打开投掷流程。
- 使用奖励骰事件的能力还必须验证普通骰投掷次数、额外投掷、Token 消费和其它同阶段状态没有被奖励骰污染；共享结算器必须有注册完整性测试。

“奖励骰已产生”“pending 已创建”“确认按钮可见”只能证明中间流程，不能替代最终状态断言。奖励骰若由真实 UI、响应窗口或右侧骰盘承接，领域测试与真实入口 E2E 必须分开报告。
