# 游戏 UI 交互主合同

> 核心：游戏感 = 即时反馈 + 状态清晰 + 操作可发现。
> 本文件只定义跨游戏交互底线；视觉 token 看 [`../styles/`](../styles/)，单游戏覆盖看 [`../games/`](../games/)。

## 1. 交互反馈原则

### 1.1 即时反馈

所有可交互元素都要让玩家知道“操作被接收”。

| 交互 | 底线反馈 | 增强 |
| --- | --- | --- |
| hover | 亮度、边框、阴影或位移变化 | 光晕、轻微上浮 |
| press / tap | 下沉、缩放或触感变化 | 音效、涟漪 |
| 禁用点击 | 无操作结果，视觉上明显不可用 | 简短拒绝提示 |
| 长按 | 进度或持续态提示 | 震动反馈 |

- hover / press 反馈应在 100ms 内出现。
- 普通状态切换控制在 150-300ms；复杂揭示或结算控制在 300-800ms。

### 1.2 状态清晰

玩家必须一眼区分可交互、悬停、按下、选中、禁用、加载和等待状态。

- 选中态不能只靠小角标、轻微亮度、文案或内部状态；至少要有外框、底色 / 饱和度变化、徽标、图标或等价视觉信号。
- 颜色不能是唯一信息来源；关键状态要同时借助形状、图标、位置、纹理或文字。
- 合法等待态必须说明等待谁或等待什么；不能长得像卡死。

### 1.3 合法下一步不能像死页

只要规则上还有合法下一步，首屏必须让玩家看出“接下来做什么”。

- 唯一主动作必须成为显式入口、主按钮、确认条或紧贴对象的动作提示。
- 多个候选必须让候选本体可见，并能看出它们就是当前步骤的操作对象。
- 空态、开局态、等待态、终局前状态和唯一下一步都是高风险态，需要单独证明可继续性。

### 1.4 文案不复述视觉信号

画面已经表达的内容，不要用常驻文字再说一遍。

- 高亮、箭头、连线、选中态、禁用态、数字徽章和位置关系已表达候选时，文案只补动作意图、成本、对象或结果。
- 不用颜色名、方位或高亮状态替代动作，例如“点绿色区域”“看右边红按钮”。
- 状态文字不得覆盖卡牌、棋子、角色、房间等对象本体；优先用描边、角标、tooltip 或摘要区。
- 为测试方便而暴露 `source / target / pending / fallback` 等内部词，按 UI 文案失败处理。

## 2. 动画规范

### 2.1 时长

| 场景 | 推荐时长 | 缓动 |
| --- | --- | --- |
| 微交互 | 100-200ms | ease-out |
| 状态切换 | 200-300ms | ease-in-out |
| 进入 / 退出 | 300-400ms | ease-out |
| 翻牌 / 掷骰 / 结算 | 400-800ms | spring / bounce |
| 全屏转场 | 300-500ms | ease-in-out |

### 2.2 性能

- 只动画 `transform` 和 `opacity`；不要动画 `width`、`height`、`margin`、`padding`。
- 禁止 `transition-all`，要指定具体属性。
- 尊重 `prefers-reduced-motion`。
- 禁用元素不做 hover / tap 动画。

## 3. 组件交互模式

### 3.1 按钮

- 按钮必须有 hover、press、focus、禁用和加载态。
- 可见文案保持短、稳定、直接表达动作；长标题、章节名和说明放到正文、标题、tooltip 或无障碍标签。
- 真正承接点击、切换、确认、取消、跳过、筛选或模式选择的控件，不能长得像正文小字、注脚或普通标签。
- 触控命中区最低 44px；移动端关键按钮按 48dp 等价目标优先。
- 辅助按钮可以扩大透明热区，但可见面不得抢走被控制对象本体。
- 清空进度、重开、删除、放弃、消耗关键资源或提交不可逆选择时，使用项目内同源确认组件；不要用浏览器默认弹窗。

### 3.2 卡牌和实体对象

- 可选卡牌：hover 上浮 / 描边；选中持续高亮；禁用灰度或降透明度。
- 可拖拽对象：拖起后源位置只保留占位或空槽，真实对象只在 ghost / preview 中出现一次。
- 已有卡图、房间、角色、棋子、物品牌等实体素材时，默认让对象本体成为主要可见内容和点击区域；不要退化成文字按钮或列表行。
- 缺少正式素材时，只能以牌背、对象名、类别等临时承接可玩路径，并把素材缺口转入资源补源；不能把“缺图”类排障标签当玩家 UI。

### 3.3 面板和结果

- 信息面板不遮挡关键游戏区域；模态面板要有遮罩、关闭策略和进入 / 退出动画。
- 资源变化要有方向反馈：增加、减少、消耗、获得各自可辨。
- 结算计分必须有过程态；若分数来自卡牌、棋子、骰子等对象，主动画应发生在这些对象本体或其附近，榜单只承载最终结果。

## 4. 游戏主交互合同

> 涉及主交互壳层、prompt、waiting、手牌区、右侧 rail、中央响应层或棋盘直选时，先读 [`source-families.md`](source-families.md)，复用已批准家族；找不到家族时先补来源，不先发明正式交互。

### 4.1 回合 / 阶段指示

- 当前行动者、当前阶段和“你的回合”属于主 HUD，不是装饰小标签。
- 阶段切换要有可辨过渡；等待别人、等待 AI、等待系统推进要明确归属。
- 绝对定位提示、浮动按钮和飘字必须进入独立 overlay / rail 层，不参与手牌区、棋盘、公共牌区或单位区的布局计算。
- 手牌、公共牌、单位、棋盘和右侧动作区的主槽位不得因临时提示而漂移。

### 4.2 选择与确认

- 可直接在对象本体上完成的选择，优先做成本体直选：卡牌点卡牌、房间点房间、角色点角色、棋子点棋子。
- 模式选择、目标槽位和归属按钮必须表达“动作 + 对象”，不能只复用对象名。
- 同一游戏内同类候选、悬停、选中和不可用状态要使用同一套视觉语法。
- 非骰子对象默认不用圆圈表达选中；描边应贴合对象本体轮廓或外接形状。
- 如果对象已有玩家归属，选中标识也要表达归属。
- 已有成熟同类交互时，新交互必须先复用，不得各自临时发明按钮样式。

### 4.3 拖放交互

- 可放置区域、拖拽过程和落点动画必须锚定同一个真实对象或区域。
- 拖拽中间态要证明 active 高亮贴住真实可投放区域，且不压住相邻按钮、资源、token 或手牌。
- 支持来回移动、取回、换位或撤销放置的对象，要分别验收正向和反向拖放。
- 无效放置要有拒绝反馈，例如抖动或回弹。

### 4.4 唯一下一步必须有常驻明文入口

- 当某一步是当前唯一可继续动作时，必须有常驻显式入口。
- 入口可以是明文按钮、横幅按钮组、确认条或等价 CTA；不能只靠 hover、tooltip、透明热区或“点盘面试试看”。
- CTA 文案必须说明动作与对象；如果 CTA 只是打开目标选择态，打开后目标对象要成为第一点击面，原 CTA 退为状态或辅助。

### 4.5 消耗型动作必须先显式选择并允许取消

- 会消耗手牌、资源、部队、人口，或触发不可逆提交的动作，默认先进入显式选择态。
- 选择态至少显示动作名、成本、已选内容、确认入口和取消入口。
- 可枚举成本必须允许逐项选择和反选；不能由系统静默替玩家选“前几张”或“默认几张”。
- 取消要清空本次临时选择，并回到未提交状态。

### 4.6 共享证据截图必须中文命名且直接表达含义

- 用于共享、汇报、验收或回归对照的关键截图，文件名必须是中文业务语义。
- 文件名至少表达页面 / 阶段、交互对象 / 动作、动作前 / 中 / 后状态。
- 联机或多席位截图还必须表达视角归属，例如房主页、接收方页、玩家 A 视角。
- 固定玩家体验链必须来自同一 viewer 页面；跨 seat 拼接不能证明同一玩家流程。
- `temp/`、`debug/`、`current/` 和工作区散图默认不是正式共享证据。

### 4.7 用户可操作 UI 必须占有固定槽位

- 承担点击、确认、选择、取消或推进职责的 UI 必须有固定槽位，不得被提示、说明、日志或状态块挤位。
- 固定槽位至少说清：入口长期停在哪里、由哪个语义父容器保留、哪些元素禁止侵入。
- 固定控件要锚定稳定父容器；不要锚定会随内容数量、文字长度、筛选、分页或加载状态变化的子内容。
- 常驻操作栏、手牌区、底部 dock、右侧 rail、中央 modal、底部 prompt 条是优先复用的槽位家族。
- 高频主动作默认进入贴近当前操作对象的动作槽；顶部区域主要承载状态，不承接高频点击。
- 移动端底部槽位不得贴系统手势区；按钮既要命中达标，也要靠近它控制的对象。
- 翻牌、发现牌、投骰、战斗结算等阻塞结果默认进入中央或等价主舞台；结果本体不能缩到侧栏、日志或不起眼 HUD。
- 重大阶段揭示按信息职责选型：非阻塞事实提示用短横幅；必须读完才能继续的内容才用阻塞 overlay。
- 固定槽位验收至少覆盖交互前、交互中、交互后，证明主槽位不漂移、不被顶走、不留抢位残影。

### 4.8 瞬时面板不得抢占另一块可操作 UI

- 弃牌确认、目标选择、响应窗口、步骤提示和检查面板只能进入自己的槽位、overlay 或 modal。
- 补充说明必须附着在对应主交互附近，且主入口保持原位可见。
- 空间不足时，优先让位的是说明、日志、帮助、提示和次级状态；不得先压缩按钮、手牌、棋盘主对象或唯一下一步。
- 只要已有真实交互承接面，等待 / 归属壳层就应退场或降为状态，不得形成两个主入口。
- 是否保留壳层只能按“当前有没有真实交互承接面”判断，不要用内部交互名或来源名特判。

### 4.9 新交互模式必须有可回查来源

- 新增或重做交互模式前，必须锁定来源：成熟实现、用户参考图、真实产品截图、规则书或设计稿里已经表达清楚的交互语义。
- 来源必须能回答玩家先点什么、候选在哪里出现、点候选后如何推进、结果在哪里反馈。
- 来源要落成可回查证据；已批准家族和仓内来源统一维护在 [`source-families.md`](source-families.md)。
- 可见卡牌候选不得退化成文字按钮；具体门禁和例外看 [`source-families.md`](source-families.md)。
- **卡面已有信息不得常驻二次抄写**：卡牌正面可读时，名称、类别、费用 / 战力 / 奖励 / VP、图标、数量或规则短语不得再用 chip、badge、标题条、角标或摘要卡常驻复写。UI 只补运行时状态、选择反馈、控制者、堆叠数量、隐藏数量、动态修正或跨牌聚合结果。
- 当前流程候选必须进入当前行动 / 确认 / 流程视线区；角落、状态栏、牌堆旁和日志旁只承载非当前流程信息。
- `跳过 / 放弃 / 不执行` 若会推进流程或改变规则状态，就是独立动作，必须有清楚按钮；如果只表示对象清单为空，不应伪装成与真实对象并列的候选。
- 请求型流程的最终确认必须和请求摘要同块，同屏只允许一个最终确认。

### 4.10 主交互壳层必须先锁五件事

- 动手前先锁定：`主交互对象`、`固定槽位`、`让位顺序`、`禁止侵入对象`、`来源家族`。
- 其中任一项说不清，禁止实现新布局、临时发明面板或用“看着能放下”作为理由。
- 正式验收必须证明当前只有一组主操作焦点，且临时 UI 不侵入主交互槽位。

### 4.11 用户可见文案禁止流程黑话

- 玩家 UI 写游戏内对象、动作和结果；不要直接暴露实现层、测试层或审查层术语。
- 内部状态要翻译成玩家动作，例如“选择目标”“确认弃置”“返回牌桌”，而不是把内部字段名原样上屏。
- 黑话判定不是固定词表；只要一句话本质是在拼内部字段给玩家看，就不合格。
- 玩家可见对象名必须来自真实游戏对象或已批准的用户故事；测试夹具名、占位名、工程标签和截图步骤名不得伪装成对象名。
- AI 过程话术、验收口令、审查结论和给助手的指令不得进入可见文本、按钮 title、aria label、sr-only、状态播报或截图标签。
- 规则解释放在规则书、帮助层、能力原文或测试断言；主 UI 只写此刻要做什么和结果发生了什么。
- 交互家族差异写在 [`source-families.md`](source-families.md)；单游戏 workflow 只引用本原则，不重复维护一套文案规则。

### 4.12 指向式引导必须同时满足“全部目标高亮 + 明显箭头”

- 需要玩家在地图、棋盘、战场或牌桌本体继续点击时，所有合法落点都要高亮，方向线要有清晰箭头头部。
- 虚线、描边、光、编号或路线标签不能替代箭头。
- 背景文字、边界和状态描边会抢焦点时，当前步骤要临时降噪。

### 4.13 提示横幅与悬浮说明不得遮挡主对象

- 横幅、tooltip、短说明、下一步提示和 hover 说明只能附着在空余槽位。
- 提示层与主对象冲突时，移动或缩短提示层，不能要求玩家自己挪开看。
- 看图验收时，主对象被盖住、裁掉或阅读路径被打断，判不通过。

### 4.14 棋盘角色必须保有唯一实体锚点

- 占据棋盘格、地图房间、战场位置或等价空间单位的角色、英雄、召唤师、首领和单位，必须以唯一可见棋盘实体承载；HUD 只做身份、资源和状态摘要。
- 同一空间单位内的角色和其它单位必须进入同一实体集合、归属分组和容量算法；不得拆成两套平行布局再靠偏移或副本维持可见。
- 手牌、法术书、结算条、提示层和覆盖 UI 必须给场上实体让位。
- 验收要证明实体在正确区域内，且实体中心实际命中实体本身；DOM 存在、坐标落格或 HUD 可见都不够。

## 5. 无障碍要求

- 正文颜色对比度不低于 4.5:1。
- 可交互元素至少 44x44px；键盘顺序合理；focus 状态可见。
- 重要信息不能只靠颜色表达。
- 支持屏幕阅读器；动画可关闭。

| 风格 | 适用 | 文件 |

游戏可以引用基础风格、做专属覆盖或新增风格；单游戏截图、素材合同、卡牌规则和设计过程不要写回本文件。

## 7. 反模式

| 禁止 | 应该 |
| --- | --- |
| 可点元素没有反馈 | 所有可点元素有 hover / press / focus |
| 颜色是唯一状态区分 | 结合形状、图标、文字或位置 |
| `transition-all` | 指定动画属性 |
| 动画 width / height | 动画 transform / opacity |
| 禁用元素仍有交互动画 | 禁用时移除动画 |
| 对象可点却做成文字按钮墙 | 对象本体承接点击 |
| 当前流程候选丢到角落 | 候选贴近行动 / 确认区 |
| 内部字段上屏 | 翻译成玩家动作和结果 |

## 8. 快速检查

- [ ] 所有按钮有 hover、press、focus、禁用和加载态。
- [ ] 当前行动者、阶段、等待归属清晰。
- [ ] 合法下一步首屏可发现，不像卡死。
- [ ] 主交互对象、固定槽位、让位顺序、禁止侵入对象、来源家族已锁定。
- [ ] 可见实体对象没有被文字按钮或摘要卡替代。
- [ ] 临时提示不遮挡主对象或唯一下一步。
- [ ] 动画只用 transform / opacity，并尊重 reduced motion。
- [ ] 玩家文案没有实现黑话、测试话术或审查口令。
- [ ] 截图证据中文命名，能看出阶段、动作、状态和视角。
