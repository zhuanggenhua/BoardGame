# 游戏交互来源家族登记册

> 适用范围：当任务涉及 `prompt / waiting / 手牌区 / 右侧 rail / 中央响应层 / 棋盘直选 / 局内 setup` 这类游戏主交互时，先在本表里找现成家族；找不到再补新来源，不得先发明正式交互。

## 使用规则

- 本表服务整个仓库未来所有游戏的主交互选型，不是给当前正在改的某一个游戏写专用说明；家族名和不变量必须保持跨游戏抽象。
- 先判断当前步骤的 `主交互对象` 是什么，再选承接家族；不要先看“哪块空位能塞面板”。
- 如果当前步骤能落进本表现有家族，就优先复用其不变量；不能只借外观，不借语义。
- `仓内真相源` 一栏允许指向某个具体游戏的现成实现，但它只承担“仓内已有成熟来源”的证据作用；不得把该实现里的单游戏机制名反写进家族名、规则正文或不变量。
- 若必须偏离现有家族，至少先说明：
  - 为什么现有家族都不适用
  - 你保留了哪些成熟不变量
  - 新家族的真实来源文件或截图是什么

## 卡牌候选本体优先门禁

- 触发条件：交互候选是卡牌、持有物、手牌、弃牌、revealed cards、临时展示牌，且当前视角按规则允许看见这些对象的正面或牌背。
- 默认做法：优先直接展示卡牌本体并让卡牌本体承接点击；选择态用描边、上抬、缩放、勾选、短标签等附着反馈表达。
- 信息去重门禁：按 `MASTER.md` 的“卡面已有信息不得常驻二次抄写”执行；卡面已可读的名称、类别、费用 / 战力 / 奖励 / VP、图标或规则短语，不得再用 chip、badge、标题条、摘要卡常驻复写。允许补充的只是不在卡面上的运行时状态、选择反馈、动态修正、控制者、隐藏数量、堆叠数量或跨多张牌的聚合结果。
- 位置门禁：如果这组卡牌候选属于当前行动步骤，或属于当前步骤的可选增强选择，必须贴近当前行动条、确认条或流程横幅；只有纯查看、历史浏览、弃牌查阅这类非推进候选，才可以作为独立查看面板放到次级位置。
- 可选门禁：先判断“不选”是不是独立动作。如果 `跳过 / 放弃 / 不执行` 会结束机会、推进流程或改变规则状态，必须给清楚按钮；如果“不选”只是这组对象候选的默认空侧，且主确认按钮已经表达完整提交结果，就不得把 `无 / 不选择 / 索要 / 换回 / 不换回` 做成与真实卡牌并列的候选或玩家-facing 模式。交易里没点己方或对方某一侧持有物，只表示该侧清单为空；摘要和同块 `提出交易` 按钮负责提交已选对象，双方全空则不出现确认按钮。
- 隐私边界：若规则不允许看见对方手牌正面，只能显示牌背、数量或已公开信息；不能为了“直接卡图”泄露私有牌面。
- 允许例外：候选不是卡牌对象、没有任何可用卡图/牌背素材、候选数量大到必须先分组/过滤、或当前输入设备/空间经截图证明卡图不可读不可点。例外也必须保留可点对象本体或分组后的卡图，不得直接降级成纯文字列表。
- 禁止行为：把可见卡牌候选改成文字按钮、文字 chips、普通列表行或摘要行，再要求玩家读文字选择；把放大镜/详情按钮当作主选择入口；在已有卡图可用时只显示卡名不显示卡面；在卡面已可读时常驻复写卡名、类型、战力、费用、奖励或规则短语；把当前步骤候选放到角落/顶部提示带/侧栏状态区，让玩家在流程条和候选之间来回找；把次级空值做成和真实卡牌同级的伪候选；规则存在独立跳过/放弃动作时不提供显式按钮。
