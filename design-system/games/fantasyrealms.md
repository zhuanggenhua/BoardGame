# 幻想国度 UI 设计规范

> gameId：`fantasyrealms`
>
> 基于：`design-system/game-ui/MASTER.md`、`design-system/styles/classic-parchment.md`、`.spec/knowledge/standards/ui-ux.md`
>
> 产出日期：`2026-06-05`

> 重要：本文当前主要约束**视觉构图与对象层级**。若某条内容涉及具体交互模式（例如点牌库、底部提示横条、先选后确认、右下确认按钮），必须再回到 `docs/games/fantasyrealms/design/README.md` 的“交互来源表”核对来源；没有来源表支持的交互，不得仅凭本文继续扩散到其它游戏或反向当成正式设计真相。

## 核心美学方向

幻想国度的界面现在应收敛为**极简中央承接牌桌**，而不是后台仪表盘，也不是继续沿旧“麻将桌底部整条手牌带”的候选往前推。

当前正式方向强调的是：

- 大面积干净牌桌先成立
- 当前这一步真正要处理的牌，集中承接到桌面中央
- 牌库、回合、分数、确认动作都退到边缘
- 没有待处理对象时，桌面保持安静，不摆巨型空盒或永久厚带

视觉重点不是“把所有对象同时摊开”，而是“每一步只把当前最该看的对象推到桌中央”，让牌桌像一个正在被处理的对局现场。

风格基线：

- `classic-parchment` 负责规则书、计分纸、温暖桌面、实体卡牌质感。
- 少量 `tactical-clean` 负责状态可读性，但不得变成蓝灰战术 HUD。
- 禁止 SaaS 仪表盘、三栏管理台、玻璃卡片、科幻 HUD、地图/区域棋盘。

## 玩家关注点

1. 第一关注点：当前这一步真正需要处理的牌。
2. 第二关注点：下一步动作是什么，例如摸牌、选牌、确认弃置。
3. 第三关注点：牌库余量、当前回合、当前总分。
4. 第四关注点：终局复盘、完整计分拆解与其它次级信息。

## 桌面端 16:9 构图

- 整体必须是一张完整桌面，而不是三个并排内容栏。
- 开局或当前无待处理对象时，桌面中心允许留白；不得为了“看起来有内容”硬摆永久空槽、永久手牌带或巨型空河。
- 当前回合真正要处理的牌，必须集中承接到桌面中央。
- 左侧保留牌库物件；顶部只保留极简状态轴；右上只保留轻量分数摘要。
- 固定单一路径动作默认直接落到对象本体：摸牌直接点牌库、拿公开牌直接点公开牌、弃牌直接点手牌；横幅只做短提示，不再额外长出确认按钮。
- 桌面端默认不保留底部常驻提示轨；若未来必须补充提示，也只能是临时态提示，不能回到底边横条家族。
- 终局排名在终局态展开；进行中不得常驻抢主区。

## 交互来源裁定状态

- 本文以下条目里，凡是涉及“点哪里”“是否需要确认按钮”“是对象本体承接还是主按钮承接”“是否出现底部提示横条”的内容，只能视为**当前实现现状**或**待裁定交互**，不是正式设计稿已经确认的交互合同。
- 当前唯一已锁定的正式视觉真相源，仍是 `docs/games/fantasyrealms/design/fantasyrealms-official-ui-design-2026-06-10.png`。
- 当前交互来源与未通过项，统一以 `docs/games/fantasyrealms/design/README.md` 的“交互来源表”为准。
- 在交互来源补齐前，不得把“点左上牌库”“先点对象再右下确认”继续向别的游戏扩散，也不得把它们反向包装成这份设计规范的正式结论。

当前实现门禁：

- 当前有效桌面实现只能有一套正式牌桌壳层；`live / compact-landscape / table / preview` 这类名字最多只能表示同一套正式壳层的响应式承载或历史候选，不能并行作为“当前完成态”存在。
- `compact-landscape` 只表示**紧凑横屏**承载：运行时断点、截图文件名、evidence 文案、任务描述都必须按横屏语义命名；不得再用 `stacked`、`堆叠态` 这类会把它误导成竖屏信息流的名字。
- `compact-landscape` 只能命中 `width > height` 的横屏视口；竖屏视口不得借用这套命名、证据或实现口径冒充“同一个紧凑分支”。
- 任何桌面端响应式变体都必须一眼看出是**同一个游戏**：同一套牌桌材质、同一组卡牌渲染、同一对象层级、同一主操作闭环。禁止出现 `1440` 桌面像一套 UI、`1024` 紧凑横屏又像另一套游戏的情况。
- 当前验收截图、evidence 文档、运行路由必须来自当前工作区真实页面；不得引用兄弟 worktree、历史分支或旧预览页的截图，冒充“当前 UI 已达标”。
- 桌面端主布局不得再是三栏等权结构。
- 手牌不再要求作为永久首屏最长区域常驻；只有当前步骤真正需要展示时，相关牌才进入中央承接区。
- 公开弃牌或待处理牌必须进入桌面中央；但空态不得为了占位做成巨型空盒。
- 当前步骤只该出现必要对象，不能为了维持“桌面感”把无关对象一口气全摊开。
- 焦点牌与推演只能贴边，不能再独立占一整列。
- 牌库、回合、分数、终局阈值只能做边缘角标或窄带。
- 边缘角标和可能存在的确认类主操作都必须落在桌面内区，保留可感知的牌桌内边距；“靠边”不是“贴屏幕边”。桌面端牌库、分数窄带与主操作若存在，都应明显离开外框，像摆在桌面上的物件，而不是浏览器角落控件。
- 左上牌库必须是可识别的桌边牌堆物件，不是迷你图标；桌面端牌库牌背宽度应保持在公开弃牌卡宽的大约 `45%-60%`，牌库计数也必须跟随牌堆比例，而不是单独压成小徽章。
- 当前实现里曾使用“先点对象再确认”“底部短提示横条”等交互承接方式；其中这两条都已退出当前桌面正式方向。当前正式方向是 `README.md` 里记录的“横幅短提示 + 对象本体直接点击 + 显式放大镜”。
- FantasyRealms 当前桌面 live 不再保留独立主推进按钮；真正推进流程的入口是牌库、公开牌和手牌本体，顶部状态条只承担回合与进度信息。
- 双人 `0` 手牌开局这类合法但容易像“页面坏了”的状态，必须额外给出显式下一步线索；但线索载体到底是按钮、牌库对象本体、局部提示还是其它模式，必须先有交互来源表，不得仅凭当前实现定案。
- 顶部回合、轮次、弃牌进度、分数只能是轻量角标/短标签；不得做成横向带框 HUD、黑金牌匾或一整条顶部面板。
- 摸牌、拿弃牌、弃牌进入公共河的动效只能作用于本次新增或接收的那张/那几张牌；不得让整条手牌带或整片公共河一起播放位移动画。验收必须保留真实页面 `start / mid / end` 关键帧图证。
- 未通过桌面端真实页验收前，不进入移动端适配实施。

共同禁止项：

- 不得把页面做成后台三栏管理台。
- 不得把弃牌区、牌库、计分做成等权重仪表盘。
- 不得为了风格展示新增规则里没有的资源、行动点、任务或地图。
- 不得让装饰挡住 7 张手牌、最多 7 张公共牌和弃牌终局进度。

## 视觉语法

- 背景：深木桌、皮革垫、微暗角，中心有暖光。
- 面板：尽量表现为实体物件，例如计分便签、桌边名牌、蜡封标签、小木牌，不使用大块半透明矩形。
- 卡牌：白边、圆角、实体阴影、轻微旋转；当前焦点牌有金色细边或蜡封标记。
- 按钮：小型实体按钮或牌桌 token，必须有厚度感；结束回合不能比卡牌更重。
- 字体：标题可用衬线感，UI 标签用清晰中文无衬线；文案短。

## 色彩

- 主色：深胡桃木 `#3a2416`、羊皮纸 `#f2dfb5`、旧金 `#d4af37`。
- 辅色：深翡翠 `#21483f`、酒红 `#7c2d27`、墨色 `#2a1b12`。
- 避免：大面积蓝灰、紫色渐变、冷白玻璃、单调米黄色铺满。

## 禁止项

- 不画地图、区域、资源矿、行动点、任务日志、科技树。
- 不做三栏后台面板，不把所有内容塞进等宽卡片。
- 不展示规则说明句，不用“点击这里”类教程文案。
- 不把日志、焦点说明或计分纸常驻成右侧大列。
- 不把手牌缩成装饰条；卡牌必须是第一视觉对象。
- 不在桌面端验收通过前提前转去做移动端细排，除非用户明确要求。

## 移动端基线

- `mobileProfile`: `landscape-adapted`
- `preferredOrientation`: `landscape`
- `mobileLayoutPreset`: `tabletop-card-hand`

移动端仍保持同一张牌桌构图：手牌横向滑动或扇形压缩，焦点牌与计分便签可临时放大，弃牌区和抽牌来源收成左右角落物件。不要重排成竖向信息流。

## 实施顺序门禁

1. 先完成桌面端真实页重构。
2. 先验证 opening / live discard / gameover 三个桌面端关键状态。
3. 只有桌面端真实页达标后，才允许开始移动端适配。
4. 只有用户明确说“移动端先做”或“桌面端与移动端并行”时，才允许打破这个顺序。
