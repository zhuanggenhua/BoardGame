## 核心方向

幻想国度当前 live UI 收敛为**极简中央承接牌桌**：当前步骤真正要处理的牌进入桌面中央，牌库、回合、分数和终局复盘退到边缘。它不是后台仪表盘、三栏管理台，也不是旧“麻将桌底部整条手牌带”候选。

优先级：

1. 当前步骤真正需要处理的牌。
2. 下一步动作，例如摸牌、选牌、确认弃置或等待。
3. 牌库余量、当前回合、当前总分。
4. 终局复盘、完整计分拆解和其它次级信息。

## 交互边界

- 真实双人开局且公开弃牌为空时，不停在摸牌按钮；唯一合法来源是牌库且无目标可选，因此直接进入摸牌后的弃牌阶段。
- 中盘公开弃牌存在时，才允许同时出现 `摸牌` 与 `拿公开牌`；进入拿公开牌选牌态后，不再保留同名按钮并列。
- 横幅只承担短提示，不承担确认按钮；固定单一路径动作默认落到对象本体。
- 牌面放大通过显式放大镜入口，不依赖二次点击猜测。
- 底部短提示横条、旧 `fr-ui-current-*`、旧 `rework-v*` 和旧 `stacked` 命名都已退出当前桌面正式方向。

## 桌面布局

- 整体必须是一张完整桌面，而不是并排内容栏。
- 开局或当前无待处理对象时，桌面中心允许留白；不得硬摆永久空槽、永久手牌带或巨型空河。
- 当前回合真正要处理的牌集中承接到桌面中央；手牌只在当前步骤需要时进入中央承接区。
- 左侧保留可识别牌库物件，牌库不能退化为迷你图标；牌库牌背宽度约为公开弃牌卡宽的 `45%-60%`。
- 顶部只保留极简状态轴；右上只保留轻量分数摘要；终局排名只在终局态展开。
- 边缘角标和可能存在的主操作必须落在桌面内区，像桌上物件，不贴浏览器边角。
- 桌面端主布局不得再是三栏等权结构；焦点牌与推演只能贴边，不能独占一整列。

## 响应式

- `mobileProfile`: `landscape-adapted`
- `preferredOrientation`: `landscape`
- `mobileLayoutPreset`: `tabletop-card-hand`
- `compact-landscape` 只表示紧凑横屏承载，只能命中 `width > height`；竖屏不得借用这套命名、证据或实现口径。
- 桌面、紧凑横屏和移动端必须仍是一套牌桌：同一材质、同一卡牌渲染、同一对象层级、同一主操作闭环。
- 未通过桌面真实页验收前，不进入移动端适配实施，除非用户明确要求移动端先做或并行。

## 视觉语法

- 风格来源：`classic-parchment` 负责规则书、计分纸、温暖桌面和实体卡牌质感；少量 `tactical-clean` 只服务状态可读性。
- 背景是深木桌、皮革垫和微暗角；中心有暖光。
- 面板尽量表现为实体物件，例如计分便签、桌边名牌、蜡封标签、小木牌，不使用大块半透明矩形。
- 卡牌保持白边、圆角、实体阴影和轻微旋转；当前焦点牌用金色细边或蜡封标记。
- 按钮是小型实体按钮或牌桌 token，必须有厚度感；结束回合不能比卡牌更重。
- 文案只用短标签；主 UI 不展示规则说明句或“点击这里”教程文案。

## 失败项

以下任一出现即判 `REVISE`：

- 页面变成后台三栏管理台，或弃牌区、牌库、计分成为等权重仪表盘。
- 旧 `fr-merge-pass2-*`、旧 full-flow 截图、历史分支或兄弟 worktree 截图被当作当前完成态证据。
- 旧官方 UI 图被恢复成当前 live 正式实现方向。
- 当前步骤无关对象被摊满桌面，或空态为了占位出现巨型空盒。
- 底部常驻提示横条、常驻手牌厚带或确认按钮重新成为桌面正式方向。
- 牌库、公开牌、手牌本体可以承接的动作，被替换成远离对象的代理按钮。
- 顶部状态、分数或终局阈值变成横向带框 HUD、黑金牌匾或整条顶部面板。
- 装饰挡住 7 张手牌、最多 7 张公共牌或弃牌终局进度。
- 大面积蓝灰、紫色渐变、冷白玻璃或单调米黄色铺满。

## 验收

- 先完成桌面端真实页；至少验证 opening / live discard / gameover 三个桌面关键状态。
- 摸牌、拿弃牌、弃牌进入公共河的动效只能作用于本次新增或接收的牌；验收保留真实页面 `start / mid / end` 关键帧证据。
- 运行截图、E2E 证据图和审计结论放 `evidence/fantasyrealms/`；设计目录只放当前仍有效的设计图本体。
