# 七大恨 UI 设计规范

> 适用范围：`qidahen` 当前 Board 前端实现、UI 指导图、生图 prompt 与验收截图。
> 当前阶段：地图玩法层接入 + HUD 布局收口。主地图进入 `Scene/MapLayer`，轮盘、玩家条、朝鲜、纪年、行动、抽牌、手牌、弃牌继续固定在 `ScreenUiLayer`。

## 当前强制方向

- **用户草图是空间合同**：当前以 `D:\gongzuo\webgame\gameasset\ui参考\七大恨ui设计.png` 为布局合同。左上轮盘、顶中玩家悬浮窗、右上朝鲜、左中纪年卡、右中可执行操作、左下抽牌、底中手牌、右下弃牌必须落在对应区域。
- **地图与 HUD 分层**：当前 Board 使用真实 `qidahen/board/qidahen-main-map` 作为地图玩法层；HUD 不得被地图缩放、拖拽或裁切影响。除地图本体、区域高亮、路线、token 和轮盘交互热区外，不新增背景纹理、装饰角、规则说明或无关工具。
- **轮盘视觉以真实地图为准**：当前左上轮盘直接使用主地图原图里的印刷轮盘作为视觉本体，前端只叠加透明命中区、当前/目标扇区高亮和 hover/focus tip。禁止再用糊图补丁擦掉原轮盘后重画一套“近似轮盘”，这会造成多层边框、颜色漂移和左上雾化。
- **轮盘不是“另裁一张糊贴图”任务**：可以复用完整主地图中的清晰印刷轮盘；不得使用低清裁图、放大截图、软遮罩或带背景残片当 HUD 本体。若未来地图支持平移/缩放，必须先保证轮盘视觉基准仍清晰且固定，再调整交互层坐标。
- **轮盘内容必须来自规则、地图素材与参数图**：轮盘扇区文字不得用八卦、卦线、数字或猜测标签替代。当前轮盘行动来自 `src/games/qidahen/rule/七大恨规则.md` 的“轮盘行动”章节与 `public/assets/i18n/zh-CN/qidahen/board/main-board.png` 左上行动轮盘：`开垦/军屯`、`征兵/训练`、`外交/雇佣`、`进攻/调度` 这四类行动在 8 个扇区中重复分布；提示文字来自规则中的移动代价与抽牌结果。改轮盘前必须先重做“规则原文 -> 地图素材轮盘 -> 参数图短标签 -> UI短标签”证据表。
- **轮盘移动分支不得常驻成旁边按钮**：`走 1 / 走 2 / 走 3` 只是轮盘目标格的分支语义，不是独立控件。当前轮盘必须在轮盘本体上叠加命中区；移动结果、抽牌代价和说明只允许 hover/focus tip 出现，不得占据左上或左中空间。
- **禁止模仿大杀四方的歪扭扇形**：七大恨当前手牌区不做旋转扇形、不做错位堆叠、不做半透明托盘罩。手牌是底部中间的大空间，卡牌直排、可读、可点击。
- **禁止借鉴其他游戏的牌库布局覆盖草图**：抽牌堆与弃牌堆按用户草图分别固定在左下、右下；不能因为某个既有游戏把牌库放在别处，就把七大恨下方两角空出来。
- **禁止无关 UI**：当前画面不显示行动记录、规则说明、地图工具、缩放提示、常驻区域说明、战斗面板、装饰角、标题分隔线、流程说明、登录框式边角装饰。区域信息只允许作为 hover/focus/tap tip 或选中后的局部反馈。
- **左右下角不是留白区**：左下必须是抽牌堆，右下必须是弃牌堆；二者是手牌簇两侧的实体，不是可省略装饰。
- **提示默认悬浮**：轮盘结果摘要、规则提示、查看说明默认是 hover/focus/tap tip 或临时 overlay；不得常驻成块占位挤压纪年、操作区或手牌。
- **按钮必须像按钮**：可执行操作必须有清晰边框、底色、hover/press/focus/disabled 态和可点击材质，不能退化为淡文字、白块或纯说明标签；轮盘分支不作为常驻按钮出现。
- **行动按钮就是执行入口**：右侧势力行动按钮不得再配一个同义的“执行”按钮，也不得在按钮上显示弃置数量、支付进度或花费圆章。当前 UI 口径是点击行动即结算，领域层自动处理必要弃牌。只有规则明确要求二次确认或危险提交时，才允许额外确认入口。

## 风格合同

- 风格名称：**明末地图墨框 UI**。这里的“风格化”不是把现代网页卡片换成米黄色，也不是给 HUD 加滤镜；它必须复刻七大恨真实地图和卡面里的视觉语法：旧地图黄褐纸底、粗黑墨框、暗茶半透明牌库框、金黄/朱砂字、印刷颗粒、硬边界。
- 颜色真相源优先级：`qidahen-main-map.png` 的左上轮盘、右侧朝鲜牌库框、底部行动表 > 真实卡背/卡面 > 设计系统通用 token。任何新增 HUD 颜色都必须能回指到这些素材区域之一；禁止凭“看起来古风”临时选一组黄/棕/红。
- 地图层必须清晰。当前不使用左上清理层或遮罩；如果未来必须遮挡地图元素，遮挡结果不能呈现软糊、雾化、低清渐变、拉伸补丁或明显色斑。左上区域如果在 E2E 截图里像被糊了一层雾，直接判失败。
- HUD 应像地图上原生印刷/叠放的桌游部件，而不是浮在地图上的网页控件。玩家条、行动按钮、tip、牌堆标签必须优先采用暗墨框、厚黑边、金字/朱砂字和轻微印刷纹理；浅纸签只允许用于真实卡面/牌堆数字章这类素材本身接近浅底的部件。
- 风格一致不等于给 HUD 加背景。地图层只使用真实地图素材；HUD 外壳不得额外铺羊皮纸大背景、模糊图、玻璃态、现代卡片阴影或登录框式装饰。
- 可交互态只用边框、底色、轻抬、短标签表达；不要靠大面积半透明罩子说明状态。
- 文案只写短名词/动作/必要数字：例如 `抽牌`、`弃牌`、`朝鲜牌库`。行动按钮不写 `需弃 / 已选`、花费或支付进度；这类规则细节只进 hover/focus/tap tip 或规则帮助。

### 风格验收

- 同屏按钮、tip、玩家条、牌堆标签必须共享 `mapInk / mapPanel / mapGold / cinnabar / shadow`，不能一个像现代网页、一个像素材、一个像登录框。
- 真实卡面可以保留素材自身颜色；所有前端新增 UI 外壳必须使用本表 token。
- 每轮 UI 改动后必须同时打开 E2E 截图和 `qidahen-main-map.png` 对比，自审左上是否清晰、颜色是否回到地图素材、HUD 是否像地图原生部件。
- 若 `ui-ux-pro-max` 推荐与本表冲突，以本表和真实素材为准；例如蓝绿 SaaS、霓虹、CRT、Bento 大圆角都不采纳。
- 风格调整不得改变已通过的布局锚点：地图、左上轮盘、顶中玩家、右上朝鲜、左中纪年、右中操作、左下抽牌、底中手牌、右下弃牌不能被重排。

## 轮盘门禁

- 必须能一眼看到 8 个轮盘扇区，不能只显示 `走 1 / 走 2 / 走 3` 三个移动选项。
- 8 个扇区必须显示素材/规则可证明的行动短标签，当前按地图轮盘显示两行行动组合：`开垦/军屯`、`征兵/训练`、`外交/雇佣`、`进攻/调度`。不得显示八卦名、卦线、序号、假 OCR 字、图腾或装饰字来冒充内容。
- 三个移动选项只是“转动方式”，不是轮盘本体；不得常驻成独立按钮列，必须从属于完整轮盘的命中区和悬浮提示。
- 改轮盘内容前必须同时核对规则文档和参数/参考卡；没有来源表时不得提交实现，也不得用“看着像素材”解释轮盘文字。
- 行动轮盘不得无中生有八卦、卦线、装饰线、占卜图腾、假 OCR、符号点阵或任何地图素材/规则没有出现的视觉元素；只有外圈、分区线、行动文字、中心“行动轮盘”、当前位置高亮、选中目标高亮/放大、必要交互热区与 tip 可以进入实现。
- 轮盘不得使用低清裁图、放大截图、遮罩补丁或第二套近似重绘作为本体。当前使用完整主地图中的清晰印刷轮盘作为视觉本体，并只叠加透明命中层、当前位置高亮和必要交互态。
- 轮盘结果摘要只允许作为轮盘局部悬浮 tip，不允许常驻成一块独立说明面板，也不允许依附到常驻步数按钮上。
- 地图玩法层将来如果加入平移/缩放，必须重新验证轮盘视觉与交互热区仍固定对齐；不能让地图移动造成轮盘点击错位。
- 对齐必须是实现，不是敷衍贴图：当前截图必须证明透明命中层、朱砂选中态和真实地图印刷扇区重合。选中态必须绑定真实轮盘目标格，并以该扇区独立图层实现描边/底色，不得只给整张轮盘加滤镜，也不得把选中效果做成旁边说明块。
- 每次轮盘 UI 改动必须交付选中态截图：截图要来自当前实现的 E2E/浏览器结果，且必须能看见轮盘命中后选中的目标扇区；参考图、素材裁图和结果图必须分开命名，禁止把参考图当结果交付。

## 地图交互门禁

- 地图交互以真实 `qidahen/board/qidahen-main-map` 的区域边界为基础；区域名、控制权、token 位置和可点击范围必须能回指到地图素材或规则文档。
- 主地图原图里的左上轮盘是当前视觉真相源；前端不得再叠第二套完整轮盘，也不得用 `left-top-clean-patch` 类软遮罩清理它。交互能力由同位置 SVG 热区和高亮层提供。
- 当前首选实现是同源区域 polygon 派生两层：离屏 2D canvas hitmap 负责点击/hover 命中，SVG overlay 负责可见高亮和选中态。命中区、高亮边界、tooltip 文案和领域结算目标必须引用同一份区域定义。
- WebGL / Three.js color picking 只在 2D canvas hitmap 无法支撑区域数量、缩放性能或复杂动态效果时升级；升级前必须保留同源区域数据，不得把区域真相散落到 shader、临时颜色表和手写 DOM 坐标里。
- 区域说明只允许 hover/focus/tap tip 或选中反馈出现，不得常驻成侧边说明卡，也不得为每个区域另做同义按钮。
- 点击地图区域后必须有明确 hover/selected 高亮；行动按钮如果已按游戏口径“点击即执行”，结算必须使用当前选中区域，不再弹出同义“执行/确认”入口。

## 当前失败项清单

以下任一出现即判 UI 未收口：

- 地图未使用真实主地图素材，或地图、区域高亮、token 不在同一坐标系。
- 点击热区、高亮边界、tooltip 名称和领域结算对象不是同一份区域定义派生。
- 左上轮盘只剩 3 个可见选项，或轮盘跟随地图层移动。
- 左上轮盘旁常驻 `走 1 / 走 2 / 走 3` 独立按钮列，挤占左上/左中空间。
- 纪年卡只显示 1 张，缺少今年/下一年两张常驻关系。
- 纪年牌堆在主态常驻，占用左中区域或把纪年卡挤小。
- 手牌后面出现半透明罩子、厚托盘、扇形旋转或被左右面板压窄。
- 左下/右下空着，抽牌堆/弃牌堆漂到别处。
- 轮盘结果摘要、规则提示或说明文字常驻占位。
- 右侧行动区出现与行动按钮同义的“执行/确认执行”按钮，造成点击行动和执行行动两套入口。
- 右侧行动按钮显示弃置数量、支付进度、花费圆章或其它解释性数字，导致按钮不再是直接执行入口。
- 右侧行动按钮按固定容器铺满，短动作名后留下明显空白横条。
- 按钮视觉弱到像标签、白块或说明文字。
- 玩家悬浮窗、按钮、tip、牌堆标签使用不同色板/圆角/阴影，看起来像几套 UI。
- 为了风格统一引入蓝绿 SaaS、霓虹、厚金属、羊皮纸大背景或登录框式装饰。
- 出现行动记录、规则说明、地图缩放工具、装饰角、背景分隔线、无关标题。
- 使用低清地图裁图、软遮罩或第二套重绘轮盘来制造 HUD 风格一致，导致左上模糊、多层边框或交互热区错位。

## 地图层口径

地图区域控制是当前玩法层。实现必须维持明确分层：

- `Scene/MapLayer`：地图、区域、路线、token，以及当前作为视觉真相源的印刷轮盘。
- `ScreenUiLayer`：轮盘透明命中/高亮层、玩家悬浮、朝鲜、纪年、操作区、抽牌、手牌、弃牌，固定屏幕布局。

不得为了接地图而把当前 UI 元素重新塞回地图底图或地图裁切层。
