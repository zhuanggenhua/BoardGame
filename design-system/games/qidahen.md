# 七大恨 UI 设计合同

适用范围：`qidahen` 的 Board 前端、UI 指导图、生图 prompt 与截图验收。当前阶段是地图玩法层接入 + HUD 布局收口：地图进入 `Scene/MapLayer`，轮盘、玩家条、朝鲜、纪年、行动、抽牌、手牌、弃牌固定在 `ScreenUiLayer`。

## 真相源

- **空间合同**：用户草图 `D:\gongzuo\webgame\gameasset\ui参考\七大恨ui设计.png` 是外部本机素材来源；左上轮盘、顶中玩家、右上朝鲜、左中纪年、右中行动、左下抽牌、底中手牌、右下弃牌必须对应。
- **规则与素材**：轮盘文字和移动 / 抽牌语义来自 [`七大恨规则.md`](../../src/games/qidahen/rule/七大恨规则.md)、主地图素材 [`qidahen-main-map.webp`](../../public/assets/i18n/zh-CN/qidahen/board/compressed/qidahen-main-map.webp)、轮盘标记素材 [`action-wheel-marker.webp`](../../public/assets/i18n/zh-CN/qidahen/board/compressed/action-wheel-marker.webp) 和区域数据 [`qidahen.map-regions.json`](../../public/game-data/qidahen.map-regions.json)。
- **实现入口**：局内布局以 [`Board.tsx`](../../src/games/qidahen/Board.tsx) 和 [`qidahen-board.css`](../../src/games/qidahen/qidahen-board.css) 为当前实现入口。
- **交互参考**：底部卡牌槽参考 [`SmashUp HandArea`](../../src/games/smashup/ui/HandArea.tsx) / [`PromptOverlay`](../../src/games/smashup/ui/PromptOverlay.tsx)，阻塞响应参考 [`MeFirstOverlay`](../../src/games/smashup/ui/MeFirstOverlay.tsx)，主承接面参考 [`SmashUp Board`](../../src/games/smashup/Board.tsx) 的 `activePromptSurface`。

## 层级与空间

- `1920x1080` 只用于设计换算和 PC 验收，不是页面固定舞台；主地图必须覆盖真实 viewport，禁止左右补纯色块、黑边、遮罩条或拼接背景。
- 地图、区域高亮、路线和 token 属于 `Scene/MapLayer`；HUD 属于 `ScreenUiLayer`，不得被地图平移、缩放、拖拽或裁切影响。
- 左上轮盘是独立 HUD SVG 控件；地图原图里的轮盘只能作比例、色彩和文字密度参考，不能承担点击本体。
- 底部手牌直排、可读、可点；禁止旋转扇形、厚托盘、半透明罩和错位堆叠。
- 左下抽牌堆、右下弃牌堆是手牌两侧实体，不是留白或装饰；不得因参考其它游戏布局而迁走。

| 区域 | 合同 |
| --- | --- |
| 左上 | 8 扇区行动轮盘，固定屏幕，带当前位置 / 目标高亮和悬浮提示 |
| 顶中 | 三方势力状态一行展示：势力、VP、手牌 / 上限、当前玩家 |
| 右上 | 朝鲜牌库与朝鲜弃牌两个实体牌堆 |
| 左中 | 今年与下一年两张纪年卡常驻；纪年牌堆只按需悬浮 |
| 右中 | 固定动作栏 + 当前交互槽位；按钮点击即执行或进入唯一必要目标层 |
| 中央 | 真实地图、区域、路线和 token；HUD 不占主要判断区 |
| 底部 | 左抽牌、中手牌、右弃牌；手牌是最大底部交互空间 |

## 主交互槽位

- **setup / 剧本投票**：使用独立 setup 页或 overlay，不与正式棋盘 HUD 同屏竞争。
- **右侧势力动作槽**：一级行动按钮、当前步骤说明和临时交互卡都进入右中 `qidahen-actions-zone`；提示、摘要、season summary 不得把动作按钮挤走。
- **底部手牌链**：弃牌、支付、科技选择等进入 `qidahen-hand-dock` 与 `qidahen-hand-interaction-tray`；不得新开右侧外部面板顶开动作栏。
- **轮盘下一步**：明文推进 CTA 放在右侧 `qidahen-wheel-next-step-banner`；左上轮盘本体保留视觉、命中区和局部 tip，不另设常驻 `走 1 / 走 2 / 走 3` 按钮列。
- **瞬时交互**：外交、调度、战后处理、响应窗口只能进入右侧槽位、底部手牌链或 overlay；不得为每个步骤新增一块常驻面板。

## 轮盘合同

- 轮盘必须完整显示 8 个扇区；三种移动方式只是转动分支，不是轮盘本体。
- 扇区短标签来自规则和地图素材：`开垦/军屯`、`征兵/训练`、`外交/雇佣`、`进攻/调度` 在 8 扇区重复分布；不得用八卦、卦线、序号、假 OCR、图腾或装饰字替代。
- 独立 HUD 轮盘只能包含外圈、内圈、8 个扇区、行动文字、中心标题、当前位置 / 目标高亮、透明命中区和局部 tip；禁止大面积纸色圆垫、软遮罩、第二套外圈、多余同心环或覆盖地图的大块背景。
- 轮盘视觉层、透明命中层和选中态必须重合；改轮盘必须交付真实实现截图，能看见命中后的目标扇区选中态。
- 改轮盘内容前必须重做“规则原文 -> 地图素材轮盘 -> 参数图短标签 -> UI 短标签”证据表。

## 地图交互

- 地图交互以真实主地图的区域边界为基础；区域名、控制权、token 位置和可点击范围必须回指素材或规则。
- 区域命中、可见高亮、tooltip 文案和领域结算目标必须由同一份区域定义派生。
- 首选实现是 2D canvas hitmap 负责点击 / hover，SVG overlay 负责可见高亮；只有性能或复杂度逼迫时才升级 WebGL / Three.js，且必须保留同源区域数据。
- 区域说明只允许 hover / focus / tap tip 或选中反馈出现；不得为每个区域常驻侧边说明卡或同义按钮。
- 地图 token 允许按可读性选择真实素材或轻量代码圆章，但控制、人口、外交、兵力四类语义必须一眼区分。

## 风格合同

- 风格名：**明末地图墨框 UI**。目标是复刻真实地图和卡面里的旧地图黄褐纸底、粗黑墨框、暗茶半透明框、金黄 / 朱砂字、印刷颗粒和硬边界。
- 色彩优先级：主地图左上轮盘、右侧朝鲜牌库框、底部行动表 > 真实卡背 / 卡面 > 设计系统通用 token；禁止凭“古风感”临时选色。
- HUD 应像地图上原生印刷 / 叠放的桌游部件；禁止蓝绿 SaaS、霓虹、玻璃态、现代大圆角卡片、登录框装饰、羊皮纸大背景或规则说明墙。
- 可交互态靠边框、底色、轻抬、短标签表达；规则细节放 hover / focus / tap tip 或帮助入口，不常驻挤压主槽位。

| Token | 值 | 用途 |
| --- | --- | --- |
| `mapInk` | `#20150d` | 粗黑边、地图牌库框、行动表边 |
| `mapPanel` | `rgba(32,21,13,0.76)` | 玩家条、行动按钮、tip、牌堆标签 |
| `mapGold` | `#d2b775` | 暗底数字、次级信息 |
| `mapIvory` | `#ead7a7` | 暗底主文字 |
| `cinnabar` | `#9f3426` | 当前、选中、危险、执行强调 |
| `paperLight` | `#f3e7c4` | 浅底数字章和必要小标签 |
| `shadow` | `rgba(56,35,15,0.24)` | 牌堆 / 按钮轻压印阴影 |

## 失败项

以下任一出现即判 UI 未收口：

- 地图、区域高亮、token、tooltip 和领域结算不是同一坐标 / 区域定义。
- 主地图不是真实地图素材，或外侧出现纯色边块、黑条、拼接线、低清裁图、软遮罩补丁。
- 左上轮盘只剩 3 个选项、跟随地图层移动、依赖地图原图透明热区，或出现低清裁图 / 大圆遮底 / 多环重绘。
- 轮盘文字没有规则 / 素材证据，或出现八卦、卦线、假 OCR、图腾等无来源元素。
- 纪年只剩 1 张；左下抽牌、底中手牌、右下弃牌任一漂移或被挤出主槽位。
- 右侧行动按钮出现同义“执行 / 确认执行”按钮、支付进度、花费圆章、铺满长横条，或被临时面板挤走。
- 地图 tip、说明块、季节摘要、日志或规则说明盖住主交互入口。
- 手牌出现厚托盘、半透明罩、旋转扇形或被左右面板压窄。
- 按钮弱到像标签、白块或说明文字；玩家条、按钮、tip、牌堆标签看起来像几套 UI。
- 常驻行动记录、规则说明、地图缩放工具、装饰角、背景分隔线、无关标题。

## 验收

- 每轮 UI 改动后，用真实页面截图同时对照主地图素材，复核左上是否清晰、HUD 是否固定、颜色是否回到素材、主槽位是否未被挤压。
- 轮盘改动必须包含选中态截图；地图交互改动必须证明命中区、高亮、提示和结算目标一致。
- 过程截图可用于诊断；只有稳定候选截图通过 AI 图面核验并被选为验收图后，才展示给用户。
