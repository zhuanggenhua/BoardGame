# 七大恨 UI 设计规范

> 适用范围：`qidahen` 当前 Board 前端实现、UI 指导图、生图 prompt 与验收截图。
> 当前阶段：地图玩法层接入 + HUD 布局收口。主地图进入 `Scene/MapLayer`，轮盘、玩家条、朝鲜、纪年、行动、抽牌、手牌、弃牌继续固定在 `ScreenUiLayer`。

## 当前强制方向

- **用户草图是空间合同**：当前以 `D:\gongzuo\webgame\gameasset\ui参考\七大恨ui设计.png` 为布局合同。左上轮盘、顶中玩家悬浮窗、右上朝鲜、左中纪年卡、右中可执行操作、左下抽牌、底中手牌、右下弃牌必须落在对应区域。
- **地图与 HUD 分层**：当前 Board 使用真实 `qidahen/board/qidahen-main-map` 作为地图玩法层；HUD 不得被地图缩放、拖拽或裁切影响。除地图本体、区域高亮、路线和 token 外，不新增背景纹理、装饰角、规则说明或无关工具。
- **`1920x1080` 只是设计稿尺寸，不是固定画面边界**：七大恨可以按 1920 宽设计稿换算轮盘、玩家条、朝鲜牌库、行动栏、手牌和弃牌的位置与尺寸，但主地图底图必须先覆盖真实视口。禁止把整页实现成固定 1920 宽舞台后在左右补纯色块、黑边、遮罩条、模糊补丁或明显拼接背景。
- **底图做法必须参考成熟页**：七大恨底图应按召唤师战争和山屋惊魂的模式拆层：外层真实视口容器负责铺满地图/桌面气氛；中间地图内容层负责缩放、拖拽、区域和 token；HUD 层独立放轮盘、玩家条、牌堆、行动栏和手牌。允许暗角或渐隐压场，但它必须覆盖在真实底图上，不能变成设计画布外的纯色边块。
- **轮盘必须是独立 HUD 交互控件**：地图原图里的轮盘只能作为比例、色彩、文字密度和分区参考，不能承担视觉本体或点击本体。地图一旦平移、缩放或拖动，轮盘仍必须固定在屏幕左上并保持可读、可点、可高亮。
- **禁止曲解“保留原轮盘”**：当用户要求接近、保留或恢复地图原轮盘观感时，只能理解为“独立 HUD 轮盘按地图素材校准外观”。不得把它解释成删除 HUD 轮盘、只保留地图底图轮盘、用透明热区点地图轮盘，或让交互依赖会被拖动/缩放的 `Scene/MapLayer`。
- **轮盘重绘必须克制且贴近素材**：允许用清晰前端 SVG 画独立轮盘，但只能画素材中必要的单一外圈、单一内圈、8 个扇区、行动文字、中心标题、当前位置/目标高亮和透明命中区。禁止为“遮残影/统一风格”新增大面积纸色圆垫、软遮罩、第二套外圈、多余同心环或覆盖地图的大块背景。
- **轮盘内容必须来自规则、地图素材与参数图**：轮盘扇区文字不得用八卦、卦线、数字或猜测标签替代。当前轮盘行动来自 `src/games/qidahen/rule/七大恨规则.md` 的“轮盘行动”章节与 `public/assets/i18n/zh-CN/qidahen/board/main-board.png` 左上行动轮盘：`开垦/军屯`、`征兵/训练`、`外交/雇佣`、`进攻/调度` 这四类行动在 8 个扇区中重复分布；提示文字来自规则中的移动代价与抽牌结果。改轮盘前必须先重做“规则原文 -> 地图素材轮盘 -> 参数图短标签 -> UI短标签”证据表。
- **轮盘移动分支不得常驻成旁边按钮**：`走 1 / 走 2 / 走 3` 只是轮盘目标格的分支语义，不是独立控件。当前轮盘必须在轮盘本体上叠加命中区；移动结果、抽牌代价和说明只允许 hover/focus tip 出现，不得占据左上或左中空间。
- **禁止模仿大杀四方的歪扭扇形**：七大恨当前手牌区不做旋转扇形、不做错位堆叠、不做半透明托盘罩。手牌是底部中间的大空间，卡牌直排、可读、可点击。
- **禁止借鉴其他游戏的牌库布局覆盖草图**：抽牌堆与弃牌堆按用户草图分别固定在左下、右下；不能因为某个既有游戏把牌库放在别处，就把七大恨下方两角空出来。
- **禁止无关 UI**：当前画面不显示行动记录、规则说明、地图工具、缩放提示、常驻区域说明、战斗面板、装饰角、标题分隔线、流程说明、登录框式边角装饰。区域信息只允许作为 hover/focus/tap tip 或选中后的局部反馈。
- **左右下角不是留白区**：左下必须是抽牌堆，右下必须是弃牌堆；二者是手牌簇两侧的实体，不是可省略装饰。
- **提示默认悬浮**：轮盘结果摘要、规则提示、查看说明默认是 hover/focus/tap tip 或临时 overlay；不得常驻成块占位挤压纪年、操作区或手牌。
- **按钮必须像按钮**：可执行操作必须有清晰边框、底色、hover/press/focus/disabled 态和可点击材质，不能退化为淡文字、白块或纯说明标签；轮盘分支不作为常驻按钮出现。
- **行动按钮就是执行入口**：右侧势力行动按钮不得再配一个同义的“执行”按钮，也不得在按钮上显示弃置数量、支付进度或花费圆章。当前 UI 口径是点击行动即结算，领域层自动处理必要弃牌。只有规则明确要求二次确认或危险提交时，才允许额外确认入口。
- **空间紧预算时允许保留特殊确认链**：若地图、右侧动作栏和底部手牌已经接近满载，把确认/支付/弃牌这类步骤强塞回通用动作槽会直接挤坏主交互区时，允许保留独立的特殊确认链，例如手牌上方独立确认条或局部 overlay。此时优先级是“主交互区不被挤坏、用户一眼知道下一步”，而不是机械追求所有确认都并回同一入口。
- **用户可操作 UI 必须有固定槽位**：左上轮盘、右侧动作栏、底部手牌是三块固定可操作 UI。它们的位置和尺寸预算必须先保留，再去安排提示、摘要、说明、hover tip、结算块；不得让这些次级 UI 反过来挤压主交互入口。
- **瞬时交互必须进入既有槽位，不得抢位**：弃牌确认、外交选择、调度目标、战后处理、响应窗口这类瞬时交互，必须进入右侧交互槽位、底部手牌选择链或 overlay；不得靠增加一块新面板去把动作按钮、手牌或地图提示顶开。
- **交互模式必须有来源表**：七大恨当前可用来源不是空白。固定构图与锚点以 `D:\gongzuo\webgame\gameasset\ui参考\七大恨ui设计.png` 为主真相；“底部常驻主交互槽位”参考 `src/games/smashup/ui/HandArea.tsx`；“底部非阻塞卡牌查看/选择”参考 `src/games/smashup/ui/PromptOverlay.tsx`；“阻塞 ownership 的中央响应层”参考 `src/games/smashup/ui/MeFirstOverlay.tsx`；“主交互承接面单一路由”参考 `src/games/smashup/Board.tsx` 中 `activePromptSurface`。没有写出这类来源表，不得再发明新的交互承载方式。

## 主交互槽位五联单（当前正式口径）

- **局内剧本投票 / setup**
  - 主交互对象：剧本介绍卡、人物/军备候选、确认投票/确认前置按钮。
  - 固定槽位：独立 setup 页或独立 setup overlay；不得与正式棋盘 HUD 同屏竞争。
  - 让位顺序：正式棋盘轮盘、右侧动作栏、底部手牌、牌堆、地图提示全部让位，只保留弱化背景或阶段装饰。
  - 禁止侵入对象：正式轮盘、势力行动按钮、底部手牌 dock、主地图交互热区。
  - 来源家族：`QidahenScenarioVoteScreen` + `QidahenInMatchSetupOverlay`，参考 `SmashUp MeFirstOverlay` 的单一 ownership/setup 壳层。

- **右侧势力动作槽位**
  - 主交互对象：一级行动按钮、当前行动说明、当前主入口明文提示、当前步骤专属交互卡。
  - 固定槽位：右中 `qidahen-actions-zone`；上半段是说明/当前步骤，下半段是固定动作 rail。
  - 让位顺序：被动状态摘要、季节总结、城防状态、说明块先退；动作 rail 与当前步骤卡不得下移。
  - 禁止侵入对象：地图 tip、season summary、fortification strip、waiting/hint/confirm strip 不得把动作按钮挤走或做成第二主入口。
  - 来源家族：`src/games/qidahen/Board.tsx` 中 `qidahen-action-slot + qidahen-action-rail`，参考 `SmashUp activePromptSurface` 的单一主承接面。

- **底部手牌支付 / 弃牌 / 科技选择**
  - 主交互对象：当前 viewer 的真实手牌，以及手牌上方的确认/取消交互条。
  - 固定槽位：底部 `qidahen-hand-dock` + `qidahen-hand-interaction-tray`。
  - 让位顺序：说明块、日志、次级摘要先退；底部手牌与确认条不改成右侧新面板，也不被其它 HUD 下压。
  - 禁止侵入对象：右侧动作条、地图 tip、season summary、setup waiting 文案、临时帮助块。
  - 来源家族：`HandZone` + `HandInteractionTray`，参考 `SmashUp HandArea` 与 `PromptOverlay displayCards` 的底部卡牌承接方式。

- **轮盘推进唯一下一步**
  - 主交互对象：右侧动作槽位中的轮盘推进横幅与明文按钮；左上轮盘盘面只保留辅助视觉与区域理解，不再承担唯一入口。
  - 固定槽位：右侧 `qidahen-wheel-next-step-banner`。
  - 让位顺序：被动摘要与其它步骤说明先退，轮盘推进按钮保持第一焦点。
  - 禁止侵入对象：地图热区提示、轮盘旁边的临时说明块、额外“执行”按钮列。
  - 来源家族：`showWheelNextStepBanner`，参考成熟项目里“唯一下一步必须有明文 CTA”的主入口策略。

## 布局合同

桌面基线：`1920x1080`，仅作为 PC 验收视口和设计稿尺寸，不是页面最大宽度。

主地图 Scene 必须铺满真实 viewport；宽屏外侧必须由真实地图、桌面或可裁切场景自然承接，不能出现纯色边块、黑条、半透明遮罩条、固定舞台硬边或明显拼接线。HUD 可以继续按 1920 设计稿换算位置 / 尺寸，但不得和 Scene 共享会裁掉或限制底图的固定外框。

| 区域 | 必须出现 | 位置与尺寸要求 |
| --- | --- | --- |
| 左上 | 行动轮盘 | 独立 HUD SVG 轮盘，8 扇区完整清晰；尺寸接近地图素材真实比例；当前格、可选步数与结果摘要属于轮盘局部；不得依赖地图原图轮盘，也不得用大圆遮底或多层边框覆盖地图 |
| 顶中 | 玩家悬浮窗 | 三方势力状态一行展示：势力、VP、手牌/上限、当前玩家；不得变成大头像面板 |
| 右上 | 朝鲜 | 朝鲜牌库与朝鲜弃牌两个实体牌堆，靠右上，不能被行动区挤到底部 |
| 左中 | 纪年卡 | 常驻显示今年、下一年两张纪年卡；纪年牌堆只有当前操作需要查看/抽取时才作为悬浮入口出现，不常驻挤占空间 |
| 右中 | 可执行操作 | 右侧必须保留固定动作栏与独立交互槽位：动作按钮长期停在同一列，弃牌确认/外交/调度/战后等瞬时面板只进入该列上方或同列内部的独立槽位，不得把动作按钮本身往下挤；按钮宽度按动作短名收紧，按内容做紧凑纸签，不做 full-width 横向空条；点击按钮即执行或进入唯一必要目标层，不放支付状态、确认执行、规则解释、日志或调试工具 |
| 中央 | 主地图 | 真实地图进入 `Scene/MapLayer`，区域、路线、token 与地图坐标同源；HUD 不得占据地图主要判断区 |
| 左下 | 抽牌 | 当前玩家抽牌堆，贴近左下边界，不得被手牌区或空白垫高 |
| 底中 | 手牌 | 最大底部空间，贴底直排多张可读手牌，无半透明遮罩，无旋转扇形 |
| 右下 | 弃牌 | 当前玩家弃牌堆，贴近右下边界，不得被手牌区或空白垫高 |

## 风格合同

- 风格名称：**明末地图墨框 UI**。这里的“风格化”不是把现代网页卡片换成米黄色，也不是给 HUD 加滤镜；它必须复刻七大恨真实地图和卡面里的视觉语法：旧地图黄褐纸底、粗黑墨框、暗茶半透明牌库框、金黄/朱砂字、印刷颗粒、硬边界。
- 颜色真相源优先级：`qidahen-main-map.png` 的左上轮盘、右侧朝鲜牌库框、底部行动表 > 真实卡背/卡面 > 设计系统通用 token。任何新增 HUD 颜色都必须能回指到这些素材区域之一；禁止凭“看起来古风”临时选一组黄/棕/红。
- 地图层必须清晰。当前不使用左上清理层或遮罩；如果未来必须遮挡地图元素，遮挡结果不能呈现软糊、雾化、低清渐变、拉伸补丁或明显色斑。左上区域如果在 E2E 截图里像被糊了一层雾，直接判失败。
- HUD 应像地图上原生印刷/叠放的桌游部件，而不是浮在地图上的网页控件。玩家条、行动按钮、tip、牌堆标签必须优先采用暗墨框、厚黑边、金字/朱砂字和轻微印刷纹理；浅纸签只允许用于真实卡面/牌堆数字章这类素材本身接近浅底的部件。
- 风格一致不等于给 HUD 加背景。地图层只使用真实地图素材；HUD 外壳不得额外铺羊皮纸大背景、模糊图、玻璃态、现代卡片阴影或登录框式装饰。
- 可交互态只用边框、底色、轻抬、短标签表达；不要靠大面积半透明罩子说明状态。
- 文案只写短名词/动作/必要数字：例如 `抽牌`、`弃牌`、`朝鲜牌库`。行动按钮不写 `需弃 / 已选`、花费或支付进度；这类规则细节只进 hover/focus/tap tip 或规则帮助。

### 风格 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `mapInk` | `#20150d` | 地图右侧牌库框和底部行动表的粗黑边 |
| `mapPanel` | `rgba(32,21,13,0.76)` | 玩家条、行动按钮、tip、牌堆标签的暗茶底 |
| `mapGold` | `#d2b775` | 暗底上的数字、次级信息和弱强调 |
| `mapIvory` | `#ead7a7` | 暗底主文字 |
| `cinnabar` | `#9f3426` | 当前/选中/危险/执行主强调 |
| `paperLight` | `#f3e7c4` | 只用于真实浅底数字章和必要小标签 |
| `shadow` | `rgba(56,35,15,0.24)` | 牌堆/按钮轻压印阴影 |

### 组件族语法

| 组件 | 风格规则 |
| --- | --- |
| 玩家悬浮窗 | 暗茶墨框底、粗黑边、真实 marker 圆章；当前玩家用朱砂暗框，不使用浅色网页卡片背景 |
| 牌堆 | 真实牌背/牌面 + 2 层暗墨叠影 + 左上暗框短标签 + 右下浅色圆形数字章 |
| 手牌 | 真实卡面直排；主态不显示 `可付/已选` 角标；需要查看或选择时使用悬浮/临时态，不加整条托盘罩 |
| 按钮 | 暗茶墨框矩形、粗黑边、金字/朱砂字、hover 轻抬、press 下沉；叶子行动按钮承担执行语义，不显示弃置数量/花费圆章，不另设同义“执行”按钮 |
| 轮盘 | 使用清晰前端 SVG 作为固定 HUD 本体；灰褐盘面、黑色外圈、墨色分区线、规则行动短标签、中心“行动轮盘”按真实地图轮盘校准；前端承担完整视觉、透明命中区、当前位置/目标朱砂高亮和 hover/focus tip，不常驻旁边按钮 |
| tip | 暗茶墨框、金字/浅字、短句；只悬浮，不占布局空间 |

### 风格验收

- 同屏按钮、tip、玩家条、牌堆标签必须共享 `mapInk / mapPanel / mapGold / cinnabar / shadow`，不能一个像现代网页、一个像素材、一个像登录框。
- 真实卡面可以保留素材自身颜色；所有前端新增 UI 外壳必须使用本表 token。
- 每轮 UI 改动后必须同时打开 E2E 截图和 `qidahen-main-map.png` 对比，自审左上是否清晰、颜色是否回到地图素材、HUD 是否像地图原生部件。
- 若 `ui-ux-pro-max` 推荐与本表冲突，以本表和真实素材为准；例如蓝绿 SaaS、霓虹、CRT、Bento 大圆角都不采纳。
- 风格调整不得改变已通过的布局锚点：地图、左上轮盘、顶中玩家、右上朝鲜、左中纪年、右中操作、左下抽牌、底中手牌、右下弃牌不能被重排。

## 轮盘门禁

- 必须能一眼看到 8 个轮盘扇区，不能只显示 `走 1 / 走 2 / 走 3` 三个移动选项。
- 8 个扇区必须显示素材/规则可证明的行动短标签，当前按地图轮盘显示两行行动组合：`开垦/军屯`、`征兵/训练`、`外交/雇佣`、`进攻/调度`。不得显示八卦名、卦线、序号、假 OCR 字、图腾或装饰字来冒充内容。
- 三个移动选项只是“转动方式”，不是轮盘本体；不得常驻成独立按钮列，必须从属于完整轮盘的命中区和悬浮提示。
- 改轮盘内容前必须同时核对规则文档和参数/参考卡；没有来源表时不得提交实现，也不得用“看着像素材”解释轮盘文字。
- 行动轮盘不得无中生有八卦、卦线、装饰线、占卜图腾、假 OCR、符号点阵或任何地图素材/规则没有出现的视觉元素；只有外圈、分区线、行动文字、中心“行动轮盘”、当前位置高亮、选中目标高亮/放大、必要交互热区与 tip 可以进入实现。
- 轮盘不得使用低清裁图、放大截图、遮罩补丁、大面积遮底或地图原图透明热区冒充本体。当前使用清晰前端 SVG 轮盘作为固定 HUD 本体，并按真实地图轮盘校准盘面、外圈、分区线、文字位置和印刷颗粒。
- 未经用户明确确认，禁止为“消除残影/统一风格”新增任何超出轮盘自身圆盘范围的大圆、纸色垫、软遮罩或额外同心环；这类做法会改变视觉真相源，不能当作样式微调。
- 独立 HUD 轮盘若覆盖在地图原轮盘附近，必须按地图素材的屏幕投影校准尺寸和锚点，避免露出两套外圈、两套分区线或错位残影；不能用放大圆盘、额外垫片或软遮罩掩盖错位。
- 轮盘结果摘要只允许作为轮盘局部悬浮 tip，不允许常驻成一块独立说明面板，也不允许依附到常驻步数按钮上。
- 地图玩法层加入平移/缩放/拖拽时，轮盘仍必须停留在 HUD 层，不得跟随地图移动造成视觉和点击错位。
- 对齐必须是实现，不是敷衍贴图：当前截图必须证明轮盘视觉层、透明命中层、朱砂选中态三者重合。选中态必须绑定真实轮盘目标格，并以该扇区独立图层实现描边/底色，不得只给整张轮盘加滤镜，也不得把选中效果做成旁边说明块。
- 每次轮盘 UI 改动必须交付选中态截图：截图要来自当前实现的 E2E/浏览器结果，且必须能看见轮盘命中后选中的目标扇区；参考图、素材裁图和结果图必须分开命名，禁止把参考图当结果交付。

## 地图交互门禁

- 地图交互以真实 `qidahen/board/qidahen-main-map` 的区域边界为基础；区域名、控制权、token 位置和可点击范围必须能回指到地图素材或规则文档。
- 主地图原图里的左上轮盘只作为 HUD 轮盘的素材参考；前端不得用透明热区依赖地图轮盘，也不得用 `left-top-clean-patch` 类软遮罩或大圆遮底清理它。交互能力必须由固定 HUD 轮盘自身提供。
- 当前首选实现是同源区域 polygon 派生两层：离屏 2D canvas hitmap 负责点击/hover 命中，SVG overlay 负责可见高亮和选中态。命中区、高亮边界、tooltip 文案和领域结算目标必须引用同一份区域定义。
- WebGL / Three.js color picking 只在 2D canvas hitmap 无法支撑区域数量、缩放性能或复杂动态效果时升级；升级前必须保留同源区域数据，不得把区域真相散落到 shader、临时颜色表和手写 DOM 坐标里。
- 区域说明只允许 hover/focus/tap tip 或选中反馈出现，不得常驻成侧边说明卡，也不得为每个区域另做同义按钮。
- 点击地图区域后必须有明确 hover/selected 高亮；行动按钮如果已按游戏口径“点击即执行”，结算必须使用当前选中区域，不再弹出同义“执行/确认”入口。
- 地图 token 若改成正式素材底座后会让地图更挤、更难分辨主次，允许人口这类辅助数值继续使用轻量代码圆章或等价简化表现；不强制所有 token 都跟控制标记使用同一素材语言。前提是控制、人口、外交、兵力四类语义仍能一眼区分，且真实截图证明可读性优于“统一素材但更拥挤”的方案。

## 当前失败项清单

以下任一出现即判 UI 未收口：

- 地图未使用真实主地图素材，或地图、区域高亮、token 不在同一坐标系。
- 点击热区、高亮边界、tooltip 名称和领域结算对象不是同一份区域定义派生。
- 左上轮盘只剩 3 个可见选项，或轮盘跟随地图层移动。
- 左上轮盘旁常驻 `走 1 / 走 2 / 走 3` 独立按钮列，挤占左上/左中空间。
- 纪年卡只显示 1 张，缺少今年/下一年两张常驻关系。
- 纪年牌堆在主态常驻，占用左中区域或把纪年卡挤小。
- 手牌后面出现半透明罩子、厚托盘、扇形旋转或被左右面板压窄。
- 左下/右下空着，抽牌堆/弃牌堆漂到别处。
- 轮盘结果摘要、规则提示或说明文字常驻占位。
- 右侧行动区出现与行动按钮同义的“执行/确认执行”按钮，造成点击行动和执行行动两套入口。
- 右侧行动按钮显示弃置数量、支付进度、花费圆章或其它解释性数字，导致按钮不再是直接执行入口。
- 右侧行动按钮按固定容器铺满，短动作名后留下明显空白横条。
- 右侧动作按钮会因为弃牌确认、调度选择、外交选择、提示摘要等瞬时面板出现而改变纵向位置，或被挤到手牌区上方。
- 地图区域 tip、说明块或其它面板盖到右侧动作栏上，导致主交互入口需要透过别的 UI 才能看见或点击。
- 按钮视觉弱到像标签、白块或说明文字。
- 右侧交互改成了仓库里从未出现过的新样式/新承载方式，但实现前没有写出参考来源、沿用不变量和不适用点。
- 玩家悬浮窗、按钮、tip、牌堆标签使用不同色板/圆角/阴影，看起来像几套 UI。
- 为了风格统一引入蓝绿 SaaS、霓虹、厚金属、羊皮纸大背景或登录框式装饰。
- 出现行动记录、规则说明、地图缩放工具、装饰角、背景分隔线、无关标题。
- 使用低清地图裁图、软遮罩、大圆遮底、透明热区依赖地图轮盘，或多环重绘轮盘来制造 HUD 风格一致，导致左上模糊、多层边框、拖图后错位或交互热区丢失。

## 地图层口径

地图区域控制是当前玩法层。实现必须维持明确分层：

- `Scene/MapLayer`：地图、区域、路线、token。
- `ScreenUiLayer`：独立 SVG 轮盘、玩家悬浮、朝鲜、纪年、操作区、抽牌、手牌、弃牌，固定屏幕布局。

不得为了接地图而把当前 UI 元素重新塞回地图底图或地图裁切层。
