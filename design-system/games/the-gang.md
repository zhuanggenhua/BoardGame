# The Gang UI 设计合同

## 视觉方向

- The Gang 使用“绿色牌桌 + 金库/警报 + 扑克协作推理”的专属风格。
- BGG 电子版只提供结构参考：顶部玩家板、中部筹码池 / 牌河、底部金库 / 手牌、结算 reveal / final 态。
- TTS / Workshop 只提供素材和对象参考，不提供 UI 风格目标。
- 首屏第一视觉必须是扑克、筹码、牌河和金库 / 警报；不能长成通用卡片面板、说明卡或后台 HUD。
- BGG 的 `.top_zone / .middle_zone / .bottom_zone` 是开放牌桌关系，不是三层外框；实现要保留空气感和对象本体优先级。

## 主界面

- 主 UI 只常驻对象名、数值、短状态和按钮标签；规则解释、结构说明和长段策略文案默认折叠。
- 顶部玩家板显示玩家、当前筹码和手牌可见 / 隐藏状态；其它玩家按当前本地玩家之后的自然座位顺序从左到右排列，本地玩家不显示在顶部。
- 中央区优先展示当前轮筹码池和公共牌河，不被帮助、日志或参考内容挤占。
- 底部区承接金库 / 警报、我的手牌、当前牌型和单一主操作。
- 容器只用于真实语义边界：玩家板、牌槽、手牌、结算；普通分区不得再叠一层卡片壳。
- 规则、扩展、工具牌、开始按钮和筹码等“玩家看得见但当前不可用”的入口必须给 toast 反馈，不能静默 disabled。

## 开局与设置

- 新房间默认处于开局配置状态；只有房主点击 `开始抢劫` 后，本次抢劫才开始。
- AI 和玩家都不得在开始前拿筹码、推进轮次或顺手锁规则。
- 抢劫开始后，扩展、模式、挑战和开局开关不锁死；房主继续修改时必须提示“会重新开始整局”，确认后重建到第一场抢劫开始前。
- 规则设置弹窗是草稿式：模式卡、挑战牌和开关只更新弹窗内草稿；只有 `应用设置` 可触发重开确认。取消或关闭不得应用草稿。

## 两副牌模式

- 两副牌模式没有独立交换阶段、确认按钮、跳过按钮或计数条；`上手 / 下手` 两副真实手牌始终留在牌桌上。
- 在 `chip-selection` 阶段，玩家可随时把上手牌拖到下手牌上，或反向拖拽，松手立即交换位置；摊牌和结束态不允许改牌。
- 拖拽换位时，源卡隐藏为占位，只显示指针下的 ghost；不得出现原位卡和 ghost 双显。
- 目标高亮锚定另一副手牌的真实卡牌本体，不得框到手牌行、按钮或空白父容器。
- `上手 / 下手` 是两副独立手牌标签；承接筹码归属的按钮必须写成 `给上手 / 给下手`，不能只写对象名。
- `给上手 / 给下手` 是手牌旁的辅助目标选择器，不是主手牌对象；移动横屏下默认锚定在两副手牌左侧动作槽，与手牌纵向对齐。
- 选择器不得贴屏幕底边、系统手势边缘、筹码池下方或手牌上方中央。
- 可见按钮面默认是小标签 / 小胶囊：单个宽度不超过手牌本体约 `45%`，两个总面积不超过手牌本体约 `25%`；触控热区仍保留 `44px` 级命中区。

## 筹码交互

- 筹码是核心比较对象，视觉权重必须接近真实筹码，不得退成小状态点。
- 筹码拿取、放回和拖拽是全桌公共动作；玩家和旁观者必须能看清谁拿走 / 放回 / 拖动了哪枚筹码。
- 信息 owner 只能有一个：玩家名优先由座位承担，筹码值优先由筹码本体承担；只有离开稳定锚点时才补文字。
- 点击拿筹码或放回筹码时，使用从来源到目标的淡入淡出白色轨迹线；不额外显示 `玩家名 · 筹码值` 气泡。
- 远端拖拽 ghost 这类没有稳定座位锚点的筹码，才允许显示 `玩家名 · 筹码值`。
- 多名玩家同时拖拽筹码时，远端拖拽体必须同屏并存、身份和值可辨；结束某一名玩家的拖拽不能清掉其它拖拽体。
- 筹码拖到 `上手 / 下手` 时，命中范围、过程高亮和落点动画同锚到整副手牌行；源筹码隐藏占位，避免与 ghost 双显。
- 已贴到 `上手 / 下手` 的筹码必须能拖回中间筹码池；反向拖拽时，中间筹码池成为 active，来源手牌不能反向高亮，另一副手牌只保持 available。
- 可松手范围高亮使用开放式牌桌语法：右侧敞开，无右侧边框；上下边界从左到右渐隐，左侧保留轻量定位线。
- 重开、重新发牌或应用规则重开后，首次拖筹码必须立即出现 ghost、源占位和目标高亮；拖拽生命周期由全局指针接管，不能依赖会被隐藏或重渲染的源按钮。

## 响应式

- `mobileLayoutPreset: board-shell` 下 Board 根容器使用 `h-full / min-h-0`，禁止 `100vh / 100dvh / min-h-screen` 成为内部高度真相源。
- 核心牌桌对象按设计画布尺寸进入 shell，再由 shell 统一等比缩放；手牌、公共牌、筹码和主交互对象不得继续吃真实 viewport 的 `sm/md/lg/xl` 后再被二次缩小。
- 手机横屏必须同时看到顶部玩家板、中部筹码 / 牌河和底部手牌 / 操作区；底部裁切即未完成。
- 手机横屏筹码验收必须校验 `移动实际尺寸 ≈ PC/设计基线筹码尺寸 × shell scale`；可点击或 44px 热区达标不能证明比例正确。
- 手机横屏两副牌还要证明 `给上手 / 给下手` 不贴底、不压手牌、不压安全区、贴近两副手牌动作区，且视觉面积不抢手牌主体。
- 左下 `牌型 / 扩展 / 工具` 和扩展 / 工具弹窗沿用 PC 承载结构，只压缩尺寸、间距和安全区；不得迁移到手牌侧或另做移动端皮肤。

## 验收

- 先验收桌面首轮、桌面摊牌 / 结算，再进入手机横屏主修；手机只能在桌面合同上降级，不能反向改变桌面构图。
- 定向单测断言 BGG 结构标记和结算标记存在。
- 真实页面 E2E 生成桌面首轮、桌面摊牌 / 结算、手机横屏截图。
- 两副牌验收覆盖：开局前和开始后均可换位、无独立交换阶段、源卡 / 源筹码隐藏占位、目标高亮锚定真实手牌、`给上手 / 给下手` 的位置 / 尺寸 / 热区 / 空间关系。
- 筹码验收覆盖：点击拿取共享过渡、多人同时拖拽、手牌筹码拖回中间筹码池、重开后的首个拖筹码性能信号。
- 联机筹码截图必须能从观察页看到其它真实玩家拿筹码；观察页本地玩家与拿筹码玩家必须不同，禁止用自己拿筹码冒充“别人拿了什么”。
- 最终展示给用户的截图必须先按项目 UI 审计和看图规范完成 AI 图面复看；旧 TTS 截图不能作为完成证据。
