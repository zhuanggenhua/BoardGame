# The Gang UI 设计合同

## 视觉方向

- The Gang 使用“绿色牌桌 + 金库/警报 + 扑克协作推理”的游戏专属风格。
- BGG 电子版只提供结构参考：顶部玩家板、中部筹码池/牌河、底部警报金库/手牌、结算 reveal/final 态。
- TTS/Workshop 只提供素材和对象参考，不提供 UI 风格目标。
- 独立风格关键词：`地下金库牌桌`、`协作抢劫指挥台`、`赌场筹码与保险箱`、`低噪声绿色毡布`。
- 不能长成其它游戏的通用卡片面板：The Gang 的首屏第一视觉必须是扑克、筹码、牌河和金库/警报，而不是层层容器、说明卡或通用 HUD。
- BGG 的 `.top_zone / .middle_zone / .bottom_zone` 是开放牌桌关系，不是三层外框；实现上应保留空气感和对象本体优先级。

## 主界面规则

- 主 UI 只常驻对象名、数值、短状态和按钮标签；禁止常驻规则解释、结构说明和长段策略文案。
- 新房间进入后默认是开局配置状态；只有房主点击 `开始抢劫` 后，本次抢劫才正式开始，AI 和玩家都不得在开始前拿筹码或推进轮次。
- 抢劫正式开始后，扩展、模式、挑战和开局开关不锁死；房主继续修改时必须先提示“会重新开始整局”，确认后重建到第一场抢劫开始前。不能依赖 AI 先手或某个玩家先拿筹码来“顺便锁规则”。
- 规则设置弹窗必须是草稿式：点模式卡、挑战牌和开关只更新弹窗内草稿；只有点击 `应用设置` 才允许触发重开确认，且确认必须使用项目内自定义弹窗。取消或关闭弹窗不得应用草稿。
- 两副牌模式的交换牌属于开局前准备动作：必须发生在房主点击 `开始抢劫` 前；开始抢劫后不得再把每轮筹码后的调换牌阶段当作正式主流程。
- 两副牌模式里，`上手 / 下手` 是两副独立手牌的标签；承接点击的目标按钮必须写成 `给上手 / 给下手`、`交换上手 / 交换下手` 这类动作 + 对象，不能只写 `上手 / 下手`。
- 上手/下手按钮不得贴屏幕底边、系统手势边缘或底部安全区下沿；移动横屏下必须抬离底边，并且默认锚定在两副手牌左侧动作槽，与手牌纵向对齐。底部可以承接手牌本体，但不能把上手/下手主按钮钉在最底边，也不能把它漂到手牌上方中央或筹码池下方。
- `给上手 / 给下手` 选择器不能挂在筹码池下方、筹码行内部或其它远离手牌的空白区域；哪怕触控尺寸达标、离屏幕底边足够远，只要玩家第一眼会把它理解成“筹码区控制”而不是“两副手牌目标选择”，就判为失败。
- `给上手 / 给下手` 是手牌旁的辅助目标选择器，不是主手牌对象；移动横屏下必须区分可见按钮面和触控热区：可见按钮面默认做成小标签 / 小胶囊，单个可见面宽度不超过手牌本体宽度约 45%，两个可见面的总面积不超过手牌本体约 25%；每个按钮热区仍必须保留 44px 级命中区，可用透明 hitbox 外扩，不得把可见按钮面画成 44px 高的大主按钮。
- 规则、扩展、工具牌、开始按钮和筹码这类玩家点得见但当前无权限/未满足条件的入口，必须给 toast 反馈；禁止只用静默 disabled 让玩家以为点不动或坏了。
- 顶部玩家板显示玩家、当前筹码和手牌可见/隐藏状态。
- 中央区优先展示当前轮筹码池和公共牌河，不被帮助说明、日志或参考内容挤占。
- 底部区承接金库/警报、我的手牌、当前牌型和单一主操作。
- 帮助/参考默认折叠或低侵入展示，不得变成主 HUD。
- 容器只用于真实语义边界：玩家板、牌槽、手牌、结算；普通分区不得再额外叠一层“卡片壳”。
- 桌面基线先验收：桌面首轮、桌面摊牌/结算的截图和 AI 复看通过前，不得开始以手机横屏为主修目标。
- 手机适配只能在桌面合同上降级，不能反向改变桌面构图、整体比例或对象主次。

## 响应式约束

- `mobileLayoutPreset: board-shell` 下 Board 根容器必须使用 `h-full` / `min-h-0`，禁止 `100vh`、`100dvh`、`min-h-screen` 作为内部高度真相源。
- `mobileLayoutPreset: board-shell` 下核心牌桌对象必须按设计画布尺寸进入 shell，再由 shell 统一等比缩放；手牌、公共牌、筹码和主交互对象不得继续把真实视口的 `sm/md/lg/xl` 断点当作主尺寸真相源。若需要紧凑态，先定义设计画布内的紧凑尺寸，再整体缩放；禁止“移动端先选小卡尺寸 + shell 再缩一次”的双重缩小。
- 手机横屏截图必须能同时看到顶部玩家板、中部筹码/牌河和底部手牌/操作区；若底部裁切，则 UI 未完成。
- 手机横屏两副牌截图必须额外证明上手/下手按钮不贴底、不压手牌、不压系统安全区、贴近两副手牌动作区，且触控命中区不小于 44px；Android/App 交付按 48dp 等价目标复核。`不贴底`、`44px` 和 `能点击` 只是底线，不能替代“按钮和手牌关系清楚、尺寸不抢手牌主体”的玩家视角判定。
- 手机横屏的左下 `牌型 / 扩展 / 工具` 和扩展/工具弹窗必须沿用 PC 承载结构，只允许压缩尺寸、间距和安全区；辅助入口必须保持左下竖排，不得因 `sm` / 横屏断点退化成水平排列，也不得在回归修复里擅自迁移到手牌侧或改成另一套移动端视觉皮肤。
- 结算态应使用 compact reveal/final 面板，不得把玩家结果列表撑爆底部安全区。

## 验收门槛

- 定向单测断言 BGG 结构标记和结算标记存在。
- 真实页面 E2E 重新生成桌面首轮、桌面摊牌/结算、手机横屏截图。
- 两副牌验收必须覆盖开局前交换牌、开始抢劫后不再调换牌、给上手/给下手按钮位置、与手牌的空间关系、与筹码池的脱离关系、触控尺寸、相对手牌的视觉比例，以及 board-shell 下移动端手牌卡面是否等于 PC 设计基线尺寸乘 shell scale。
- 最新截图必须打开给用户看，并单独做 AI 复看；旧 TTS 截图不能作为完成证据。
