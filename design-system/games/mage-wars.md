# 法师战争 UI 设计合同

> **gameId**：`mage-wars`
> **当前基线**：Open Design `v80` 红框对象交换修正版；竞技场格子使用人物 / 肖像法师本体，玩家 HUD 使用密集文字法师规则 / 提示卡。
> **设计路线**：继续使用 Open Design artifact，不改走 `od media generate`、imagegen 生图或静态 mock。旧 artifact / HTML 预览只作历史证据，不恢复为当前验收依据。

本文件只保留 Mage Wars 的长期 UI 合同。逐版本记录、用户纠正明细和素材矩阵分别看 [`design/README.md`](../../docs/games/mage-wars/design/README.md)、[`user-correction-traceability-ledger.md`](../../docs/games/mage-wars/design/reference/user-correction-traceability-ledger.md)、[`rule-to-ui-element-list.md`](../../docs/games/mage-wars/design/implementable/rule-to-ui-element-list.md) 和 [`board-ui-preflight-matrix.md`](../../docs/games/mage-wars/design/implementable/board-ui-preflight-matrix.md)。

## 必读前置

- 继续改设计稿、Open Design artifact、真实 Board/UI 或截图验收前，先消费规则对象清单、用户纠正账本、素材前置矩阵、外部 UI 方法论和 [`apprentice-zone-layout-contract.md`](../../docs/games/mage-wars/design/implementable/apprentice-zone-layout-contract.md)。
- `AI_PASS` 只表示 AI 图面核验可送人工看，不等于用户批准实现。
- 用户未明确批准前，真实 Board/UI 实现、真实页面 E2E 和移动端适配仍冻结。
- 当前首轮默认服务学徒 / 基础预设法术书，不服务完整自由构筑。

## 现实任务

- 让两名在线玩家在同一桌面视图里看懂当前阶段、当前行动者、可行动对象、可施放法术、合法目标和结算结果。
- 让施法成为画面主事件：来源、目标、路径 / 扩散、命中、骰子、伤害和状态 token 必须形成一条可见因果链。
- 保护隐藏信息：对手不能看到己方法术书、已计划法术正面或未展示结界身份；旁观者默认看玩家 0 或当前回合玩家视角。
- 失败命令不能播放成功 FX；非法施法、资源不足、目标不合法、目标移动导致取消都要有短拒绝反馈。

## 当前基线

- **法师对象拆三层**：`法师战场实体 / 法师本体`、`玩家 / 法师规则提示卡`、`法师规则 / 提示卡详情` 必须分开命名、分开素材职责、分开验收。
- **v80 裁定**：竞技场格子放人物 / 肖像法师本体；玩家 HUD 放密集文字规则提示卡；详情层只放大规则提示卡，不创造第二个可操作法师。
- **区域锚点**：学徒竞技场按 `2列 x 3行` 半场设计，区域 ID 为 `A1/B1/A2/B2/A3/B3`；场上卡牌必须声明唯一 `zoneId`。
- **位置门槛**：卡牌中心点必须落在所属区域内；旋转后可见包围盒至少 `85%` 在所属区域内，相邻区域重叠超过 `12%` 判失败。
- **素材门槛**：已有正式竞技场、卡图、卡背、token、攻击骰贴图不得被程序化占位替代；生命 / 法力 / 聚魔等动态读数可自制，但必须有明确对象锚点、材质和状态变化。

## 规则对象

| 对象 | UI 合同 | 禁止 |
| --- | --- | --- |
| 竞技场区域 | 中央最大主舞台，承载移动、范围、目标、墙体和对象归属 | 自由坐标摆放、卡牌骑线、用代理列表替代格子直选 |
| 法师战场实体 | 代表法师本人，作为来源 / 目标 / token 宿主，放在所属区域 | 用密集文字规则卡、纯文字、圆点或 HUD 提示卡当场地本体 |
| 法师规则提示卡 | 承载玩家归属、法师能力参考和当前操作归属，位于玩家 HUD | 与战场实体混用，或把详情层当第二个可操作法师 |
| 法术书 | 己方可支配候选集合，底部一排候选卡 + 分类 + 分页 | 写成“手牌”、缩成小牌堆角标、卡外复写卡面已有费用 / 目标 |
| 已计划法术 | 本回合可施放来源，最多 2 槽，靠近法术书和当前行动 | 与“已选法术”重复成两个实体，或压成角落挂件 |
| 对手已计划法术 | 隐藏信息，只显示卡背、数量和所属关系 | 显示正面、卡名，或称为对手手牌 |
| 公开弃牌堆 | 已消耗公开归档入口，边缘低权重，显示所属、数量、紧凑顶牌正面 / 半露正面 | 用卡背伪装隐藏信息，放进中央施法链，或完全不显示 |
| 生物 / 魔物 | 场上实体，唯一所属区域，可作为来源 / 目标 | 多对象压成 count，头像 / 圆点替代卡面 |
| 装备 / 结界 | 附着宿主；隐性结界按视角显示卡背或正面 | 和普通状态 token 混用，或公开对手看不到的身份 |
| 状态 token | 守卫、燃烧、腐化、眩晕、昏迷、沉睡等贴附宿主 | 普通 badge、emoji 或 HUD 文本替代正式 token |
| 攻击骰 / 效果骰 | 真实攻击事件的当前结算主体，靠近来源 / 目标 / 主舞台链路短暂出现 | 放到右侧栏、角落、日志区或用普通数字骰 / 蓝圆替代 |
| 状态 HUD | 生命、伤害、法力、聚魔、费用预扣，水平贴近法师对象 | 整张状态板常驻、关键数值倾斜、普通彩色圆点 |
| 法术 FX | 规则事件的视觉投影：来源、目标、路径、命中 | 按钮点击直接播放成功态，或用 FX 掩盖缺卡 / 缺骰 |

## 交互链

- 默认流程：`选来源对象 -> 高亮合法目标本体 -> 点击目标本体 -> 结算层锚定来源 / 目标`。
- 没有规则或系统授权时，不得常驻“确认 / 执行 / 取消”；可撤销、支付分支或响应窗口只使用临时交互。
- 准备就绪的法师或生物由对象本体承接选择；移动格、攻击对象和守卫动作留在棋盘或单位附近，不转交右侧全局动作栏。
- 法术书负责检索和准备，不允许玩家绕过计划阶段从全书直接施放。
- 攻击骰、效果骰、伤害 token、燃烧 token、守卫 token、行动 token 是饱和态必检物件；不能为了画面干净删掉。

## 布局

| 区域 | 职责 |
| --- | --- |
| 中央竞技场 | `2x3` 半场、区域锚点、法师 / 生物 / 墙体 / 目标高亮、当前结算 overlay |
| 玩家 HUD | 双方法师规则提示卡、水平生命 / 法力 / 聚魔 / 伤害读数、行动 / 快速施法标记 |
| 法术书区 | 底部候选卡行、分类按钮、分页按钮、已计划 2 槽、公开弃牌堆入口 |
| 附件区 | 贴近对应法师 / 生物，承载装备、结界、状态 token 和 inspect 入口 |
| 阶段 / 结束槽 | 右侧偏下，只承载当前阶段、结束回合、跳过和必要短状态 |
| FX 层 | 棋盘上方独立 overlay，表现施法来源、目标锁定、路径和命中反馈 |

- 桌面基线先按 `1920x1080` 验收；首屏内必须完整显示竞技场、双方状态、当前主动作、法术书、已计划法术、弃牌堆和附件入口。
- 移动端只声明 `landscape-adapted + board-shell`，后续单独验证；不得为了手机反向压缩桌面棋盘或污染桌面构图。
- 同一步只保留一个主交互焦点；提示层不能遮住棋盘、法术书入口、已计划法术槽、弃牌堆或目标对象。

## 视觉

- 视觉气质：魔法竞技场、奥术仪式、实体桌游卡牌质感；中央棋盘沉浸，HUD 稳定、克制、低框感。
- 色彩不能做单一紫蓝；使用深炭黑、古铜金、羊皮纸暖白、奥术蓝、火焰红、毒雾绿形成多色语义。
- 卡牌、棋盘格、token 是实体边界；UI 容器只做轻量组织，禁止多层大框、黑色说明卡、重复胶囊壳和规则正文墙。
- 允许的边界：素材自带印刷边、棋盘区域边、卡牌 / token 本体边、合法目标轻量高亮、必要按钮底板。若去掉某个框后对象关系仍清楚，该框默认删除。

## 失败项

以下任一出现即判 `REVISE`：

- 第一眼看到的是面板、边框、彩色圆点或说明文字，而不是竞技场、法师、卡牌、token 和当前施法对象。
- 场上卡牌中心落在区域边界 / 缝隙 / 未使用半场，或玩家无法判断目标属于哪个区域。
- 密集文字法师规则卡被放进竞技场当法师本人，或人物 / 肖像法师本体缺失。
- 法术书退化为小牌堆角标、没有候选卡行、没有分类切换或没有分页策略。
- 公开弃牌堆被画成隐藏卡背，或被放到中央与当前目标同权。
- 对手计划法术、隐性结界或未公开法术书泄露正面、卡名或内容。
- 攻击骰、效果骰、命中 / 伤害 / 治疗结果离开来源 / 目标 / 主舞台链路，进入边栏、日志或空白角落作为主承载。
- 生命 / 法力 / 聚魔 / 伤害退成普通圆点、倾斜读数或脱离法师对象的仪表盘。
- 常驻规则解释、代理目标面板、无授权确认按钮、第二个可操作来源或第二个可操作目标。
- 素材未落盘对象被宣称完成，或 `temp/` 裁图被当作正式验收素材。

## 验收

- 设计 / 实现 / 送验前先建立或更新“规则对象 -> UI 承载”覆盖矩阵；用户纠正账本每条都必须回指至少一个规则对象。
- 验收截图必须是饱和交互态：法术书候选、已计划 2 槽、公开弃牌正面、骰子、效果骰、伤害 / 燃烧 / 守卫 / 行动 token、来源和合法目标高亮同时可见。空开局只作技术诊断。
- E2E、lint、单测只能证明链路可运行，不能证明 UI 通过；送人工前必须按用户原话和纠正账本逐条自审。
- `AI_PASS` 只能说明可人工看图；任一用户点名项缺失、弱化、误用术语或低质替代，必须先返工。
