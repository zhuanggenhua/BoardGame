# 山屋惊魂 UI 设计规范

> 适用范围：`betrayal` 的 UI 生图、设计稿收敛、Board 复刻与真实页面验收。
> 说明：这份文件是**实现约束与 UI 规范**，不是位图设计稿本体。
> 当前规则：没有明显说明时，默认按四步走，且通过前一步才进入下一步。
> 当前模式：**默认模式（不动总框架）**。

## 当前设计状态

- 当前 UI 目标不是“资料录入壳层”，而是**运行时主界面**，优先是 `pre-haunt` 的桌面牌桌。
- `foundation`、`录入页`、`资源目录墙` 这些说法如果没有明确标记为历史，只能算误方向，不算当前设计目标。
- 当前对话里已经点名继续沿用 `docs/games/betrayal/design/generated/betrayal-runtime-prehaunt-board-v4.png` 往下收敛；除非用户明确要求，否则**不再默认重开布局裂变或风格裂变**。
- 当前处于 **Step 2 布局收敛**：重点不是“继续补更多信息”，而是以 `v4` 为硬基线重构出**同一版式下更合适的运行时布局**；新稿若比 `v4` 更碎、更重、更像多区块面板，直接判失败。
- 设计稿未批前，不进入 skeleton、前端实现、运行页验真。

## 主视觉素材观察结论

### 1. 标题横幅

- 路径：`docs/games/betrayal/sources/image-index/contact-12-1795-350.jpg`
- 尺寸：`1795x350`
- 结论：
  - `BETRAYAL` 标题处于暗绿墙纸底上
  - 文字偏旧铜色 / 暗金色
  - 适合作为顶部品牌横幅，不适合作为独立按钮或装饰卡

### 2. 探索者牌

- 路径：`docs/games/betrayal/sources/image-index/contact-04-1270-1289.jpg`
- 尺寸：`1270x1289`
- 结论：
  - 探索者牌是官方属性面板语法来源，不是普通矩形列表卡
  - 角色信息围绕头像沿边布局，说明它更适合做角色选择/角色摘要语法
  - 后续收敛时，属性表达优先沿用这种官方五角属性板 / 徽记语法，而不是先替换成通用条形数值 UI

### 3. 牌背 / 参考卡

- 路径：`docs/games/betrayal/sources/image-index/contact-03-675-1275.jpg`
- 尺寸：`675x1275`
- 结论：
  - 事件、物品、预兆、叛徒、怪物牌背都有明确家族感
  - 参考卡更适合做按需查看或紧凑预览，不适合作为常驻大段说明正文

### 4. 候选房间 / 楼层素材

- 路径：`docs/games/betrayal/sources/image-index/contact-11-1425-1426.jpg`
- 尺寸：`1425x1426`
- 结论：
  - 当前可见的是少量候选房间牌与楼层示意
  - 说明未来 UI 的核心不是棋盘格，而是“房间板块 + 楼层分层”的拼接桌面

## 四步门禁

### Step 1 规则提炼 / 运行时布局

### Step 2 布局收敛

- 当前默认只围绕 **1 张** 已选母版继续收敛；对 `betrayal` 来说，就是 `betrayal-runtime-prehaunt-board-v4.png`。
- 除非用户明确要求比较方案，否则不再继续生成多版布局方向稿。
- 布局收敛时必须先过友好性审计：
  - 前兆前玩家能做的事是否都有入口：`移动`、`探索`、`交易`、`使用物品/预兆`、`结束回合`；
  - 当前探索者持有物若没有固定上限，布局上是否存在不扩区块的承载办法；
  - 队友信息是否能在动作按钮下方承担“同房间 / 可交易 / 危险状态”的最小语义，而不是新开一块说明区。
- `v4` 是当前实施基线，不是规则真相源。继续稿必须满足：
  - 主棋盘仍然是最大主体；
  - 左侧仍然是单一探索者主区，不额外长出第二块焦点卡大区；
  - 右侧仍然是单一牌堆辅助区，不拆成多块状态面板；
  - 底部仍然是同一条动作入口带，不新增第二排动作或独立说明区；
  - 所有新增规则承载默认只能通过缩放、重排、叠放、徽记和轻量标签，在 `v4` 原槽位内解决。
  - 分区关系默认靠同一牌桌画布里的落位关系成立，而不是靠左区一盒、右区一盒、底区一盒的分舱式面板成立。
- 前端复刻 `v4` 时，不能把“有房间数据和点击目标”降级成抽象列表或条形目标卡：
  - 中央必须呈现为房间牌 / 房间板块拼接舞台，而不是目标列表、资源目录、任务列表或普通网格按钮；
  - 房间本体就是移动/探索的选择载体，目标可用态用高亮、描边、徽记或 hover tip 表达；
  - 禁止在每个房间下面常驻显示“选择 / 可移动到此 / 点这里”这类解释文字；
  - 若正式房间裁图暂缺，可以使用 2D 印刷牌面占位语法，但必须明确记录为“素材缺口下的可实现占位”，不得宣称已经复刻真实房间素材。
- 素材优先规则继续成立：
  - 复用官方探索者板、属性语法、牌框、牌背、帮助卡、楼层/房间拼接语言；
  - 即使你知道原素材对动态状态表达不够理想，也先保留它；
  - 对属性、状态、等级这类内容，优先沿用官方五角属性板 / 徽记 / 指示物语法，不先引入通用进度条或二次 HUD。

### Step 3 风格统一

- 只允许在 Step 2 已收敛的单一布局上统一风格，不得改主结构。
- 风格要求只有一个：**和素材统一**，即暗绿墙纸、旧纸、黑框、铜黄强调。
- 当前默认优先 **2D 印刷版面语法**：平面板块、卡面、牌背、图标、描边、高亮与少量投影。
- 不再默认追求厚木边、古铜机关件、强烛光、重体积、实物模型感。
- `style-a / style-b / style-c` 这些旧稿只保留为历史候选，不再代表当前默认流程。

### Step 4 分界面出稿

- 在 Step 3 已选定风格下，再分别出不同界面。
- 默认顺序：
  1. 运行时
  2. 角色选择
  3. 结算 / 终局
- 若用户没有特别说明，优先把运行时做对，再补角色选择和结算。

## Step 1 规则提炼 / 运行时布局

### 目标

- 先确认必要元素和布局，不先追风格。
- 素材本身就是 UI 元素的一部分，地图、牌库槽、弃牌槽、流程轨、卡位、边界、图例都必须先当成 UI 约束处理。

### 运行时主界面主次关系

1. 中央主视区
   - 房间板块拼接区优先
   - 没有正式裁图前，可以先用结构占位，但不能做成资源目录墙
2. 左侧角色区
   - 当前探索者大卡
   - 属性表达优先沿用官方探索者板 / 五角属性语法，不先替换成泛化数值条
   - 其他玩家摘要
   - 当前探索者持有的 `Item / Omen` 必须有可见的紧凑持有区或可读持有机制，不能被忽略；若规则没写固定上限，必须先根据牌池、补充来源、交易与使用规则估算峰值，再决定是否需要滚动、溢出或聚合机制
   - 若没有正式物品牌面，必须使用真实标记素材 + 对象名做最小可区分正脸；禁止继续把统一牌背当成每张持有物的主画面
3. 右侧牌堆区
   - `Omen / Item / Event` 紧凑摆放
   - 弃牌可保留紧凑入口
   - `Player reference / turn order / traitor reference` 不能整张常驻展开；最多保留帮助入口
   - 队友默认锚定在交互按钮下方，不得再漂回底部动作区或中央牌桌下沿
4. 顶部状态区
   - 阶段、当前回合、步数等短状态
5. 当前动作区
   - 必须能看出当前玩家此刻能做什么
   - 至少要有从规则/参考卡提炼出来的短操作入口，例如：`移动`、`探索`、`交易`、`使用物品/预兆`、`结束回合`
   - 这些入口可以做成底部短条、角落浮岛或贴近对象的动作组，但不能缺席
   - 主 UI 里默认只显示动作标签本身；按钮功能解释若需要出现，只能放在 hover tip / 小问号 tip / 帮助入口展开层里，不能常驻写在按钮下方

## 当前选中 `v4` 的友好性补审

- `v4` 的 5 个主动作入口方向是对的，和前兆前规则一致；问题不在“少动作”，而在“动作可用态和推荐态还不够明显”。
- `v4` 左下当前只露出 `2 Item + 1 Omen`，这不足以支撑长期运行态。规则里没有看到固定持有上限，而交易时又允许一次交换任意数量，所以这块不能按“三张刚好够用”设计。
- `v4` 右下队友目前更像 3 枚头像装饰，难以支撑交易判断。至少还要补“谁和我同房间 / 谁可交易 / 谁状态危险”的最小语义。
- `v4` 当前回合与剩余移动信息还不够显性。玩家应该不用先读角色板细节，就能知道“轮到谁、还能不能继续移动”。
- `v4` 右侧 `Omen / Item / Event` 抽牌堆已经成立，但“弃牌 / 帮助 / 当前抽到牌的阅读入口”还需要更明确的轻量入口，不能只靠猜。
- 当前新增硬约束：继续稿默认必须是 **2D 印刷桌游 UI 稿**。即使要去掉软件后台面板感，也不能转成厚板块、古铜机关、烛光写实的 3D 实体渲染图。
- 当前新增硬约束：主 UI 禁止描述性正文；像“Move to an adjacent room”这类按钮功能说明，只能进 hover tip / 小问号 tip / 帮助入口，不能直接常驻在按钮附近。
- 当前新增硬约束：如果一张继续稿需要比 `v4` 更多的常驻区块才能成立，它就不是合格继续稿；要回到 `v4` 版式内重新解题。
- 当前新增硬约束：无论继续生图还是前端实现，默认禁止把“区域划分”机械翻译成独立边框盒子。除探索者板、牌面、参考卡等素材自带框体外，额外边框只能做次级收口，不能成为主分区手段。
- 当前新增硬约束：进入前端实现后，队友区的默认锚点是右侧功能按钮下方；持有区的默认约束是“对象可区分优先于统一牌背美术”。
- 当前新增硬约束：即使需要做承重板件，也要优先保持官方桌游物件那种偏直边、旧纸板、旧铜框语法；禁止把左栏、右栏、终局分区顺手做成现代大圆角卡片。
- 当前新增硬约束：当用户说“参考成熟游戏做法”时，这里默认按**商业游戏成品**理解，不按“常见通用 UI 模式”或“便于解释的后台式面板”理解。判断持有区是否合格时，优先看商业桌游电子游戏成品里那种真实对象密排、露边、可点选、按需放大的摆放感，而不是看它是否更像一组解释充分的小组件。
- 当前新增硬约束：若左栏里“位置/属性/辅助入口”的壳层节奏，会直接压缩真实持有物的可读面积，默认优先收这些辅助壳层的宽度、留白和占位；不得先牺牲真实持有物，把 `item / omen` 再压成更小的占位片。
- 当前新增硬约束：高密度持有区若在“继续重叠压缩”和“保持对象可认、允许横向延展”之间二选一，默认优先后者。也就是宁可让玩家横向拖看更多真实对象，也不要把对象压到只剩几个字或几条边。
- 当前新增硬约束：若持有区是按 `item / omen` 两排分区承载，则第二排必须在默认运行态下仍然**肉眼可见且可点击**；禁止为了保住第一排大图或底部辅助入口，把第二排压到视觉上接近消失。
- 当前新增硬约束：左下持有区不得被上方探索者板/位置/属性那条窄列壳层整体锁死。上方角色信息可以保持窄列，但持有区默认必须作为左下独立承载块去吃真实空位，而不是继续困在同一个窄框里。
- 当前实施阶段直接以 `betrayal-runtime-prehaunt-board-v4.png` 为基线；`v5-v12` 只保留为过程稿，不再作为当前实现目标。
- 当前实现硬约束：实施阶段必须直接使用项目内真实素材。房间牌、探索者、牌背、参考卡、标记等核心视觉不得用 CSS 渐变、emoji、程序纹理或临时 HTML 假图标替代。
- 当前素材状态：运行时已从 `contact-11-1425-1426.jpg` 裁出真实房间正面/背面并接入 `public/assets/i18n/zh-CN/betrayal/rooms/`；但完整高清房间拼版原图缺失，因此当前只是可运行素材接入，不是最终房间素材验收。
- 当前架构硬约束：正式领域 `setup()` 必须先服从规则真相源，再决定配置落点。对 `betrayal` 当前已确认的一条就是：恶兆前共享 setup 的探索者起点在 `Entrance Hall`；如果某个预览 helper 需要使用更分散的代表态房间分布，只能明确标为测试/预览夹具，不能再冒充正式规则开局。

### 禁止项

- 资料录入页当成当前 UI 目标
- 假牌桌、假角色选择墙、假剧本入口
- 常驻大段规则说明
- 按钮下方或按钮旁边的功能解释句
- 资源目录墙
- 把参考卡整张放进运行界面当主交互说明
- 只有牌堆、没有当前探索者持有 `Item / Omen` 的运行态

## 可见性边界

- `进行中可见`：当前回合、阶段、主视区对象、必要操作入口
- `仅按需展开`：日志、帮助、完整说明、规则摘要
- `仅终局揭示`：待结算信息
- `旁观者不可见`：待裁定的私有信息

## 桌面与移动端基线

### 桌面基线

- 参考分辨率：`1920x1080`
- 默认构图：中央主视区最大，左右为角色和牌堆紧凑辅助区

### 移动端基线

- `mobileProfile`：`landscape-adapted`
- `preferredOrientation`：`landscape`
- `mobileLayoutPreset`：`board-shell`
- 地图/牌桌类主视图优先横屏，交互层必须让位给主视区

## 当前必须禁止的 UI

- 假手牌区
- 假牌堆翻牌按钮
- 假地图网格
- 假房间探索路径
- 常驻大段规则说明
- 资源目录页
- “开始回合”“确认行动”之类暗示已可玩的主按钮

## 候选共享抽取项

当前默认不动总框架，只记录候选项：

| 机制 / 模块 | 当前处理 | 候选落点 | 当前为什么不抽 |
|---|---|---|---|
| 剧本 / 鬼屋模块 | 先留在游戏层 | `framework` 或 `engine + games/shared` | 当前连正式对象目录、私有信息边界和交互模式都未冻结 |
| 房间板块拼接语义 | 先留在 betrayal 后续 change | `framework` 级空间载体 | 还没完成单房间裁图与正式布局 |
| trait track / 属性轨道 | 先留在游戏层 | `framework` 通用轨道组件 | 目前只有素材，没有玩法与交互合同 |

## 当前结论

- 用户本轮已明确批准直接以 `betrayal-runtime-prehaunt-board-v4.png` 作为运行时实现基线，不再继续生图。
- 角色选择基线为 `betrayal-character-select-style-b.png`，终局基线为 `betrayal-endgame-style-b.png`。
- `v5-v12` 以及后续过程稿只保留为失败/过程参考；它们不能覆盖 `v4` 的版式纪律。
- 当前已进入首剧本实现线：目标是跑通 `角色选择 -> 恶兆前运行时 -> 终局`，并用真实页面截图补最终验收。
