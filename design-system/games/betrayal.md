# 山屋惊魂 UI 设计合同

> **gameId**：`betrayal`
> **角色**：约束运行时、角色选择、终局和教程入口的视觉结构。设计入口与历史稿处理看 [`docs/games/betrayal/design/README.md`](../../docs/games/betrayal/design/README.md)。

## 当前口径

- 当前目标是**运行时主界面**，优先是恶兆前桌面牌桌；`foundation`、录入页、资源目录墙不是当前设计目标。
- 停止继续生图；沿 `v4` 版式纪律进入首剧本实现线：`角色选择 -> 恶兆前运行时 -> 终局`。
- `v4` 是版式纪律和历史基线名，不是规则真相源；当前仓内不保留对应生成稿图片时，不能把缺失路径当作验收证据。
- 角色选择和终局沿 `character-select-style-b`、`endgame-style-b` 的结构裁定；它们是实现基线名，不是过程探索稿。
- 当前截图只能证明基本流程和第一剧本分段可跑通；高保真最终验收必须回到真实页面截图。

## 设计门禁

1. 规则提炼 / 运行时结构稿。
2. 布局收敛，只保留一张默认继续母版。
3. 在已选布局上统一风格。
4. 在已选风格下分界面出稿。

默认沿单线推进；除非用户明确要求，不再开多版布局或风格分叉。继续生成、改布局或实现前，先回答三件事：持有物最多放多少、玩家当前能做什么、玩家第一眼看哪里。

## 运行时布局

| 区域 | 合同 |
| --- | --- |
| 中央 | 房间板块拼接舞台是最大主体；移动、探索和房间目标必须落在房间牌 / 板块本体上 |
| 左侧 | 当前探索者大卡、官方五角属性语法、紧凑持有区和最小状态摘要 |
| 右侧 | `Omen / Item / Event` 三堆牌、弃牌 / 帮助 / 当前抽到牌的轻量入口 |
| 底部 | `移动 / 探索 / 交易 / 使用物品或预兆 / 结束回合` 等短动作入口 |
| 顶部 | 当前回合、阶段、剩余移动等短状态，不做厚顶部栏 |

- 主棋盘仍是最大主体；左侧、右侧和底部只服务当前行动，不新增第二焦点卡大区。
- 房间本体就是移动 / 探索选择载体；目标可用态用高亮、描边、徽记或 hover tip 表达。
- 禁止把中央主视区降级成目标列表、资源目录、任务列表、普通网格按钮或抽象房间目标卡。
- 房间地图移动方式必须是牌桌内拖拽平移 / 缩放；不能依赖页面滚动条或房间容器滚动条。
- 房间大图、持有物大图的检视预览只展示对象本体和必要阴影；关闭默认点击空白遮罩。

## 持有物与队友

- 当前探索者持有的 `Item / Omen` 必须有可见且可读的承载机制，不能只露出三张样例后宣称长期运行态成立。
- 持有物对象可区分优先于统一牌背美术；若没有正式物品牌面，使用真实标记素材 + 对象名做最小可区分正脸。
- 高密度持有区宁可允许横向延展或滚动，也不要把对象压到只剩几个字或几条边。
- 若持有区分 `item / omen` 两排，第二排在默认运行态下必须肉眼可见且可点击。
- 队友区默认锚定在右侧功能按钮下方，至少表达谁同房间、谁可交易、谁状态危险；不得漂回底部动作区或中央牌桌下沿。

## 素材与风格

- 风格优先 **2D 印刷桌游 UI**：暗绿墙纸、旧纸、黑框、铜黄强调、官方牌框、牌背、帮助卡和房间板块语法。
- 素材优先：探索者板、五角属性、牌框、槽位、徽记和牌背先复用原素材；不先替换成泛化进度条或二次 HUD。
- 即使原素材不完美，也先保留其视觉语言；只有素材缺口明确时，才使用标注为占位的 2D 印刷牌面语法。
- 当前实现已从 `contact-11-1425-1426.jpg` 裁出房间正反面并接入运行时，但完整高清房间拼版原图仍缺失；这只能算可运行素材接入，不是最终房间素材验收。
- 后续增加或替换房间图时，从原始房间 atlas / 原始单图建立裁剪合同；不得回退到 `contact-*` 或低清索引图裁片。

## 教程入口

- 教程章节目录属于 `betrayal` 体验，不套通用网页卡片，也不套七大恨明末地图墨框。
- 默认使用暗绿墙纸底、旧铜标题、旧纸 / 黑框印刷卡片、克制红褐危险强调。
- 章节入口采用“调查档案 / 房间门牌”语法：窄竖编号、黑框旧纸条、直角或切角、竖向开门签；避免巨型按钮感。
- 移动横屏必须可纵向滚动、无横向溢出。

## 禁止项

以下任一出现即判 `REVISE`：

- 资料录入页、资源目录墙、假牌桌、假角色选择墙或假剧本入口被当成当前运行时 UI。
- 常驻大段规则说明、按钮功能解释句、参考卡整张展开或教程文案占据主界面。
- 房间目标被做成抽象列表、普通网格按钮或每格常驻“选择 / 可移动到此 / 点这里”文字。
- 左右侧变成多个等权重面板，或额外边框成为主分区手段。
- 持有区被探索者板窄列锁死，真实持有物不可辨或第二排接近消失。
- 队友只剩头像装饰，无法判断同房间 / 可交易 / 危险状态。
- 当前回合、剩余移动、弃牌 / 帮助 / 当前抽到牌入口缺失或只能靠猜。
- 主 UI 从 2D 印刷桌游语法转成厚木边、古铜机关、强烛光、重体积或 3D 实体渲染图。
- 使用 CSS 渐变、emoji、程序纹理或临时 HTML 假图标替代已存在的房间牌、探索者、牌背、参考卡或标记。

## 验收

- 实现验收必须回到真实页面截图；HTML mock、静态图、E2E 过程截图都不能冒充最终设计验收图。
- 当前运行时必须证明中央房间牌拼接舞台、左侧探索者 / 持有区、右侧牌堆 / 弃牌、底部五动作同屏成立。
- 首剧本截图只能证明首剧本链路；不能自动外推角色选择、运行时、终局、教程或完整房间素材均已高保真完成。
- 具体实现证据看 [`current-implementation-audit.md`](../../evidence/betrayal/full-audit/current-implementation-audit.md) 和 [`runtime-implementation-consumption-audit-2026-07-29.md`](../../evidence/betrayal/full-audit/runtime-implementation-consumption-audit-2026-07-29.md)。
