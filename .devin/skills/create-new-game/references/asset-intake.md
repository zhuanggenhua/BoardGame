# 新游戏图片 Intake 快速参考

## 适用场景

当用户只给了图片、图片位置、裁片顺序、行列数、网站链接或部分素材清单，但希望**先开始做新游戏接入**时，使用这条快车道。

它解决的不是完整玩法实现，而是：

- 素材落盘
- 根据图片内容自动命名
- 自动移动到正式目录
- 压缩与图集配置
- 真相源 / 对照源合同
- 静态资源索引与 i18n 录入前置

## 启动前默认询问

1. 是否先同步 `main`，再从最新基线开 `feat/game-<gameId>`。
2. 是否先执行 `npm run assets:download -- --check` 或 `npm run assets:download` 拉本地缺失资源。
3. 本轮主真相源是什么，是否要把 Wiki / 官网 / 用户指定站点作为对照源一起比。
4. 是否允许 AI 根据图片内容自动重命名、自动移动、自动压缩素材。
   默认只对明显随机名/默认名自动改名；如果原名看起来就是用户有意命名，先询问，默认不改。

## 可直接开工的最小输入

1. `gameId`
2. 图片路径或链接
3. 素材类别
4. 位置口径：行列、顺序、坐标、对象列表之一
5. 主真相源 / 对照源裁定

## 默认目录与命名

| 素材类型 | 默认命名 | 默认目录 |
| --- | --- | --- |
| 缩略图 | `cover.png` | `public/assets/<gameId>/thumbnails/` |
| 卡牌 atlas | `<batch>.png` | `public/assets/i18n/zh-CN/<gameId>/cards/` |
| 基地 atlas | `<batch>_base.png` | `public/assets/i18n/zh-CN/<gameId>/base/` |
| 角色/英雄面板 | `<entityId>-board.png` | `public/assets/i18n/zh-CN/<gameId>/hero/` |
| 棋盘/地图/公共插图 | 按语义命名 | `public/assets/i18n/zh-CN/<gameId>/board/` 或 `common/` |
| atlas 配置 | `<name>.atlas.json` | `public/assets/atlas-configs/<gameId>/` |

## 正式命名依据

1. 正式命名默认依据图片内容语义，不依据原文件名。
2. 原文件名只作为输入线索；像 `IMG_1234.png`、`scan0007.png`、`image(1).png` 这类随机名/默认名不能直接当正式资产名。
3. 如果原文件名已经是明显语义化的用户命名，默认保留，先询问是否要统一改成项目规范名。
4. atlas 命名看整张图承载的对象集合；单张裁片命名看具体对象内容。
5. 若图面名与 canonical 名冲突，必须在合同里分开记录“显示名”和“正式命名/defId”。
6. 图片看不清时不得强行命名，必须进入待确认或对照源比对。
7. 默认自动改名只适用于随机字符串、设备默认导出名、截图默认名、扫描流水号、下载站无语义序号等情况。

## 执行顺序

1. 先写来源合同：真相源表、切图表、核对合同表、对照表、冲突待裁定表。
2. 先读图确认对象，再判断原文件名是否明显随机：
   - 随机/默认名：按图片内容改成正式名后再移动
   - 用户语义名：先询问，默认保留原名并移动
3. 运行 `npm run compress:images -- public/assets/<gameId>` 或最小必要子目录。
4. 如果用户给的是行列/顺序，直接生成索引映射与命名合同。
5. 若涉及远端默认资源，交付前执行 `npm run assets:check`。

## 完成判据

- 图片已落正式目录
- 压缩产物已生成
- 素材命名与索引合同已写
- 真相源 / 对照源已裁定
- 后续静态数据或 i18n 录入可直接继续
