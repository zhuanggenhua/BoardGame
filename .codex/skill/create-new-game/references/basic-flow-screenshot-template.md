# 基础玩法截图链示例

> 用途：当用户要“一个新游戏最基本的端到端流程”，并要求每步都有真实截图、能指出下一步点哪里时，直接照这个结构交付。
> 这是一份**交付模板与示例**，不是固定文案。实际交付时必须替换成当前游戏、当前截图和当前真实操作。

## 适用范围

- 适用于“让第一次看的人看懂这款游戏怎么运作”的基础流程。
- 不适用于只验证单个 bug、单个控件、单个 prompt 的局部验收。
- 如果当前只证明到中段，不得把这份模板包装成“整局流程”；必须明确写出截止边界。

## 交付物清单

至少同时交这两样：

1. 真实截图目录：`test-results/evidence-screenshots/_shared/<gameId>-基础玩法流程/`
2. 逐步说明文档：`evidence/<gameId>/<gameId>-basic-flow-e2e-<date>.md`

## 已填充示例

```md
## qidahen 基础玩法截图链

### 流程边界
- 开始点：进入对局后，第一次出现可操作的行动窗口
- 结束点：完成一次核心动作，并进入下一阶段可继续操作的状态
- 当前未覆盖：终局计分、多人联机不同视角、特殊战斗分支

### Step 1 - 进入第一次可操作状态
- 截图：D:/gongzuo/webgame/BoardGame/test-results/evidence-screenshots/_shared/qidahen-基础玩法流程/01-进入行动窗口-可开始操作.png
- 这一步玩家现在要做什么：先看当前有哪些可执行行动
- 下一步点击哪里：点击右侧行动区中的“赐印招安”
- 点击后结果：页面会进入该行动对应的支付或选择步骤
- 肉眼确认：这张图里右侧行动区和当前可选按钮都在首屏，第一次看的人能直接知道下一步是从右侧行动里选一项

### Step 2 - 选择第一次主动作
- 截图：D:/gongzuo/webgame/BoardGame/test-results/evidence-screenshots/_shared/qidahen-基础玩法流程/02-右侧行动区-点击赐印招安前.png
- 这一步玩家现在要做什么：正式选定这回合要执行的主动作
- 下一步点击哪里：点击右侧“赐印招安”按钮
- 点击后结果：页面会切到该行动的支付步骤
- 肉眼确认：主动作按钮本体清楚可见，不需要靠规则书猜“该点哪里开始”

### Step 3 - 完成第一次成本或目标选择
- 截图：D:/gongzuo/webgame/BoardGame/test-results/evidence-screenshots/_shared/qidahen-基础玩法流程/03-支付步骤-等待弃牌确认.png
- 这一步玩家现在要做什么：完成这次行动要求的支付
- 下一步点击哪里：点击手牌区需要弃掉的牌，然后点击确认支付按钮
- 点击后结果：支付完成后会进入下一阶段，例如轮盘推进或地图选择
- 肉眼确认：截图里既能看到手牌区，也能看到确认入口，用户不会误判成卡死

### Step 4 - 看到第一次结果落地
- 截图：D:/gongzuo/webgame/BoardGame/test-results/evidence-screenshots/_shared/qidahen-基础玩法流程/04-支付完成-进入轮盘推进.png
- 这一步玩家现在要做什么：执行支付完成后出现的新阶段动作
- 下一步点击哪里：点击右侧或中央明确出现的轮盘行动入口
- 点击后结果：会正式推进轮盘动作，地图或阶段状态发生变化
- 肉眼确认：这张图已经从“支付”切到了“轮盘推进”，能看出前一步操作真的产生了新阶段结果

### Step 5 - 进入下一阶段并可继续
- 截图：D:/gongzuo/webgame/BoardGame/test-results/evidence-screenshots/_shared/qidahen-基础玩法流程/05-轮盘推进-等待选择目标.png
- 这一步玩家现在要做什么：在新阶段里继续完成一次目标选择或推进
- 下一步点击哪里：点击地图上高亮的目标地区
- 点击后结果：系统会进入下一次结算、移动或交接给下一阶段/下一位玩家
- 肉眼确认：高亮目标和下一步入口都在同一屏里，第一次看的人知道这局不是结束，而是进入了下一段可继续的流程
```

## 写法约束

- `下一步点击哪里` 必须先写现实对象名，不要先写 `locator`、`test id`、字段名。
- `点击后结果` 必须写玩家肉眼会看到的变化，不要只写“触发 command”或“状态更新成功”。
- `肉眼确认` 必须回答“为什么第一次看的人也知道该怎么继续”，不能只复述断言通过。

## 交付前自查清单

- [ ] 已写明开始点、结束点、当前未覆盖范围
- [ ] 至少 5 步，且步骤顺序可回放
- [ ] 每步都有真实截图绝对路径
- [ ] 每步都有“下一步点击哪里”
- [ ] “点击哪里”使用的是现实对象名，不是内部字段名
- [ ] 每步都有“点击后结果”
- [ ] 至少有 1 步真实展示了这款游戏的核心特色，不只是“按钮能点”
- [ ] 若用了局部辅助图，已明确标注它来自哪张真实截图，且没有替代原图
- [ ] 最终汇报里至少附了 1 条说明文档路径和 2 张关键截图绝对路径
