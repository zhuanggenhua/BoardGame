# Tutorial Workflow

这是 BoardGame 项目专用的教程 workflow。它处理的不是“教程能不能走通”，而是“教程是否真的在教玩家玩这款游戏”。

## 使用时机

- 用户明确说 `教程`、`新手引导`、`onboarding`
- 用户说教程 `只在教按钮`、`像规则书`、`看不懂`、`不是真实游玩`
- 你准备新增、重做、压缩或补审某个游戏的教程步骤、教程文案、教程 E2E

## 必读入口

1. `docs/ai-rules/tutorial-design.md`
2. `docs/ai-rules/e2e-verification.md`
3. `.codex/skill/game-audit-workflow/SKILL.md`

## 核心不变量

1. 基础教程默认只教常规对局，不掺双人变体或扩展规则，除非用户明确要求。
2. 先出完整教程文案，再改实现；文案方向没锁定前，不得先改 `tutorial.ts` 硬做一版。
3. 开场第一句默认固定成：`目标 + 一个基础回合动作 + 结束/胜负条件`。
4. 后续步骤不得复读已经讲过的规则。
5. 禁止空提示句、过渡废话和“本局教学目标”这类作者口吻标题。
6. 文案应贴真实局面，能直接点名当前牌、当前收益和当前动作。
7. 教程不只教显式规则，也要教真实隐性交互，例如点卡/悬浮看分数、读懂关键提示。
8. 计分制游戏必须出现一次清晰的计分因果，不得只展示一个结果数字。
9. 结语必须短，只做收口与鼓励，不再重讲规则。

## 固定流程

### 1. 先锁教程真相

- 读取当前：
  - `src/games/<gameId>/tutorial.ts`
  - 对应语言包
  - 对应教程测试
  - 对应教程 E2E
- 明确当前教程到底在教哪条真实流程：
  - 常规局还是变体
  - 点按钮还是点卡牌
  - 有没有真实案例
  - 有没有结果反馈

### 2. 先写完整教程文案

- 先输出完整步骤文案，不要只给 2 句样例。
- 若用户正在强审文案，默认先停在文案稿，不直接实施。
- 文案自检时至少过这 6 问：
  1. 玩家第一句能不能立刻知道怎么赢
  2. 有没有只教常规对局
  3. 有没有重复前面已经说过的规则
  4. 有没有空提示句或作者腔废话
  5. 有没有一次真实案例和一次真实计分因果
  6. 结语有没有保持简短

### 3. 文案锁定后再改实现

- 同步更新：
  - `tutorial.ts`
  - `public/locales/**/game-<gameId>.json`
  - 教程单测
  - 教程 E2E
- 如果教程口径改成常规对局，注入态也必须切回常规对局语义，不能只改文案。

### 4. 跑真实教程验证

- 至少跑：
  - 教程单测
  - 教程 E2E
- E2E 截图必须覆盖：
  - 开场目标/基础回合
  - 第一条正式行动
  - 至少一个真实案例
  - 计分或等价结果反馈
  - 结语/结束态

### 5. 收口规范与 skill

- 如果本轮暴露的是可复用教程问题，而不是某个单游戏私货，回写：
  - `docs/ai-rules/tutorial-design.md`
  - 本 skill
- 如果只是当前游戏局部特例，则写进项目内对应教程实现或专项文档，不要抬升成全局规则。

## 最终回复门禁

1. 不得只说“教程跑通了”。
2. 必须说清这轮教的是哪条真实流程。
3. 若提到 E2E 通过，必须附真实截图绝对路径。
4. 只有最终达标截图才需要按 `screenshot-delivery` workflow 主动打开。
