# Tutorial Workflow

这是 BoardGame 项目专用的教程 workflow。它处理的不是“教程能不能走通”，而是“教程是否真的在教玩家玩这款游戏”。

## 使用时机

- 用户明确说 `教程`、`新手引导`、`onboarding`
- 用户说教程 `只在教按钮`、`像规则书`、`看不懂`、`不是真实游玩`
- 你准备新增、重做、压缩或补审某个游戏的教程步骤、教程文案、教程 E2E

## 必读入口

1. `docs/ai-rules/tutorial-design.md`
2. `docs/ai-rules/e2e-verification.md`
3. `.codex/skill/game-audit-workflow/SKILL.md`

## 核心不变量

1. 基础教程默认只教常规对局，不掺双人变体或扩展规则，除非用户明确要求。
2. 先出完整教程文案，再改实现；文案方向没锁定前，不得先改 `tutorial.ts` 硬做一版。
3. 开场第一句默认固定成：`目标 + 一个基础回合动作 + 结束/胜负条件`。
4. 后续步骤不得复读已经讲过的规则。
5. 禁止空提示句、过渡废话和“本局教学目标”这类作者口吻标题。
6. 文案应贴真实局面，能直接点名当前牌、当前收益和当前动作。
7. 教程不只教显式规则，也要教真实隐性交互，例如点卡/悬浮看分数、读懂关键提示。
8. 计分制游戏必须出现一次清晰的计分因果，不得只展示一个结果数字。
9. 结语必须短，只做收口与鼓励，不再重讲规则。
10. 即使是“示范题教学”，也必须从开局开始的主要交互入口进入；不得直接把玩家切到中段预设题面，再让他突然支付、结算或收口。
11. 教程要求玩家处理某张具体牌时，必须高亮到单牌级；禁止只高亮整片手牌区、整片中央区或整段面板。
12. 教程步骤一旦完成，上一张目标牌的高亮/选中/聚焦态必须及时退场；禁止把旧目标牌描边残留到下一步。
13. 基础教程必须覆盖这款游戏自己的核心规则面，不能只靠一条最短闭环冒充“学会了怎么玩”。
14. 如果某一步只是当前案例前提，玩家文案只能解释当前局面为什么从这里开始，不得出现“这道示范题”“为了教学”“这不是通用规则”之类作者口吻。
15. 动手前必须先列教程覆盖矩阵：规则条目、对应章节/步骤、截图证据三者先对齐，再写教程文案。
16. 教程进度不会持久化时，默认优先拆成多个短章节，而不是一条超长教程。
17. 战争、推图、区域控制类游戏的教程体系，必须单独覆盖真实战斗；若城战/围城/占领显著不同，也必须单独覆盖。
18. 章节只是控制教程长度和刷新风险的手段，不是固定交付模板；如果一条短教程已经完整覆盖当前规则面，不必强拆。
19. 同一基础回合链里的资源使用、目标选择、主行动推进与结果反馈，默认合并在“基础回合”主章节里教学；不要按程序模块名机械拆章。
20. 章节划分按玩家心智任务命名，不按 UI 面板、代码模块或内部系统命名；先回答“这一章学会哪段玩法”，再决定是否拆章。

## 固定流程

### 1. 先锁教程真相

- 读取当前：
  - `src/games/<gameId>/tutorial.ts`
  - 对应语言包
  - 对应教程测试
  - 对应教程 E2E
- 明确当前教程到底在教哪条真实流程：
  - 常规局还是变体
  - 是不是从开局主入口开始
  - 点按钮还是点卡牌
  - 有没有真实案例
  - 有没有结果反馈

### 2. 先写完整教程文案

- 先给出教程覆盖矩阵，再给分章节或单教程结构；不要直接跳到某一章的句子级微调。
- 先输出完整步骤文案，不要只给 2 句样例。
- 若用户正在强审文案，默认先停在文案稿，不直接实施。
- 文案自检时至少过这 10 问：
  1. 玩家第一句能不能立刻知道怎么赢
  2. 有没有只教常规对局
  3. 有没有从开局主入口进入，而不是直接切到中段题面
  4. 有没有重复前面已经说过的规则
  5. 有没有空提示句或作者腔废话
  6. 有没有一次真实案例和一次真实计分因果
  7. 结语有没有保持简短
  8. 有没有讲到这款游戏真正靠什么资源运作
  9. 有没有覆盖这款游戏首次上手就会碰到的核心结算概念
  10. 有没有把示范题前提误说成通用规则

### 2.1 先列覆盖矩阵

- 至少列出三列：
  - 规则条目
  - 教程章节 / 步骤
  - 证据截图
- 如果当前教程会因为刷新丢进度，默认先设计为多短章：
  - 第 1 章：真实开局主入口与一个完整基础回合
  - 中间章节：战斗 / 资源 / 特殊结算
  - 后续章节：城战 / 年中 / 新年 / 终局等重规则
- 只有覆盖矩阵能证明“核心规则都有人教”，才进入具体文案。

### 3. 文案锁定后再改实现

- 同步更新：
  - `tutorial.ts`
  - `public/locales/**/game-<gameId>.json`
  - 教程单测
  - 教程 E2E
- 如果教程口径改成常规对局，注入态也必须切回常规对局语义，不能只改文案。
- 若步骤目标是单张牌，同步检查：
  - `highlightTarget` 是否命中单牌锚点
  - 完成操作后旧目标牌的选中态是否被清掉
  - 下一步是否只保留当前步骤真正需要的目标高亮

### 4. 跑真实教程验证

- 至少跑：
  - 教程单测
  - 教程 E2E
- E2E 截图必须覆盖：
  - 开场目标/基础回合
  - 开局后的第一个主要交互入口
  - 第一条正式行动
  - 至少一个真实案例
  - 计分或等价结果反馈
  - 结语/结束态
- 若教程含“指定这张牌”的步骤，E2E 还必须验证：
  - 当前目标牌确实是单牌级高亮
  - 步骤推进后旧目标牌不再残留描边/选中态

### 5. 收口规范与 skill

- 如果本轮暴露的是可复用教程问题，而不是某个单游戏私货，回写：
  - `docs/ai-rules/tutorial-design.md`
  - 本 skill
- 如果只是当前游戏局部特例，则写进项目内对应教程实现或专项文档，不要抬升成全局规则。

## 最终回复门禁

1. 不得只说“教程跑通了”。
2. 必须说清这轮教的是哪条真实流程。
3. 若提到 E2E 通过，必须附真实截图绝对路径。
4. 只有最终达标截图才需要按 `screenshot-delivery` workflow 主动打开。
