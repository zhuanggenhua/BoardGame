# Mage Wars 卡牌选择 UI 跨游戏端到端对照验收

> 审计日期：2026-10-01  
> 范围：DiceThrone、Smash Up 的真实卡牌选择链，以及 Mage Wars 法师魔杖 / 元素魔杖选择链。  
> 结论：`REVISE`（上一版 PASS 已作废）

## 本轮要求

1. 先用同类游戏真实入口验证卡牌选择的成熟承载方式。
2. 卡牌本体是名称、费用、类型和效果的唯一视觉信息 owner。
3. 选择态必须贴合卡牌本体，不用卡外重复牌名解释。
4. 多选流程必须有可见计数和确认；单选即时流程必须保留取消。
5. 参考链与 Mage Wars 都必须有当前工作树的真实 E2E 证据。

## 参考 E2E

| 游戏 | 真实用例 | 选择态 | 直接结论 |
|---|---|---|---|
| DiceThrone | `参考链：真实手牌卡牌选择应显示卡本体且不复制牌名` | 单张手牌卡牌本体、上方任务标题、取消 / 确认 | 不在卡外复制牌名；卡牌通过本体和 `aria-label` 承载内容 |
| Smash Up | `我不知道要拿什么从真实打出入口展示牌库并把两张行动加入手牌` | 卡牌网格、`已选 0 / 2`、卡牌本体直选、确认 | 多选需要计数和确认；名称仍由卡面承载 |
| Mage Wars | `正式页面法师魔杖施放和快速重绑覆盖法术选择 UI` | 法术牌网格、上下文标题、取消 | 法师魔杖与快速重绑共享同一选择壳 |
| Mage Wars | `正式页面元素魔杖施放和快速重绑覆盖法术选择 UI` | 元素法术牌网格、上下文标题、取消 | 元素魔杖走同一共享选择壳，未复制卡外牌名 |

## 抽象裁决

- 共享层保留：卡牌预览、候选网格、禁用态、选中态、无障碍名称、取消入口、可选确认栏和已选计数。
- 游戏层保留：交互标题、候选生成、搜索 / 翻页、卡牌放大、特殊跳过项、网络命令和规则结果。
- 不把 DiceThrone 的搜索框、Smash Up 的牌库揭示 / 多选排序或 Mage Wars 的绑定语义写进共享层。
- 当前共享实现：`src/components/game/framework/CardChoiceOverlay.tsx`。

## 退回原因

- 参考实现不是自动合格范式：Smash Up 截图明确存在卡外牌名重复和底部控件拥挤。
- Mage Wars 选择弹层中的卡面缩得过小，玩家无法可靠阅读效果后再选择。
- Mage Wars 当前截图在点击前保存，不能证明候选已经被选中；只能证明候选集合出现。
- 旧查看器 `http://127.0.0.1:4867/?key=2fb41003ee70` 对应的 PASS 结论作废，不得继续作为验收依据。
