## 1. 自动断言摘要

- 入口：`/play/betrayal?players=3&playerID=0&seat0=human&seat1=human&seat2=human`。
- 状态注入：`createHelpingHandsPendingRewardRuntimeCore()` 生成力量攻击获胜后的奖励选择场景。
- 投骰回顾：攻击投骰回顾可见，空白处关闭被禁用，必须点击“返回牌桌”进入后续选择。
- 奖励选择：牌桌显示“造成伤害 / 偷走急救包”两种合法选择。
- 偷牌结算：点击“偷走急救包”后，玩家 0 获得急救包，玩家 1 失去急救包，反馈显示偷走急救包。
- 巨魔手攻击入口：`createHelpingHandsTrollHandAttackRuntimeCore()` 生成同房间双巨魔手场景，牌桌同时显示“第1只 攻击 力量5”“第2只 攻击 力量5”和“合击 力量8”三个入口；合击是可选替代，不遮掉两只单手攻击。
- 合击结算：随机队列驱动巨魔手投出力量 8 的代表骰面后，合击按钮消失，反馈包含“巨魔手合击”，两个巨魔手 id 都进入本回合已行动记录，并显示受伤方的“巨魔手攻击”8 点物理伤害分配面板。
- 巨魔手移动：同一代表态下点击“移动巨魔手”后，巨魔手 token 本体显示可选状态，地图房间本体出现移动目标高亮；点击高亮房间后，巨魔手 token 落到目标房间，反馈显示“移动到...”。
- 结束巨魔手回合：点击“结束巨魔手回合”后，巨魔手怪物回合状态条退场，反馈显示“巨魔手怪物回合结束”，当前行动者推进到下一名探索者。
- 控制权换手：`createHelpingHandsTransferredAmuletOldHolderRuntimeCore()` 生成奇异护符已交给玩家 1、当前视角仍是玩家 0 的牌桌；断言状态条显示巨魔手由玩家 1 控制，旧持有人没有巨魔手行动入口。
- 新控制者入口：`createHelpingHandsTransferredAmuletControllerRuntimeCore()` 切到玩家 1；断言状态条仍显示玩家 1 控制，并且巨魔手攻击入口出现。
- 无人持护符：`createHelpingHandsNoAmuletRuntimeCore()` 移除所有探索者的奇异护符；断言状态条显示“无人持有奇异护符，巨魔手跳过”，且没有巨魔手行动入口。
- 命令：`node scripts/infra/run-e2e-single.mjs ci e2e/betrayal/helping-hands-combat.e2e.ts`，3 passed。
