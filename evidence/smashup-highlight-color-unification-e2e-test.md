# Smash Up 交互颜色语义 E2E 证据

## 范围

- 大杀四方交互高亮按语义分层：
  可选 = 紫色；
  可用 = 绿色；
  激活确认/armed = 琥珀色。
- 覆盖对象：基地直选高亮、随从直选高亮、手牌选中后进入部署态。
- 目标：明确区分“可选”和“可用”，避免把选择目标与能力可用混成一层。

## 运行记录

- E2E 1：
  `npm run test:e2e:ci:file -- e2e/smashup-base-minion-selection.e2e.ts "描边高亮只作用于卡框，不连带基地记分和随从外置徽记"`
- E2E 2：
  `npm run test:e2e:ci:file -- e2e/smashup-local-gameplay.e2e.ts "本地模式：默认模式下点击随从会进入部署选择，点击基地后才真正打出"`

## 截图与观察

### 1. 基地可选高亮

截图：
`test-results/evidence-screenshots/smashup-base-minion-selection.e2e/描边高亮只作用于卡框，不连带基地记分和随从外置徽记/smashup-outline-base-highlight.png`

人工观察：
- 三个可选基地都使用统一紫色外发光和描边，说明“可选基地”已与“可用能力”分层。
- 基地右上角的断点记分圆章仍保持深色独立样式，没有被高亮描边一起染黄。
- 基地下方的玩家力量标记和外置小挂件仍在高亮框之外，说明高亮只收在卡框本体，没有污染外挂 UI。

### 2. 随从可选高亮

截图：
`test-results/evidence-screenshots/smashup-base-minion-selection.e2e/描边高亮只作用于卡框，不连带基地记分和随从外置徽记/smashup-outline-minion-highlight.png`

人工观察：
- 进入“选择随从”后，可选区域使用统一紫色高亮。
- 随从卡自身的可选反馈与基地高亮观感一致，说明“选择目标”语义现在有独立颜色。
- 随从下方力量点数、外挂卡和基地上的其他记分元素没有被一起包进高亮范围，视觉边界是干净的。

### 3. 手牌选中进入部署态

截图：
`test-results/evidence-screenshots/smashup-local-gameplay.e2e/本地模式：默认模式下点击随从会进入部署选择，点击基地后才真正打出/smashup-click-mode-selection-state.png`

人工观察：
- 手牌被选中后，卡牌外框使用紫色，和“下一步要选择放到哪里”这层语义一致。
- 上方三个基地同时进入可部署态时，和手牌选中态都使用紫色高亮，说明“待你继续选择”的层级已经统一。
- 画面里保留木桌背景、便签和记分板原有配色，没有因为绿色高亮破坏整体桌游木桌氛围。

### 4. 可用与激活确认色保留

人工观察：
- 当前实现已经形成稳定口径：紫色负责“你现在正在选它”，绿色负责“该能力当前可用”，琥珀负责“armed / 再次点击发动”。
- 本轮文档修订的重点就是把这三层拆开，避免再次把“可选”和“可用”写混。

## 结论

- “可选”高亮使用紫色。
- “可用”高亮使用绿色。
- “激活确认/armed”使用琥珀色。
- 基地、随从、手牌三类核心交互入口现在能区分“正在选目标”“能力可用”“即将发动”三层语义。
- 当前截图中未发现新的高亮串色、记分徽记被误描边、或高亮范围外溢问题。
