# Home V2 作者态真实画布流程 E2E 证据

## 范围

- 页面入口：`/?homeV2Draft=1&author=1`
- 目标：
  - 默认态左右栏和底部源码抽屉收起，不再常驻挡住书页
  - 点击画布节点后，右侧属性抽屉自动打开并聚焦当前节点
  - `图层 / 组件 / 资源` 共用同一个左抽屉，而不是三栏工作台
  - 图层树支持拖拽重排，并支持拖入容器
  - 画布支持框选、多选和群组移动，而不是只能单节点裸拖
  - 画布内支持把节点直接拖进容器，并在释放后真正修改父子关系
  - 流式容器在画布内支持插入排序，而不是只能 append 到末尾
  - 右下角 / 边缘控制柄支持 `Shift` 锁比例与 `Alt` 中心缩放
  - 缩放中的辅助提示直接用中文显示，而不是英文开发态文案
  - 左右抽屉与底部源码抽屉支持拖拽改尺寸
  - `高级源码` 抽屉可以展开与收起
  - 编辑器顶部提供中文的 `撤销 / 重做 / 删除所选` 能力，并支持 `Esc` 取消选择

## 正式 E2E

- 测试文件：`e2e/_shared/lobby.e2e.ts`
- 用例名：`Home v2 作者态按真实画布流程工作：选中即开属性、同抽屉切换与尺寸拖拽`
- 执行命令：

```bash
npm run test:e2e:ci:file -- lobby.e2e.ts "Home v2 作者态按真实画布流程工作：选中即开属性、同抽屉切换与尺寸拖拽"
```

- 结果：`1 passed`

## 断言链路

- 进入作者态后，校验 `home-v2-left-drawer / home-v2-right-drawer / home-v2-source-drawer` 初始 `data-state=closed`
- 点击画布上的 `tab_button_changelog`
- 校验右侧 `home-v2-inspector-panel` 自动打开，并且 `data-selected-node=tab_button_changelog`
- 点击顶部 `图层`，校验左抽屉打开，且 `home-v2-hierarchy-item-tab_button_changelog` 处于选中态
- 在左侧图层树中，把 `关于页签按钮` 拖到 `房间页签按钮` 前面，校验层级树里的 DOM 顺序真的发生变化
- 在画布上框选 `房间 / 榜单` 两个页签按钮，校验 `home-v2-overlay-selection-summary` 出现，`home-v2-overlay-multi-selection-bounds` 可见，8 个 `home-v2-overlay-group-handle-*` 控制柄出现，且右侧 `home-v2-inspector-panel` 的 `data-selected-count` 进入多选态
- 在多选态下拖动右下角组控制柄，校验 `房间 / 榜单` 两个节点的宽高都同步增长，证明多选缩放不是假把手
- 在多选态下拖动 `多选边界框`，校验 `房间 / 榜单` 两个节点都按近似相同位移一起移动，证明群组移动不再依赖“碰巧点中其中一个节点”
- 故意把 `房间页签按钮` 单独下移，再通过 `Shift` 把 `榜单页签按钮` 加回多选，点击右侧属性抽屉里的 `顶对齐`
- 校验两个页签按钮的 `Y` 坐标重新贴齐，证明多选对齐不是只有按钮，没有真正写回布局
- 再把 `更新日志页签按钮` 加进多选，点击 `垂直分布`
- 校验三个页签节点在 `Y` 轴上的上下间距重新接近一致，证明多选分布不是装饰按钮，而是真正的批量排版
- 校验 `更新日志页签按钮` 自动成为当前 `主参考`
- 再把 `房间页签按钮` 切成新的 `主参考`
- 校验画布顶部多选摘要和右侧属性面板都同步显示新的主参考名称，证明关键对象不是隐藏状态，而是当前可见且可切换的编辑基准
- 继续点击 `同宽`
- 校验 `房间 / 榜单 / 更新日志` 三个页签节点的宽度重新贴齐，且最终宽度跟随新的主参考，证明多选尺寸统一已经不是“按默认第一个节点碰运气”
- 在保持多选的前提下，按一次 `方向键左`
- 再按一次 `Shift + 方向键上`
- 校验多选节点整体发生细微左移与明显上移，且多个节点位移近似一致，证明编辑器已经支持 Figma 式键盘微调与大步移动
- 点击顶部 `组件`，校验左抽屉切换到 `home-v2-component-panel`
- 通过 `home-v2-component-insert-panel` 插入一个新的 `panel_*` 容器节点，并校验画布里出现对应 overlay 节点
- 对新面板执行 `Shift + 右下角控制柄` 缩放，校验宽高同时增长且宽高比维持稳定
- 对新面板执行 `Alt + 右侧控制柄` 缩放，校验宽度增长且 `X` 向左移动，满足从中心对称扩张
- 在画布里把 `关于页签按钮` 直接拖到新容器上，校验 `home-v2-overlay-drop-target-panel_*` 出现
- 同时校验 `home-v2-overlay-drop-inside-hint-panel_*` 可见，说明拖到容器内部时会出现明确的中文 inside 提示，而不只是淡淡一层高亮
- 释放后切回 `图层`，校验右侧 `home-v2-inspector-panel` 明确显示 `父容器：panel_*`
- 再插入一个 `stack_vertical_*` 纵向容器，把 `房间 / 榜单` 两个按钮拖进该容器
- 在画布里把 `更新日志页签按钮` 拖到纵向容器中段，释放后校验图层树里的顺序变成 `房间 → 更新日志 → 榜单`，证明画布拖放已支持 `before/after` 排序
- 在释放前，校验画布上至少出现一个 `drop-indicator` 和一个 `drop-slot`，说明容器中段插入时已经出现明确的插入条与插入槽位反馈
- 点击顶部 `资源`，校验左抽屉切换到 `home-v2-asset-panel`
- 通过浏览器 DOM 事件链拖拽 `home-v2-left-drawer-resize / home-v2-right-drawer-resize / home-v2-source-drawer-resize`
- 校验左抽屉宽度、右抽屉宽度、源码抽屉高度均发生增长
- 点击顶部 `高级源码` 再次收起底部抽屉，校验 `data-state=closed`
- 再插入一个 `text_*` 文字节点，校验属性面板自动切到新节点
- 按 `Esc`，校验属性面板的 `data-selected-count=0`，证明可以快速取消选择
- 重新选中文字节点后点击顶部 `删除所选`，校验该节点从画布 overlay 中消失
- 点击顶部 `撤销`，校验该节点回到画布
- 点击顶部 `重做`，校验该节点再次消失，证明基础编辑历史链已经闭合

## 结论

- 这轮不再是“临时脚本点一遍”，而是仓库内正式 Playwright 用例跑通。
- 当前作者态流程已经满足“真实画布优先”的这一层要求：默认不挡页面、选中即开属性、左侧单抽屉切换、源码抽屉可开合。
- 抽屉尺寸调节、节点 8 向缩放控制柄、`Shift` 锁比例、`Alt` 中心缩放、层级树拖拽重排、画布内拖入容器、框选、多选、群组移动、多选顶对齐、流式容器内排序、删除、撤销、重做、`Esc` 取消选择都已纳入正式 E2E 链路，说明这部分不是只改一个偏移属性，而是可实际操作的编辑器交互。
- 当前“容器支持”不再只停留在左侧图层树，画布里已经可以直接把节点拖进容器，并在释放后真正写回新的父容器关系。
- 当前多选已经具备可见的群组边界框、8 向组控制柄、直接拖动边界框整体移动、基础群组缩放、批量对齐、垂直分布、统一尺寸、键盘微调，以及可见可切换的主参考对象；还没做到的是更完整的等间距策略和更强的批量属性编辑。
