# evidence 证据目录入口

本目录是历史证据、截图、审计记录和修复收口材料的存放区，不是默认开发说明入口，也不是 AI 规范正文来源。

## 职责分层

| 区域 | 职责 | 使用口径 |
| --- | --- | --- |
| `evidence/_shared/` | 跨游戏、跨模块、平台级审计 / 修复 / 合并 / 反馈证据 | 适合放不属于单一游戏的报告；被历史审计清单引用时优先保留。 |
| `evidence/<gameId>/` | 单游戏证据，如 `dicethrone/`、`smashup/`、`betrayal/` | 游戏专项报告、测试截图、链路验收默认放这里。 |
| `evidence/<feature-or-flow>/` | 一次性流程截图、真实入口验收图组、命名为中文的专项链路 | 保留当次验收上下文；不能仅按图片哈希删除。 |

## 去重规则

- **Markdown / 文本 / JSON 精确重复**：可以在哈希一致、引用已迁移、保留侧职责更清楚时删除副本；删除前必须记录保留侧和引用裁决。
- **0 字节文件**：若没有完整路径引用、没有文件名引用、也不是脚本输出路径，可以删除；若被历史清单引用或由脚本生成，先保留并记录理由。
- **截图 / 图片重复**：默认不按哈希直接删除。相同截图可能代表不同验收时点、不同用户交付批次、不同标注集合或 PureRef / AI 审图流程中的不同角色。处理前必须先证明：
  1. 两张图的现实含义完全相同；
  2. 被删侧没有被报告、用户验收、脚本、台账或历史路径引用；
  3. 保留侧能继续证明同一个验收结论；
  4. 删除动作已经写入合并台账。
- **生成物重复**：先改生成脚本或入口，防止副本回潮；不能只删生成结果。

## 截图命名与证据组

- 同一条验收流程只建立一个 canonical evidence 目录；后续复核优先更新该目录，不复制整组截图到带时间戳的子目录。
- `latest`、`rerun`、协议片段或临时修复词不能单独制造同图别名。若确实是不同验收阶段，即使图片像素相同，也必须在报告 / JSON 中说明阶段差异；否则保留稳定命名的一份。
- 设计图 / 最终图、修复前 / 修复后、不同分支或不同用户交付批次可以保留相同像素的图片，但必须有不同的验收角色或上下文，不能只靠文件名猜测。
- `00-sequence-index` 等索引图是派生物；它只能索引所属证据组的现有截图，不应通过复制截图建立新的独立事实组。
