- 用户原话：之前流畅，现在多设备的任何动画、派系选择弹窗都卡；其他游戏正常。
- 最后正常版本：未锁定。Pixi 地图渲染器未发现由大杀四方直接调用，不能仅凭依赖存在归因。
- 10 月 29 日 `fc297a6e4` 接入 HUD 的反馈截图后台缓存；4 倍 CPU 限速、软件渲染下克隆产生 4585ms 主线程任务。移除 HUD 调用后同类采样最大空闲回调约 1ms。此项不能解释全部症状。
- 派系海盗详情：生产包、1920×1080、4 倍 CPU 限速、Chromium SwiftShader；约 965 DOM 节点、37 张图片。真实点击弹窗，预热后 1 秒窗口基线约 12–19 次帧回调；临时禁用全部 backdrop-filter 约 48–56 次。单独禁用两层任意一层均无相同改善；隐藏卡图也无改善。实验只证明该环境下重叠模糊成本高，不证明用户设备或所有动画的共同根因。
- 静止列表 CSS blur 候选：正式构建交替对照约 19–25 次帧回调，明显差于移除模糊的实验，已撤回；不可用作通过证据。
- 自然新局选择海盗、忍者后进入对局；在上述环境内选取手牌，23 次运动更新间隔大部分约 17ms，少量 33–50ms。代表态和环境不覆盖用户所有设备、场上满载或其他动画。
- 用户明确要求暂不操作已连接手机；未切换或操作该手机。系统 App 累计帧统计不是大杀四方证据。
- 测试期间本轮失败构建使 D 盘空间耗尽；删除失败构建目录被自动安全审查拒绝，之后观察到 D 盘空间已恢复。未采用其他方式绕过拒绝。
- Android 模拟器最初使用 SwiftShader 时，空白页单个 CSS 旋转也仅约 38 FPS，不能据此归因游戏；切换宿主 GPU 后才用于以下对照。空白页同环境约 53 FPS，并非真实手机或原生 App 验证。
- 对局手牌：真实新局选海盗、忍者后，给玩家手牌提前准备 transform 合成层，交替采样比原版运动更新更多；仍有长帧，只能称局部改善。
- 派系详情：将遮罩和面板标记为合成层的候选未能在最终构建中稳定复现收益，已撤回；隐藏面板时约 62 帧/1.2 秒，隐藏外层遮罩无同等改善。面板有 12 个大图集卡牌和一个泰坦图集，隐藏图集能减轻开销，但将图集直接替换为 CSS 背景无稳定收益。
- 派系详情图集使用 `content-visibility:auto` 后，同场景交替三组：原版 8、20、14 帧/1.2 秒；候选 42、45、40 帧/1.2 秒。正式构建再交替三组，原版 6、5、19 帧，优化后 40、39、44 帧；首屏和滚动到底部截图均看到相应卡图，未达到稳定满帧。
- 预置对局状态后通过界面出牌触发战斗特效：约 87 帧/1.8 秒，存在长帧；隐藏连线画布、场上卡图，或分别隐藏特效源/目标的对照无稳定改善。CPU 采样中 React 提交及读取布局有成本，但无法从采样确定用户持续卡顿的单一根因。
- 后续按用户澄清重测完整出牌链：Android 模拟器、宿主 GPU、生产构建，预置五张手牌后实际点击选牌和基地。旧版曾在随从入场阶段只记录到 2 次 transform 更新、最大帧间隔 583ms；同时临时禁用阴影等绘制属性后，三组入场分别有 24–25 次更新。单独关闭基地选择高亮的阴影有可重复收益，普通滤镜、图集隐藏、base 容器提前合成的收益不稳定。
- 根因之一：`BaseZone` 的可选基地高亮每 1.5 秒无限动画修改 `boxShadow`，选牌时多个基地同时逐帧重绘。已改为两个固定阴影层的透明度交叉变化，保留描边、端点阴影和 1.5 秒节奏。选牌后 3 秒 trace：旧版 507 次 RasterTask、约 851ms GPU raster；新版同场景未记录 RasterTask（单次对照，含预热）。四组持续选牌采样旧版 143/109/136/116 帧，新版 141/151/138/157 帧，仍有波动，不能外推到手机型号。
- 新版自然选海盗、忍者并出牌，确认随从 UID 已进入基地，结束回合后状态最终进入第 2 回合；`temp/smashup-performance/natural-play-2.mp4` 与同名 GIF 为 Android 模拟器录制，状态未预置。回合切换 2.5 秒窗口旧版 103/111 帧，新版 106/97 帧，仍有 233–400ms 最大间隔；一次 trace 中点击处理约 150ms，仍未证明此段已修复。录屏最初一版被 Chrome 自身通知提示遮挡，已排除；以上数据不覆盖用户手机或原生 App。
- 上述自然新局为测试入口，不能当作联机入口的图集门禁或玩家切换行为证据。真实联机房间中 Android 模拟器主机完整加载了 77 张图集；辅助桌面玩家为加快测试跳过了自己的门禁。
- 联机静止时，房间页面每次渲染都重建页面属性对象，导致 HTML/body 属性反复移除和写入；稳定对象引用后，6 秒观察内未再出现这类写入。移动画布单位还在通用值和棋盘值间往复设置，优化后同房间 6 秒内未再发生无意义的单位写入。两项均有针对性回归测试。
