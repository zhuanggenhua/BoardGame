# Home V2 Detail 商业化 UI 自审

## 目的

把 `Home V2` 详情页的 UI 自审从“凭感觉看图”收成固定门禁。后续只要继续改 `src/components/home-v2/GameDetails.tsx`，都必须先过这份检查，再宣称“达标”。

## 固定门禁

### G1. 书页边界

- 详情内容必须完整落在书页纸面内。
- 不得压住书本外框、书脊、书签槽位、桌面暗区。

### G2. 主次结构

- 左页负责“认知”：标题、类型、人数、玩法概览。
- 右页负责“行动”：房间列表是主体，建房是单一主操作。
- 禁止把“创建房间”做成压过房间列表的第一视觉中心。
- 右页可用高度里，房间簿主体（真实列表/空态/骨架）必须明显大于标题、标签、说明、按钮这些辅助信息。

### G3. 非后台面板化

- 详情页必须像书页阅读内容，而不是几坨按钮或 dashboard 卡片。
- 允许有轻量信息块，但不能出现整页堆满按钮、标签胶囊、管理后台式模块切割。

### G4. 首屏主体可见

- 默认截图里必须先看到房间簿主体。
- 即使当前没有房间，也必须先看到“空态房间簿”，不能只看到说明文案和按钮。

### G5. 空态/加载态稳定

- 没有实时房间时，右页必须给出稳定空态。
- 实时数据未返回时，右页必须给出稳定骨架，不得塌陷或留出大块无解释空白。

### G6. 商业化可读性

- 正文不超过必要长度，首屏说明只保留一层引导。
- 信息密度要服务主要任务，不靠堆字充实页面。
- 主操作最多一个；其余信息降级成正文、标签或状态说明。

### G7. 素材体系一致性

- 详情页主按钮必须优先复用 `home-v2` 现有素材与九宫格思路。
- 禁止手写一颗脱离书页素材体系的按钮皮肤，再用渐变/圆角硬凑“游戏感”。
- 如果能走项目现有 `holder` / `nineSlice` 素材，就不能自己发明新按钮底。

## 本轮肉眼观察

1. 详情页左右页内容都在纸面内，没有压住书脊、书签和外框线。
2. 右页首屏先看到真实房间条目，再看到底部“创建房间”，主次已经回到“房间列表优先、建房次之”。
3. 真实房间条目现在能同时读到房名、人数和动作文字“加入”，不再出现按钮把标题或人数挤坏的情况。
4. 左页已经回到“返回目录 + 标题 + 基础事实 + 玩法概览”的阅读结构，块感明显弱于上一版后台式卡块。
5. 通过 E2E 先创建一间真实 `smashup` 房间后，右页书页里能直接看到真实房名 `HomeV2房间5306`、人数 `1/2 人` 和动作文字 `加入`。

## 仍需继续收的点

- 右页房间条目已经能读，但条目本身的纸面装饰仍偏克制，后续还可以继续往“书页条目”而不是“浅底容器”收。
- 左页 `玩法概览` 正文在小横屏下仍略密，后续可继续压字数或优化断句。
- 首页总览和详情页现在已经解耦；后续再修首页时，禁止顺手把 detail 改回按钮面板。
- 后续自审时，如果看到“房间簿只占一点点，标题/说明/按钮反而更大”，即使未越线也一律判定为不通过。
- 当前 E2E 只证明“真实房间可展示”，还没单独覆盖“点加入/点创建房间后完整进入对局”的 detail 专用链路。
