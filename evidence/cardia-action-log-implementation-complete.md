### 3. Command Coverage

The ActionLog system records the following commands:

1. **PLAY_CARD** - Playing a card to a slot
   - Format: "打出 [卡牌名] 到位置 X"
   - Includes card preview and slot index

2. **ACTIVATE_ABILITY** - Activating a card ability
   - Format: "激活 [卡牌名] 的能力"
   - Includes card preview and ability reference

3. **SKIP_ABILITY** - Skipping ability activation
   - Format: "跳过能力"

4. **END_TURN** - Ending the turn
   - Format: "结束回合"

5. **ADD_MODIFIER** - Adding a modifier token
   - Format: "添加修正标记到 [卡牌名] (+X)"
   - Includes card preview and modifier value

6. **REMOVE_MODIFIER** - Removing a modifier token
   - Format: "移除 [卡牌名] 的修正标记"
   - Includes card preview

7. **RESPOND** (Interaction events)
   - **CARD_REPLACED**: "替换 [旧卡牌] 为 [新卡牌] 在位置 X"
   - **FACTION_SELECTED**: "选择派系 [派系名]"

## Key Design Decisions

### 1. i18n Segment Approach
Used i18n segments instead of pre-translated text to avoid server-side i18n issues. This allows:
- Server to generate log entries without i18n context
- Client to translate segments on-demand
- Language switching without re-generating logs

### 2. Card Preview Integration
Integrated with global card preview system:
- Card segments include `previewRef` for tooltip display
- Supports both i18n keys and plain text card names
- Gracefully handles missing cards (returns null)

### 3. System Configuration
Followed the pattern from other games (smashup, dicethrone, summonerwars):
- Manually expanded systems instead of using `createBaseSystems()`
- Explicit system imports and configuration
- Clear separation of concerns

### 4. Event-Driven Architecture
- ActionLog records events generated by commands
- Supports multiple events per command (e.g., RESPOND → multiple CARD_REPLACED)
- Timestamp offsets ensure chronological ordering
