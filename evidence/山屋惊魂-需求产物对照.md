# 山屋惊魂需求-产物对照

> 目的：把用户在当前任务线里点名的需求逐条对到当前产物。`测试通过`、`截图存在`、`状态文件 complete` 不能自动覆盖没有列入本表的需求。

## 对照结论

- 之前的验收矩阵覆盖了移动端主链、投骰/事件牌同屏、关闭退场、剧本翻页和视角跟随，但没有完整吸收用户所有点名项。
- 有些需求已有产物但未纳入最终状态文件，例如角色面板与 token 对应、连续移动、角色详情滚动到特性、属性颜色。
- 有些需求只有部分覆盖或没有可追溯产物，例如“参考山屋惊魂电子辅助软件”的参考记录、“先选择线路再判定”的对象全集/时序家族清单。
- 因此，按完整需求口径，当前不能只用 `temp/betrayal-mobile-playability-2026-07-16.json` 的旧 `complete` 结论收口；需要把缺口继续作为待补或明确不适用。
