## 3. 正确审计口径

审计文档必须按以下顺序组织，不能倒过来：

1. **对象全集**：先确认对象是否在当前范围内。当前游戏牌为 43 张事件、22 张物品、9 张预兆，共 74 张；房间 42 个；当前默认首剧本为「木乃伊横行」。
2. **规则子句**：每个对象拆成触发、选择、结算、状态、清理、例外/限制等子句。
3. **实现消费**：每个子句必须找到真实消费者，例如数据字段、命令、校验、reducer、事件、读模型、Board/UI 入口。
4. **证据层级**：区分数量/atlas、领域行为、Board 组件代表链、真实入口 E2E/截图、治理残余。
5. **残余分类**：所有未闭合项必须先分类，不能直接变成“继续补组合”任务。

## 4. 残余分类

| 分类 | 什么时候算 | 当前处理方式 |
| --- | --- | --- |
| `实现正确性阻塞` | 规则子句未实现、玩家没有入口、合法动作无法完成、状态没有写入/清理、UI 和命令消费不一致、已锁合同与实现冲突 | 进入当前优先队列，必须定位代码并修复 |
| `验证层级缺口` | 实现和代表链存在，但缺真实入口、截图、自然整局、负向 UI 或发布级完整链证明 | 只影响对外结论等级，不自动变成实现任务 |
| `非阻塞扩展` | 更多房间特殊状态、更多伤害来源、更多死亡保护/兔脚/减伤叠加、全部组合排列 | 默认不作为下一步；只有命中具体规则错误或用户反馈才升级 |

## 6. 当前优先队列

### P0：实现正确性审计候选

这些是“必须先检查是否真的没实现”的队列；只有查到规则子句无法被当前实现消费，才升级为正式修复任务。

| 候选 | 要检查的现实问题 | 不是在检查什么 |
| --- | --- | --- |
| 事件剩余分支 | 某张事件的某个分支是否没有最终状态写入、没有玩家选择入口、或分支后卡住 | 不是要求 43 张事件全部跑真实截图 |
| 物品主动/被动入口 | 玩家是否能在规则允许时使用，使用后是否正确消耗、记录、清理或持续生效 | 不是要求每个物品和每个作祟/死亡保护组合全排列 |
| 预兆逐卡入口 | 每张预兆的效果是否有正确触发窗口、UI 或自动消费者 | 不是用 9 张数量正确判完成 |
| 作祟公共规则 UI 消费 | 风险条、抽预兆骰数、最后一张自动作祟、翻牌确认队列是否都被页面正确承接 | 不是重新录入预兆数量 |
| 房间显式效果 | 11 个带效果房间是否按规则触发、结算、清理并反馈给玩家 | 不是审所有无效果房间的截图 |
| 「女孩」触发牌版本冲突 | 当前合同是否仍存在版本争议，是否影响木乃伊关键流程 | 不是靠实现猜规则 |

### P1：验证层级补证

- 「木乃伊横行」同一整局自然跨回合链。
- 已有 Board 组件代表链但缺真实 Playwright / 截图的对象。
- 负向 UI，例如非法目标提示、非持书/非同房/已死亡状态提示。

### P2：非阻塞扩展

- 更多房间特殊状态和怪物移动交叉。
- 更多伤害来源、减伤、胸针、头骨、兔脚、死亡保护叠加。
- 全部事件/物品/预兆/房间的组合排列。

这些默认不进入下一步，除非具体规则子句、玩家反馈或当前实现证据证明它们改变规则结果。

## 9. 下一步执行模板

继续任务时必须按这个模板开工：

1. 从本文 P0 队列选一个具体对象或对象分支。
2. 回到对应专项文档和合同，锁规则子句。
3. 查当前实现入口：数据字段、命令、校验、reducer、读模型、Board/UI。
4. 判定残余类型：
   - 规则子句消费失败：修实现。
   - 只有证据等级不足：补最小验证或降级结论。
   - 只是更多组合：登记为非阻塞扩展，不作为默认下一步。
5. 修改后回写本文和对应专项文档，避免旧结论继续误导。
