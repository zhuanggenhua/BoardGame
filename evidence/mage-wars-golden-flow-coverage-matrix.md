# Mage Wars current-scope 综合候选链核心机制覆盖矩阵

## 范围裁决

- 本文件是 evidence，不是规范主源；通用黄金链规则以 [`.spec/knowledge/standards/e2e-verification.md`](../.spec/knowledge/standards/e2e-verification.md) 为 canonical-source。
- 当前链路等级：`current-scope 综合候选链`。它能证明标准竞技场、兽王 / 女祭司两派系标准起始书中已实现代表机制跑通，但不能登记为 `stable / pre-push` 主黄金链。
- 当前 E2E 用例：`e2e/mage-wars/online-runtime.e2e.ts` 中 “Mage Wars 当前范围候选链：标准竞技场两派系覆盖计划、部署、移动、守卫、装备结界、魔物、攻击、能力和终局”。
- 墙体局部链：`e2e/mage-wars/online-runtime.e2e.ts` 中 “正式页面墙体法术可选择边界并在穿越时触发通行伤害” 已通过，覆盖本地正式墙体卡面、边界施放、墙前 / 墙后视线阻挡对照和穿墙通行伤害，证据见 [`mage-wars-wall-mechanics/e2e-test.md`](mage-wars-wall-mechanics/e2e-test.md)。
- 为什么不是稳定黄金链：当前主候选链中仍使用代表态桥接与近终局代表态；墙体公共机制虽已局部跑通，但主链整合、服务器资源发布、自由构筑、全卡表、自然整局、完整 AI、教程、撤回、行动日志 UI、刷新恢复仍未形成稳定门禁证据；`2500` 烈火之墙目前按共享流程判等覆盖，不是默认逐对象完整浏览器链缺口。
- DiceThrone 反推结论：DiceThrone 黄金链不是把散件截图改名，而是把已打绿的页面动作、断言口径、响应窗口和逐阶段截图复用进一条连续浏览器链。Mage Wars 也必须先列核心机制族，再决定主链、分段链、低层测试和 deferred 分别证明什么。

## 复用散件端到端的规则

- 可以复用：已打绿分段 E2E 的页面 helper、真实点击路径、断言口径、截图命名、等待素材 / 动画稳定的工具函数。
- 可以作为矩阵证据：低层测试、代表态 E2E、专项截图组、已有分段链，但必须逐行说明它覆盖哪一个核心机制族。
- 不能复用成黄金链：把多条散件 E2E 的结果拼成一条结论、把状态快照中途注入多段、把截图组数量当作端到端本体、把候选链命名成 stable/pre-push 黄金链。

## 当前候选链图组

- 最新更名后验证：`1 passed (2.7m)`；用例和截图目录均为 `当前范围候选链`。
- 完整展示顺序：24 张原图；第 1 张必须是 `01-双方计划后-对手计划仍隐藏.jpg`。
- 用户要求看完整流程图时，应打开完整有序图组，不能只打开终局图、收口图或从召唤阶段开始的旧图组；附件目标选择图 `10A`-`10D` 和治疗过程帧 `15-阿希拉牧师治疗之光-治疗光效和恢复数字过程帧.jpg` 属于本轮核心补证。

## 升级到 stable / pre-push 前的最低缺口

| 缺口 | 为什么阻止稳定黄金链 | 最小后续切片 |
| --- | --- | --- |
| 墙体主链整合和资源发布 | 墙体公共机制、本地正式卡面和局部 E2E 已跑通，`2500`、`25700` 的数据按现有录入基线使用；`2500` 通过共享流程判等覆盖；但主候选链尚未把墙体作为顺序核心机制纳入，也未证明服务器资源发布 | 把墙体 helper 复用进主黄金链候选；如需 `2500` 独立浏览器证明，只在独有规则、入口差异、证据冲突或用户点名时补；如需线上 / 手机证明，走资源发布并回查；仅在 Wiki、玩家反馈或新主真相源冲突时复审数据 |
| 响应 / 反应窗口代表链 | 复杂桌游的响应窗口是核心交互，不应只由领域逻辑或静态结果代表 | 挑一条可见响应窗口，覆盖触发、可响应对象、跳过 / 确认、结算和回到行动权 |
| 隐藏结界揭示与附件主动能力 | 当前只证明显性附件表达，不证明隐藏 / 揭示或主动使用 | 挑代表结界揭示和装备 / 附件主动能力各补真实链 |
| 自然终局或稳定极简整局 | near-end 代表态不能证明完整行动轮转自然打到胜负 | 用极简测试局或调试种子跑自然终局，记录胜负和轮转证据 |
| 自由构筑 / 全卡表 / 扩展法师范围裁决 | 当前运行池不是完整实体版 Mage Wars | 按产品 change 拆成构筑入口、卡表能力矩阵和法师能力矩阵 |
