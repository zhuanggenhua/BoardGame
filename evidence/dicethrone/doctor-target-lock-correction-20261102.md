# 指定对象、原界面与复用效果的纠正

用户原话：“更新规范，没定位到我说的具体内容就不要行动，把需求问清楚，然后把我说的东西和你新实现或者复用的效果截图对比，现在去找啊”。补充：“某个效果可以从牌堆拿牌，效果没统一注册吗”。

## 治理处置

|对象|角色与处置|理由|
|---|---|---|
|conversation-handoff-target-lock|项目canonical-source，合并补全具体内容同一性|已有四项锁定，但本轮把相邻承载认成指定内容；明确候选不算已定位、沿注册表查源、仍不唯一则问最小问题，回答前不实施相关改动|
|ui-change-gates|项目canonical-source，补全指定原入口截图与实际效果成对核查|原有旧新职责表不足以阻止用本聊天修前图代替用户指定原UI；明确真实入口、可比视口/状态及借尺寸不算完整复用|
|AGENTS、skills、系统层|保留已有引用，不新增平行正文|现有路由已能到达两份主源；不把本英雄、卡名或某个尺寸升级为通用规范|
|历史PASS、截图与新对照|evidence|只能记录直接事实，不反向定义原UI或产品完成；旧清单的复用完成结论撤回|

首次偏移发生在“指定原UI尚未对应”时：用现有牌库选择器名与多卡阅读尺寸代替了用户指的具体效果界面，随后继续改共享承载并验收。后来读取血色杀戮源码和改后截图，也不能追认前面的变更已获批准。一般锁定条款原已存在，本轮执行未满足；补的是具体内容同一性与指定原入口截图对照，未另造规范入口。

## 当前实际定位

- 注册入口：`src/games/dicethrone/domain/customActions/index.ts`统一初始化各英雄CustomAction；公共注册由`registerCustomActionHandler`承接。
- 直接命中：吸血鬼领主终极技“血色杀戮”，actionId `vampire-lord-bloody-slaughter-search-deck-card`。
- 消费链：`heroes/vampire_lord/abilities.ts → customActions/vampire_lord.ts:handleBloodySlaughterSearchDeckCard → INTERACTION_REQUESTED/selectDeckCard → InteractionOverlay`。候选来源为当前玩家抽牌堆，选择一张加入手牌；不是出牌特写队列，也不是点击弃牌堆只读浏览。
- 博士选择器是同一共享owner的来源适配；本聊天确实改过这个共享owner的尺寸和布局，因此“目前两个入口使用同组件”不能证明没有改旧UI。
- 原历史截图文件缺失；旧组件重放只能证明对应历史源码运行时的样子，不是原时截图或用户批准的正常基线，必须单独标注。

## 四项回查

1. 负向：未新增系统层/单英雄规则正文，未把CardSpotlightQueue等邻近对象认成牌堆取牌效果；未改产品代码继续猜尺寸。
2. 正向：从before-you-code与UI入口均能到达原有目标锁定、UI门禁；新增同一性小节与成对截图项可直接检索。
3. 顺序复演：先最小澄清，按补充语义查统一注册，再追具体效果、真实点击与渲染owner；先改canonical-source及校验，未先改游戏实现。
4. 错误阻断：只有相邻组件/尺寸时，同一性仍未完成；无指定原入口图与当前对应状态图时，复用项不能PASS。`spec:lint`通过只证明规范结构，不证明UI完成。

## 用户确认后的实施

用户随后回答“是这个”，确认第一组所指原完整选择UI。该确认锁定了对象；灰色骨架仍不证明正式卡图。后续已补齐带正式卡图的原组件重放及同状态当前效果对照，再按该owner整体恢复，未改成借用另一界面尺寸。当前结果见[用户确认的原UI恢复](doctor-confirmed-deck-ui-restoration-20261102.md)。最终角色验收仍未获得。
