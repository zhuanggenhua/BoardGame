# DiceThrone 旧英雄新版面板槽位合同

## 本轮范围

- 问题对象：旧六角色在新版玩家面板上的技能槽、升级牌覆盖、高亮与点击反查。
- 真相来源：`test-results/evidence-screenshots/dicethrone-slot-audit/*-v2-slot-crops.png` 中从正式玩家面板图裁出的物理槽位；槽位内中文技能标题为本轮合同依据。
- 代码入口：`src/games/dicethrone/ui/abilityOverlayHelpers.ts` 与 `src/games/dicethrone/ui/abilitySlotMapping.ts`。
- 验收口径：火法“熔岩护甲”必须落在防御槽 `meditate`，圣骑士满升级截图里每张升级牌必须覆盖对应底图技能槽。

## 收口说明

- 旧六角色不再按共享槽位语义推断技能位置；共享坐标只表示新版面板物理格子。
- 2026-08-26 复核：火法 `炎爆术 / 炽热波纹` 两行曾残留反向运行时技能 id；当前已按 `升级牌槽位全量回图审计-2026-07-04.md`、`abilitySlotMapping.ts` 和 `AbilityOverlays.test.tsx` 修正为 `sky -> pyro-blast`、`combo -> fiery-combo`。
- 当前运行时合同已统一到 `abilitySlotMapping.ts`：它负责按角色玩家板图面合同解析物理槽对应的基础技能，并服务点击、高亮、E2E 反查和升级牌覆盖。
- `abilityOverlayHelpers.ts` 只负责查询升级牌和委托槽位合同，不再维护第二份 `slotId -> abilityId` 完整表。
- 后续发现单张升级牌错槽时，不能只看这份旧六角色合同；必须回到全英雄 `replaceAbility` 矩阵和正式玩家板图面合同重扫同类对象。
