# 牌堆选择操作位置稳定补修

状态：本次稳定操作区补修、当前源码真实入口与图面复验完成，供用户验收。角色仍为 `in_progress`，没有用户最终验收。

用户原话：“我看明白了，是uiskill要更新吧，这里为什么不用固定容器大小呢，你这样按钮的位置变来变去，也不方便交互吧”。

## 对象与范围

用户已确认的血色杀戮从牌库选择卡牌完整界面，由原 `InteractionOverlay` 承接，奇异博士继续复用该 owner。本次只改这个选择器的容器高度、内部滚动归属与操作区落位；原卡宽、卡面皮肤、选择/确认/取消语义、来源候选与阅读入口不改。其它旧 UI、骰盘左中提示、手牌与技能界面不在修改范围。

补丁前同一真实效果六态保存在 `temp/doctor-deck-effect-source-capture-20261102/stable-before-desktop/capture.json`。完整候选时确认按钮纵坐标为 559.5，过滤到单张时变成 393.203125，位移约 166 像素。先前静态图审遗漏了这一跨状态问题，旧 PASS 不能证明本项通过。

## 规范处置

| 对象 | 处置 | 职责与原因 |
| --- | --- | --- |
| `ui-responsive-layout` 弹窗滚动规则 | 保留并补全 | 唯一布局主源补充连续选择时的容器/操作目标稳定与跨状态验收；不把全部 UI 固定成统一像素大小 |
| `game-ui-design` 布局交互分卷 | 增加薄引用 | 路由到同一主源，不复制可执行正文 |
| 静态可见/可点击验收结论 | 限定证明范围 | 不能继续证明搜索/清空/选中过程的位置稳定 |

根因是原候选窗仅设最大高度，操作行处于内容自然流，候选减少后容器收缩；此前验收只逐张检查可见性，没有对照连续状态的操作目标位置。

修复为随当前视口确定稳定外壳，候选区在内部滚动，确认占独立中间列，原合法取消动作位于左侧，不新增假按钮或第二套交互。

规范顺序复演：先锁定用户指出的选择器 → 查现有规范并确认缺少跨状态验收条款 → 主源补全、分卷仅引用 → 保存补丁前同入口六态 → 原 owner 最小布局修改 → 连续状态与当前图面复验。旧误判会在同视口连续状态位置比较时被拦住。
