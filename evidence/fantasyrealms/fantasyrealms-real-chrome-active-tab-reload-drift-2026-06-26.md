# Fantasy Realms 活端口旧运行时页诊断（2026-06-26）

## 本轮要回答的问题

这份证据只回答一件事：

- 为什么同样是当前活着的 `4275` 开发页，用户眼前某个真实 tab 仍可能和当前代码、当前 E2E 不一致

也就是说，这里不是“死端口旧页”那条线，而是更隐蔽的一条：

- 端口还活着
- 页面也还是应用页
- 但这个 tab 自己挂着旧运行时，刷新前后几何会明显跳变

## 直接证据：同一活页刷新前后发生了几何翻转

目标页：

- `http://127.0.0.1:4275/play/fantasyrealms/match/phfcLsMc8Yh?playerID=0`

这是当前活跃开发端口 `4275` 上的一张真实 Chrome 页，不是死端口错误页。

我对同一页做了 `reload` 前后对比，得到的关键值如下。

### 刷新前

- `tableClass = fr-live-table fr-live-table--early-draw`
- `data-slot-count = 7`
- `data-visible-count = 2`
- 手牌列宽：约 `132.87px`
- 两张手牌落在第 `3/4` 列
- 手牌组中心相对手牌行中心偏差：`-71.36px`

这不是“看起来有点偏”，而是 DOM 直接表明：

- 当前页把 2 张手牌仍按 `7 槽` 摆
- 宽度因此被撑大
- 牌组整体左偏一整张半左右

### 刷新后

- 仍是同一页、同一路由、同一端口
- `tableClass = fr-live-table fr-live-table--early-draw`
- `data-slot-count = 8`
- `data-visible-count = 2`
- 手牌列宽：约 `115px`
- 两张手牌落在第 `4/5` 列
- 手牌组中心相对手牌行中心偏差：`-0.004px`

这说明刷新后它才回到当前实现对应的运行时状态。

## 现实含义

这条证据证明了一件之前还没说硬的事：

- **“端口是活的”不等于“眼前这个 tab 就是当前实现”**

在本轮 Fantasy Realms 里，至少已经实际出现过：

1. 死端口旧页
   - 例如 `4276`
   - 现象是直接掉到浏览器错误页，正文出现 `ERR_CONNECTION_REFUSED`

2. 活端口旧运行时页
   - 例如这条 `4275/phfc...`
   - 现象是页本身仍能打开、端口也确实活着
   - 但刷新前它仍然表现出旧的 `7 槽 / 132px / 左偏 71px`
   - 刷新后才回到当前实现的 `8 槽 / 115px / 中线归零`

所以以后再遇到“我眼前这页和你现在代码/E2E不一致”，不能只做“端口还活着吗”的检查，还必须再做一次**同页刷新前后几何对比**。

## 和本轮牌大小问题的关系

这份证据还顺手回答了本轮一个关键疑问：

- 为什么我前面已经证明“当前实现下 2 张手牌和 8 张手牌都应是 `115x160`”，但真实活页里仍曾读到 `132.875`

原因不是当前代码又坏了，而是：

- 这个活页在刷新前仍挂着旧运行时
- 旧运行时里 `early-draw` 还保持 `7 槽`
- 所以会出现 `132.875` 与 `-71.36px`
- 刷新后立刻翻正成当前实现

## 已补规范

已在 [.spec/knowledge/standards/e2e-verification.md](/D:/gongzuo/webgame/BoardGame/.spec/knowledge/standards/e2e-verification.md:92) 追加两条：

- 活端口旧 tab 也可能挂过期运行时，不能只凭端口存活就当当前实现
- 真实浏览器几何争议默认补同页刷新前后对比

## 当前结论

当前对话里，可确认的事实已经分成三层：

1. Fantasy Realms 的“牌大小和 E2E 不一致”业务问题，本体已修到当前实现与真实 Chrome/E2E 一致。
2. `4276` 这种死端口旧页，不能再当真实现场。
3. 即使是 `4275` 这种活端口页，也可能在长时间不刷新后挂着旧运行时；这种页刷新前后的几何若明显跳变，刷新前画面同样不能再当当前实现证据。
