# 七大恨手牌决策托盘局部重构

本轮根据用户“该优化重构的可以做一下”实施支付交互的职责拆分和局部可用性修复，不重做棋盘布局或游戏规则。

最终展示使用[当前已核验清单](verified/focused-pass-manifest.json)，顺序为桌面支付、手机横屏支付；[查看图组](http://127.0.0.1:14587/?key=3c80d7e46bd0)。该图组只证明下述局部界面要求。

- [手牌交互投影](../../../src/games/qidahen/ui/handInteractionView.ts) 只读取正式状态，保持原有五类决策的优先级与确认门槛。
- [统一托盘](../../../src/games/qidahen/ui/QidahenHandInteractionTray.tsx) 接收窄投影和原命令回调，合并重复面板，区分确认与取消、跳过。
- [主题常量](../../../src/games/qidahen/ui/qidahenTheme.ts) 从主棋盘原样迁出，不另建一套主题配置。
- 手机横屏托盘上移，为已选牌卡头、悬停和查看入口留出间距。

## 验证范围

- 支付、轮盘进攻调度支付、征兵训练、操作提示及托盘渲染行为：五个套件共 36 项通过，其中新增托盘渲染行为测试 8 项。
- 真实浏览器流程：选择征召军队、选牌、切换手机横屏并悬停、取消、重新打开；断言取消不扣手牌、不增加弃牌、重开清空选择，手机托盘与选中牌至少相隔 8 像素。
- 图面范围：1920×1080 桌面、932×430 手机横屏的征召军队支付代表态。保留了开工前完整源码在同入口复跑取得的两张基线图。
- 局部代码审查通过；源码检查和全部测试不能替代图面审查。

## 未通过与未覆盖

- 原有棋盘结构套件有 3 项字串断言失败，涉及右侧栏高度、地图聚焦和教程结果反馈；重构前后均存在，没有为取得通过而放宽这三项断言。
- 全仓类型检查未通过，报错分布于共享、服务端和既有游戏代码；新增三个生产模块没有报错。不声明全仓检查通过。
- 未覆盖竖屏、其它支付种类的完整图面、完整教程、整游戏规则、联机和生产环境。
- 战斗面板布局，以及移动端纪年、朝鲜信息的替代入口，未在本轮改造。
- 最新图面复查还发现手机手牌原有类别角标覆盖部分印刷标题；支付托盘的退让修复不等于这项卡面布局问题已经解决。
- 工作区后来出现的战斗投入兵力预览修改已保留，未纳入本轮重构归属。
