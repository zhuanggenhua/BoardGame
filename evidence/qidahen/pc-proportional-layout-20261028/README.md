本目录只证明本次主棋盘、手牌支付、人口定位和地图浏览修复。用户明确要求手机继承桌面构图等比缩放；旧手机专版图组已失效。

## 结果

- 冻结源码中同一轮浏览器测试：三项通过，见 `e2e-run.log`。

## 真实验证范围

1. 相同开局代表态下，桌面 1920×1080、宽屏 2560×1304、手机 936×432、小屏 740×342 的主要对象几何、文字与行高按同一设计坐标映射。
2. 支付选牌、取消、地图缩放与复位；八张支付手牌的首末张可触摸选择。八张牌由合法牌数据构造的压力代表态提供，不是这条链自然抽到的结果；横向滚动范围通过滚动位置验证，不等同于手指横滑验收。
3. 原被手牌覆盖的地区通过真实触摸缩放、两次上滑和惯性停止恢复可见，点选命中同一地区，并能保留原地区说明框阅读。
4. 三十七区的区域归属、人口完整占位、窄区引线与开局军队避让由专项单测覆盖，截图只提供本次可见局面的观察。

## 源码与环境

运行入口是快照内原项目命令：

```powershell
node scripts/infra/run-e2e-command.mjs isolated e2e/qidahen/mobile-population-layout.tmp.e2e.ts --workers=1 --retries=0
```

快照为 `temp/qidahen-acceptance-snapshot-20261028`。它是普通文件副本，不是 Git 分支或 worktree；依赖和静态素材目录复用原资源。前端与后端源码身份检查均保留。这样避免并行任务修改其它游戏时，测试服务缓存与整仓源码身份发生变化。

原工作区的测试已整理为 `e2e/qidahen/pc-proportional-layout.e2e.ts` 并补齐类型标注。它与快照中已执行版本生成的运行代码逐字节相同，见 `test-emission-equivalence.json`；没有改变测试操作或断言。`geometry.json` 和 `map-reachability.json` 的本轮源码指纹相同，且与交付时工作区对应源码字节一致。`snapshot-source-identity.json` 和 `source-comparison.json` 保留更广的快照来源与差异，不能把其它模块不同写成整仓一致。

本组三项通过后，教程任务只给战术牌教学节点增加了提示避让对象。该参数不进入本组已关闭教程的场景；已保存实际受测版本的精确原始字节 `sources/tutorial-tested.ts`，并由独立代码审查记录有限的来源等价。不得将这组图扩称为新增教程节点已通过。

随后教程系统的一项类型引用修正，经精确受测字节和转译运行代码核对，确认不改变本次运行逻辑；其差异也在 `source-scope-equivalence-review.json` 单独记录。当前全仓类型检查仍未通过，日志为 `test-results/qidahen-r79-typecheck.log`，本目录不构成发布门禁通过。

- 两层手牌从起点处理溢出，保留少牌居中，修复首牌在滚动范围外的问题。
