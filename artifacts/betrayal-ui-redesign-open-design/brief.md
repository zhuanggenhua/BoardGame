## 玩家任务与界面对象

玩家第一眼要看到当前行动者、自己的角色/token 所在房间、当前阶段/剩余移动和可执行动作；随后在房间本体选择移动/探索目标。探索者左侧区域承载身份、四条属性轨、能力入口及持有物；中央房间网络是主舞台；右侧预兆/物品/事件牌库、预兆轨、队友和剧本入口属于次级信息；底部短动作入口不得压迫地图。角色 token 是地图位置实体，不复制成第二个角色面板。

规则结论：属性轨必须连续、逐格等距并保留重复数值，骷髅是死亡端点；预兆状态是 0–9 轨道而非说明墙；持有物与可读卡牌必须能检视；牌库未公开内容只显示牌背/数量；已公开弃牌可回看；书页按真实顺序翻页且正文是阅读焦点。

## 必须在图上解决

1. 手机上能力入口不能仅截成“特性：无…”。常驻入口应完整显示能力名称与有用的短摘要；点击后用阅读层显示完整正文，最终视觉正文至少约 16 CSS px，必要时滚动。无特殊能力也须明确完整显示“无特殊能力”，不能让省略号伪装成缺内容。
2. 四个属性名称、轨道起点与行中心逐行对齐；高亮、重复数值和死亡端点可读；不得靠 DOM 几何但肉眼仍错位。
3. 手机和 PC 保持同一对象结构及比例语义。地图始终是主舞台；固定结构可缩放，文字不能随画布压到不可读。手机端可使用按需展开/检视层，但不可让侧栏信息和底部动作抢掉地图或遮住持有物。手机无需真机，按 796×360 CSS px、DPR 3 导出与审查。
4. 当前回合在右上；楼层切换保持既有右侧/右下稳定槽位，不漂移；移动/平移/缩放后应回到玩家 token 位置的镜头焦点，这属于实现验收，不以设计稿代证。不要添加剧本书额外标题。
5. 过程文案与“继续”按钮保持均衡字阶；正文先可读，不允许按钮比正文大两倍。剧本书的前/后翻页、关闭操作大小一致，三者归属与锚点清楚；剧本选择页底部三个操作同排。
6. 至少设计主态、能力详情展开、剧本书正文、过程文案/继续、剧本选择/确认五种状态，每种展示 PC 与目标手机宽高比或解释状态复用。饱和态需含 1–2 件持有物和队友，不使用空态掩盖拥挤。
