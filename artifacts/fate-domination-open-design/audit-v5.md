# Fate/Domination OpenDesign v5 审计记录

- 视觉候选稿：可供人工评审
- 人工设计验收：`not-approved`

## 视觉检查

- 1920x1080：中央棋盘保持主视觉，其他玩家在棋盘上方，手牌直接悬浮在桌面下沿。
- 手牌：3 张正式牌图按角度、垂直位移和层级重叠，选中牌上浮；没有手牌底部方框。
- 顶部移除手牌式牌背扇形，换成基于规则的局势/区域事件状态摘要；底部手牌按通常 3 张规则口径标注编成状态。
- 右上角：移除 Supply / Log / Menu 矩形按钮，改为单一圆形工具球和圆形动作入口。
- 下一阶段：使用右下角阶段球、文字和箭头，没有矩形主按钮。
- 棋盘：使用未标记正式底图；白色半透明格和字母均为 HTML 测试层，未使用标记参考图作为画面素材。
- 高亮仅使用颜色、边框和光晕，不对热点做位移，避免高亮边界与半透遮罩错位。
- 右侧积分轨道已由脚本识别为 4 列 x 10 行圆形节点，移除 F1/F2/H 的矩形覆盖；底图改为完整映射，测试遮罩与参考坐标统一。
- 未发现明显的遮挡、溢出或断图。

## 浏览器检查

- 桌面 `1920x1080`：`scrollWidth=1920`，60 个交互目标可见（20 个区域热点 + 40 个积分轨道节点），0 个断图，0 个页面错误。
- 移动 `390x844`：`scrollWidth=390`，页面总高 `1030px`，60 个交互目标可见（20 个区域热点 + 40 个积分轨道节点），0 个断图，0 个页面错误。
- 交互：热点高亮与区域文字更新、工具球展开、卡牌检查弹窗、阶段球状态更新均通过。

## 组件落地说明

DiceThrone 现有通用手牌组件为 `src/games/dicethrone/ui/HandArea.tsx`。本候选稿使用独立 HTML 复刻其视觉和交互契约；设计确认后，运行时应直接复用该 React 组件，并把 Fate/Domination 的卡牌数据与回调接入，不再维护两套手牌组件。
