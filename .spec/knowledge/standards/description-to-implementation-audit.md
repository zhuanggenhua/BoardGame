# 描述到实现全链路审查规范

## 主源定位

本文档是 BoardGame **规则 / 玩法 / 机制审计的项目级 canonical-source**。它只定义跨游戏都成立的审计方法：从权威描述出发，追到实现消费、玩家真实入口、最终权威状态和证据边界。

项目级审计回答的是抽象问题，不回答某个游戏的具体规则答案：

- 真实语义是什么。
- 实现有没有消费这份语义。
- 玩家入口、命令、状态、UI、AI / 自动推进和测试是否共享同一份业务真相。
- 缺口属于功能实现、语义一致性、验证范围、审计留档还是非阻塞扩展。
- 当前结论能否支撑“已审计 / 已收口”的对外口径。

本文档不承载单游戏答案、卡牌裁定、骰面公式、房间效果、教程章节安排、截图结论、历史事故清单或某个批次的对象全集。这些内容只能落到对应游戏规则合同、`docs/games/<gameId>/...`、`evidence/<gameId>/...`、用户故事或游戏专项 workflow。

旧 `testing-audit-*` D 维度分卷只保留为历史链接兼容，不再作为新的项目级审计基准。新审计以本文档的“语义 -> 消费 -> 真实入口 -> 证据”链路为基准；证据文档格式看 [`audit-evidence-template.md`](audit-evidence-template.md)，规则 bug 合同裁定看 [`rule-contract-audit.md`](rule-contract-audit.md)，E2E 与截图看 [`e2e-verification.md`](e2e-verification.md)。

## 项目级审计最小维度

审计不是机械填表。除非用户或任务明确要求更细矩阵，项目级默认只按下面六个维度裁定：

| 维度 | 要回答的问题 | 常见结论 |
| --- | --- | --- |
| 语义一致性 | 权威描述拆出的原子断言是否被完整表达，没有多做、少做、错对象或错时机？ | `语义一致` / `语义不一致` / `合同未锁定` |
| 消费完整性 | 静态定义、注册、合法性、命令、执行、状态、UI、AI / 自动推进和测试是否消费同一份真相？ | `消费闭合` / `消费缺口` / `多重真相` |
| 功能结果 | 玩家动作或系统触发后，最终权威状态是否正确变化并完成必要清理？ | `功能已实现` / `功能实现阻塞` |
| 交互可用性 | 真实玩家入口是否可见、可点、可完成；可选、跳过、多步、私有或延迟交互是否能收口？ | `真实入口已证实` / `当前范围验证缺口` |
| 共享影响 | 缺口是否位于共享 helper、系统、状态字段、UI 组件或 AI 消费者；受影响对象是否能列出？ | `当前对象` / `最小受影响集` / `候选残余` |
| 证据状态 | 旧 evidence、旧测试、截图或总结是否仍传播旧结论；当前证据能否支撑对外口径？ | `可收口` / `需降级` / `审计留档缺口` |

编号、脚本、矩阵和截图都只是帮助回答这些现实问题的证据，不是审计本身。不得把“填完编号表”“跑过脚本”“截图存在”当作审计结论。

## 审计流程

### 0. 锁定本轮前提

开始前必须写清四件事：

- **问题对象**：本轮审的是哪个游戏、哪类对象、哪条规则子句、哪条共享链路或哪份旧 evidence。
- **真相来源**：规则合同、已锁录入表、用户当轮原文、规则书、图片合同或其它来源中，哪一份承担本轮裁定。
- **目标入口 / 环境**：审计对象最终由哪个玩家入口、命令、系统触发、AI / 自动推进或测试入口消费。
- **验收口径**：本轮要证明功能已实现、语义一致、验证补齐、旧结论失效，还是只做范围裁定。

缺任一项，只能继续定位或标为 `合同未锁定 / 当前范围验证缺口`；不得直接写“通过”。

### 1. 锁定权威描述

审计阶段默认消费当前项目已经存在的规则文档、配置、实现、测试、evidence、已建立的数据合同或用户当轮明确提供的材料；不默认重新查 Wiki、网页、在线文本包、OCR 或卡图来建立新规则。

如果现有材料缺规则原文、对象归属、版本差异或图片合同，先按 [`rule-contract-audit.md`](rule-contract-audit.md) 或数据录入 workflow 标成 `blocked / disputed`。审计不能临时把实现字段、i18n 文案、测试断言或代码注释补成权威规则。

### 2. 拆成原子语义

把自然语言描述拆成可验证断言，每条断言至少说明：

- 触发条件和时机。
- 执行主体。
- 作用对象。
- 玩家是否有选择权。
- 数值、资源、状态或区域变化。
- 持续时间、清理条件和不应发生的反向路径。

复杂描述按独立交互链拆分；不同触发时机、不同玩家选择、不同目标集合、替代 / 防止、额外行动、延迟收口和可选 / 强制分支不能混成一条。

### 3. 追实现消费链

每条原子语义都要追到真实消费者。推荐按下面顺序记录证据，但不要求机械填固定表格：

| 消费层 | 要确认什么 |
| --- | --- |
| 静态定义 | 配置、规则数据、i18n 和资源引用没有把语义写偏 |
| 注册与合法性 | registry、validator、候选生成和权限判断能让正确玩家在正确时机行动 |
| 命令与执行 | command、handler、system、resolver 或 reducer 实际执行了该语义 |
| 最终权威状态 | HP、资源、Token、区域、阶段、队列、pending / deferred 状态或等价权威状态正确落地并清理 |
| 玩家真实入口 | 正式 UI 中可见、可点、可确认、可跳过；玩家看到的文案和状态没有把入口层级讲错 |
| AI / 自动推进 | AI、watchdog、auto-continue、阶段推进或服务端恢复消费同一合法动作真相 |
| 测试与证据 | 单测、GameTestRunner、E2E、截图或日志直接覆盖当前断言，而不是只证明相邻现象 |

审计必须追到最终权威状态；`prompt / modal / pending / sourceAbilityId / 按钮可点` 只能证明流程中段，不能替代功能结果。

### 4. 判缺口类型

每个发现先分类，再决定是否阻塞当前口径：

| 分类 | 含义 | 默认处理 |
| --- | --- | --- |
| `功能实现阻塞` | 规则对象、玩家合法动作、候选生成、资源消耗、流程态、共享消费者或最终权威状态确实错误 | 修实现并补验证 |
| `语义不一致` | 实现多做、少做、错对象、错时机或把可选 / 强制 / 替代语义理解错 | 回权威描述与消费点修正 |
| `当前范围验证缺口` | 实现可能正确，但缺本范围必要证据、负向断言、真实入口或关键组合证明 | 补证据或降级口径 |
| `审计留档缺口` | 证据存在但没有被总账消费、旧结论未回写或截图目录未索引 | 回写 evidence；不得误报成功能未实现 |
| `非阻塞扩展` | 不改变当前范围规则正确性的额外排列、额外截图或更宽覆盖 | 记录为范围外扩展，不阻塞当前收口 |
| `合同未锁定` | 真相源缺失、冲突或对象归属不清 | 转入录入 / 合同裁定；不得写通过 |

### 5. 控制范围和扩审

审计默认只覆盖本轮已锁定范围。发现问题后是否扩审，取决于直接影响证据：

- 缺口位于共享消费者、共享状态字段、共享 UI 组件、共享 AI 合法动作或共享规则合同，扩到可列出的最小受影响对象集。
- 只是相似命名、同批次、同主题、同素材包，不能自动扩成整批审计；只能登记候选残余。
- 扩审前必须在 evidence 或任务记录里写清触发证据、纳入对象、排除对象和理由。

### 6. 复用代表链

代表链只能在以下事实都等价时复用：

- 触发时机等价。
- 候选生成和权限判断等价。
- 玩家真实入口等价。
- payload / command 结构等价。
- resolver / handler / reducer 消费路径等价。
- 最终权威状态和清理语义等价。

任一项不同，就只能复用较浅层证据，并把本对象剩余差异写成当前范围验证缺口或功能实现阻塞。

## 输出最低要求

审计结果或 evidence 至少包含：

- 本轮范围和不在范围内的对象。
- 权威描述或合同状态。
- 原子语义断言。
- 每条断言的实现消费点和最终权威状态。
- 玩家真实入口或说明为什么本轮不需要真实入口。
- 测试、E2E、截图、日志或人工核对证据各自证明了什么。
- 缺口分类、是否阻塞当前口径、最小补救动作。
- 旧 evidence / 旧测试 / 旧总结是否需要降级或回写。

对外口径必须和证据强度一致。只做抽样、代表链或局部对象时，不能说“全面审计完成”；只补留档时，不能说“功能已修复”；只看到入口时，不能说“玩法已收口”。
