# 共享层重构与语义回退防护

## 适用范围

修改共享工具、共享状态结构、共享 helper、共享门禁、transport、watchdog、recovery、flow、interaction 或 response-window 逻辑时，先按本文执行。这里的“共享层”按实际消费者判断，不按目录名判断。

满足任一条件即属于共享层：

- 被两个或以上游戏 / 页面消费；
- 位于共享引擎或共享基础设施；
- 会同时影响多个游戏的传输、布局、动画、交互、回合推进、恢复或测试桥。

单游戏目录内、且无其它消费者的实现，不自动升级为共享层。

## 核心不变量

- **重构默认不改功能**：用户或任务说的是重构、收口、清理、通用化、对齐或抽象时，默认保持玩家可观察行为不变。改行为必须有明确需求、规格或用户授权。
- **语义差异不能合并成默认**：输入、拒绝条件、中间态、生命周期、时序、fallback 顺序和最终可见结果只要有一项不同，就不能强行并成共享默认。
- **特化不是坏味道本身**：游戏级 / 阶段级 / 交互级 helper 如果承载真实语义，应保留、迁移或显式 adapter，不能为了统一而删除。
- **旧实现先问保护什么**：没写清旧逻辑保护的现实行为前，不得删旧分支、并 helper 或改 fallback 顺序。
- **共享不变量要单一解析**：同一运行时不变量被两个以上消费者读取时，应抽成带现实语义的 selector / helper；消费者只能读 helper 结果，不各自拆字段猜状态。

语义回退指重构后玩家可观察行为发生变化，而本次变更没有被声明为需求变化。它不是 git 回滚，也不是代码风格问题。

## 动手前四项

共享层改动前必须写清：

| 项 | 必答问题 |
| --- | --- |
| 旧语义 | 旧逻辑保护什么现实行为；哪些是共享默认，哪些是特化 |
| 消费者矩阵 | 哪些游戏 / 页面 / 服务端入口消费；每个是否走默认或 override |
| 等价性 | 输入、拒绝、中间态、fallback 顺序和最终可见结果是否等价 |
| 保护测试 | 哪些测试或真实入口锁住这些语义；缺失时先补最窄保护 |

五项等价性缺任一项，就不能宣称“可以收口到共享默认”。

## 代表验证

不要求手工测完所有游戏；要求按语义家族抽代表链：

- 至少 1 条共享默认 happy path；
- 至少 1 条特化 / override 场景；
- 至少 1 条拒绝或异常路径；
- 至少 1 条 fallback 顺序场景；
- 至少 1 条用户原始失败位点。

如果原始症状是“只坏一部分 / 只坏某个身份 / 只坏某一步”，测试也必须保留这个症状形状，不能只测全流程能走通。

## 关键门禁

| 场景 | 必须证明 | 禁止 |
| --- | --- | --- |
| helper 替换 | 旧 helper 的真实语义、新 helper 如何覆盖、代表回归测试 | 因为名字统一或调用点少就删特化 |
| fallback 顺序改写 | 旧顺序、新顺序、旧顺序保护的异常场景 | 未经证明把“先收口 A 再 B”改成“直接 B” |
| 当前操作者解析 | 真实操作者、主动回合玩家、响应者、防守者等身份边界 | 把真实操作者偷换成通用当前回合玩家 |
| 状态真相源迁移 | 玩家入口、命令、调试工具、测试夹具、AI 和外部消费者矩阵 | 保留第二套可观察状态或旧入口抢写 |
| transport / provider | 调用发起、传输接受、服务端确认、占用释放四段结果 | 把调用了发送函数当成命令已送达 |
| 旧游戏接共享能力 | 本轮兼容点、旧 UI / 流程 / 特效不变证据 | 借接入共享能力重做旧游戏表现 |
| 重构提交 | 是否改变玩家可观察行为；改变时的批准来源 | 提交写重构，实际夹带功能改动 |

## 状态迁移边界

迁移、统一、替换或删除会被 UI、调试工具、测试夹具、AI 或命令处理读取的状态时，默认同轮删除旧入口。只有真实旧客户端、混部服务、外部工具、持久化滚动迁移或无法同轮切换的证据，才允许短期 adapter。

adapter 只能转发到正式新真相源，必须写清剩余消费者、同步方向、卸载条件和删除验证。内部恢复记录、迁移标记、快照、兼容字段、调试状态和审计数据只能服务实现；没有独立规则来源时，不得暴露成玩家按钮、玩家命令或流程文案。

## 传输与恢复

命令派发接口若会影响 AI 占用、手动入口、重试或流程推进，必须明确返回“本次是否已被传输层接受”。同步中、断线、销毁或拒绝不能伪装成成功；调用方收到未送达结果后必须同轮释放占用或进入唯一恢复入口。

页面恢复、后台回前台或重新可见时，不能因为旧同步仍在进行就静默跳过恢复。必须证明旧请求会在有界时间内给权威结果、取消并重发，或发起可区分的强制刷新。

## 禁止项

- 禁止把单游戏需求提升为共享默认。
- 禁止只看改动文件、只跑一个游戏或只看公共测试通过，就宣称共享层安全。
- 禁止用一个代表游戏跑通外推所有旧游戏表现一致。
- 禁止调试面板只写旧字段，导致玩家实际看到的对象不变。
- 禁止新增内部恢复 / 回到 / 结算按钮，除非规则、已验证旧行为、已批准设计或用户明确授权要求它成为玩家动作。
- 禁止在 evidence 或汇报里把“某测试漏了”当作语义回退根因；若根因是特化语义被共享默认覆盖，必须直接写明。
