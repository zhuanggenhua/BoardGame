# UI 双端与响应式布局规范

本文件规定 PC / 移动端布局的职责分层、裁决顺序、参考视口和验收门槛。通用 UI 审美见 [`ui-ux`](ui-ux.md)，UI 改动门禁见 [`ui-change-gates`](ui-change-gates.md)。

## 基本裁决

- 默认一套 React UI 架构，通过 `manifest + runtime viewport + 终端能力探测 + layout preset` 条件化适配；不要长期维护互相漂移的桌面 / 移动双份 Board。
- PC 版是同一游戏的视觉基线。移动端继承 PC 色彩、材质、边框、按钮语气、对象层级和主要视觉关系，只因屏幕、触控、安全区和方向限制调整密度、尺寸、收纳、滚动或位置。
- 手机横屏、窄屏或触控端不是“另做移动布局”的理由。动手前必须证明 PC 同源承载在目标移动视口发生不可读、不可点、遮挡、溢出或流程无法完成。
- 移动端改造不得改写 PC 基线。共享 Board、玩家状态、手牌、主动作栏、教程层、事件 / 骰子面板或断点变更，都必须隔离移动端条件并回查 PC。
- 设备差异只能改变触发方式，例如 hover 改长按、单击改 armed 后激活；不能维护两份可用性判断或业务真值。

## 承载规则

- 能用 PC 同源承载通过尺寸、间距、安全区、滚动或触控命中区解决时，不新增 `mobile-*` 主交互承载。
- 新增移动专用承载前必须有三项证据：PC 原承载的具体失败、为什么样式调整不够、新旧承载的唯一可见关系。
- 移动端不能无声丢失 PC 一级信息。每个 PC 一级区块必须有去向：继续显示、压缩显示、贴边、滚动可达、抽屉 / 按钮可达，或证明当前阶段不需要。
- 验收先查缺失，再查重复，再查样式。只证明“无重复 UI / 能点 / 没溢出 / E2E passed”不足以判合格。
- 若 PC 原动作栏本可适配却被替换，即使移动端只剩一套按钮也不算通过；必要性未证明就是承载错误。

## 弹窗与阻塞层

- 事件牌、投骰、prompt、确认框、教程浮层、发现 / 结算面板等临时 UI，移动端默认沿用 PC 承载结构、周边玩家状态 / 手牌 / 主动作栏可见性和信息层级。
- 只有出现真实重叠、裁切、触控尺寸不足或安全区遮挡，才对弹窗本身做最小尺寸、间距、换行、滚动或局部避让。
- 隐藏常驻玩家界面对象前，必须证明它与当前弹窗发生现实遮挡，并提供等价入口或说明该阶段确实不需要。
- 弹窗验收必须用同状态 PC 基线截图或等价 DOM 证据逐项对照：承载、内容区、选项方向、结果区、确认 / 关闭、主动作、角色 / 常驻界面对象、地图 / 牌桌。

## 场景层与界面锚点

- 开放式地图 / 棋盘 / 牌桌分场景层和界面锚点层：底图、地图纹理、远景装饰属于场景层；玩家状态、轮盘、牌堆、手牌、动作按钮、关闭按钮、放大查看、阶段提示属于界面锚点层。
- 场景层可以用 `cover` 铺满并裁掉非关键边缘；玩家状态、手牌 / 法术书、计划区、主动作栏等界面对象只避让真实设备刘海、系统条或浏览器 inset，正常桌面视口按类似 Unity Canvas 的整屏九宫格 / 边缘 / 中轴锚点直接对齐。锚点只定义对齐关系，不能把设计稿尺寸、固定比例容器或自造摆放范围当成限制。
- 缩放舞台只管理棋盘内容、地图贴图、命中区和界面对象的相对关系，不承担页面背景边界。
- 固定设计画布不是页面外框。不得把 `1920x1080` 或 `designWidth/designHeight` 实现成居中小岛、最大宽高或外层裁切框。
- 手游横屏主手牌、持有物栏和主动作 dock 默认贴真实视口底边；不要用固定黑边、遮罩条或舒适留白把主内容抬高。
- 场景层与界面锚点层不能共享裁切容器。若出现轮盘露半截、关闭按钮出屏、手牌被底边吃掉，先判分层错误，再谈微调比例。

## 架构分层

| 层级 | 职责 | 禁止 |
| --- | --- | --- |
| L1 页面路由层 | 路由、页面语义、错误兜底、方向提示、环境门禁 | 承担游戏细部布局 |
| L2 页面壳层 / 运行时层 | viewport、安全区、键盘 inset、终端能力探测、根 CSS 变量 | 各页面自建 viewport 计算 |
| L3 游戏壳层 | `MobileBoardShell`、rail、dock、缩放舞台、layout preset | 承载游戏规则 |
| L4 游戏画布层 | 棋盘、卡牌、角色区、日志区、手牌区 | 读取原始 viewport 自建移动壳 |
| L5 交互适配层 | hover 替代、long press、armed、drag fallback、触控热区 | 改变业务可用性 |
| L6 原生壳边界层 | Capacitor / Android / iOS、返回桥、更新和原生包 | 泄漏到共享业务 UI |

## 视口基线

- PC 默认主参考分辨率是 `1920x1080`。它是验收视口和设计稿基线，不是页面最大宽高。
- 移动端默认主参考分辨率是 `375x812`。若用户或任务明确指定横屏分辨率，按当轮声明执行。
- 正式 E2E 验证行为，不服务某次截图取证。特定分辨率截图走独立取证路径，不为出图改写正式 E2E。
- PC 同构通过必须使用当前工作区、当前代码、同一路由、同一交互状态的 PC 基线；历史截图和旧 evidence 只能作参考。
- 开放式移动横屏验收至少包含 PC 主基线、移动横屏主状态和移动横屏关键 overlay / 放大态。

## 单位选择

- 文本、按钮、表单、日志和常驻界面对象：优先 `rem`，必要时 `clamp()`，不要用裸 `vw` 做正文字号。
- 固定构图主布局只适用于“整个可交互空间本身就是一张固定画布”的页面。开放式地图、棋盘、牌桌自由查看，或玩家状态、手牌 / 法术书、计划区、主动作栏需要贴真实视口边缘时，必须先按“场景层与界面锚点”分层处理，不得把 `16:9`、`designWidth/designHeight` 或统一缩放实现成桌面内框或 UI 摆放范围。确认适用固定画布后，才用设计画布 `px` + 外层统一等比 `scale = min(availableWidth / designWidth, availableHeight / designHeight)`。
- 壳层高度和移动可视高度：优先运行时 viewport 变量；`board-shell` 内禁止直接依赖裸 `100vh / 100dvh`。
- 局部装饰可少量用 `vw / vh`，前提是它不承担可读性和主布局稳定性。
- 触控命中区用 `px / rem` 下限。最低 `44px x 44px`，移动端优先 `48px x 48px`；小图标可以更小，但按钮盒子必须足够大。

## 验收口径

- 固定构图的 PC 响应式验收必须使用同一真实入口、同一交互状态，至少对照 `1920x1080` 基线与一个更宽但高度不同的横屏视口；除允许的留白外，牌桌、卡牌、界面对象、间距和操作区应沿同一缩放倍率变化，不能只用“未溢出 / 未重叠”判定通过。
- 移动端截图必须证明主对象可读可点、信息去向明确、无无故双份承载、PC 风格继承、PC 基线未被改坏。
- 用户看图判不合格时，先撤回通过结论，把截图放回 PC / 移动对照矩阵逐项核查；不能用 E2E 绿灯或局部 DOM 断言维持合格。
- PC 出现元素消失、样式变化、主区域尺度变化、教程位置变化或按钮漂移时，先收回移动端外溢，再继续移动端验收。
- 手机错误方向下，固定牌桌仍应可看可滚动；不得切成全屏阻断页，也不得为了截图整齐隐藏真实牌桌。
