# Home V2 移动横屏设计规范

> 适用范围：仅约束 Home V2 首页、详情页、登录/创建房间/密码弹窗在移动横屏书本界面中的实现与验收。它不是全项目通用 UI 规范。

## 真相源

- 目标稿必须优先来自 [`artifacts/home-v2-design/`](../../../artifacts/home-v2-design/)，例如：
  - `home-v2-mobile-book-catalog-target.png`
  - `home-v2-auth-modal-target.png`
  - `compare-crops/*target*`
- 外部参考图只作为用户标注问题、红框定位和风格参考；除非用户明确说“以这张为目标稿”，否则不得替代 [`artifacts/home-v2-design/`](../../../artifacts/home-v2-design/)。
- Home V2 当前只按移动横屏验收；PC 端历史通过结果不能证明移动端达标。

## 总体构图

- Home V2 是书本界面，不是普通网页面板。任何控件必须服从“书页内框、书页分割线、纸面纹理、账本表格”的视觉语法。
- 受限高度下允许压缩字号、行高和局部内容，但禁止把移动端做成另一套廉价 UI：不能把按钮缩成普通胶囊、不能把列表变成大卡片、不能让描述区消失。
- 目录和详情缩略图必须显示真实游戏视觉，不得退化成空纸面、纯人数、纯分类或重复文案。若 Home V2 参考缩略图本身只是人数/纸纹/占位图，不能覆盖游戏共享 `thumbnail`；应回退到 V1/manifest 的共享缩略图组件。`thumbnailPath` 只有在对应本地资源或服务器资源主源真实存在时才允许声明，禁止用不存在的路径让 UI 先失败再等待兜底。
- 当本轮目标是“恢复/补回”目录项、工具项、详情入口或分类入口时，不能只证明“名字重新出现了”。回归判定必须同时锁四件事：历史上它是否真的存在、历史上它出现在哪个入口/分类、点进去后是否仍能到达原页面、目录卡面是否仍保留原来的视觉承载（缩略图、图标、标签层级）。若只证实了前两三项，最多只能说“入口恢复”，不得直接说“已按历史恢复”。
- 视觉验收必须同时看目标稿、最新 E2E 截图和关键量测。断言通过但截图不达标时，以截图为准继续修。
- Home V2 的位置口令以截图观感为最终约束：像“左下”“同一排”“不要居中”“贴页码左侧”这类自然语言要求，只要最新截图看上去仍违背该要求，就视为未完成；禁止在自审未通过时先让用户代替验收。
- 总览页与详情页对“当前我的房间 / 当前对局”的语义必须一致：如果当前房间允许返回、销毁或离开，这些管理动作不能只存在于详情页或只存在于首页其中一处。禁止出现“首页只能继续、详情页才能管理”或反过来的半套入口。
- Home V2 的相对摆位词必须按锚点理解：`同一排`、`页码左侧`、`页码右侧` 指的是与页码/分页控件共用同一条水平带，而不是只要同属左下或右下区域即可。若用户同时说“左下”和“同一排”，默认解释为“位于左页底部，并与底部分页行同轴”。

## 详情页左页

- 左页必须保留四层信息：返回目录、游戏缩略图/封面、标题与标签、简介/推荐人数/教程动作。
- 移动横屏下缩略图是辅助视觉，不得挤压描述。若描述空间不足，优先缩缩略图和标签密度，不得隐藏简介。
- 简介必须有独立正文区和书页分割线语法，不能挤在标题右侧变成注脚。
- 推荐人数可以压缩为一行，但必须保留，不得因 compact 分支隐藏；若沿用 V1 语义，应使用逐个数字方块表达可玩/推荐人数，禁止退化成长条文本徽记。
- 移动横屏详情页左页底部的推荐人数默认写成一行语法：`推荐人数：数字方块`。标签与方块必须同轴、居中、单行；禁止把“推荐人数”单独占一排、数字另占一排，或把整个推荐人数组硬贴到左下角。
- 教程模式是可执行动作，不能弱到像背景说明、灰色遮罩或隐形文字链接；但也不能通过叠多层内描边、角饰、阴影来抢成第二个创建房间主按钮。默认使用一层书本动作按钮：清楚可点、单层边框、单层底色。
- 返回目录是轻量导航：可以透明、可以文字+箭头，但不能被压成无语义小图标，也不能强行画成主按钮。

## 详情页右页

- 右页大厅是账本表格，不是卡片列表。移动横屏下至少应能看到 5 行以上房间信息，行高、缩略图、状态和操作按钮都要按表格密度收敛。
- tab 是同级导航：active 态使用规则线、中央菱形、颜色或字重表达，不能把 active tab 画成标题、其它 tab 画成小链接。
- 搜索框是书页内输入线框，不是现代网页圆角搜索框；在 compact 下要薄、轻、贴合账本表头。搜索图标必须属于输入框本体并与输入框垂直居中，禁止漂在输入框外侧或像独立按钮。
- 房间状态是状态戳，不是动作按钮；不得画成可点击胶囊。加入/观战/锁定等行内动作按钮必须有书本按钮语法：深色底、金色细边、低高度、单层视觉，禁止普通胶囊按钮、纯标签，或叠多层内描边/阴影/角饰。
- 排行榜在移动横屏下不是“空白书页 + 很小数据角标”。若有排行数据，前三名必须有明确金/银/铜区分；胜场记录默认收成单行 `x/x`（例如 `12/20`）或等价的紧凑账本语法，禁止拆成两行小字后让中段留下大块无意义空白。

## 翻页实现与真实性门禁

- Home V2 目录与详情之间的主翻页真相源是当前真实首页使用的 `jQuery 1.12.0 + turn.js` 页片容器和其真实中间几何状态。主翻页实现必须复用这条职责链，不能把它替换成 `FrameSequencePlayer`、序列帧图片或把最终页静态图伪装成翻页中间态；开场书本动画、侧边 tab 出现等其他明确的序列帧动画不属于这条主翻页合同。
- 翻页中的视觉结果必须来自真实页片：书页内容、页片折叠、透视、阴影和 `turn.js` 产生的页片层级必须在同一运行时中真实渲染。为了截图而暂停进度、注入测试时钟或读取页片状态是允许的，但测试钩子只能控制取证时机，不能替换渲染本体。
- E2E 翻页证据至少要覆盖翻页前、真实中间态和翻页后；中间态必须能同时从页片 DOM/几何和整屏截图看出正在翻页。只有状态字段变化、最终页截图不同、或序列帧图片地址变化，都不能证明翻页实现成立。

## 翻页与预热

- 详情页或 tab 翻页后若目标页还依赖房间快照、榜单、日志、评价或其他加载结果，必须在翻页进行中并行预热；禁止把“开始加载”的时机拖到翻页完成事件之后，导致用户看到“翻完书还要再等几秒内容才显形”。
- 预热可以通过隐藏挂载、共享缓存、请求预发起或目标页数据 warm-up 实现，但不能改变最终页面语义，也不能为了预热额外叠一层可见假页面。

## 弹窗

- 登录、创建房间、密码浮层和危险确认浮层必须复用同一套纸面壳层、边框、角饰与排版语法；同类确认弹窗不得在 overview/detail 各自手写一版尺寸、间距和按钮样式。
- 装饰层必须可命名、可计数、不可重复堆叠；灰色框、折角、斜纹、额外分割线如果不能说明角色，默认删除。
- 创建房间内容多时，应采用同壳层内的表单密度与局部滚动，不得改成满屏大表单。
- 危险确认弹窗的正文不能复读标题或当前动作名。标题已经写了“销毁房间/离开房间”时，正文必须补充后果、范围或下一步影响，禁止再写一遍“确定要销毁房间吗”这类同义句。
- 危险确认弹窗默认按单一中轴排版：标题、说明、对象卡片、主次按钮都应围绕同一视觉中线组织。除非有明确对话式表单需求，否则对象卡片和按钮行不得右偏、贴边或各自跑到不同轴线上。
- 销毁/离开/强制退出这类危险确认浮层，虽然沿用同一纸面壳层，但主按钮必须表达“管理/危险动作”语义，不能直接复用成功态或提交流程的绿色主按钮。若当前动作是销毁房间，优先使用暖棕/深棕系按钮，并与取消按钮形成清晰主次层级。

## E2E 与截图门禁

- Home V2 移动横屏用例必须使用真实移动 context：`isMobile=true`、`hasTouch=true`、移动 UA，并以 CSS 视口而不是物理像素为准。
- 详情页 E2E 至少量测：
  - 左页缩略图尺寸、描述宽度、推荐人数是否可见；
  - 返回入口宽高与透明背景；
  - 右页 tab 基线、搜索框底线、搜索图标垂直居中、账本表头高度、房间行高、缩略图高度、操作按钮高度、可见房间行数；
  - 创建房间弹窗和密码弹窗的中心点、宽高占比、键盘/聚焦位移。
- 最终汇报提到 E2E 通过时，必须附上本轮实际复看的移动横屏截图路径。
