# 数据录入规范

本文件定义基于图片、规则书、Wiki、PDF、截图或用户素材录入业务数据时的通用合同。游戏专属字段、脚本、索引、站点和卡牌结构写到对应游戏 `rule/` 文档或专项 skill，不写进本通用规范。

项目内默认先走 [`data-entry-workflow`](../../skills/data-entry-workflow/SKILL.md)；本文件是录入质量和真相源口径。

## 核心原则

- 先建合同，后写代码。录入前必须有可回查的 Markdown 合同，不能先落运行时数据再补解释。
- **数据录入是新游戏和新增派系的第一优先级**：在规则、素材或图片已可读取时，第一批实质动作必须是建立对象全集、图片登记和规则数据录入；不得先写 Board、卡牌描述、i18n、运行时定义或机制实现，再回头补录入。
- **读取图片即触发登记，不以“是否有用”作为跳过条件**：只要实际打开、读取、OCR、裁切、抽样或从图集中定位过一张图片，就必须在图片登记表中留下记录。登记完成前不得判断它是否进入运行时、是否只是参考或是否应排除。
- **每张被读取的图片必须有最终处置**：最终处置只能是 `runtime`（进入运行时）、`reference`（只作可回查参考）、`duplicate`（与已登记对象重复）、`excluded`（经证据确认不属于本范围）或 `blocked`（无法判定）。非 `runtime` 处置必须写明依据、对应对象 / 槽位和后续影响，不能用“无用图片”一句话代替。
- 数据录入负责把主真相源完整还原成可执行合同；审计负责核对合同是否被实现正确消费，不能替录入阶段补写、猜测或改造缺失规则。
- 每个字段都必须能追溯到当前任务约定的主真相源；对照源只用于发现冲突，不自动覆盖主真相源。
- 图片、截图或扫描件清晰覆盖某字段时，图片优先于 Wiki、社区资料、旧实现和测试。
- 用户指定图包、规则书、PDF、素材目录或本地图片时，它在本轮就是主真相源；未指定的外部资料只能作对照源。
- “已录入的现有数据”（静态数据、i18n、规则文档）是无新真相源指定时的默认项目基线；如果清晰图片或用户指定来源覆盖该字段，以后者为准。
- 零猜测：读不清、对不上、来源冲突或索引无法定位时，标 `blocked / disputed / unknown-slot`，不得用相邻条目、经验、旧实现或 AI 补全。
- `blocked` 是阶段门禁，不是整轮停工口令。能继续核对其它对象、字段或来源时继续推进；只有本地证据耗尽才请求用户补源。

## 数据真相与消费边界

- 规则原文、正式图片和用户指定来源负责提供事实；完成核对并锁定的录入合同，是项目唯一可执行数据真相。任何实现、描述或验收结论都必须回到这份合同，而不是回到各自记忆、旧实现、测试快照或临时裁图。
- 卡牌名称、卡牌描述、玩家板能力文案、i18n、运行时卡牌 / 能力定义和机制实现必须消费同一份 `locked` 录入数据。它们可以是合同的生成物、索引或实现映射，但不得各自重新抄写、删减或猜测规则。
- 录入合同尚未 `locked`、存在 `partial / blocked / disputed`，或字段没有实现去向时，相关卡牌描述和运行时定义不得标记为完成；可以登记缺口，但不能用显示出来、测试通过或能进入游戏替代数据录入。
- 如果卡牌描述、i18n、运行时定义与锁定合同不一致，先判定为数据消费链不一致：以主真相源为事实、回修录入合同，再修消费方并重新审计，不得反过来修改合同迁就实现。

## 对象全集

用户要求“整包 / 整牌库 / 全部能力 / 全部流程节点 / 全部组件”时，第一步必须建立官方对象全集，而不是读取当前运行池。

对象全集至少记录：

| 字段 | 要求 |
| --- | --- |
| 官方类别与数量 | 来自主真相源，不能来自当前实现 |
| 官方对象名或槽位 | 能读名称就写名称；读不出写槽位 / 编号 |
| 素材实测数量 | 区分正面、背面、空格、非对象、复用 alias |
| 主真相源定位 | 页码、文件、图集、裁图、组件清单或用户来源 |
| 当前运行状态 | `in-runtime / not-in-runtime / duplicate-alias / unknown-slot` |
| 合同状态 | `locked / blocked / disputed / partial` |
| 缺口原因 | 缺图、缺原文、缺索引、缺实现、来源冲突等 |

每个被读取的图片还必须进入图片登记表，至少记录：

| 字段 | 要求 |
| --- | --- |
| 图片来源定位 | 原文件、图集、页码、URL、frame、裁图路径或截图时间 |
| 读取动作 | 打开、OCR、裁切、抽样、定位或其它实际读取方式 |
| 图面对象 / 槽位 | 能识别则写名称、类别、槽位和数量；不能识别则写 `unknown-slot`，不得跳过 |
| 图面数据 | 名称、数字、关键词、规则文本、顺序、视觉状态和其它可见字段；读不清要逐项标记 |
| 最终处置 | `runtime / reference / duplicate / excluded / blocked` |
| 处置依据 | 为什么进入、不进入、重复、排除或阻塞；必须能回查到规则、对象全集或图面证据 |
| 数据去向 / 影响 | 录入合同、资源路径、运行时对象、对照对象或阻塞的实现范围 |

没有对象全集时，不得说“全部 / 整体 / 全面 / complete / full audit”。

## 真相源优先级

默认优先级：

1. 用户指定的本轮主真相源。
2. 清晰覆盖当前字段的正式图片、截图、扫描件或完整单对象裁图。
3. 官方勘误、规则书、PDF、数据库、页面或 API。
4. 项目内既有规则文档、静态数据和 i18n。
5. Wiki、社区资料、论坛整理、脚本抓取结果。

补充规则：

- Wiki、搜索结果和社区资料默认不是录入真相源，除非用户明确指定某个可回访页面为准。
- 外部来源被抄成项目静态数据时，必须记录来源链接、获取日期、对象定位和采集方式；缺这些只能标“历史对照 / 待回填来源”。
- 用户故事允许覆盖真相源，但只覆盖被点名字段和场景；覆盖原因、影响范围和验收口径必须留档。

## 图片与裁图

- 先锁正式原图 / 正式图集，再按需裁到“单个对象能完整看清”的粒度。
- 物理卡牌、玩家板、提示板、地图板、事件板等对象必须先保留完整单对象图；局部放大只能辅助读字，不能替代完整图。
- 低清 contact sheet、整页缩略图、OCR 预览图和后处理核对图只能定位对象和疑点，不能直接定稿字段。
- 几何裁图、OCR 图、放大图、拼接图、归一化图都属于中间产物，默认放 `temp/**`；不得进入 `public/assets/**`、manifest 或服务器资源主源。
- 图面能直接判定区域、槽位、顺序、空格、display-only、交互性时，录入阶段必须写成可视合同；不能留给实现或审计阶段猜。
- 新对象复用旧系统、旧槽位或旧 atlas 语义时，也必须用当前图片逐槽重建合同；不得靠旧对象同名槽位外推。
- 图片即使最终处置为 `reference / duplicate / excluded / blocked`，也必须完成图面数据和处置依据登记；“判断图片没有用”只能作为登记后的结论，不能作为不登记的前提。

## 录入合同

每个对象完成录入核对后，必须标成：

- `locked`：主真相源、字段、原文、索引、裁图、对照差异和未决项都已登记，可进入实现审计。
- `blocked`：缺图、缺页、不可读、缺索引或无法定位，不能凭实现文案补规则。
- `disputed`：主真相源与对照源、旧实现或用户故事冲突，必须先裁定。

`locked` 最低字段：

| 字段 | 要求 |
| --- | --- |
| 对象标识 | `id / defId / variant / slot` 等 |
| 主真相源定位 | 路径、页码、URL、图集 frame 或裁图 |
| 原始名称与原文 | 图面 / 规则原文；摘要不能替代原文 |
| 规则定义字段 | 类型、费用、数值、资源、阵营、可见性、次数、触发、目标、索引等 |
| 原子子句 | 把复合效果拆成可审计的最小动作 |
| 图面 / 可视合同 | 槽位、区域、交互性、display-only、空位和复用关系 |
| 对照差异 | Wiki、旧实现、规则书、用户故事等差异 |
| 消费映射 | 卡牌描述、i18n、运行时定义、机制实现、测试和资源各自消费哪些锁定字段 |
| 未决项 | 无未决，或明确挂起且不进入实现 |

可视合同表至少记录 `visualRegion / slotId`、图上对象、运行时对象、允许状态、是否可交互、共享旧语义是否适用和备注。

### 录入完整性门禁

凡是一个对象同时包含“使用条件 + 资源变化 + 效果 + 次数 / 重置”中的两项或以上，必须建立逐条规则语义表，不能只写一句效果摘要。最低字段为：

| 字段 | 必须记录 |
| --- | --- |
| 使用门槛 | 需要拥有 / 达到多少资源、骰面、牌型、状态或其它条件 |
| 实际成本 | 执行时支付 / 消耗 / 弃置多少，以及何时扣除 |
| 效果结果 | 每个档位或分支实际产生的伤害、治疗、抽牌、状态、Token、阶段等结果 |
| 次数限制 | 每回合 / 每轮 / 每阶段 / 每场，以及限制作用于单个效果还是整组效果 |
| 重置边界 | 次数何时恢复，取消、失败或回滚是否恢复 |
| 累计与档位 | 高阈值是否同时解锁低阈值；一次执行后剩余资源如何影响其它档位 |
| 选择与目标 | 玩家是否选择效果、对象、数量、顺序或是否执行 |
| 负向路径 | 条件不满足时不可执行、可见但禁用、隐藏或自动跳过的规则依据 |

规则原文写出“拥有 N 个即可使用”“花费 N 个”“每回合每个效果一次”等限定时，以上字段必须逐项填入原文、结构化值和实现去向。`未写成本`、`未写次数`只能在已经检查完整主真相源后明确登记为“原文未声明”，不能由缺失字段、旧实现或相邻对象推导。

只有每个规则字段都有主真相源定位、原文摘录或图面定位、结构化值和去向，且无冲突 / 未决项，才允许标记 `locked`。缺任何一项必须是 `partial`、`blocked` 或 `disputed`，不得进入实现或审计通过口径。

## 标准流程

1. 锁定主真相源和对照源，记录来源、版本、获取时间和适用字段。
2. 立刻建立图片登记表；所有实际读取过的图片先登记，再判断运行时用途、重复关系、排除理由或阻塞原因。
3. 若是整包范围，先建对象全集和规则-素材数量对账。
4. 从正式来源裁出完整单对象图和必要局部图，登记路径、坐标、hash 和可读性；新产生或实际读取的裁图也必须回填图片登记表。
5. 建 Markdown 核对合同：原文、结构化字段、可视合同、对照差异、图片最终处置、状态。
6. 全口径核对名称、类型、数值、关键词、限定词、使用门槛、实际成本、目标、范围、时机、次数、重置、累计档位、例外、图片索引和资源路径。
7. 映射字段去向：静态数据、卡牌描述、i18n、规则文档、资源注册 / atlas、运行时定义、机制实现、测试或后续实现依据。
8. 同步对应游戏 `rule/` 文档、i18n、资源索引或配置说明；同步内容必须能回指锁定录入字段。
9. 只有本批次要实现的对象均为 `locked`，所有已读取图片均有最终处置和依据，且消费映射完整，才进入代码实现；`blocked / disputed` 只能登记缺口，不能猜补。

## 实现与续跑

- 进入实现后，`locked` 合同是实现审计的结构化入口，但不高于其主真相源；发现原文与合同冲突时，主真相源优先，先回录入层作废 / 修正合同，再继续实现审计。
- 实现错误直接修实现并补测试；合同缺字段或来源冲突才退回录入层。
- 已有 `locked` 合同和实现对照矩阵时，续跑应从 `proof-needed / suspected-gap / match-with-proof` 等实现审计状态继续；不得无故重新 OCR 或重录。
- 若用户反馈“卡图不对 / 效果不一致 / 怀疑录入错误 / 怀疑索引用错”，先打开当前对象主真相源图片逐项对照，再判断错在录入、索引还是运行时消费链。
- 若反馈描述已经与当前录入口径一致，而问题发生在 UI、命令校验、结算或状态消费链上，按实现 bug 修复，不要用“重新看图”拖住。

## 复合对象

- 同一张物理对象里出现多个标题、子区、分支、副标题或相关技能名时，先判断它是一个对象的 variants / 子效果，还是多个独立运行时对象。
- 结论未锁定前，不得新增多个运行时 `id`、多个 `previewRef.index`、多个 atlas frame，或把一张图硬拆成多张对象。
- 若同系统已有成熟复合语义实现，先对照它的 variants、共享 handler、升级 / 替换链和测试合同，再决定结构。
- E2E 和截图只能证明当前实现表现，不能反向证明素材语义正确；素材语义未裁定时，测试结果只能作现象记录。

## 资源收口

录入新增、替换或移动运行时会访问的资源时，交付前必须完成：

- manifest 重建或校验。
- 服务器资源主源发布，或明确说明该对象只随包内索引交付。
- 代表性公开 URL、包内 file-index / manifest 或远端对象 hash 回查。

无法发布时，最终汇报必须写清未发布对象、原因和现实影响。只改本地资源、不上传、不回查，不能说线上、手机或资源包已修好。

## 禁止项

- 根据英文原版猜中文，或根据上下文补完整句子。
- 根据相邻条目、运行顺序、旧测试、旧 evidence 或当前运行池推断官方全集。
- 未打开主真相源图片，就裁定“不是录入错误 / 不是索引用错”。
- 用半张卡、局部放大图、缩略图或后处理图直接决定整张对象结构。
- 先录进去、先写代码、先跑 E2E，再把核对合同当补充说明。
- 把某个游戏的爬虫、字段命名、索引结构或脚本升级成项目通用默认。

## 专项归属

- 游戏专属爬虫、字段结构、atlas 口径、脚本命令和旧实现对照写到该游戏 `rule/` 文档或专项 skill。
- 本文件只保留通用录入门槛、真相源优先级、合同字段、零猜测和进入实现的门槛。
