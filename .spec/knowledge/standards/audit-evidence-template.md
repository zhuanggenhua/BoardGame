### 2.0 缺口分类与范围裁定（强制）

所有 finding、待补项、残余范围和“还差什么”必须先落到下表，禁止直接把缺口写成笼统的“未完成”：

| 条目 | 分类 | 是否阻塞当前规则实现 | 是否阻塞已审计/已收口口径 | 当前范围裁定 | 后续入口 |
| --- | --- | --- | --- | --- | --- |
| 示例：某卡主效果未结算 | `功能实现阻塞` | 是 | 是 | 当前范围内 | 修实现 + 补 L2/L3 |
| 示例：截图目录缺说明 | `审计留档缺口` | 否 | 可能 | 当前范围内 | 回写总账 |
| 示例：额外房间×额外状态排列 | `非阻塞扩展` | 否 | 否，若已裁定范围外 | 当前范围外 | 后续扩展清单 |

分类口径：

- `功能实现阻塞`：规则对象、玩家合法动作、候选生成、资源消耗、流程态、共享消费者或最终权威状态不正确。
- `当前范围验证缺口`：实现可能已正确，但缺本范围必要证据、负向断言、关键组合证明或真实入口截图。
- `审计留档缺口`：证据存在但没有被审计总账消费、旧结论未回写、截图目录未索引。
- `非阻塞扩展`：不改变当前发布范围规则正确性的额外组合、额外截图或更宽覆盖；必须写清为什么不影响当前范围。

### 2.1 对象级完成门禁（默认强制）

若标题、任务名或对外汇报中使用“审计 / 全面审计 / 深入审计 / 收口审计 / 做到底”，则本文档默认必须满足：

- 当前范围内每个对象都有独立审计行，不能只写“派系 A / 模块 B 总评”；
- 每个对象都拆出规则子句 `C1/C2/C3...`，逐项写清实现入口与证据；
- 每个对象都给出 `L0/L1/L2/L3/L4` 当前层级或阻塞原因；
- 只有“共享链路完全同构，仅配置不同”的对象，才允许复用代表链；
- `共享链路 / 复用依据` 不允许只填 `shared`、`同构`、`同 helper` 或“已覆盖”；必须写清 `共享链名称 / 代表对象 / 六项判等依据 / 本对象剩余差异`，缺任一项时结论只能写 `representative_only` 或 `仍有残余范围`；
- 若当前范围内仍有阻塞性对象级 L3/L4 缺口，结论只能写 `代表性玩法已验证` 或 `仍有残余范围`，不得写 `当前发布口径已收口`。若某 L3/L4 候选只是额外排列或当前范围外扩展，必须先在 2.0 表裁定为 `非阻塞扩展`，不能留在对象级缺口里。

### 2.2 全面审计自检表（声称已收口时强制）

若结论或对外汇报要使用 `已审计 / 已收口 / 当前发布口径已收口 / 当前代码验证口径已收口 / 全面审计完成`，必须在 evidence 前部补本表，并在审计完成后运行 `npm run audit:evidence:selfcheck -- <本 evidence 文件>` 自检通过。该自检不默认接入发布阻断。

| 自检项 | 状态 | 证据 |
| --- | --- | --- |
| 对象全集 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 规则子句表 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 完整技能流程矩阵 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| L0-L4 证据层级 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 命中 D 维度 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 关键组合矩阵 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 真实入口 E2E 与截图核验 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 测试语义对账 / 旧测试失效检查 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 同类扩审记录 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 缺口分类与范围裁定 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 残余范围声明 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |
| 旧 evidence / 旧结论对账回写 | `passed` / `representative_only` / `blocked` / `scoped_debt` |  |

强制口径：

- 只有所有必需项都是 `passed`，才允许使用已审计/已收口口径。
- `representative_only` 表示只做了代表链或抽样验证，必须降级为 `代表性玩法已验证`。
- `blocked` 或 `scoped_debt` 表示仍有残余范围，必须写清剩余对象、缺口与下一步。
- `非阻塞扩展` 不能写在自检表里当 `scoped_debt` 后再继续声称已收口；必须先移到“当前范围外 / 后续扩展”清单，并写明它不改变当前规则正确性，相关自检项才可按当前范围写 `passed`。
### 2.3 继续任务、防重复与范围升级门禁（rollup / full-audit 强制）

P1/P2 不是“不审”。任何条目进入 P1/P2 或可回顾残余池前，必须已经完成 P0 实现正确性筛查，并在表内或相邻正文写明证据入口；未经 P0 筛查的对象不得降级入池，只能留在 P0 候选、未审对象清单或数据/合同阻塞中。

执行范围规则：

- 共享缺口只扩到能由共享消费者证据直接命中的对象；单对象录入、素材或显示异常默认不扩审兄弟对象。
- 扩审前必须先回写范围表；范围表没有“触发证据、受影响对象、排除对象及理由”，不得生成新的测试或截图队列。
- 若当前范围已闭环且没有升级触发，后续动作只能消费已有证据，不能重新人工复核同一事实。

证据集中规则：审计留档默认落在当前专项审计文档、full-audit 总账或运行态审计真相源；E2E 截图目录通常只作为原始产物目录被上级文档引用。只有截图目录本身是独立交付物、没有上级审计文档承接，或用户明确要求单独证据包时，才新增目录级 `e2e-test.md` / README。目录级说明缺失只能记为审计留档缺口，不能直接推导为功能未实现或 E2E 未执行。

### 2.4 行为闭环总账（数据录入 / UI 证据默认强制）

当任务目标包含数据录入、图集 intake、规则实现、真实入口 E2E 或 UI 截图证据时，必须先把每类行为登记到下表。下表是行为级唯一主表，后续章节只能引用它，不能再创建第二套行为队列：

| 行为 | 唯一责任入口 | 主完成证据 | 执行到位判定 | 未闭环最小补救 | 禁止重复路径 |
| --- | --- | --- | --- | --- | --- |
| 素材 / 图集录入 | 资源合同、图集 frame、manifest、previewRef、hash / 尺寸 / 数量对账 | 合同校验结果 + 对象数/索引/运行时引用对账 | 资源合同一次通过，或明确记录 `blocked/disputed` 字段 | 回资源合同补缺失 frame、manifest 或引用 | 不得用 E2E 截图或肉眼复看截图反向证明图集录入正确 |
| 规则 / 数据录入 | 规则子句矩阵、领域测试、最终权威状态断言 | 子句到 handler / resolver 的映射 + 正负状态测试 | 每个对象的规则子句、执行入口和最终状态均有记录 | 回规则合同或领域执行层补缺失子句/状态 | 不得把“截图看起来对”当规则实现证据 |
| 玩家交互链 | 真实入口 E2E、手动选择断言、最终状态 / 队列清理 | 真实入口操作链 + 最终状态/队列收口断言 | 需要选择时，即使只有一个候选也有可见、可点击的手动入口 | 回真实入口或候选生成修复 | 不得靠自动选择、注入型 interaction 或旧截图冒充真实入口 |
| UI 布局证据 | 代表性真实整屏压力态截图 | 当前真实入口整屏图 + 人工图面结论 | 新 UI 与原版布局竞争元素同屏可见，且不遮挡、不重复、不误导 | 回布局实现或当前真实截图状态重拍 | 不得把每张卡都变成独立人工审图任务 |
| 截图干净度 | 统一截图夹具 / helper | 干净截图 + 截图前置断言 | 调试面板、特效、toast、悬停层均按夹具规则退出 | 回统一夹具/等待点修复后重跑受影响链 | 不得发现脏图后逐张手工补图 |
| Evidence 回写 | 单一总账 / rollup 入口 | 唯一证据路径 + 结论回写 | 同一命令、截图、结论只登记一次且能被后续消费 | 回总账补索引或降级旧结论 | 不得在 temp、summary、旧 evidence 之间复制同一事实后让“继续”重新接管 |

执行规则：

- 开始审计前必须先声明本轮主目标属于哪类入口：`素材/图集录入`、`规则/数据录入`、`真实入口交互`、`UI 布局证据` 或 `总账收口`。多类并存时按依赖顺序执行，但不得互相替代；每类行为只能在 2.4 总账登记一次。
- 数据录入类任务默认以合同和自动化验证为主；截图只证明运行时消费和 UI 没被破坏，不能扩大成逐卡肉眼复核。
- 截图证据失败时，第一动作是修截图夹具或真实入口等待点；只有证明确实是单一对象资源/渲染问题，才回到素材或 UI 实现。
- 若某步骤已经有权威通过证据，后续“继续”只能消费该证据，不得重启同类人工审查；除非出现新证据冲突、用户点名该对象、或真相源版本改变。
- 对外汇报必须区分“数据/规则已验证”“代表 UI 已验收”“逐对象 UI 仍未覆盖”；不得把 UI 代表性抽查写成数据录入未完成，也不得把数据合同通过写成 UI 全面验收。

### 2.5 行为闭环与重复动作裁定（继续任务强制）

当用户质疑“为什么又看一遍 / 为什么又审一遍 / 是否重复流程 / 是否没执行到位”，或任务处于“继续”阶段时，先回到 2.4 总账裁定每个行为是否已经闭环。禁止把交接摘要、临时清单、截图目录或旧 evidence 当成新的默认任务队列。

闭环裁定规则：

- 一个行为只能有一个责任入口和一个主完成证据；其它证据只能作为消费验证或回归验证，不得重新承担同一主证明职责。
- 已经闭环的行为进入“证据消费”状态，后续只能引用其证据路径和结论；不得因为继续任务、截图失败、上下文摘要变化而重启同类人工复核。
- 未闭环时必须写清 2.4 总账中缺的是“源数据 / 合同校验 / 领域状态 / 真实入口 / UI 布局 / evidence 登记”哪一层；补救动作只能回该层唯一入口执行，并更新同一行，不得新增同义行为。
- 如果同一失败被反复处理两次以上，第三次前必须先重构流程：找出重复动作的共同源头，修 helper、合同、索引或等待点；不得继续生成更多人工待办。
- 截图只能证明 UI 消费和布局，不得承担素材、规则或数据录入的主验收；领域测试只能证明状态和规则，不得冒充玩家真实入口存在。
- 对外收口时必须明确“本次新完成的行为”和“只是消费已有证据的行为”；不得把历史已完成事项包装成本轮新成果。

## 5. 逐项结论

每个对象至少一条，禁止只写总评。推荐表头：

| 对象 | 规则子句 | 实现入口 | 共享链路 / 复用依据 | 命中维度 | 证据层级 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 示例 | `C1 打出时` `C2 选择 1 个基地并移动` | `src/...` | `shared-move-base / 与 foo 同 handler，同 skip 路径，仅筛选参数不同` | `D1 D5 D8` | `L1/L2/L3` | `代表性玩法已验证` |

补充要求：

- `规则子句` 不能只写对象摘要，必须覆盖时机、主效果、替代入口、额外触发、例外/否则、once/turn、清理。
- `共享链路 / 复用依据` 为空时，表示该对象未复用代表链；若复用，必须写清共享链名称、代表对象、触发时机 / 候选生成 / 交互入口 / payload 字段 / resolver 或 handler / 最终权威状态六项判等依据，以及剩余差异。
- 任一对象缺独立行，即视为未审。
- 若对象行写 `可玩 handler + 测试`、`定向测试覆盖`、`测试覆盖` 或等价口径，必须补“测试语义对账”：测试到底断言了哪些最终权威状态、哪些玩家选择/可选/数量边界、哪些负向路径；若旧测试断言了错误语义，必须在本节或修订记录里标成旧测试失效，不能继续把它当正向证据。

### 5.0 语义门禁快照（高风险对象默认强制）

凡对象涉及 Token、状态、伤害修正、响应窗口、阶段触发、自动移除、候选生成或“看起来像资源/看起来像被动”的语义边界时，每个对象至少补下表一行：

| 对象 | 承接语义 | 触发时机 | 效果宿主 | 作用范围 | 触发后清理 | 不应发生什么 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 示例 | `被动自动触发` | `造成攻击伤害时` | `攻击者自己` | `仅攻击伤害` | `自动移除全部层数` | `不应打开主动响应窗；不应作用于 direct damage` | `通过` |

填写要求：

- `承接语义` 必须从真实语义出发填写，例如 `主动响应/主动消耗`、`被动自动触发`、`阶段触发`、`持续生效`、`纯展示位`。
- `效果宿主` 必须写清状态/Token 挂在哪一侧，而不是只写“对手/自己”这种结果语义。
- `作用范围` 不能省略 `攻击/直接/本回合/下一次/本阶段/仅命中后` 这类限制。
- `触发后清理` 必须写清是自动扣层、自动移除、持续保留、还是延后到某阶段统一清理。
- `不应发生什么` 至少写 1 条负向断言，防止把对象误实现成另一种语义。

### 5.0.1 窗口与来源归属快照（共享链 / 提示窗 / 奖励骰 / 响应对象默认强制）

凡对象复用了共享提示窗、共享奖励骰、共享响应链、共享清理链、shared helper，或用户反馈集中在“时机不对 / 看起来像绑到了别的资源 / 审计没看出来”时，每个高风险对象至少补下表一行：

| 对象 | 玩家看到的入口/提示 | 真实结算窗口 | 来源归属 | 共享消费者 | 易混淆对象 | 负向断言 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 示例 | `攻击修正提示 + 右侧奖励骰骰盘` | `攻击掷骰结束后，防御前` | `来源于技能自身，不依赖兄弟 Token` | `shared-bonus-reroll` | `另一个也会进入同类奖励骰结算的 Token` | `防御后不应再打开；缺少该来源时不应继续生效` | `通过` |

填写要求：

- `玩家看到的入口/提示` 写的是玩家主观感知到的 UI 壳层，例如横幅、提示条、右侧奖励骰骰盘、响应窗、simple-choice。
- `真实结算窗口` 必须落到规则阶段，不能只写“点了之后”或“弹窗时”；推荐写成 `攻击掷骰结束后 / 防御前 / 防御后 / 造成伤害后 / 回合结束时` 这类口径。
- `来源归属` 必须写清这次效果到底由哪个对象授予、由谁持有、由谁消耗或清理；禁止只写“可以重掷/可以加伤”这种结果语义。
- `共享消费者` 用来登记真正吃这次效果的共享链路、helper、resolver、continuation 或 finalize 消费点；若无共享链可写 `无`。
- `易混淆对象` 至少写 1 个最容易和它串语义的兄弟对象/共享对象；没有候选时写 `无明显混淆对象`。
- `负向断言` 至少覆盖一种“窗口错位”或“来源串绑”风险，例如“防御后不应再出现”“没有该来源时不应生效”“不应借另一个对象的共享链继续结算”。

### 6.2 生产反馈收口证据分层（生产反馈默认强制）

若本文档对应的是**线上/生产反馈**，则必须把以下状态分层写清，禁止混成一句“已修好”：

1. `本地已修`
   - 代码/测试/evidence 已覆盖本地根因。
2. `已推送`
   - 对应 commit 已进入远端分支，给出 commit SHA / push 证据。
3. `已部署`
   - 生产容器或生产 bundle 已跑到目标 revision，给出 deployed revision / health check / 访问探活证据。
4. `已回写状态`
   - 生产 `feedbacks` 文档或管理后台状态已从 `open/in_progress` 改为 `resolved/closed`，给出回写前后证据。

强制口径：

- `已回写状态` 和 `已部署` 是两条**并列状态轴**，不是前后置门禁关系。
- 只要该反馈已经有“根因定位 + 修复 + 验证 + evidence”，就应立刻回写 `resolved/closed`；`已部署` 只能影响“发布状态是否完成”的口径，**不能**成为回写前提。
- 若此时尚未部署，正确写法是：`反馈状态已回写，部署状态未完成/未核对`；禁止写成“因为还没部署，所以暂不回写”。

最低要求：

- 若只有 `本地已修`，结论最多写 `本地验收完成`，不得写 `线上已收口`。
- 若已部署但未回写状态，必须明确写 `代码已上线，但反馈状态仍未回写`。
- `已回写状态` 是独立门禁，不能被 `已推送`、`已部署` 或“用户口头说应该好了”替代；没有回写前，禁止对外汇报为 `已闭环`。但**一旦**满足“修复 + 验证 + evidence”，就应立即补上这道回写，而不是继续等待部署。
- 若回写状态依赖用户授权或人工操作，必须在“当前边界”里单列，禁止把缺少回写证据的条目写成已闭环。
- 对外汇报时，至少给出：目标 commit / 生产 revision / health check / 当前反馈状态 这四项中的实际证据。
