# 引擎伤害计算管线

本文定义 `engine/primitives/damageCalculation.ts` 的项目使用合同。具体函数签名、迁移入口和代码样例见 [`damage-calculation-pipeline-migration-guide`](../../../docs/refactor/damage-calculation-pipeline-migration-guide.md) 与源码。

## 目标

新游戏涉及伤害、生命值、护盾、防止、减伤或等价数值扣减机制时，必须通过伤害管线生成伤害事件，禁止手写正式 `DAMAGE_DEALT` 作为主路径。旧游戏可兼容历史格式，但触碰伤害、生命值、护盾、防止、日志或动画消费时，必须判断是否迁到本文合同。

伤害管线承担四件事：

- 从规则输入生成统一伤害计算；
- 收集 Token、状态、护盾、攻击上下文和手动修正；
- 产出可解释的 breakdown；
- 为 reducer、行动日志、动画、AI 和玩家摘要提供同一份正式数值来源。

## 职责归位

| 层 | 职责 | 不允许 |
| --- | --- | --- |
| 游戏规则层 | 提供伤害来源、目标、基础值、攻击上下文和必要手动修正 | 让引擎直接读取私有攻击账本 |
| 伤害管线 | 统一计算、排序修正、生成 `DAMAGE_DEALT` 和 breakdown | 自行决定游戏专属触发或跳过 reducer |
| reducer | 写入正式 HP / 队伍 HP，并回填正式净掉血 | 让动画、日志或摘要反向计算 HP |
| ActionLog / UI / AI | 读取 reducer 已提交事件和正式净掉血 | 用技能估算、骰面、hover 文案或动画值推导最终伤害 |

## 计算合同

- `amount` 表示进入扣血处理的伤害输入。
- `actualDamage` 表示 reducer 结算后的正式净掉血；护盾、防止、闪避、无敌、HP 下限钳制和队伍共享 HP 同步都必须已经处理完。
- reducer 是正式生命值的唯一写入口；表现层只能读正式结果。
- 伤害不得为负；需要减免到 0 时，由管线或 reducer 按合同钳制。
- 致死替代、防止死亡、保留生命或消耗保命资源必须在正式扣血入口保留不变量，不能只在事件构造阶段保护。

## 修正来源

伤害修正只能来自明确合同：

- Token / 状态定义中的伤害加减字段；
- 护盾或等价防护账本；
- 游戏层投影出的攻击上下文；
- 本次事件链中尚未写入 state、但已由规则确认的手动修正；
- 迁移期旧 `modifiers`，只作兼容输入。

如果本次规则先授予资源再造成伤害，而 state 还没正式写入，必须显式传入本次链路的手动修正，并关闭会读取旧 state 的自动收集项。

## Breakdown 和日志

每个玩家可见伤害都应能解释：基础值是什么、每步修正来自哪里、应用后累计值是多少。ActionLog 优先读取 breakdown；旧 modifiers 只能作为兼容降级。

伤害来源标注的 UI 展示规则见 [`engine-action-log.md`](engine-action-log.md)。伤害来源解析器只负责把 source id 映射成玩家可读标签，不得重新计算伤害。

## 事件输出与副作用

伤害管线可能同时产出正式伤害事件和副作用事件，例如状态移除、Token 消耗、自定义防止伤害或反伤。调用方必须先判断这次输出是不是正式结算路径：

- 正式扣血、攻击结算、回合维持伤害、奖励骰结算和 custom action 中要落到玩家结果的伤害，必须把副作用事件与 `DAMAGE_DEALT` 一起送入事件流。
- 只做估算、门槛判断、AI 评分、展示预览或不会写入正式状态的计算，不得把副作用事件送入事件流。
- 引擎层 `toEvents()` 默认只返回 `DAMAGE_DEALT` 以保持兼容；游戏正式结算入口若使用该输出，必须显式请求携带副作用。
- 终极伤害、直接伤害、防御反击等伤害类型必须由游戏层传入明确上下文；不能靠默认伤害事件让状态或 Token 自己猜它是不是攻击伤害。

## 迁移边界

- 新游戏直接使用伤害管线，不新增手写伤害事件主链。
- 旧游戏手写事件可短期保留，但不得绕过 reducer 的正式净掉血合同。
- adapter 只能把旧输入投影到管线合同，不能继续成为第二套伤害真相源。
- 具体游戏迁移状态不写进本标准；放到任务、evidence 或对应专项 workflow。

## 禁止项

- 禁止 UI、行动日志、AI 或动画按护盾消耗、技能预估、骰面、custom action 或展示值二次推导最终伤害。
- 禁止为某个游戏的 `pending*`、combat session 或卡牌专属账本在引擎层开私有读取分支。
- 禁止用日志显示正确替代正式 HP / `actualDamage` 验收。
- 禁止用防御性兜底吞掉内部不变量破坏；伤害链不完整时应暴露错误来源。
- 禁止把 custom action 动态估算结果喂给正式 HP 结算、玩家正式摘要或响应窗口当前伤害账本；它只能服务规则门槛或 AI 评分等估算场景。

## 验收

- 单元测试覆盖伤害管线主合同：`src/engine/primitives/__tests__/damageCalculation.test.ts`。
- 改动某个游戏时，补该游戏的窄集成测试或真实入口 E2E，证明正式 HP、`actualDamage`、日志、动画数值和 AI 消费来自同一正式结果。
