# UI 动画设计规范

本文件只规定 UI 动画的触发方式、直接操控生命周期和结果揭示身份。FX 技术选型、粒子、Shader、冲击帧和视觉质量见 [`animation-effects`](animation-effects.md)。

## 核心原则

- 涉及命令验证、服务端确认、随机结果、规则结算或乐观回滚的动画，必须由数据 / 状态变化驱动，不能在 `onClick` 里先播放。
- 纯 UI 行为，例如展开、折叠、标签切换、hover，可以由事件直接触发，但仍要有清理和可访问状态。
- 规则层同步完成结算，表现层只控制可见节奏；动画不写正式状态。
- 若验证失败、乐观预测回滚或阶段切换，过渡层必须清理，不能留下“画面已经成功但业务没成功”的错觉。

## 玩法因果动效

技能、攻击、治疗、召唤、移动、附着、摧毁和结果奖励等动画，画面必须回答四件事：

| 阶段 | 玩家要看懂什么 |
| --- | --- |
| `source-wake` | 谁发动 / 谁出手 |
| `travel` | 效果从哪里到哪里；无单体目标时展示范围 |
| `impact / resolve` | 什么时候命中，目标发生什么变化 |
| `settle` | 效果结束，界面可以继续操作 |

规则状态可以先结算，但伤害、治疗、token、资源、附着、离场等可见变化应在 `impact / resolve` 阶段释放。只靠日志、toast、说明面板、标题或按钮名解释因果链，判不达标。

## 表现边界

- 来源对象和目标对象优先。真实对象可见时，动画应作用在对象本体、快照层、轨迹或命中区上。
- 文字只作辅助，可写对象名、数字和短状态；不要把规则解释或验收说明放进动画层。
- 结果符号属于命中帧或最终状态，不承担飞行路径。路径使用投射物、能量束、粒子、卡牌残影或对象移动。
- 销毁 / 离场要由目标本体变化表达，例如碎裂、分离、淡出或离场；不要用线条、叉号或骷髅替代目标结果。
- 同一对象进入运动层时，源层必须隐藏、占位或交给同一快照层接管；禁止“原地本体 + 飞行投影”双身。
- 特效颜色来自参考动态证据或项目语义色；没有依据时用项目语义色，不凭感觉选高饱和随机色。

## 直接操控

拖拽、长按、滑动、投放、飞行转移和对象移动必须先定义生命周期 owner：

- 开始、持续移动、命中高亮、取消、松手、退场分别由谁接管。
- 源对象隐藏或重渲染后，后续 `pointermove` / 松手链路不能继续依赖源元素。
- ghost 与源对象职责互斥：源对象负责占位和归属，ghost 负责当前运动；不得双显。
- 多对象 / 多人并发动效必须有独立实例身份，一个实例完成只能清理自己。
- 验收必须覆盖启动、中途持续、指针离开源对象后仍响应、松手 / 取消清理和最终结果。

## 结果揭示

投骰、重掷、翻牌、抽牌、亮出事件和阻塞式结算属于结果揭示交互，不是背景状态刷新。只要结果发生，UI 必须给出可感知承载；除非同语义的更高优先级前台已经完整接管。

结果动画必须区分：

- **结果状态**：最后展示什么，例如点数、牌面、数量。
- **事件身份**：这是第几次揭示 / 哪次重掷 / 哪个 EventStream entry。

以下情况必须使用独立事件身份，不能只监听结果值变化：

- 新事件可能与上一次结果相同。
- 组件不会因新事件自动卸载重挂载。
- 玩家看到的是一次性揭示过程，而不是稳定状态展示。
- 重掷或改骰可能只改变其中一部分骰子，甚至新旧点数相同。

优先使用领域事件 ID、EventStream entry id、结算序号或重掷 key；最后才允许在展示聚合层生成局部 `presentationKey` / `nonce`。业务状态里不得为了动画保存纯表现字段。

## 触发与清理

- 数据驱动动画监听权威状态字段、事件 ID 或 presentation key；点击处理只发送命令。
- 阶段切换、路由切换、Undo、取消、失败回滚和新结算开始时，清理旧动画状态。
- 需要完整播放的动画可设置最短播放时间，但不能用固定 timer 代替组件 `onComplete`。
- 连环效果必须用队列、时间线或 FX sequence，包含 `effectId`、来源快照、目标快照、阶段和完成回调；不要用单个 `activeKey` 抢占全部效果。

## 验收

- 过程动画至少检查 source / travel / impact / end 四段；同格效果可以没有 travel，但必须有来源唤醒、命中 / 结果和收口。
- 翻页、翻卡、折叠和转场必须有真实运行时来源态、过渡态、目标态；不能用截图拼接或点击前后两张图冒充动画。
- 重掷/改骰必须有可见的独立过程态：被介入对象要从旧结果进入运动、翻转、闪烁或等价变化，再落到新结果；只更新数字、日志或最终静态骰盘，不算重掷动画通过。
- 过程帧必须在正常观看尺寸下可读。只有 DOM 节点、弱像素、测试字段或口头解释，不算视觉通过。
- 用户反馈“只有结果没有过程”“第二次同结果不动”“看不出谁打谁”时，先查事件身份、来源 / 目标快照和生命周期 owner，再调时长或样式。
