# 关键图片预加载规范

## 目标

关键图片预加载用于避免进入对局时白屏、闪烁、首帧错图或图片占位长期可见。新增游戏、新增可玩对象、修改 Board 图片资源或排查图片加载慢时，必须按本文裁定 `critical` / `warm` 分层。

## 分层合同

| 分层 | 含义 | 资源类型 |
| --- | --- | --- |
| `critical` | 首屏立即可见，加载完成前可阻塞渲染 | 背景、地图 / 牌桌、玩家面板、首屏卡背、已选对象主图、当前阶段必要图集 |
| `warm` | 当前不阻塞，但后续很可能打开或切换到 | 未选对象、非首屏图集、按需弹窗、后续阶段资源 |

门禁落在 `MatchRoom` / `CriticalImageGate` 入口层；各游戏通过 `criticalImageResolver.ts` 提供动态解析。路径相对 `/assets/`，不手写 `compressed/`，由加载器解析压缩资源和 manifest 远端条目。

## 强制规则

- 有素材不等于已接好加载链；只要 Board、设置弹窗、持有区、卡牌网格、帮助面板或结算区会消费图片，就必须进入 resolver 的 `critical` 或 `warm`。
- 用户反馈“某张图 / 某类图加载慢”时，先锁定真实玩家视角、资源类别、请求路径和加载状态；没有证据不得把其它资源提升到 `critical` 冒充修复。
- `phaseKey` 必须稳定，且只在阶段、已选对象、语言或关键资源集合实际变化时改变。
- locale 必须从 Board / match props 进入预加载和图集初始化链；语言相关图集不得只在模块顶层写死一次。
- `OptimizedImage` 的占位不能随手关闭；只有图片已在首屏前必定加载完成，或该位置有稳定骨架 / 明确空态，才允许关闭占位。

## 教程模式

教程 setup 阶段如果用户看不到选角 / 选派系界面，resolver 只返回用户会看到的通用资源，不预加载全量可选对象。进入 playing 阶段后，只加载教程实际选中的对象和共享图集；未选对象不得因为“可选全集”进入 critical。

## 图集初始化

- 均匀网格优先走懒注册，由已预加载图片尺寸推导格子尺寸。
- 不规则图集使用静态 config，构建时内联。
- 图集注册必须在首帧渲染前可用；禁止在 `useEffect` 中异步注册首屏必需图集。
- 依赖 locale 的图集必须在语言变化时重新注册或刷新路径。

## 音频协同

音频预加载应等待关键图片信号完成后再空闲分批启动，避免图片和音频同时抢首屏网络。取消 warm 队列时，未完成路径必须保留到下一次 warm 预加载，不得丢失。

## 验收

- 新增或修改 resolver 时，测试必须证明 `critical` / `warm` 路径不含 `compressed/`，且能解析到本地压缩文件、图集配置或 manifest 远端条目。
- 真实房间页必须证明对应阶段的关键资源进入加载链；只证明文件存在、压缩完成或 manifest 有条目不算运行时接入。
- 新增可玩对象时，至少核对选择阶段预览、游戏阶段完整资源、教程 setup 裁剪、locale 路径和占位关闭证据。
