# 目标、范围与对话接续

> 适用：开工或排查时确定问题范围、上下文压缩后继续、读取交接摘要、用户说“继续”、读取 `task_plan.md` / `progress.md` / `findings.md` / `temp/**` / evidence 清单，发现上个模型总结和用户当前主线不一致，或需要判断用户当轮话语是陈述、流程问题还是验收不合格。

## 核心不变量

- 用户最近明确表达的当前目标，是接续时的第一真相源。
- 交接摘要、压缩摘要、长期计划、临时覆盖矩阵和工具状态只提供候选线索，不自动授权继续其中任何一项。
- 任何不确定都先停在“目标未锁定”：只能继续读证据、核入口、核用户原话或问最小问题；不得先改代码、测试、规范、数据、发布配置或交付物。
- 用户当轮话语先分类再动作。陈述 / 观察不是 bug，也不是画面不合格。

## 用户话语分类

动手或接续前先判定用户当轮话语属于哪一类，再选动作。分类错了必须先纠正，不能按错误类别去重拍、重审、改实现或发明新门禁。

| 类别 | 判定 | 正确动作 |
| --- | --- | --- |
| 陈述 / 观察 | 描述自己看到的现象、确认现状、说明覆盖已经发生、把某件事说成好事或符合预期 | 记录理解。不得当成 bug、画面不合格或新门禁 |
| 流程 / 规范问题 | 质疑重复验收、规范落点、工作顺序 | 按系统 `skill-governance` 处理规范。不得改写成画面 `REVISE` |
| 验收不合格 | 指出某张图、某个对象或某个可见结果不对 | 按下节确定纠偏范围，再失效该范围直接覆盖的结论和媒体；范围外无变化的已验收事实保留 |
| 明确改实现 / 明确改规范 | 给出要改的对象和方向 | 锁定四项后执行 |

不得把陈述里的事实当成缺陷。用户说已经看到覆盖后的新截图，表示同一查看器目录覆盖写回正在按预期工作；正确动作是继续做必要验收并给链接，不得改成先写暂存再晋升。

## 问题范围确定

锁定问题对象时，分开记录**用户目标范围、症状样本、根因假设和实际改动范围**，并用证据确定影响边界：

- **举例保留总体语义**：“比如 / 例如 / 等”后的部位或对象只提供症状样本，不构成排他范围。整体尺寸、整体位置、整体流程等问题必须保留对应对象层级；不得自行改写成某处文字、某个控件或某一步的问题。用户明确限定“只有 / 仅 / 只修”时，再按该限定确定边界。
- **排查顺序不改变任务范围**：可以从样本位置开始，继续检查同层代表对象与共同依赖，分别标记已证实受影响、待核查、已排除及证据。未经检查的部分保持待核查；不能因局部容易测量、已有测试或先修成功，就只验该局部并宣布原问题解决。
- **疑似共享先查影响**：“其它也可能 / 是不是底层”等是待验证的影响与根因假设。先只读追查共同依赖和差异路径，确定实际影响面；不能直接宣称全部受影响，也不能默认仅示例对象受影响。扩展到共享层实现，须有用户明确要求通用能力或确认共享根因的证据，并遵守对应授权与共享边界；证据确认仅局部受影响时，按已证实边界实施。
- **收窄必须有依据**：减少原目标的覆盖或验收范围，必须有用户明确限定，或直接证据排除其余部分，并记录依据。局部测试、单张截图和局部改善只支持局部事实；缺少总体证据时继续定位，不把局部完成改写成整体收口。用户纠正对象层级或示例含义后，先重锁范围，原有证据只保留仍直接成立的事实。

## 实施前四项锁定

开始或接续任务，准备实施前必须同时写清四项；缺一项只能定位或补证据：

1. **问题对象**：本轮到底处理哪个游戏、页面、流程、记录、接口或资源对象；按上节写清总体范围与症状样本，标记已证实、待核查和已排除部分。
2. **真相来源**：用户最近明确原话、当前仓库证据、真实运行入口、日志、截图或线上记录中，哪一项直接命中了这个对象。用户点名某份文件或截图时，真相来源就是该文件本体的读取结果；打开另一张同产品截图不能填这一项。
3. **目标入口 / 环境**：当前 `cwd`、worktree、路由、运行模式、设备、服务或发布通道是什么。
4. **验收口径**：修完必须回到哪个原始位点，用什么 E2E、截图、日志、状态断言或真实结果证明；证据的对象层级和覆盖边界必须对应已锁定目标，不能以症状样本通过替代整体问题验收。

## 冲突处理

- 如果摘要说的是 A 游戏 / A 页面 / A 反馈，但用户最新明确说的是 B 游戏 / B 页面 / B 反馈，默认判定摘要失效，只能处理 B。
- 如果当前临时文档写着 `Next:` / `当前优先级` / `active goal`，但它和用户最新目标不一致，必须先把该文档标成历史或非当前入口；不得让它继续作为执行队列。
- 如果两个候选目标都可能成立，且当前证据无法单边裁决，必须停止并向用户说明候选项、冲突证据和缺的最小信息。
- 多游戏仓库里，用户只说通用症状、简称、空间关系或上次修改次数，而没有明确游戏 / 页面 / 入口时，近期 evidence、脏工作区集中点、交接摘要或“更像某游戏”只能作为候选线索；只要至少两个游戏仍可能命中，就不得改任一候选游戏的源码、测试或数据。下一步只能继续查能唯一锁定目标的真实证据，或问“你说的是 A 还是 B”这类单一最小问题。
- **共享能力范围必须上提到公共 owner**：用户明确说“每个游戏 / 所有游戏 / 全部游戏 / 底层通用”，或举出 TTS 这类跨游戏共同能力时，问题对象锁定为跨游戏共享能力，不得选一个游戏当代表，也不得把实现拆成随机游戏补丁。必须先锁定公共 owner、对象识别合同和跨游戏覆盖矩阵；若公共 owner 或覆盖边界仍不清楚，停在定位，不得先改任一游戏。
- 如果为了修正被污染的交接材料而改文档，改动只允许落在交接 / 规范文件本身；不得顺手改业务代码。

## “继续”的解释

用户说“继续”时，只能继续最近一个已锁定且未被用户纠偏的目标。

- 最近用户已经纠偏目标时，以纠偏后的目标为准。
- 最近目标已完成或转历史时，不得从旧 `Next:` 自动取下一项；必须重新锁定。
- 最近消息只是质疑“你跑错目标 / 这是什么鬼 / 不是这个”时，当前动作是纠错和目标重锁，不是继续旧实现。

## 交接文件最低格式

会被后续模型读取的交接 / 覆盖文件，顶部必须先写：

```text
目标状态：active / historical / blocked / superseded
当前目标：
非当前历史背景：
禁止自动接管：
更新时间：
```

- `active` 只能有一个主目标；多个待办必须明确排序和依赖。
- 历史背景不能写成 `当前优先级`、`下一步` 或 `继续处理`。
- 如果保留非当前条目，必须写清“除非用户重新点名，否则不得按此实施”。

## 停止汇报模板

目标不确定时，对用户最少说明：

- 当前无法锁定的是哪一项：问题对象、真相来源、目标入口 / 环境、验收口径。
- 冲突来自哪里：用户最近原话、交接摘要、计划文件、代码证据或运行入口。
- 已确认不能做什么：不能按摘要继续、不能改某个候选模块、不能用历史截图 / 旧测试收口。
- 继续所需最小动作：本地继续查哪份证据，或需要用户补哪一个事实。

## 目标污染判定

- 用户当前主线是某个已锁定的问题对象。
- 交接摘要或临时覆盖矩阵若写成另一个对象的继续项，必须立即判为目标污染。
- 正确动作是先把非当前对象降为历史背景，再重新锁定当前问题对象、入口和验收位点；不得继续修改无关源码或 E2E。
