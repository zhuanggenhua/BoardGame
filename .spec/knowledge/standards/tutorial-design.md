# 教程与新手引导设计规范

本文件是 BoardGame 多游戏教程设计与验收的唯一通用正文。项目执行入口是 [`tutorial-workflow`](../../skills/tutorial-workflow/SKILL.md)；规则、代表局面、牌序、章节裁定与证据记录在对应游戏的覆盖文档中。截图与媒体合同引用 [`e2e-verification`](e2e-verification.md)，不在这里另立一套。

## 交付目标

玩家能够读懂当前局面，知道规则允许什么，理解为什么采取当前行动，亲手操作，并看见后果与下一入口。教程代替视频或文本规则时，范围内的规则必须都有玩家可见的教学落点；核心决策与电子版特有交互必须实际操作。帮助入口供回看，不能代替首次教学。

完整性、教学质量、运行正确和视觉可用分别验收。步骤数量、章节数量、字数、测试通过或截图存在，均不能单独证明教会了玩家。

## 一、锁定范围并读取来源

开工先锁定用户原话、游戏与模式、玩家身份、真实入口、目标环境、交付范围和验收要求。用户只要求文案、结构或覆盖审查时，先交付指定对象，不抢跑修改实现。

区分三类来源：

| 来源 | 负责的事实 | 记录方式 |
| --- | --- | --- |
| 规则书、官方勘误、卡面或已锁定规则合同 | 时机、主体、目标、费用、次数、限制、顺序、效果与胜负 | 文件或链接、页码 / 小节 / 卡牌原文位置 |
| 当前正式 UI 与交互合同 | 点按、长按、检视、选择、确认、响应、自动跳过、等待、退场与恢复 | 实际入口、源码 owner、当前画面及命令 / 事件 |
| 参考游戏的教学材料 | 如何呈现信息、何时解释、如何把学习接入行动 | 实际看过的页面 / 截图 / 视频时间点、观察、采纳与舍弃 |

用户要求参考其它教程时，执行实际阅读 / 观看，再记录“哪个节点教了什么、依附哪个对象、玩家随后如何使用”。宣传语、搜索摘要、章节目录和他人评价只用于定位，不能证明具体教学行为；规则书图解可以借鉴读图方法，但不能被称作数字版交互教程。参考材料不能作为当前游戏规则来源。

要教的规则缺少权威原文时，在作者记录标 `规则合同缺口` 并补源；不靠实现现状、经验或泛化文案填补。范围外且没有规则或正式 UI 支撑的内容直接不纳入。

## 二、建立覆盖总账

写步骤前，把规则源、旧教程和正式 UI 对照成一份作者总账。可以用同一文档的不同视图，不机械维护多套重复清单。

| 总账视图 | 最低字段 |
| --- | --- |
| 内容与覆盖 | 内容项、规则 / 卡面来源、旧落点、新落点、教学深度、实际玩家动作、结果、证据、缺口 / 移除理由 |
| 图面读法与电子交互 | 对象或字段、现实含义、正式位置、首次识别时刻、首次应用时刻、后续新增差异、真实入口、证据 |
| 阶段与交互链 | 触发、操作者、候选、选择、支付、确认、自动后果、响应 / 等待、结果承载、退场与下一入口 |

教学深度明确区分 `玩家实操`、`规则说明`、`自动过程观察`、`回看帮助`、`范围外`、`待补缺口`。只写“已介绍”不合格；说过某分支不等于操作过该分支。

- **选择教学内容**：规则原文是候选来源，不是课程目录。先把规则拆成玩家学习目标，再逐项决定去留。纳入主线的规则限于理解胜负目标、看懂当前关键状态、判断眼前合法行动、完成一局基础循环所必需的内容；在真实决策发生前教到足够使用即可。未进入本次局面的罕见例外、完整术语分类、策略建议、其它角色 / 模式专属规则，不因规则书有记载就搬进主线；在游戏覆盖文档记录排除理由，保留原规则来源。不能把关键前提静默删掉，也不能把整段原文改写后当作教程。
- **读图覆盖**：只教会影响当前或随后重复决策的卡面 / 棋盘信息。费用、卡面印刷的时机线索（包括规则规定的边框颜色和图标）及效果正文，在第一次读卡时连到同一张实际卡与随后的出牌；后续只解释新出现的标志或差异。按规则源说明线索代表的时机，不把颜色单独升格为牌名或分类。正式 UI 的可用提示若影响眼前选择，可说明它只表示“此刻能用”，并与卡面规则线索、教程焦点框区分。装饰、直白名称和普通关闭按钮不机械编成课程。
- **交互覆盖**：当前主线会用到的隐藏或非显然操作（如长按检视、出售筹费、响应选择）在首次真实用途处教学并由玩家操作。常规按钮不逐个讲；超出当前教学目标的交互明确留作范围外，不为凑“全面”加入空转练习。
- **信息归属**：正文、目标高亮和证据绑定同一视角、owner 与对象；看对手信息时使用正式视角切换或正式公开区，不能拿自己的同名区域、摘要或新增副本替代。

重构前后逐项核对覆盖差异。移走的内容必须有新教学时刻和入口；实操退化为说明、范围内内容失去落点时，明确记 `覆盖退化 / 待补回`。

## 三、先跑通玩家因果链

先设计合法局面和行动链，再写玩家提示。默认使用常规首局身份，从正式开局走入主要公共循环；可固定合法牌序与随机结果，使必要内容自然出现。

每个节点登记：

`上一画面与正式状态 → 当前选择为什么有用 → 玩家真实输入 / 系统动作 → 规则后果 → 下一可操作入口`

在修改文案和制作浏览器截图前，沿链复演资源、手牌、状态、轮序、行动额度、合法时机和目标。每一步的前提必须由开局或上一动作真实产生；预期要花的资源、要用的牌或标记必须确实存在。能用最窄领域测试验证的费用链与状态链，先验证，避免把 E2E 当主调试器。

- 行动理由可以来自当前真实局面：补足下一张牌的费用、保留响应预算、避免损失或满足一个合法条件。理由必须由规则与当前状态推得；不得把脚本选择说成普遍最优策略，也不凭空补出效果。
- 初次属于当前玩家的防御、响应、支付、选择、确认或放弃交给玩家。其他席位和系统用正式命令行动，首次公开后果与等待归属仍要教学，不让玩家代操作。
- 每个会改变选择、提交内容或权限的中间判断都保留教学时刻。一次输入后、没有新选择的连续自动后果可以合并；不能吞掉目标、数量、方向、路径、顺序、模式、是否执行或共同确认。
- 动作前先呈现当前合法集合与必要限制，再承接一个具体选择。固定示范不等于正式规则禁止其它选择；同类正式候选不得由教程过滤成另一套规则。
- 非示范合法选择有独立教学价值时，承接真实分支；没有时由运行时恢复完整检查点，不把停止卡、错误卡或“点击上一步”写成正常课程。验证至少一条非推荐合法分支。
- 进入可见链后不直接补牌、补资源、改状态或切结果来修补前因。突然出现的对象先追溯来源，修牌序、行动顺序或合理延长同一局。

## 自然流程与章节边界

默认一条连贯主线。只有同时满足以下条件才另开章节：该机制属于必教范围；调整或合理延长同一流程仍无法自然讲清；独立入口能让玩家亲自决策并看见后果。

视角、控制者、私密信息、罕见触发、测试便利、长链不稳定或代表态本身都不是拆章理由。先尝试在同一流程可见承接；稳定性问题修正式运行与测试等待。

每个核心含义只有一个主教学时刻。后续只复用、补新差异或分支；“完整回合”必须走到该主循环真实收口。独立预设态单独分组并说明起点，不能用连续编号伪装成上一段自然后果。

## 四、把规则写成当前决策

### 教读法，再让玩家使用

首次进入视野时给必要的基础识别；在某字段第一次影响决定前，解释它的规则含义并让玩家据此行动。不要一开始预讲所有未来字段，也不要到结算时才补已经使用过的关键信息。

卡面只显示数字、颜色、图标或缩写时，不能以“牌上已经有了”为由略过含义；只指出位置或颜色也不算教会。首次相应决策处要说明卡面实际标志允许何时使用。若规则源同时用颜色和图标识别时机，玩家提示优先说出印刷图标及规则含义；颜色只在确有辨识价值时作为辅助。先前已经教过的含义不重讲，新类型 / 限制出现时只补差异。

用当前真实对象、必要图例和极短文案解释读法，不复念整张牌。玩家亲手检查费用 / 时机 / 目标后完成正式动作，才证明读法已被应用；仅点开详情不算。

隐藏长按、组合手势或非直觉交互要在当前需要它时教。普通点叉、导航和显然控件无需逐个解释；必要输入仍真实执行并验证。触屏检视与桌面入口在同一节点承接，长按与合成 click 不得误出牌或耗资源，关闭后回到牌桌。

### 每张卡只有一个新增教学意图

提示可承担当前规则、当前动作或刚发生的结果；简短理由可以和动作同卡，不机械拆成“规则卡 + 操作卡 + 复述结果卡”。新决策才增加步骤，普通连续点击不机械加课。

- **当前规则**：给足眼前决定所需的条件；同层选项总览绑定真实父容器，只列必要名称、数量、顺序与限制，再进入子项。
- **当前动作**：点名真实对象，说明这次行动解决什么或准备什么；正文、焦点与实际输入一致。不把几步之后的计划塞进当前提示。
- **当前结果**：直说已发生的变化与下一入口，不用“去看看”代替反馈；取权威状态中的真实前后值。总量不能倒推分类、等级或归属，未决分支不能写成已经执行。

本标准中的“规则原文”指权威规则原意在当前教程语言中的准确译文，不要求照抄规则来源的语种、字形、标点或排版。作者记录保留来源定位和采用的译文；玩家界面只呈现当前教学原子所需的译文，不加“原文”等制作标签。译文可以符合目标语言习惯，但不得增删主体、对象、数量、时机、费用、限制、顺序或效果；额外解释作为教程说明，不冒充规则文本。

规则说明忠实呈现当前译文，保留主体、对象、数量、时机、限制和后果。规则来源留作者记录，玩家只读当前需要的信息。当前局面的可验证行动理由允许出现；作者设计意图、测试解释、内部状态词、章节安排、“本教程示范”与导航补救不进入正文。中英文逐句核对事实与职责。

相邻步骤只讲新信息。能从上一张直接理解、且没有新规则 / 决策 / 结果的句子删除。为了“全面”堆阶段表和大段分类、为了“简短”删除关键含义，都不合格。

完成文案前做一次精简审稿：每句话都要服务当前规则、输入理由或刚发生的结果之一；不要把规则源整段搬进主线，也不要提前讲后续尚未出现的字段。删掉一句后若不影响合法选择、行动理由、输入或结果理解，就删。教程长短不按规则书章节或规则条数决定，按本次选择的学习目标决定；范围外条目留在覆盖总账及规则源，不塞进玩家提示。

## 五、接入正式交互与教程生命周期

教程复用正式对局的对象本体、候选态、选中态、确认、结果和撤回语义；多对象映射遵循 [`rule-driven-interaction-design`](rule-driven-interaction-design.md)。正式状态能从玩家一次选择唯一推导的关联事实，不增加冗余选择。

提示负责看哪里、为什么；真实对象负责输入。教程不创建假确认、假跳过、平行状态条、对象副本或额外权限，不为讲解重复改造通用反馈。正式 UI 无法表达目标或结果时，先修其唯一承接物，不能用长文补看不见的状态。

文案点名的对象本体必须可见，高亮贴合该对象；多个合法候选保留可辨的次级状态，具体推荐目标有清楚主焦点。来源与目标关系、类型到结果映射必须在相邻画面可追溯。层级、槽位和候选视觉遵循 [`ui-change-gates`](ui-change-gates.md)，不能仅凭隐藏锚点或测试字段判定。

每步绑定当前 manifest、正式命令、操作者、目标、推进事件、动画等待和有效性。收到规则事件后仍有可见过程时等待该过程完成；画面已到下一确认态时先推进过期步骤，不让旧白名单拒绝真实操作。高亮暂缺时保留提示并暴露定位失败，不静默隐藏教程。

自动动作批次按声明顺序完整消费；前一动作只改变游戏状态时，后续动作仍要执行。只有真实响应、动画或新状态依赖才等待，超时要定位到失败动作，不静默锁住初始化或下一步。进入可见链后的隐藏自动化只压缩已教过且前提、动作、权限和后果等价的重复，并在总账注明可见承接。

教程会话只属于对应教程入口，与持久化进度分离。离开、完成或退出后移除提示、高亮、输入限制与自动动作，普通房间不得激活旧教程。重排步骤或改变前提时更新清单版本，按产品要求废弃或迁移旧进度；不强行恢复不兼容快照。

恢复时，正式局面、当前结果、步骤和允许动作来自同一当前清单；恢复等待态不重播并重新锁住已完成动画。回退恢复完整正式状态和随机游标，不只改步骤号。首次打开、刷新重进、回退重做、退出进入普通房间均纳入实际受影响的生命周期验证。

### 教程设置思路与入口契约

自然开局保留规则前置、控制者、行动额度和首个真实决策；固定牌序 / 随机不能预做玩家任务。确需独立机制练习才声明 `representative-state`，登记阶段、注入差异和边界。

入口契约登记已成立的规则前因、首个真实决策、当前行动人、已用行动额度、待结算对象与连续关系；沿用各游戏现有配置或覆盖文档，不强制新增通用字段。只有真正连续承接才能标为延续。运行态与契约不符时修起点，不靠跳步。语言包、E2E 与截图消费同一入口合同，不另写第二套顺序。

## 六、行为与图面分别验收

先核实证据命中用户原问题的同一入口、对象、操作者和失败状态，再判断方案有没有解决。全量教程重构覆盖该游戏所有 manifest、玩家文案、入口契约、分支与证据；缺项明确留缺口。

| 验收层 | 必须证明的事实 |
| --- | --- |
| 规则与状态 | 合法费用、时机、对象来源、资源变化、结算及下一状态；由领域 / 行为测试断言 |
| 实际操作 | 真实入口、真实输入、候选到选择再到确认与结果；响应至少一次介入和一次合法放弃，并继续操作 |
| 玩家理解 | 决策前有必要规则与图面读法，当前动作有真实理由，首次与后续差异清楚，不重复、不突兀 |
| 图面与过渡 | 提示与对象同帧可读、素材真实、焦点准确、对象归属清楚；相邻图有真实动作或自动结算承接 |
| 生命周期 | 本次涉及的初始化、刷新 / 重进、回退、完成与退出不会卡住、漏提示或污染普通房间 |

不以 dispatch、force click、手造教学清单或测试预填代替玩家输入。教程证据只能证明教程；要声称正式对局交互可用，还需同视角、同阶段、同对象和同点击区域的正式对照。

E2E 必须完整走过并断言所选教学目标、真实输入和后果；截图是便于玩家 / 审查者阅读的关键节点图组，不是逐步录屏，也不逐张导出每张提示卡。测试中用明确的截图白名单与逐步操作断言分开：每步都要走、要核对，只有白名单中的独特视觉事实才截图。只保留能证明独特 UI 含义、重要选择、真实结果、模式 / 阶段转换或隐藏交互的画面；若删掉一张图不会丢失新的视觉事实，就不单独收图。截图数量由独特事实决定，不由步骤数决定；若截图接近步骤数，逐张说明不可合并的视觉事实，否则合并或删除。选中的图按玩家顺序组成连贯短链，细小数值和未截取动作由行为断言证明。跨视口先选一个完整主链；其它视口只补该平台独有的手势或布局问题，不重复截整套相同教学节点。结果页不是收口，仍须实测到教程退场后的下一可操作入口；模式切换后也实测到第一项新决策。

阅读界面验证首次打开、必要翻页、信息承接与返回；回看独立验证当前决策页，不能重播已完成的一次性情境，也不把无教学价值的回看塞入主线。

每张最终媒体按 [`e2e-verification`](e2e-verification.md) 完成视觉账本，不能抽查冒充全量。被改写或用户否定的画面重新取证；未改写且有效的证据按该标准沿用，禁止机械重审。不同代表态、分支与视口分组，不能拼成一条虚假连续链。

实际核对正文、对象本体、高亮、输入与可见结果；DOM、内部字段和绿灯不能替代图面。教程浮层与被讲对象必须同时在前景，不能遮住持续参与决策的资源、手牌、骰盘或主入口。运行与视觉分别给结论。触发截图交付时，最终通过图组按项目 [`show-image-to-user`](../../skills/show-image-to-user/SKILL.md) 交出脚本生成的 `VIEWER_URL`。

## 重构与删减

连续出现遗漏、重复、跳步或“为什么做这个”时，停止逐句补丁，依次回查来源 → 覆盖总账 → 因果链 → 文案 → 正式交互 → 证据。先找首个偏移点，再修改对应层。

规范更新只保留本文件的通用正文。skill 是项目适配入口，游戏文档记录实例与证据，不互相复制规则。重构后复演用户指出的失败：新流程必须能在实现前发现缺项 / 前提不成立，并在验收时拒绝只跑通操作的证据。

## 最低验收

收口逐项回答：玩家知道怎样赢、能读哪些关键信息、眼前有哪些合法选择、为什么执行当前动作、亲手改变了什么、结果后还能做什么；范围内规则与额外交互是否都有落点；哪些只讲过、哪些实际操作过、哪些仍未证明。

存在未解决的范围内缺口时，交付只能写 `局部完成 / 待补缺口`。计划、矩阵、lint、领域测试、E2E 和视觉证据分别证明其直接覆盖的事实，不相互替代。
