# Tutorial Workflow

这是项目适配入口。多游戏教程的唯一设计与验收正文是 [`tutorial-design`](../../knowledge/standards/tutorial-design.md)；本文件只绑定仓库落点和验证命令。

## 使用入口

新增、补全、重构或审查教程，以及反馈规则遗漏、卡面读不懂、操作无理由、流程跳步、重复教学、新交互未教或退出 / 恢复异常时，读取 `tutorial-design`，按其中六个阶段执行。已有来源和上下文可沿用，不要求用户重复回答。

| 主源阶段 | 项目落点与检查对象 |
| --- | --- |
| 一、来源与范围 | 当前游戏规则目录、官方来源、正式 Board / 交互合同、实际查看的参考材料 |
| 二、规则与界面事实盘点 | 优先使用该游戏已有教程覆盖文档；只登记规则源、正式 UI、旧教程与缺口，暂不排教学步骤 |
| 三、正常对局行动链 | 在该游戏覆盖文档先记录无教学话术的正式对局行动及每次行动的局面用途，用正式状态转移复演牌序、随机、费用、阶段与续局；通过后再填教学落点和课程选择，写分支文案前完成主标准「区分规则选择与课程分支」裁决 |
| 四、决策文案 | 对应中英文语言包及 manifest 的首次教学位置 |
| 五、正式交互与生命周期 | 游戏教程注册、正式 UI、教程系统、页面生命周期与进度版本；按受影响 owner 修改 |
| 六、验收 | 先按主源核对逐句来源、首个规则决策、教学范围与一级临时信息，再验当前游戏教程领域测试、真实入口逐步 E2E、明确白名单的关键节点截图链、视觉账本与最终用户查看器；链接资格以 e2e-verification 为准 |

具体游戏的规则取舍、牌序、资源因果与例外只放在该游戏覆盖文档。先完成来源与事实盘点、正常对局行动链，再确定教学落点和玩家提示。跨游戏的选材、卡面读法、精简与截图标准只以 [`tutorial-design`](../../knowledge/standards/tutorial-design.md) 为准。

## 文案落到操作前的核对

正常对局行动链通过后，开始写玩家文案或测试之前，沿用标准里的作者总账，逐个关键节点核对这条链：

`规则来源与语义 → 具体动作身份 / 运行时 ID → 当前可见 UI 对象 → 玩家允许输入 → 结算结果与下一状态`

- 每个规则动作单独核对来源、动作身份、UI 对象和效果。名称相近或都含“征兵 / 招募”的手牌行动、轮盘行动、卡牌效果，不因名称相似而合并成一个规则解释。
- 文案列出“可选项 / 或”时，要同时对照规则来源和本次 setup 下运行时真正显示的候选；条件选项单独核验条件是否成立。运行时出现了规则来源没有支撑的候选时，登记为 `规则合同缺口`，不能把实现现状当规则，也不能静默漏掉玩家眼前的选项。
- 第一句必须服务玩家此刻面对的决定。若文案说可以自由选择多个动作或顺序，当前步骤的高亮、正式控件与允许输入必须共同承接这些选择；高亮单个分支时，不得让它承担多个分支的总说明。调整提示时机、锚点或步骤边界，直到三者一致。
- 用户要求先审文案再实施时，先交付对应节点和流程供其审阅，不改实现；用户已明确授权直接重构时，仍先在作者记录中锁定规则来源、动作身份和文案职责，再进入实现，不另设审批门槛。
- 文案测试不能靠“包含了预期句子”证明规则正确。精确字符串断言只用于有来源定位的规则忠实译文；其余提示需回到作者总账，核对目标动作、当前 UI、允许输入和结果。测试通过不能替代这项语义核对。

## 仓库验证

改源码 / 测试先遵循 [`code-design`](../../knowledge/standards/code-design.md)。读取当前 `package.json`，选已有安全入口运行直接相关的领域测试；使用 `node scripts/infra/vitest-cli-safe.mjs run <测试文件> --configLoader native` 可限定文件。

真实页面证据遵循 [`e2e-verification`](../../knowledge/standards/e2e-verification.md) 与 [`ui-audit-loop`](../ui-audit-loop/SKILL.md)，运行 `npm run test:e2e:file -- <当前教程 E2E 文件>`；完整走测与逐步断言不等于逐步截图。媒体交付引用 [`show-image-to-user`](../show-image-to-user/SKILL.md)。

- 源码变更：`npm run typecheck -- --pretty false`。
- 规范变更：`npm run spec:lint`、`git diff --check -- .spec`。
- 最终媒体：`npm run verify:e2e-evidence -- <当前 PASS 清单>`。

最终汇报区分：通用流程改动、当前游戏实际改动、规则覆盖 / 操作 / 视觉 / 生命周期各自的证据与缺口。没有实际发布，不能把本地结果称作线上更新。
