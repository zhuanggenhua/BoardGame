# Rule To UI Design

规则驱动游戏 UI 时，先把规则对象翻译成界面对象，再谈视觉风格。

## 真相源账本

每轮至少记录：

- 规则来源：规则书页码、状态机、领域数据、项目 spec。
- 素材来源：卡牌图集、token、骰子、地图、角色、TTS/Workshop、旧平台实现。
- 入口环境：设计稿、Open Design artifact、真实页面、PC/移动、截图验收位点。
- 验收口径：UI 设计批准、设计稿人工验收、实现截图、E2E、项目门禁。

只列路径不算理解；写出与本轮目标有关、会改变画面的规则结论。

## 对象职责表

为每个对象写清：

| 字段 | 要回答的问题 |
| --- | --- |
| 规则对象 | 它在规则里叫什么 |
| 现实职责 | 玩家操作、检视、结算、归档、隐藏、提示、状态、装饰 |
| 当前阶段权重 | 主动作、当前候选、可浏览、低权重归档、隐藏 |
| 实体锚点 | 它在画面里的唯一主位置 |
| 素材职责 | visible-subject、reference-only、programmatic-runtime-ui-source |
| UI 裁定 | 常驻、折叠、弹出检视、只读详情、隐藏、暂不覆盖 |

同名或相似素材必须拆开判断，例如角色实体、角色肖像、角色规则卡、提示卡、状态卡、token、牌堆和参考卡。

## 隐藏信息和公开归档

- 隐藏信息：卡背、模糊、数量、所属关系；不展示正面。
- 公开归档：可降权，但不能伪装成隐藏；默认显示数量、所属、紧凑顶牌正面或展开入口。
- 当前候选：必须可读可点；不能只剩缩略图或色块。
- 历史日志：可折叠，不与当前动作同权。

## UI 元素清单

UI 设计前输出清单：

- 主舞台和空间单位：棋盘格、地图区域、轨道、牌桌区。
- 场上实体：角色、单位、建筑、状态宿主。
- 当前可支配对象：卡牌、行动、技能、装备、资源。
- 计划/准备对象：已计划、已装备、已承诺但未结算的对象。
- 公开归档：弃牌堆、墓地、历史堆、日志。
- 隐藏对象：对手未公开牌、牌库、暗置效果。
- 结算对象：骰子、伤害、治疗、状态 token、支付结果。
- 程序化读数：生命、法力、冷却、行动点、进度条。

遗漏用户点名对象、规则必需对象或当前可支配对象，当前稿直接 `REVISE`。
