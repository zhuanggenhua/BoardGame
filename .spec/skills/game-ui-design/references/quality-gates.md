# Quality Gates

送视觉 UI 设计包、Open Design 设计稿、截图或实现验收前，逐项判定。用户可见交付默认是图、草图、截图或 Open Design artifact；文字表格只作内部证据 / 审计附件，除非用户明确要求。

## 规则理解门禁

- 已读本轮真相源，而不是只引用旧摘要。
- 有三条以上影响画面的规则结论。
- 有对象职责表，且相似对象已拆分。
- 对关键对象有 `职责 -> 可选承载模式 -> 当前选择理由`；不能只写“必须放某处”。
- UI 名称来自规则或项目合同。
- 隐藏信息、公开归档、当前候选已裁定。

任一缺失：`REVISE / source-comprehension-failed`。

## 设计自由度门禁

- 通用验收只判职责、可读、玩家任务、隐藏边界、对象守恒和素材语义；不把固定坐标、固定 HUD 布局或某一游戏皮肤当作跨项目硬规则。
- 项目已批准的视觉稿可以成为本项目基线，但必须标为 `project-baseline-decision`，不能改写成系统规范。
- 用户纠正如果是具体落位偏好，先记录为当前项目裁定；只有抽象出可复用不变量后，才进入跨项目通用层。
- 若同一职责存在多种可行承载模式，审计必须比较“为什么本稿选这一种”，而不是只检查它是否等于上一张图。

违反以上任一项：`REVISE / overfitted-layout-rule`。

## 对象守恒门禁

- 用户点名对象没有被删除、弱化或替换成无关控件。
- 当前可支配对象可读可点。
- 骰子/token/状态/资源读数在饱和态可见。
- 归档对象有可恢复入口；公开归档不是卡背隐藏。
- 每个规则对象只有一个主实体锚点，详情或选中态只是引用。

任一缺失：`REVISE / actionable-object-lost`。

## 玩家任务门禁

- 第一眼能看出当前玩家、当前阶段、当前来源、可点目标和下一步动作。
- 真实对象能直选时，没有新增同义代理工作台。
- 确认/取消有明确规则或系统授权。
- 当前结算在来源/目标附近或主舞台上层，不在边栏。
- 取消、退场或恢复路径明确。

任一缺失：`REVISE / player-workflow-failed`。

## 基础浏览交互门禁

- 默认 / 非操作阶段中，正面可见卡牌、法术书、卡池、弃牌堆、角色卡、场上卡和公开对象仍能通过点击、hover、focus 或长按打开详情 / 放大 / 规则回看；不能因为当前阶段不可打出、不可计划或不可提交而整体禁用检视。
- 操作态与浏览态的点击语义已拆清：操作态点击对象会选择 / 打出 / 指定目标；浏览态点击对象会检视 / 放大。两者不能互相吞掉，也不能让父层禁用导致卡牌、分类、分页全部失效。
- 分类标签、筛选按钮、搜索、范围切换和分页都改变真实可见集合、页码、排序或焦点；只变按钮样式但内容不变，或因父层拦截导致不能点击，判为假控件。
- 地图 / 棋盘 / 竞技场在目标视口中若不能稳定完整可读，已提供自由拖拽、滚轮缩放、触控等价路径、缩放读数 / 重置反馈，并保持对象命中区随同一坐标父容器移动。
- 详情 / 放大层关闭后回到同一真实页面，卡牌、筛选、分页、地图和规则动作仍可继续操作。

任一缺失：`REVISE / basic-browse-interaction-failed`。

## 空间和可读性门禁

- PC 100% 缩放下，当前候选卡/物件可读。
- 主舞台、候选区、计划区、归档入口、资源区和结算层有空间预算。
- 无职责空白、暗带、边框壳、死角没有占住关键空间。
- 背景没有支配布局；必要 overlay 允许覆盖低权重纹理。
- 没有文字裁切、重叠、漂移、布局跳动、过小按钮或低对比文本。
- 每条关键信息有且只有一个当前可见主 owner；若玩家名、数值、状态、目标或动作已经由对象本体、座位、token、卡牌、骰子、线条或图标清楚承担，临时标签不得再次复写。只有 owner 不可见、离开锚点或多对象会混淆时才允许补充最少文字。

几何不相交只是底线；玩家仍看不懂下一步时仍判 `REVISE`。

## 动效生命周期门禁

- 拖拽、长按、滑动、投放、转移和结算动效已经指定稳定生命周期 owner，不依赖会隐藏、重渲染、移出命中区域或退场的源元素继续派发关键输入。
- 已验证起点、持续中途态、离开源元素后的响应、取消/松手清理和终点结果；不能只用起始截图、最终截图或“动画出现过”证明动效成立。
- 需要隐藏源对象时，源占位、ghost、关系线和目标高亮的职责清楚：不双显、不丢归属、不阻断输入、不遮挡关键可读对象。
- 多人或多实例动效已验证并发实例互不抢占；结束一个实例不会清掉其它仍在运动的实例。

任一缺失：`REVISE / animation-lifecycle-failed`。

## 外部范式门禁

当用户指出“看不懂、太丑、拥挤、能不能给人看、为什么空着、为什么像另一个游戏”时，下一版必须引用成熟范式或可回查参考，并写清：

- 来源不变量。
- 本稿吸收的空间/交互裁决。
- 明确不复制的皮肤、术语或素材语义。
- 由该范式反推出的禁止项。

只说“参考了某游戏”不算通过。

当用户点名平台内成熟参考，或项目已经存在同类成熟组件 / E2E 时，还必须写清 `参考有而目标没有` 和 `目标有而参考没有` 的正反对照。卡牌放大、筛选、自由拖拽缩放、详情层、可见状态反馈这类基础交互已经有成熟实现时，目标游戏缺失即判 `REVISE / mature-reference-not-consumed`，除非有规则差异或素材 / 输入模型证据证明不能复用或抽共享组件。

## 送验门槛

- `AI_PASS` 只表示可以交给用户人工看，不表示已批准实现。
- 用户批准视觉 UI 设计包前，不生成更精细设计稿；该 UI 设计包必须直观到能从图上判断布局、交互和元素是否成立。
- 用户批准设计稿前，不实现真实运行页。
- 实现截图不能替代设计稿；设计稿截图不能替代规则理解。
- 不用长文字解释替代图面问题；如果图上看不懂、看不全或不好判断，当前稿继续 `REVISE`。
- 若最终交付是图片或 Open Design 截图，必须先 AI 图面核验，再按项目看图流程打开给用户。
