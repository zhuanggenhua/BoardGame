# Show Image To User

## 单一职责

本 skill 定义“把本地图片、GIF 或录屏交付给用户”的项目入口。所有最终 `PASS` 媒体都必须先完成 AI 图面核验和 `PASS` 清单校验，然后统一注册并输出脚本返回的 `VIEWER_URL`；默认不打开查看器。单图、多图、PC/移动对照、GIF、视频和录屏都使用同一套“校验后给查看器链接”规则。只有用户明确要求“打开查看器”或“重新打开查看器”时，才真实打开或复用查看器。链接、路径、查看器状态都不是验收依据：AI 验收必须先基于图片 / 录屏本身、E2E / 断言和 `PASS` 清单完成。

- 截图是否具备 E2E / UI 验收资格，不在本入口定义。
- AI 自己读图、核图和 `PASS` / `REVISE`，不在本入口定义。
- 大图安全读取、降采样和裁切，不在本入口定义。
- 本入口不维护第二套截图验收正文；它只裁决最终媒体链接、显式查看器打开、证据路径和失败回报。

AI / 开发者快速检查端到端截图目录时，可使用项目工具索引里的本地网页目录查看器（见 [`docs/tools.md`](../../../docs/tools.md)）。先锁定最终 `PASS` 媒体，再用 `open-verified-image.mjs --dry-run` 校验清单，随后用同一入口的 `--no-open` 注册目录并输出脚本返回的 `VIEWER_URL`。只有用户明确要求查看器打开时，才去掉 `--no-open`。不使用 `--force-reopen` / `--reopen`，除非用户明确要求强制重开。

项目约定：

- 主证据目录：`test-results/evidence-screenshots/<game>/<测试文件>/<用例>/`。
- 候选图、失败图、中间排查图不能冒充最终验收图；它们只能作为路径或诊断材料报告，不允许代理打开给用户看。
- 服务器相册不是默认交付。只有用户明确要求上传、发布链接、服务器相册或手机查看时，才允许发布到 `http://8.148.71.102:18080/#/boardgame/<task-id>`。
- 获得上传授权后，只允许更新 `/home/admin/image-preview/data/projects/boardgame/tasks/<task-id>/`，禁止改预览站壳层、根路由或客户端代码。
- **大图查看不得设置人为放大上限**：本地网页查看器默认只限制最小缩放，不得用固定最大比例阻止用户阅读卡面、规则文字或高亮细节；放大后必须仍可拖拽查看局部，并保留适配 / 重置入口。

## 查看器身份与网址（强制）

- 用户可见查看器网址的稳定身份统一由**截图目录**决定：`VIEWER_URL` 中的 `key` 必须是最终媒体所在截图目录的目录 key；目录 key 不是图片文件名、单张图片 key，也不是测试名或手工命名的别名。
- `scripts/verify/open-verified-image.mjs` 是目录注册、目录复用和网址生成的唯一入口。必须让脚本根据 `--dir` 解析并返回 `VIEWER_URL`，不得手工拼接、替换或修剪 `?key=`、`focus`、`show`、`files` 等参数。
- `focus`、`show`、`files` 只表达当前目录内的临时焦点或媒体筛选，不得改变查看器的目录身份。需要筛选媒体时，把 `--focus` / `--files` 交给脚本，最终仍原样输出脚本返回的网址。
- 用户明确说“给网址 / 我自己打开 / 给我截图链接”时，执行 `node scripts/verify/open-verified-image.mjs --dir "<最终截图目录>" --no-open`，只输出脚本实际返回的 `VIEWER_URL`。
- **截图链接唯一口径**：`VIEWER_URL` 是当前最终 PASS 截图组的用户交付链接。它不是完整图片路径，也不能用 `D:/...`、`file://...` 或手工拼接的本地文件路径代替。最终回复禁止裸露完整图片路径；源路径只留在 PASS 清单、evidence 和命令参数中。
- 用户明确说“只需要给我网页查看器链接”“只给网页查看器链接”或等价表达时，优先解释为“只注册目录并输出链接”：不得调用真实打开、浏览器接管、系统查看器、`--viewer system`、`--force-reopen` 或其它回退通道；只允许使用 `--dir ... --no-open`，并原样返回脚本生成的 `VIEWER_URL`。若链接注册失败，只报告注册失败及最小补救，不得自行打开或换通道。
- 同一截图目录后续复用同一个目录 key；若切换到新的最终证据目录，必须由脚本产生新的目录 key，并以脚本返回结果为准。

## 统一媒体链接交付（强制）

- 单图、多图、PC / 移动端对照、GIF、视频和录屏，用户输出统一使用脚本返回的 `VIEWER_URL`。
- 媒体数量只影响 `PASS` 清单和说明顺序，不影响用户交付方式；不再把单图、多图作为两套用户展示流程。
- 默认不打开查看器，不启动系统图片查看器，不做内联展示，不自动复用旧查看器。
- 每组最终媒体必须给一个脚本返回的 `VIEWER_URL`。媒体说明写在回复中；不逐张输出完整图片路径。
- 默认只注册目录，不打开窗口。只有用户明确说“打开查看器”或“重新打开查看器”时，才真实打开或复用查看器。

### AI 核图与链接交付分离

- AI 核图只负责判断媒体是否真实覆盖本轮要求，以及结论为 `PASS` 还是 `REVISE`。
- 只有通过本轮 `PASS` 门禁的最终媒体，才允许输出直链。
- `view_image`、OCR、缩略图和裁切图只有在宿主不会把结果展示给用户时才可用于私有 AI 自检；否则只用非展示型机器检查、路径和文字证据推进。

## 输出与代开时机（强制）

- 用户当轮说看图、打开图、给截图、截图验收、录屏、玩家视角检查、`图呢`、`我看看` 或类似表达时，先完成 `PASS` 清单和路径核验，再用 `--no-open` 注册最终媒体目录并输出 `VIEWER_URL`。
- 单图、多图、PC / 移动对照、GIF、视频和录屏统一交付 `VIEWER_URL`。不按媒体数量分流。不默认打开查看器。不默认启动系统图片查看器。不默认内联展示。
- 只有用户明确说“打开查看器”或“重新打开查看器”时，才去掉 `--no-open`，真实打开或复用查看器。用户只要链接时，不打开查看器。
- 录屏、GIF 和视频也只先注册并输出 `VIEWER_URL`。只有用户明确要求打开查看器，才真实打开。
- 输出路径、输出 `VIEWER_URL`、打开或复用查看器都是图片型或动效型交付动作，不是验收动作。实现、测试、截图 / 录屏链、AI 核图或证据选择还没完成时，不得把任何媒体交付给用户；最多报告候选路径、缺口和下一步。
- **用户要链接但不要打开时的交付格式**：先完成当前 `PASS` 清单和 `--dry-run` 校验，再执行 `node scripts/verify/open-verified-image.mjs --dir "<最终截图目录>" --no-open`，输出脚本实际返回的 `VIEWER_URL`、截图说明和 `PASS` 结论。不得输出完整图片路径。
- 用户说 `图呢`、`给截图`、`我看看` 或类似表达时，只输出已经通过当前 `PASS` 的 `VIEWER_URL`。没有最终 `PASS` 时，继续补实现、补 E2E、补截图 / 录屏链或补核图。禁止为了回应催图而打开旧图、单张候选图、过程图、诊断录屏或截图目录。
- 同一轮同一份媒体或同一组媒体只输出一次 `VIEWER_URL`。不得因为单图、多图或动态媒体切换交付流程。只有用户明确要求“打开查看器”或“重新打开查看器”时，才真实打开；此时仍输出同一个脚本返回的 `VIEWER_URL`。
- **连续任务中的截图请求持续生效（强制）**：在同一条连续 UI / E2E 修复或验收任务中，用户首次明确要求给截图、图呢或给链接后，后续每轮只要产生新的、对应当前工作树和当前验收要求的最终 `PASS` 媒体，就用 `--no-open` 输出新的 `VIEWER_URL`。用户说“继续”不取消该要求。默认仍不打开查看器。
- **最终 PASS 前禁止输出最终图证据或打开（强制）**：本条只在已经触发图片 / 动效交付时生效。本轮截图、录屏、过程图、候选图、诊断图、失败图、过期图和历史图，只要尚未被当前验收流程选为最终交付物并明确判定 `PASS`，一律不得包装成最终可点击网址证据，也不得通过本地网页查看器、系统查看器、PureRef、Codex App 内联图、会在对话中渲染图片的 `view_image` / `Viewed Image` 预览或服务器相册展示给用户。用户明确要求“先打开看看 / 打开失败图 / 打开候选图 / 我看看”也不能绕过；正确动作是继续验收、说明尚未通过，不输出失败图链接。若本轮没有触发图片 / 动效交付，则不需要为了满足本条而主动输出 `PASS` 图或录屏。
- **PASS 只看本轮要求（强制）**：最终 `PASS` 的判断对象是用户本轮明确交给你的要求，不是整页 UI、全游戏完成度或其它顺手发现。输出证据或代理打开前必须先写出“本轮要求清单”，每一项都要有直接证据并标为 `PASS`；任一项未达标、缺证据或被用户刚指出仍不对，都不得作为最终图证据输出或代理打开。非本轮要求的问题可以记录为备注或后续项，但既不能阻塞本轮交付，也不能拿来替代本轮要求的达标证据。若非本轮问题会让本轮截图 / 录屏无法证明目标要求，例如遮住目标、截图不是目标状态、录屏没有覆盖目标动作或流程没有触发，则它按“本轮证据无效”处理。
- **证据相关性先于查看器交付（强制）**：查看器只负责展示已经通过 [`e2e-verification`](../../knowledge/standards/e2e-verification.md) 证据相关性硬门的媒体，不负责把不相干截图包装成可交付证据。生成 `VIEWER_URL` 前，必须逐项确认媒体直接覆盖用户原始问题；若图中没有目标对象本体、关键状态、真实动作前后或用户要求的可见结果，立即撤销该媒体的 `PASS` 资格并重拍 / 重录 / 重跑。需要多个状态或关键帧时，必须保留独立、可读的原图组；合并图只能作导航，不能替代独立证据。
- **连续任务逐项覆盖（强制）**：当用户在同一条连续修复或验收任务中提出多个相互独立的问题、修复点或验收条件时，`PASS` 清单必须把每个问题或条件作为独立 `requirement` 列出，并为每项提供直接覆盖它的当前媒体或运行证据。一个子问题的截图、测试通过或 `PASS` 状态不得代表其它子问题；缺任何一项时，只能交付已覆盖的部分并明确剩余缺口，不能用 `scope: "current-user-request"` 的总标签包装成整轮完成。若用户后续明确缩小查看范围，才按缩小后的范围重建清单，不得把未覆盖的相邻问题混入当前交付。
- **可见文案逐字验收（强制）**：当本轮要求涉及描述、提示、结果、说明或“用户能不能看到”时，必须用真实可见节点或截图证明；`sr-only`、`hidden`、`aria-*`、状态对象、日志和隐藏结算账本只能证明语义或内部数据，不能证明普通玩家能看到。若文案被保留但只存在于无障碍节点，结论必须写成“数据仍在但视觉缺失”，不得判为可见 UI `PASS`。

## 一步到位输出流程

用户要求看图、给截图、打开图或最终截图验收时，只允许按这条正向顺序执行一次：

1. 锁定本轮交付要求清单，并确定最终媒体集合。单图、多图、PC / 移动对照和动态媒体统一按 `VIEWER_URL` 交付。
2. 完成当前工作树、当前入口、当前目标状态的截图 / 录屏与必要测试；若需要重跑、补图、同步目录或重建证据，必须在证据交付前完成。
3. 选定最终原图 / 原录屏，并准备链接说明：写清截图组入口 / 状态、关注点和 `PASS` / 过程结论。多张媒体写清顺序。不得把查看器目录、英文文件名或内部路径当成用户链接。
4. 创建或更新只覆盖本轮要求的 `PASS` 清单，确保清单里的测试结果、原图路径、标记图路径和当前证据运行一致。
5. 先用 `open-verified-image.mjs --dry-run` 校验清单和路径；发现旧图、缺图、标注遮挡、清单不匹配或验收项不足时，回到第 2 步修正，不得先输出最终证据或先打开再补救。
6. dry-run 通过后，统一执行 `node scripts/verify/open-verified-image.mjs --dir "<最终截图目录>" --no-open`，输出脚本实际返回的 `VIEWER_URL`。单图、多图、动态媒体都走同一交付方式。
7. 只有用户明确说“打开查看器”或“重新打开查看器”时，才去掉 `--no-open`，调用查看器真实打开或复用。此时仍输出同一个 `VIEWER_URL`。用户只说“给链接”“给我截图链接”“图呢”“给截图”“我看看”时，不打开查看器。

 完成第 6 步后，禁止重复输出同一份媒体；若后续修复或重拍产生新媒体，应按本节规则重新校验并输出新直链。若同一轮中输出后才发现截图、清单或标注不是最终状态，这次交付必须按失败处理；修正后只能在说明前次作废的情况下重建完整链路。

## 触发条件

这些表达默认表示只输出最终 `PASS` 的 `VIEWER_URL`，不打开窗口：`打开图片`、`打开图`、`图呢`、`给我看图`、`给截图`、`给我截图`、`截图给我`、`截图呢`、`我看看`、`重新打开`、`录屏`、`动图`、`GIF`、`视频`、`看实际效果`、`看动画效果`、`给我链接`、`给我截图链接`、`我自己打开`。
只有这些表达才允许真实打开或复用查看器：`打开查看器`、`重新打开查看器`。用户说“只给网页查看器链接”时，只执行 `--no-open` 注册，输出 `VIEWER_URL`，不打开窗口。

- 用户明确要看图或给截图时，先判断最终 `PASS` 是否成立；成立后输出脚本返回的 `VIEWER_URL`，并说明用户该看什么。未成立时不得输出最终证据链接或打开，只能继续补验收或说明阻塞。
- 工作流已经选定最终验收图、最终有序图组或最终录屏，且 AI 核图通过时，直接输出 `VIEWER_URL`。不要等用户再追问“图呢”。若只是过程截图、诊断截图、候选截图或非视觉任务附带截图，仍只能报告结论，不输出失败图链接。
- 用户只要求“给链接 / 证据链接”时，只给脚本返回的 `VIEWER_URL`，不输出完整图片路径，不打开查看器。
- `E2E passed`、`截图已生成`、`录屏已生成`、`证据已更新` 不是打开本地查看器的充分依据。用户明确要看图 / 录屏、本轮交付物就是图片型 / 动效型验收物，或本轮已经完成 UI / 游戏画面 / 截图最终验收并选定 `PASS` 验收图时，才进入证据交付流程；进入后仍必须等最终验收物 `PASS` 才允许输出最终证据或打开。
- 已经在上一轮或上一专题收工、打开、输出过或明确降级为独立证据的图组，不得因为新一轮修其它问题而重新打包交付旧图。新一轮只需要引用这些旧证据时，报告既有 `VIEWER_URL` 和结论即可；但只要新一轮产生了对应当前工作树的新最终 `PASS` 媒体，且连续任务中的截图请求仍有效，就必须创建或更新当前用户交付清单并输出新的 `VIEWER_URL`。

## 选图规则

- 选图必须匹配当前目标：PC / mobile / 横屏 / 当前游戏 / 当前流程不能靠宽泛关键词或最新时间戳乱配。
- 修代码、样式、数据后要看当前效果时，默认先重拍当前工作树、当前入口、当前目标状态的新图；旧图只能标为历史证据。
- 单图只能证明单帧。翻页、前后态、PC/移动对照、弹窗开关、流程步骤或分支状态默认交付最小有序图组。
- 原图优先：用户说 `原图`、`未压缩`、`压缩前`、`原始截图` 时，禁止把缩略图、裁切图、OCR 图、contact sheet 或压缩预览当作最终证据输出或代理打开。
- 验收图默认用真实原始截图；标记副本只作为多图顺序辅助，必须保留并汇报原始路径。
- 如果最新相关图是失败、过期或诊断图，只能报告路径和失败原因，不得输出为最终图证据或代理打开；需要继续补实现、补截图或重新验收直到出现最终 `PASS` 图。
- 用户点名只看某个编号之后、某个章节、某个分支或“后续流程”时，必须先按该范围生成新的标注图组和 PASS 清单；不得用更大的历史 PASS 清单顺手输出或打开前置图、辅助图、移动端对照图或诊断图。局部图组第一张必须说明从哪个真实流程点接起；如果接下来进入专题 / 代表态 / 视角分支，用户可见标题必须写明分段起点，不能让连续编号暗示自然承接。

## 代理打开通道

默认不打开任何查看器。用户只要截图链接，统一给脚本返回的 `VIEWER_URL`。

1. 本地网页查看器：默认用 `scripts/verify/open-verified-image.mjs --dir "<最终截图目录>" --no-open` 注册目录并输出 `VIEWER_URL`；只有用户明确说“打开查看器”或“重新打开查看器”时，才去掉 `--no-open` 真实打开。一次调用传入整个最终媒体集合。
2. Windows / 系统查看器：只有用户明确要求系统查看器时使用；不能把系统查看器和网页查看器串联打开同一媒体。
3. Codex App Markdown 内联：只有用户明确要求“在这里打开 / 内联展示 / 发在对话里”时使用；默认仍给 `VIEWER_URL`。
4. PureRef：不再是默认通道；只在用户当轮明确要求 PureRef，或排查历史 PureRef 清单时显式使用。

### 稳定目录身份

- **目录是唯一身份**：端到端结果必须落在一个固定截图目录内；网页地址中的 `key` 只能代表这个目录，不能用单张图片文件名、测试标题、时间戳或 `focus/show` 参数充当身份。
- **固定文件名覆盖最新结果**：同一问题重跑时，成功用例覆盖同一目录内的固定截图文件名；测试开始或失败时不得先清空当前稳定图组，避免用户打开目录时看到半成品。
- **网页入口不是唯一可达性**：网页查看器 `VIEWER_URL` 是用户交付链接，但它依赖本机查看器进程和端口；注册目录时必须同时生成目录内的 `index.html` 离线入口。用户无法访问 `VIEWER_URL` 时，报告查看器阻塞和离线入口已生成，不在回复中裸露完整文件路径。
- **输出字段必须可回查**：目录入口命令应同时输出 `DIRECTORY_KEY`、`DIRECTORY_PATH`、`OFFLINE_VIEWER_FILE` 和 `VIEWER_URL`，其中 `DIRECTORY_KEY` 必须是短目录 key，不得再次输出本地路径冒充 key。

执行要求：

- 一次打开只选一个用户展示通道；一个通道成功后，不要再重复打开同一组图。
- 多图用本地网页查看器时必须一次传入同一最终图组目录内的媒体；如果最终证据来自多个截图目录，先生成本轮最终展示目录、中文索引和对应 `PASS` 清单，再真实打开。只做跨目录 `--dry-run` 不能证明用户可见多图能被真实打开。
- 查看器按目录去重，目录已打开时复用既有网址或返回已打开状态，不重复开窗口；只有用户明确要求强制重开时才使用 `--force-reopen` / `--reopen`。
- 多图交付后必须写清顺序映射，例如 `1. PC 选择态：事件牌 + 骰盘 + 属性选项`，不能只说“给了 4 张图”或“打开了 4 张图”。
- `view_image`、OCR、缩略图、裁切图、contact sheet 只有在宿主不会把图片渲染给用户时才可作为 AI 自检；一旦宿主会在对话、任务面板、网页查看器或外部窗口中展示图片，就按用户可见交付处理，必须满足最终 `PASS` 门槛。若没有私有看图通道，未 `PASS` 候选只能用非展示型机器检查、路径和文字证据推进，不能为了 AI 自检先打开。
- 给用户输出截图证据或代理打开，不等于 AI 验收；AI 核图必须另写图面事实和 `PASS` / `REVISE` 结论。

## 多图索引与标记

多张最终验收图默认依赖本地网页查看器左侧目录显示中文标题和承接说明，不额外生成重复索引表；只有用户明确要静态索引表、查看器不可用，或需要离线顺序图时，才用项目唯一标记脚本生成带序号的全尺寸标记副本：

```powershell
python ".spec/skills/show-image-to-user/scripts/label-image-sequence.py" `
  --out-dir "<evidence-dir>\_labeled-for-pureref" `
  --title "交互流程截图顺序" `
  --image "<absolute-image-path-1>" --label "万箭齐发卡牌：打牌前" --transition "起点：攻击已选中，卡牌仍在手牌" `
  --image "<absolute-image-path-2>" --label "万箭齐发卡牌：卡牌特写" --transition "从 01 打出万箭齐发 -> 弹出卡牌特写，并显示首次奖励骰结果描述"
```

- `.spec/skills/show-image-to-user/scripts/label-image-sequence.py` 是项目内唯一标记脚本；它生成 `NN-labeled-*` 和可供网页查看器读取的图组说明，只有显式未传 `--no-index` 时才生成 `00-sequence-index.png`。需要突出规则原文时传入 `--circle-effect --effect-only`，用户展示版只保留序号、逐字原文和红色框线，不重复打印步骤标题、承接描述或原图文件名。`_labeled-for-pureref` 是历史目录名，不代表默认使用 PureRef。
- 标记副本必须保持原始截图完整可见；如果序号、标题、说明栏、遮罩或水印压住了游戏画面、牌面、教程卡、按钮、地图、骰子或其它验收对象，该标记副本只能作诊断废图，不能进入 PASS 清单、不能输出为最终图证据，也不能替代原图验收。
- 本地网页查看器使用截图目录作为稳定身份；地址栏使用短 `key`，页面左侧索引显示中文说明，并按目录去重。默认注册但不打开。若用户明确要求网页查看器打开，才真实打开；若截图目录还包含其它媒体，查看器入口必须过滤到本轮 `PASS` 清单媒体，避免用户可见列表混入未验收内容。
- 标记图和索引里所有用户可见标题、步骤标签、承接说明和补充说明必须使用中文；原始文件名、代码文件名、测试名、`PASS` / `VIEWER_URL` 等技术输出可以保留作机器证据或终端日志，但不能替代用户可见中文说明。
- 用户可见说明只用于定位截图步骤，不得再写一段代理自己的技能 / 规则描述；凡是要解释卡牌、技能、状态或事件效果，必须直接显示规则真相源中的逐字原文。默认只保留序号、极短步骤索引和“效果原文”区，不能用 `label`、`transition`、测试名、内部 key 或 AI 改写充当效果说明。若用户要求红圈，使用 `--circle-effect --effect-only`，不重复显示步骤标题、承接描述或原图文件名。
- 标签必须写玩家能懂的步骤和对象类型，例如 `卡牌`、`技能`、`响应窗口`、`骰盘`，不能只写文件名、测试名或内部字段。
- 每张图从第二张开始必须说明相对上一张发生了什么；第一张必须说明起点或前置状态。
- 用户明确要求打开查看器且不加标记时，打开或复用原图目录并输出 `VIEWER_URL` 和有序映射；不在用户回复输出原图目录或完整图片路径。如果多图原图分散在多个目录，先复制到本轮最终展示目录并写入中文索引。必要时可另开独立序列索引。

## 执行入口

默认执行入口不按媒体数量分流：先完成 `PASS` 清单和路径核对，再用 `--no-open` 注册并输出脚本返回的 `VIEWER_URL`。用户明确要求打开查看器时，再去掉 `--no-open` 调用真实打开 / 复用。

校验单图 / 录屏 / 视频：

```powershell
node scripts/verify/open-verified-image.mjs --dry-run --pass-manifest "<本轮要求达标清单.json>" --path "<单张最终原图或录屏绝对路径>"
```

校验多图：

```powershell
node scripts/verify/open-verified-image.mjs --dry-run --pass-manifest "<本轮要求达标清单.json>" --paths "<01-labeled-*.png>" "<02-labeled-*.png>"
```

只生成可点击网址（仅当用户明确不要打开）：

```powershell
node scripts/verify/open-verified-image.mjs --dir "<最终媒体所在目录>" --focus "<首张媒体文件名>" --files "<媒体文件名1>" "<媒体文件名2>" --no-open
```

需要网页查看器时打开或复用单图 / 录屏 / 视频：

```powershell
node scripts/verify/open-verified-image.mjs --pass-manifest "<本轮要求达标清单.json>" --path "<单张最终原图或录屏绝对路径>"
```

打开或复用多图：

```powershell
node scripts/verify/open-verified-image.mjs --pass-manifest "<本轮要求达标清单.json>" --paths "<01-labeled-*.png>" "<02-labeled-*.png>"
```

- `scripts/verify/open-verified-image.mjs` 是最终媒体的 `PASS` 清单、路径校验和 `VIEWER_URL` 注册入口。默认先执行 `--dry-run` 校验，再用 `--dir ... --no-open` 注册并输出 `VIEWER_URL`。
- `scripts/verify/open-verified-image.mjs --dir ... --no-open` 是“给截图链接、不打开”的唯一入口。输出中的 `VIEWER_URL=...` 必须保留脚本生成的截图目录 `key`，是用户交付链接；不得把文件名、完整本地路径或手工 `focus/show` 参数当成目录身份。
- `scripts/verify/open-verified-image.mjs --dir ... --no-open` 注册目录时还会生成目录内 `index.html`。用户只需要长期保存这一目录；网页 key 和 `index.html` 都指向同一目录，目录内固定文件更新后，重新打开即可看到最新截图。
- `--pass-manifest` 指向的 JSON 必须只覆盖本轮用户要求，最低结构为：`verdict: "PASS"`、`scope: "current-user-request"`、`display: { "purpose": "final-user-visible-delivery", "trigger": "user-requested-evidence" | "user-requested-proxy-open" | "task-final-delivery", "viewer": "web", "finalPassBeforeOpen": true }`、`requirements: [{ requirement, status: "PASS", evidence: [...] }]`、`images: [...]` 或 `media: [...]`。脚本会校验每项要求都是 `PASS`、证据非空、交付目的为最终用户可见交付，并且本次涉及的图片 / GIF / 视频全部在清单中；这防止用“过程核图 / 我确认过了 / 泛化 UI PASS”代替本轮最终达标。
- `user-requested-open` 只作为历史 PASS 清单兼容值保留；新清单必须按现实动作区分 `user-requested-evidence` 和 `user-requested-proxy-open`。
- 查看器入口会记录最近成功打开的 PASS 清单和媒体列表；同一份清单或同一组媒体默认复用或返回已打开状态，不应报成失败。只有用户明确说没看到、打开错图、要强制重开或要改用另一通道时，才允许在同一命令后追加 `--force-reopen` / `--reopen`。
- PASS 清单必须覆盖截图可理解性所依赖的关键画面对象：如果最终图组里可见的卡牌、法术、技能、装备、附件、单位或牌库 / 法术书是本轮流程、动画来源、目标或上下文承载，必须有证据说明这些牌面 / 素材已经真实渲染、不是空白壳层或纯色占位。关键牌面空白时，不管动画像素、E2E、文件路径或脚本校验是否成功，都不得创建 `PASS` 清单，也不得输出为最终图证据或代理打开给用户。
- PASS 清单只写本轮验收对象；相邻按钮、牌堆、阶段条、HUD 或其它同屏元素只能作为“不遮挡 / 不相交 / 不抢职责”的辅助证据，不能混成第二个独立需求。若用户要求看“回合流程”，清单主项必须是阶段信息条；“确认计划 / 结束行动 / 结束回合”这类主操作按钮只能按按钮自己的任务另开验收项。
- 多图、`--paths`、`--path` 重复参数一律直接调用上述 `node` 入口；不要通过 `npm run verify:open-image -- --paths ...` 转发参数，避免 npm 把 `--paths` 或图片路径解析成自己的参数并产生误导性 warning。
- `open-verified-image.mjs --dir ... --no-open` 成功只证明可点击网址已经生成；打开脚本成功只证明打开 / 复用动作已发起并有进程 / 命令结果。用户说没看到、打开错图、图被标注遮挡、图为空或图组顺序错误时，按展示失败处理。若问题来自最终图或标记副本本身不真实，必须撤销本轮 PASS 清单并重新生成无遮挡图组；不得用同一清单反复重开。
- Codex App 内联只能使用绝对本地路径：`![说明](D:/absolute/path/image.png)`；路径含空格时用 `![说明](<D:/path with spaces/image.png>)`。

## 收口门禁

发送最终回复前做五问：

0. 本轮是否明确触发图片 / 动效交付：用户要求打开 / 看图 / 给截图 / 截图验收 / 录屏 / GIF / 看实际动效，任务交付物本身就是图片型 / 动效型验收物，或本轮已经完成 UI / 游戏画面 / 截图最终验收并选定 `PASS` 验收图？
1. 本轮是否已经选定最终用户验收图、最终有序图组或最终动效录屏？
2. AI 是否已经对同一张原图、同一组原图或同一份录屏给出通过结论，并用 `open-verified-image.mjs --dry-run` 校验过清单和路径？
3. 是否按用户要求交付：默认用 `--no-open` 注册并输出 `VIEWER_URL`，不打开查看器；用户明确要求查看器时，才打开或复用查看器并输出同一个 `VIEWER_URL`？
4. 若用户明确要求查看器，是否复用 / 返回已打开状态而不是重复开窗口？如果打开失败，是否给出失败证据和最小补救动作？

如果 0 为否，不主动调用查看器；只按任务需要汇报截图清单、核图结论或 evidence。若 0、1、2 为是，默认用 `--no-open` 注册并输出 `VIEWER_URL`。只有用户明确要求查看器时，才需要真实打开 / 复用查看器。子 agent 可以协助找图、核图、生成标签、执行 dry-run 或生成 `VIEWER_URL`；父 agent 负责当前用户可见回复，不能把子 agent 私有消息、`view_image` 预览、路径或查看器命令当成用户已看到。

## 失败处理

- 路径找不到：先列目录核实，再用解析后的绝对路径重试。
- 文件来自截图工具：先确认存在且大小非零。
- `--dry-run` 未通过：不得输出最终 `VIEWER_URL` 或代理打开；汇报哪个现实交付条件未满足、证据在哪里、为什么阻止交付、最小补救动作是什么。
- 用户明确要求打开 / 复用本地网页查看器，或默认注册 `VIEWER_URL` 但失败：汇报本地网页查看器失败的现实后果、`logs/e2e-image-viewer.log` 或命令输出里的证据、为什么阻止用户按链接看图、最小补救动作。不得用完整图片路径冒充链接。
- 输出入口不足：`VIEWER_URL` 是默认用户交付。`VIEWER_URL` 注册失败时，不能宣称截图链接已交付；汇报现实后果、证据和最小补救。
- 本地网页查看器启动失败：先查看 `logs/e2e-image-viewer.log`，确认端口和目录。只有用户明确要求系统查看器时，才转系统图片查看器。
- 目录复用失败或意外打开了新网页窗口：汇报目录 key、端口和状态文件，不说“已复用旧窗口”。
- 用户明确要求查看器但未渲染：先确认查看器目录、端口和日志。不得把查看器失败改写成截图文件直链失败。默认直链交付仍可继续。
- 本地网页查看器、系统图片查看器和内联都失败：汇报目标路径、文件是否存在、尝试过的通道、最小补救动作；不要反复重开。
