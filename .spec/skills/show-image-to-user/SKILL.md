# Show Image To User

## 单一职责

本 skill 定义“把本地图片展示给用户本人看”的项目入口。

- 截图是否具备 E2E / UI 验收资格，不在本入口定义。
- AI 自己读图、核图和 `PASS` / `REVISE`，不在本入口定义。
- 大图安全读取、降采样和裁切，不在本入口定义。
- 本入口不维护第二套截图验收正文；它只裁决选哪张图、用什么用户展示通道、失败时怎么回报。

项目约定：

- 主证据目录：`test-results/evidence-screenshots/<game>/<测试文件>/<用例>/`。
- 候选图、失败图、中间排查图不能冒充最终验收图；它们只能作为路径或诊断材料报告。
- 服务器相册不是默认交付。只有用户明确要求上传、发布链接、服务器相册或手机查看时，才允许发布到 `http://8.148.71.102:18080/#/boardgame/<task-id>`。
- 获得上传授权后，只允许更新 `/home/admin/image-preview/data/projects/boardgame/tasks/<task-id>/`，禁止改预览站壳层、根路由或客户端代码。

## 开图时机（强制）

- 打开图片是本轮图片型交付的完成信号，不是排查过程动作。实现、测试、截图链、AI 核图或证据选择还没完成时，不得调用 PureRef、系统图片查看器或 Codex App 内联展示；最多报告候选路径、缺口和下一步。
- 用户说 `图呢`、`我看看` 或类似表达时，先判断是否已经具备最终验收图或最终有序图组：具备则展示；不具备则先补实现、补 E2E、补截图链或补核图。禁止为了回应催图而先打开旧图、单张候选图、过程图或截图目录。
- 同一轮同一张图或同一组图只展示一次。展示通道成功后，除非用户明确说没看到、打开错图、要重开或要改用另一通道，否则不得重复调用查看器。
- 只有用户明确要求“现在就打开这张诊断图 / 失败图 / 历史图 / 候选图”时，才允许在未完成收口前打开非最终图；汇报必须同时标明它不是最终验收图，不能把这次开图当完成信号。

## 触发条件

这些表达都表示用户要看见图片本身：`打开图片`、`打开图`、`图呢`、`给我看图`、`截图呢`、`我看看`、`重新打开`。

- 用户明确要看图时，先完成用户可见展示，再解释；不能先用 `view_image`、OCR、contact sheet 或路径回复替代。
- 工作流已经选定最终验收图或最终有序图组，且 AI 核图通过时，最终回复前必须展示同一张原图或同一组原图。
- 用户只要求“给路径 / 证据路径”时，只给绝对路径，不打开查看器。
- `E2E passed`、`截图已生成`、`证据已更新`、`我需要看一下图` 都不是打开本地查看器的授权；只有最终验收图已通过或用户明确要看时才展示。

## 选图规则

- 选图必须匹配当前目标：PC / mobile / 横屏 / 当前游戏 / 当前流程不能靠宽泛关键词或最新时间戳乱配。
- 修代码、样式、数据后要看当前效果时，默认先重拍当前工作树、当前入口、当前目标状态的新图；旧图只能标为历史证据。
- 单图只能证明单帧。翻页、前后态、PC/移动对照、弹窗开关、流程步骤或分支状态默认交付最小有序图组。
- 原图优先：用户说 `原图`、`未压缩`、`压缩前`、`原始截图` 时，禁止打开缩略图、裁切图、OCR 图、contact sheet 或压缩预览。
- 验收图默认用真实原始截图；标记副本只作为多图顺序辅助，必须保留并汇报原始路径。
- 如果最新相关图是失败、过期或诊断图，用户明确要看时也要打开，但必须标明它不是最终验收图。

## 展示通道

BoardGame 默认展示顺序：

1. PureRef：默认用户展示通道，Codex App / Codex desktop 也一样。
2. Windows / 系统图片查看器：PureRef 不可用、未保持运行或无法接收图片时使用。
3. Codex App Markdown 内联：只有用户明确说“在这里打开 / 内联展示 / 发在对话里”，或外部查看器都失败时使用。

执行要求：

- 一次交付只选一个用户展示通道；一个通道成功后，不要再重复打开同一组图。
- 多图用 PureRef 时必须一次性传入整个路径数组，禁止每张图各启动一次 PureRef。
- 多图交付后必须写清顺序映射，例如 `1. PC 选择态：事件牌 + 骰盘 + 属性选项`，不能只说“打开了 4 张图”。
- `view_image`、OCR、缩略图、裁切图、contact sheet 是 AI 自检，不是用户展示。
- 给用户看图不等于 AI 验收；AI 核图必须另写图面事实和 `PASS` / `REVISE` 结论。

## 多图标记

PureRef 打开多张最终验收图时，默认先生成带序号的全尺寸标记副本：

```powershell
python ".spec/skills/show-image-to-user/scripts/label-image-sequence.py" `
  --out-dir "<evidence-dir>\_labeled-for-pureref" `
  --title "交互流程截图顺序" `
  --image "<absolute-image-path-1>" --label "万箭齐发卡牌：打牌前" --transition "起点：攻击已选中，卡牌仍在手牌" `
  --image "<absolute-image-path-2>" --label "万箭齐发卡牌：卡牌特写" --transition "从 01 打出万箭齐发 -> 弹出卡牌特写，并显示首次奖励骰结果描述"
```

- `.spec/skills/show-image-to-user/scripts/label-image-sequence.py` 是项目内唯一标记脚本；它生成 `00-sequence-index.png` 和 `NN-labeled-*`，不覆盖原图。
- PureRef 多图默认打开顺序：`00-sequence-index.png` 在前，后接 `01-labeled-*`、`02-labeled-*` 等，路径顺序必须和可见编号一致。
- 标记图里所有用户可见标题、步骤标签、承接说明和补充说明必须使用中文；原始文件名、代码文件名或测试名可以保留作证据，但不能替代中文说明。
- 标签必须写玩家能懂的步骤和对象类型，例如 `卡牌`、`技能`、`响应窗口`、`骰盘`，不能只写文件名、测试名或内部字段。
- 每张图从第二张开始必须说明相对上一张发生了什么；第一张必须说明起点或前置状态。
- 用户明确要求不加标记时，打开原图，但仍提供有序映射；必要时可另开独立序列索引。

## 执行入口

单图：

```powershell
node scripts/verify/open-verified-image.mjs --viewer pureref --path "<单张最终原图绝对路径>"
```

多图：

```powershell
node scripts/verify/open-verified-image.mjs --viewer pureref --paths "<00-sequence-index.png>" "<01-labeled-*.png>" "<02-labeled-*.png>"
```

- `scripts/verify/open-verified-image.mjs` 是查看器执行入口；它负责解析路径、调用 PureRef / 系统查看器并回报结果。
- 多图、`--paths`、`--path` 重复参数一律直接调用上述 `node` 入口；不要通过 `npm run verify:open-image -- --paths ...` 转发参数，避免 npm 把 `--paths` 或图片路径解析成自己的参数并产生误导性 warning。
- 脚本成功只证明打开动作已发起并有进程/命令结果；用户说没看到、打开错图、只有一张或图为空时，按展示失败处理并重选正确原图或完整图组。
- Codex App 内联只能使用绝对本地路径：`![说明](D:/absolute/path/image.png)`；路径含空格时用 `![说明](<D:/path with spaces/image.png>)`。

## 收口门禁

发送最终回复前做三问：

1. 本轮是否已经选定最终用户验收图或最终有序图组？
2. AI 是否已经对同一张原图或同一组原图给出通过结论？
3. 同一轮是否已按本 skill 完成 PureRef / 系统查看器 / 明确内联展示，或给出展示失败证据？

如果 1、2 为是而 3 为否，禁止收口；先展示再汇报。子 agent 可以协助找图、核图、生成标签或执行查看器命令，但父 agent 负责当前用户可见回复，不能把子 agent 私有消息、`view_image` 预览或路径当成用户已看到。

## 失败处理

- 路径找不到：先列目录核实，再用解析后的绝对路径重试。
- 文件来自截图工具：先确认存在且大小非零。
- PureRef 未安装、未保持运行或未接收图片：转系统图片查看器。
- 复用 PureRef 失败并开出新进程：汇报前后进程 ID，不说“已复用旧窗口”。
- 内联图未渲染：改走 PureRef / 系统图片查看器。
- 两类外部查看器和内联都失败：汇报目标路径、文件是否存在、尝试过的通道、最小补救动作。
