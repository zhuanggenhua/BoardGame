# 新增派系 / 角色 / 可玩单元工作流

## 职责边界

本 skill 只承载已有游戏新增可玩对象的通用端到端顺序。新游戏从零创建走 [create-new-game](../create-new-game/SKILL.md)。已有更具体专项 workflow 时，以专项 workflow 为主，本 skill 只保留通用完成门槛。

主源分工：

- 数据录入：[data-entry](../../knowledge/standards/data-entry.md)
- 资源链路：[asset-pipeline](../../knowledge/standards/asset-pipeline.md)
- 机制审计：[description-to-implementation-audit](../../knowledge/standards/description-to-implementation-audit.md)
- 审计 evidence：[audit-evidence-template](../../knowledge/standards/audit-evidence-template.md)
- E2E 证据：[e2e-verification](../../knowledge/standards/e2e-verification.md)
- 测试审计：[testing-audit](../../knowledge/standards/testing-audit.md)

本 skill 不复制这些标准；冲突时先改主源，再同步 workflow。

## 完成定义

新增对象不是“能显示图”或“能进入游戏”。只有以下六类都闭合，才能说新增完成：

1. **数据录入**：逐对象真相源、结构化字段、i18n、代码定义可追溯。
2. **资源链**：正式资源、压缩、manifest、运行时引用、服务器素材主源发布和远端回查完成。
3. **机制实现**：规则子句、技能、token、状态、卡牌效果、时机、目标、强制/可选语义已实现或明确冻结。
4. **审计 evidence**：当前锁定对象集都有对象级审计行、原子语义、实现消费点、最终权威结果、测试 / 截图证据和残余范围。
5. **真实入口 E2E**：按玩家可见生命周期验收；隐藏阶段证明玩家入口不可见且内部入口可初始化，进入实施中或完成态后才证明玩家可选择、关键 UI 可见。
6. **风险收口**：未实现或未验证项只能是 `blocked` 或用户确认的 `scoped-debt`，不能混入完成结论。
7. **真人完成确认**：即使实现、审计、E2E 和 evidence 全部通过，也必须收到用户当轮明确同意进入完成态，才能移除实施中标记；测试通过不能替代真人确认。

数据录入是新增派系的第一优先级。任何实际读取过的派系图片、图集、截图或裁图，都必须先登记对象、槽位、图面字段、最终处置和处置依据；不能先判断图片是否有用来跳过登记。锁定录入合同后，卡牌描述、i18n、运行时定义和机制实现只能消费该合同，不能分别重写规则。

角色能选、入口可见或成功进入牌桌，只能填入口轴证据。它不能替代机制实现、交互截图、审计 evidence、风险收口，也不能单独支撑“全面审计”“新增完成”或“实施完成后可进入实施中”的结论。

## 范围锁定

开工前先锁：

- `gameId`
- 新增对象 ID、中文名和英文名
- 素材目录、规则书、Wiki 或用户指定真相源
- 当前 worktree / 分支职责
- 用户目标：只做 intake、做到可选、做到可玩，还是彻底收口
- 是否存在专项 workflow

新增任务默认需要审计留档，但不自动扩大到同游戏全部兄弟对象。只有用户明确要求整批全集，或缺口位于共享消费者、同一素材合同源、同一规则合同源等直接影响路径，才扩大范围。

## 批次矩阵

必须建立批次矩阵：

| objectId | 数据录入 | 资源链 | 机制实现 | 审计 | E2E | 状态 |
| --- | --- | --- | --- | --- | --- | --- |

每格只能填：

- `pending`
- `in_progress`
- `passed`
- `blocked:<现实原因>`
- `scoped-debt:<用户确认冻结范围>`

没有证据不得填 `passed`。当前锁定范围全为 `passed`，或剩余只是不阻塞且用户确认冻结的 `scoped-debt`，才允许停止。未锁定兄弟对象不得自动阻塞当前范围，也不得被当前代表链自动外推完成。

## 玩家可见生命周期

新增对象默认按三段玩家可见生命周期推进，不能把“刚新增 / 素材上传 / 部分测试通过”直接放进玩家选角入口：

1. `hidden`：数据、资源、机制、审计或真实入口仍未完成时使用。玩家可见入口、自动选角和直接玩家命令必须过滤；内部测试、状态注入、配置审查和资源验证可以保留完整对象。
2. `in_progress`：实施已完成并经过当前范围审计，但仍有明确非发布级风险、体验验证缺口或用户确认的残余范围时使用。此时才允许玩家可见，并用既有实施中标记说明未完成发布级收口。
3. 完成态：当前范围全部 `passed`，或只剩用户确认且不阻塞的 `scoped-debt`，evidence 没有未冻结风险，并且已收到用户当轮明确同意进入完成态后，才能移除实施中标记。

`in_progress -> 完成态` 是人工确认闸门，不得由审计通过、测试通过、截图通过、任务勾选或 agent 自行判断自动触发。用户只说“继续”“审计完了吗”或“可以继续新派系了吗”，不等于同意移除实施中标记；必须保留 `in_progress`，直到用户明确表达完成态批准。

从 `hidden` 切到 `in_progress` 前，必须同时满足：实现子项已完成、审计 evidence 已覆盖当前范围、玩家入口风险已说明、直接命令和自动选角不会绕过当前状态门槛。

若新增对象引入任何新交互族、新状态消费、新按钮、新选择、新骰子 / 随机流程、响应窗口或新 UI 表现，切到 `in_progress` 前还必须按 [E2E 与截图验收规范](../../knowledge/standards/e2e-verification.md#流程截图) 完成交互截图组，或把未完成部分在批次矩阵和 evidence 中登记为用户确认的 `scoped-debt`。没有交互截图组时，只能说“入口已开放为实施中候选 / 入口轴通过”，不得说“当前范围已审计完成”。

## S1 数据录入

每个对象至少落三类资料：

- 真相源表：素材、路径、用途、获取日期、对照源。
- 录入核对：技能、单位、token、状态、基础规则逐项结构化。
- 对象核对表：每张卡、每个单位、每个子对象逐行记录。

最低粒度：

- 每个技能、token、状态、卡牌、单位、建筑、基地等都独立一行。
- 每行包含来源定位、原文要点、结构化字段、实现状态、疑点。
- 玩家板上的每个基础技能、每个升级技能等级和每个卡牌技能区都必须逐句拆成规则子句 / 原子语义表：触发时机、入口、主效果、附加条件、阈值奖励、替代入口、额外触发、例外/否则、资源 / 状态变化、清理、每回合/每局限制。不能把同一技能的“造成伤害”和“满足条件后获得资源 / 状态”合并成一行，也不能因为同一物理槽位或同一升级链就省略某一级的语义核对。
- 可选、至多、任意数量等语义必须记录“合法候选存在时可以跳过/空选”的证据需求。
- 图片能判定槽位、区域、atlas 或布局时，S1 同步产出可视合同表：`visualRegion/slotId -> 图上对象 -> 运行时对象 -> 允许状态 -> 是否可交互`。

禁止：

- 只录名称、费用或图片索引就写录完。
- 看不清数字、目标、时机时靠猜。
- 把临时裁图当正式运行时资源。
- 对大图、扫描图或拼图直接整张视觉读取；大图先做总览、分块和必要单格裁图。

## S2 资源链

必须区分原始素材、临时核对裁图、正式运行时压缩资源、atlas/config 资源。

步骤：

1. 生成或确认正式 `compressed/*.webp`。
2. 确认代码引用不硬编码 `compressed/`。
3. 对照新素材与旧合同：一致则复用；不一致则建立新增对象独立合同或分流。
4. 重建 manifest，并验证新增键实际写入根级和游戏级 manifest。
5. 运行资源校验。
6. 单对象 / 单批次优先用带 `--asset-prefix` 的资源发布预检和上传；只有任务本身是全仓资源发布或用户明确授权，才跑无过滤全仓上传。
7. 对代表 URL 做 `HEAD` 或等价远端回查。

共享资源禁令：

- 新增对象的新素材、新尺寸、新索引模型不得反向覆盖既有对象依赖的共享 atlas、sprite、索引、公共路径、解析函数或渲染合同。
- 怀疑共享合同错误时，必须升级为共享合同迁移/修复任务，列出既有消费者和影响范围，取得明确授权，并提供老对象回归证据。
- 缓存、manifest hash 或实际请求 URL 问题不能通过改共享合同来修。

## S3 机制实现

从真相源逐项裁定：

- 子句：每一句、每个分号、特殊能力、持续、否则、额外、每回合一次、任意顺序等都独立验收。
- 权限：玩家操作、响应、特殊行动、替代、防止、延迟、额外行动必须裁定授权玩家、入口、允许命令和禁止命令。
- 目标：self / opponent / any / player / unit / card / base 等必须明确。
- 时机：打出时、结算前、响应窗、回合结束等必须落到正式消费点。
- 强制/可选：必须有交互或自动结算理由。
- 消耗：资源、手牌、token 何时消耗。
- 状态归属：正式状态、系统交互状态、EventStream、UI 派生必须分开。

每个可执行对象建立机制消费清单：

| objectId | 真相源 | 静态定义 | 候选/入口 | 命令/执行 | 消耗/限制 | 主效果 | 分支/否定 | 后续清理 | 证据 | 状态 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |

入口证据不能替代最终权威结果。prompt 出现、slot 可点、pending 状态存在，只能证明进入中间态；主效果和清理必须回到生命、token、手牌、资源、状态、交互队列或等价权威状态。

选角图、玩家板静态图、角色可选、进入牌桌、单条主伤害断言或一条代表性流程通过，都只能证明对应证据轴；它们不能证明派系的附加条件、阈值奖励、资源 / 状态消费、新选择、新骰子结果或其它新交互已经实现。每个新增交互族都必须补自己的命令 / 状态 / 最终结果断言，并在需要时提供真实入口截图组。

使用共享框架字段时，必须反查实际 resolver / system / pipeline 消费点，而不是只看类型定义允许。新增对象命中共享消费点时，补合同测试或等价验证；若测试同时命中旧对象，旧对象纳入同轮修复、降级或残余范围说明。

## S4 审计 evidence

审计必须落到 `evidence/<gameId>/`；无文档等于未审计。

用户或任务名只说“审计 / 全面审计 / 深入审计 / 收口审计 / 做到底”时，默认含义是当前锁定范围内每个对象都有独立审计行，且逐项覆盖：

- 对象范围。
- 真相源状态。
- 原子语义断言。
- 实现消费链。
- 最终权威结果。
- 真实入口证据。
- 验证证据。
- 共享影响和代表链依据。
- 旧 evidence / 旧结论回写。
- 残余范围声明。

审计自检表必须放在 evidence 前三屏内，并使用可搜索状态：`passed`、`representative_only`、`blocked`、`scoped_debt`。任一项缺失，只能降级为代表性验证或仍有残余范围，不得写“全面审计完成”。

代表链复用只允许在“共享链路完全同构，仅配置不同”时使用，且必须写清代表对象、共享链名称、判等依据和剩余差异。差异不止配置项时，不得复用深层证据。

旧 evidence 被当前代码、测试或真实入口推翻时，先回写旧结论，标明历史快照、替代证据和当前残余范围；正文高风险旧行不能只靠文首声明遮盖。

## S5 真实入口 E2E

E2E 必须来自真实入口，最低证明：

- `hidden` 阶段：新对象不会出现在真实选择 / 组建入口，直接玩家命令和自动选角也不能选到它；内部状态注入或测试入口仍能初始化对象并验证资源 / 机制。
- `in_progress` 或完成态：新对象能在真实选择 / 组建入口出现，并能被真实玩家选择或使用。
- 能进入真实游戏或真实交互场景。
- UI 中能看到新增对象本体或关键识别特征。
- token、状态、标记图标必须证明使用预期 sprite / atlas / 图片，而不是纯色、文字、加载态或兜底样式。

上述最低证明只覆盖入口合同。新增对象的规则交互、状态消费、骰子 / 随机、响应窗口或特殊 UI 必须另按 [E2E 流程截图](../../knowledge/standards/e2e-verification.md#流程截图) 形成交互截图组；不得用选角图、角色头像、开局牌桌或静态玩家板证明这些交互已可用。

复杂交互必须补成功路径截图链：

- 触发前 / 入口。
- 每段选择出现；候选只有一个时也要证明玩家手动点选 / 确认，除非它不是玩家选择而是固定结果收口。
- 执行关键动作后状态变化。
- 收口后可继续推进。

新增交互类型、新 UI 表现或新操作方式时，必须至少补一条 direct E2E，并在汇报中给出 E2E 文件路径、至少一张本轮核对截图路径、观察结论。

## S6 完成判定

只有当批次矩阵全部为 `passed`，且 evidence 中没有未冻结风险，才能说新增完成。

不得完成的情况：

- 自检表仍有 `representative_only`、`blocked`、`scoped_debt`。
- 结论段仍写有残余范围。
- 真实入口只覆盖代表对象，但没有共享链判等矩阵证明其它对象仅配置不同。
- 真实入口只证明可见、可选或进入牌桌，缺少新增交互族截图组或共享流程判等矩阵。
- 本轮只是降级旧误称、补自检表、列残余范围或修正 evidence 口径。

仍有 `blocked` 或未冻结 `scoped-debt` 时，只能说“完成到某证据轴”，并列剩余对象与缺口轴。用户要求“重来 / 彻底完成 / 做完再停”时，继续执行，不得停在总结。
