# 移动端适配审查清单

本清单只服务 [`adapt-game-mobile`](../SKILL.md)，不另立规范。

## 读取输入

- 游戏入口：`src/games/<gameId>/manifest.ts`、`Board.tsx`、`ui/`。
- 共享能力：`src/shared/mobileSupport.ts`、移动壳、手势 hook、共享按钮 / 弹层组件。
- 标准：`ui-responsive-layout`、`ui-ux`、`engine-systems`。
- 实现入口不清时，再查 [`docs/mobile-adaptation.md`](../../../../docs/mobile-adaptation.md)。

## 风险归属

每个问题先归类：

- `framework`：应沉到通用移动壳、公共 hook 或公共组件。
- `game`：游戏层必须声明或小范围修正。
- `blocked`：当前框架缺能力，先补框架再适配游戏。

不得把框架能力缺口写成单游戏补丁，也不得把单游戏例外上抬成通用规则。

## PC 护栏

- PC 主布局、主战区比例、阅读顺序和视觉层级未被移动端改动影响。
- 所有尺寸压缩、折叠、触控入口和移动 shell 样式都被 `1023px` 窄视口或明确移动条件门控。
- `coarse pointer` 只用于 hover 替代显隐，不用于缩小桌面 UI。
- 主体画布、棋盘、地图、卡面、格子和背景保持等比缩放，不为塞进视口单独改宽高。
- 触控命中区和可见视觉尺寸分开处理；不得统一加大 / 缩小共享按钮或全局图标类。

## 交互检查

- hover 详情有点击、长按或信息按钮 fallback；原有点击查看 / 放大 / 展开语义仍保留。
- 关键拖拽有点击选中 -> 点击目标 -> 确认的备选路径。
- 次要侧栏、日志、帮助可折叠；核心摘要信息仍在主视图可发现。
- 触控状态机不得让桌面端多出“先选中 / 先展开 / 先 armed”步骤。
- 若触及共享 inspect、手势 hook 或 `coarse pointer` 分支，必须补原点击语义防回归。

## 手机横屏验收

默认至少验证一个手机横屏；若用户明确说平板按 PC 看，则不单独补平板。

- 基线保持 `2340x1080` 的 `13:6`；E2E 可用 `936x432` 等比例缩小。
- 能进入对局、查看手牌 / 资源、查看状态 / 说明 / 日志、完成一个主操作、完成确认或取消。
- 不手动缩放也能读懂当前局面。
- 主体画布等比，关键入口在视口内，`.mobile-board-shell` 不横向溢出。
- 主状态截图必须人工核对：主棋盘锚点、浮动控件缩放、手牌 / 底部空间、遮挡、出屏和主次关系。

## PC 对照验收

- 默认对比 `1920x1080` 桌面主态。
- 主战区、侧栏、顶部 / 底部操作区没有被移动端样式压缩。
- 桌面 hover、按钮尺寸、面板宽度、点击查看 / 放大 / 展开语义保持。
- 桌面端主体画布比例未变，棋盘 / 地图 / 卡面没有拉伸或压扁。

## E2E 与 evidence

- 只为本轮声明支持移动或改动触及的路径补移动视口 E2E。
- 单文件 / 单用例优先：`npm run test:e2e:ci:file -- <测试文件名> "<用例名>"`。
- 整文件复跑：`npm run test:e2e:ci -- <测试文件名>`。
- evidence 记录视口、交互路径、截图绝对路径、PC 对照结论和移动结论。
- 线上问题至少保留一张线上现状截图；本地修复图不能替代线上现状。

## 容器升级门槛

只有 H5 / PWA 横屏适配、E2E、截图核图、非 hover 主循环、非高精度拖拽主循环和性能风险都通过后，才允许声明 `app-webview` 或 `mini-program-webview`。
