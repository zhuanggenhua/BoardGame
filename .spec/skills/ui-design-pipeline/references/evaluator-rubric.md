# UI Evaluator Rubric

用于评估设计稿、实现截图或真实页面。评分不是为了好看，而是为了判断是否能进入下一步。

## 检查维度

| 维度 | 回到声明 | 通过标准 |
| --- | --- | --- |
| 目标与状态 | `spec` | 主路径、空态、加载态、错误态、权限/等待态和验收标准清楚 |
| 参考基线 | `reference` | 有成熟答案时已抽象第一眼信号、对象关系、状态链和禁区 |
| 探索基线 | `exploration` | 无标准答案时已锁约束、假设、设计轴、风险和收敛矩阵 |
| 业务语义 | `domain` | 状态、风险、分类、资源、危险动作没有混用 |
| 组件职责 | `components` | Badge/Tag/Dialog/Drawer/Button/Table/Card 等用途符合语义 |
| 骨架与密度 | `template` | 主视线、操作入口、辅助区和最大承载量成立 |
| 视觉系统 | `design` | 颜色、字号、间距、动效走 token 或设计系统，不随手 hardcode |
| 工艺质量 | `craft` | 没有 AI 味、等大白卡、无意义动效、解释性常驻正文 |
| 可实施性 | `execution contract` | 明确哪些必须高保真复刻，哪些可降级 |
| 真实验收 | 项目 workflow | 按用户授权判断是否需设计稿批准；实现回到真实路由和截图/E2E 验收 |

## 回流格式

```text
issue:
  具体描述用户看得见的问题
source:
  spec | domain | design | components | craft | template | execution contract
fix:
  下一轮应修改的声明、prompt、设计稿或代码位置
severity:
  blocking | major | minor
```

## 阻塞级问题

- 缺少主路径、关键状态或用户原始目标。
- 用户要求商业级或复刻成熟产品，却没有 reference baseline 和 gap matrix。
- 用户要求探索没有标准答案的 UI，却没有约束、设计依据或假设验证；要求多方案时还缺少可比较的设计轴和裁决记录。
- 用户要求设计稿，却交付网页、静态 HTML 或运行截图顶替。
- 规则/素材已有对象被程序化占位或相似元素顶替，且没有批准。
- 成品里的核心对象仍像程序化占位、文字壳、网页组件或调试图形，却被描述成商业级 / 正式资产。
- 关键动作只有状态变化，没有成熟产品级按压、选中、移动、落点、切换或结果揭示反馈，却被描述成完整动效生命周期。
- 组件语义错误导致用户判断变慢，例如风险、状态、分类混用。
- 主交互入口不可发现、对象选择被代理按钮替代、唯一下一步像卡死。
- 设计稿依赖不可复刻材质/光效表达关键信息。
- 真实页面截图中当前任务所需内容被错误遮挡或不可操作、主对象过小，或违反布局合同；合法上层模态覆盖下层不单独构成失败。
- 截图只证明技术链路可用，但无法证明成熟 UI 的核心状态链和第一眼信号成立。

## 通过口径

- **通过**：无 blocking；major 都有明确修复或用户批准延期；验收入口已覆盖。
- **回流**：存在 blocking 或关键 major，必须回到对应声明或实现步骤。
- **部分通过**：只证明某一层成立，例如“视觉方向可用，但组件语义未锁定”。
