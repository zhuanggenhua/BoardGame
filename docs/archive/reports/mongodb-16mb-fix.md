# MongoDB 16MB 限制修复归档

本文记录传输层迁移前的一次历史存储问题。旧框架字段已不再代表当前结构；当前状态清理逻辑必须以现有 `StoredMatchState` 和存储代码为准。

## 当时问题

单个对局文档超过 MongoDB 16MB 限制，触发 BSON 文档过大错误。

## 当时根因

- 清理路径访问错层，实际游戏状态在旧结构的 `G.sys` 下，导致清理没有生效。
- 事件日志、旧框架 deltalog 和 undo 快照持续增长。
- 部分事件 payload 保存了完整能力定义或完整牌库顺序。

## 当时修复

- 修正状态清理路径。
- 限制持久化日志和 undo 快照数量。
- 大型事件 payload 改为只保留必要摘要。
- 增加状态大小诊断和数据库清理脚本。

## 当前使用口径

本文只作为历史背景。遇到当前存储膨胀问题时，必须重新查看现有存储结构、真实文档大小和清理代码。
