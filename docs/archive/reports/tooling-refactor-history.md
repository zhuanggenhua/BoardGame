# 调试工具重构归档

本文是旧调试面板重构记录的精简归档，不作为当前调试工具规范。当前调试入口、作弊命令和测试工具以现有源码、`.spec` 支撑能力标准和测试为准。

## 当时目标

旧重构要解决的是通用调试面板承载过多单游戏作弊指令，导致通用组件越来越难维护，也不利于其它游戏复用。

## 当时改动

### 通用调试面板职责收窄

`GameDebugPanel` 当时被保留为通用框架，负责：

- 视角切换。
- 标签页和布局。
- 状态查看。
- 动作执行。
- 重置 / 新建房间。
- 状态复制和赋值。

当时从通用面板中移除了硬编码的 DiceThrone 资源作弊 UI。

### 游戏专属配置下沉

旧文档记录新增过 `src/games/dicethrone/debug-config.tsx`，承载 DiceThrone 专属调试工具：

- CP / Health 资源修改。
- 5 个骰子独立改点，含全部设为 1 或全部设为 6。
- Token 数量调整。

旧接入形态：

```tsx
<GameDebugPanel G={rawG} ctx={ctx} moves={moves} playerID={playerID}>
  <DiceThroneDebugConfig G={rawG} ctx={ctx} moves={moves} />
</GameDebugPanel>
```

当前文件名和 props 以现有源码为准，不能照搬。

## 当时架构裁决

当时保留的裁决是：

- 通用面板只管通用调试框架，不放单游戏资源、骰子、Token 的具体按钮。
- 单游戏作弊命令 UI 放到该游戏自己的配置组件。
- 引擎层可以保留通用作弊命令，例如设置资源、阶段、骰子、Token 或直接设置状态。
- 新游戏若需要调试工具，应新增游戏专属配置，不继续膨胀通用组件。

## 当时测试建议

旧文档要求手动验证：

- 启动开发服务器。
- 进入 DiceThrone。
- 打开右下角调试面板。
- 切到系统标签页。
- 检查资源修改、骰子调整、Token 调整和状态更新是否生效。

当时还记录过一些构建错误属于其它历史问题，不应当作本归档能证明的当前状态。

## 后续记录

旧文档后来补过“卡牌名称显示通用化”：

- 当时发现 Smash Up、DiceThrone、Summoner Wars 的调试面板卡牌名称解析方式不一致。
- 曾新增通用解析器，按 DiceThrone i18n、Smash Up 翻译 key、Summoner Wars `card.name` 等路径依次解析。
- 当前是否仍存在该解析器，需要回到现有 `src/components/game/framework/debug/` 或等价位置确认。

## 当前使用口径

- 本文保留职责拆分思路，不是当前接口说明。
- 若当前要改调试工具，先确认通用调试面板和游戏专属配置的真实职责。
- 不要把某个游戏的临时按钮塞回共享组件。
