# E2E 测试重构旧提案归档

本文是旧测试重构提案摘要。当前 E2E 口径以 [`.spec` E2E 标准](../../../.spec/knowledge/standards/e2e-verification.md) 和当前测试脚本为准。

## 当时问题

- 启动慢：每次依赖前端、游戏服务器和 API 服务器。
- 设置慢：完整 UI 选人 / 选派系流程耗时高。
- 不稳定：网络、UI、随机性和异步状态同步都会引入波动。
- 难并行：服务端缺少 per-test 状态隔离时只能串行。

## 当时建议

- 短期：用 fixture 和状态注入缩短 setup，先稳定高风险场景。
- 长期：采用混合方案，将低层合同测试、代表态 E2E 和少量真实黄金链分层。
- 保留原则：真实黄金链只证明连续玩家流程；状态注入链只能作为分段或代表态证据。

## 当前使用口径

不要按本文旧方案新建测试体系；遇到 E2E 设计问题，先查当前 `.spec` 标准和项目 skill。
