# 纸牌帮两副牌与上手/下手触控裁定（2026-07-28）

## 用户原始裁定

- 纸牌帮的上手、下手按钮不能贴在屏幕底部；这是最不好按的位置。
- 本轮说的是上手、下手按钮，以及两副牌模式。
- 交换牌发生在开始游戏前，不是在正式抢劫开始后或每轮筹码后。
- 这类 UI 设计必须先对齐触控规范，再更新文档，不能靠临时感觉摆按钮。

## 覆盖范围

- 纸牌帮（`the-gang`）两副牌模式的产品合同、UI 合同和验收口径。
- `上手 / 下手` 作为两副牌目标选择按钮、手牌行标签和筹码归属的表达方式。
- 两副牌交换牌的发生时机：开局配置期、房主点击 `开始抢劫` 前。
- 移动横屏和桌面截图验收中，上手/下手按钮的触控位置、尺寸和语义。

## 正式口径

1. `两副牌` 指每名玩家有上手和下手两副独立手牌；两副手牌分别拿筹码、分别参与排序和摊牌。
2. `上手 / 下手` 可以作为手牌行标签；承接点击的按钮必须表达动作，例如 `给上手 / 给下手`、`交换上手 / 交换下手`，不能只写 `上手 / 下手` 让玩家误读成普通标签。
3. 上手/下手按钮不得贴屏幕底边、系统手势边缘或安全区下沿；底部手牌槽位存在时，按钮必须抬离屏幕底边并贴近对应手牌行、当前行动摘要或右侧偏下动作槽。
4. 上手/下手按钮至少满足 44px 级触控命中区；Android/App 交付按 48dp 等价目标优先。移动横屏下还必须给底部安全区、手牌扇形和系统手势留出清楚间距。
5. 两副牌的交换牌是 `开始抢劫` 前的开局配置/准备动作；房主开始抢劫后继续修改扩展或规则时，必须提示“会重新开始整局”，确认后回到第一场抢劫开始前，并重新生成两副牌结构和交换入口。
6. 正式抢劫开始后不得再出现“每轮筹码后调换上/下手”的主流程；若旧测试、旧文案或旧实现仍这么描述，先按本用户故事修正合同，再谈实现和验收。
7. 验收必须同时证明：开局前能看到两副手牌和交换入口；上手/下手按钮不贴底且可点；点击 `开始抢劫` 后不再进入交换牌阶段；筹码阶段只保留给上手/给下手的目标选择。

## 覆盖原因

- 现有文案和测试里曾把两副牌的 `hand-swap` 描述为“每轮投票完成后进入调换阶段”，与用户当前明确裁定冲突。
- 现有设计合同只写了底部手牌和单一主操作，没有明确禁止把上手/下手按钮贴到底边，导致移动端最难按的区域被误用成主按钮位。
- 这条裁定属于纸牌帮专项产品和 UI 真相源，不能只靠一次代码改动隐含保存。

## 验收标准

- 新增或修复纸牌帮两副牌 UI 前，必须先引用本文件作为用户裁定真相源。
- 桌面与移动横屏截图必须包含开局前两副牌交换态；截图中上手/下手按钮不得贴屏幕底边。
- 几何断言或截图复看必须证明按钮命中区不小于 44px；Android/App 交付按 48dp 等价目标复核，且与底部安全区、手牌槽位没有重叠。
- 开始抢劫后的流程截图或测试必须反向证明不存在正式对局中的调换牌阶段。
- 如果实现还未按本裁定修正，只能说“文档合同已更新，实现待修”，不得宣称纸牌帮两副牌问题已经修复。

## 不覆盖

- 不改变基础版 3-6 人、四轮筹码、公共牌、红筹码摊牌和胜负判定规则。
- 不重新裁定工具牌、专家牌、挑战牌、Joker 或其它扑克变体。
- 不把“上手/下手按钮不能贴底”扩大为“所有底部手牌槽位都禁止存在”；底部可以承接手牌本体，但当前主按钮不能贴屏幕底边或系统手势边缘。
