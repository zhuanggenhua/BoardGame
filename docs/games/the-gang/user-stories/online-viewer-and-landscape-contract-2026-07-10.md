# 纸牌帮联机视角与移动方向裁定（2026-07-10）

## 用户原始裁定

- 用户确认当前纸牌帮改动是在修复问题，不应被审查为“删除热座入口导致功能回归”。
- 如果既有规范或用户故事没有记录这项产品口径，应当补充留档，避免后续审查再次按旧热座实现误判。

## 覆盖范围

- `src/games/the-gang/Board.tsx` 的玩家列表、公开筹码、隐藏手牌与操作身份。
- `src/games/the-gang/manifest.ts` 的移动方向与本地 AI / 测试运行能力。
- `e2e/the-gang/the-gang-runtime.e2e.ts` 的状态注入、可见 UI 操作和移动端证据口径。
- `openspec/specs/the-gang/spec.md` 与 `add-the-gang-data-and-runtime-closeout` 的运行入口验收合同。

## 正式口径

1. 正式牌桌的一个客户端只代表一个玩家视角，不提供让同一客户端切换并冒充其它真人座位的热座按钮。
2. 牌桌应常驻展示所有玩家的名称和公开筹码状态；当前查看者只能看到自己的隐藏底牌，不能因为移除热座切换而隐藏其它玩家的公开状态。
3. `allowLocalMode`、本地 AI 和测试运行能力只用于一个真人视角加 AI 座位、教程、开发或自动化验证，不自动构成“多个真人共用一个客户端轮流操作”的产品合同。
4. 单客户端 E2E 可以用状态注入或测试命令补齐其它座位的公开决策，以快速构造多人代表态；当前查看者自己的关键操作仍应通过可见 UI 完成。
5. 使用状态注入或测试命令补齐其它座位时，测试名称和汇报必须明确是“代表态 / 状态注入”，不得宣称已经证明多人自然操作、座位权限或多端同步。需要证明这些联机合同时，必须使用多个独立客户端。
6. 纸牌帮移动端主交付方向为横屏。竖屏只承担兼容降级和关键区域可见性，不要求游戏 Board 内层提供直接横向拖动或热座切换。
7. 纸牌帮横屏依赖 Android 原生壳中的 `game-orientation-map.json` 与方向策略。stable OTA 只能交付 H5，不能替代 native APK；线上 APK 缺少 `the-gang: landscape` 时，必须发布新原生壳。

## 验收标准

- 牌桌不存在 `the-gang-hotseat-switcher` 和 `the-gang-showdown-hotseat-switcher`。
- 玩家列表显示全部玩家名称和公开筹码；选筹阶段不公开其它玩家底牌。
- 当前查看者可通过可见筹码和进度按钮完成自己的操作。
- 代表态测试若驱动其它座位，明确标注状态注入；多人联机合同使用多客户端验证。
- manifest 以 `landscape-adapted` 和 `landscape` 作为移动主方向；竖屏测试只验证兼容显示，不把内层横向滚动当正式交互要求。
- 线上 stable APK 内的 `assets/game-orientation-map.json` 必须包含 `"the-gang": "landscape"`，且版本码高于仍缺少该映射的 `0.6.1 / 564`。
- 最终验收必须在安装更新后的真实 App 中打开纸牌帮并确认实际横屏；OTA workflow 成功不能单独作为此项验收证据。

## 不覆盖

- 不取消本地 AI、教程或测试运行能力。
- 不把单客户端代表态测试升级成多人联机同步证明。
- 不改变纸牌帮筹码选择、拿走他人公开筹码、四轮推进或摊牌规则。
