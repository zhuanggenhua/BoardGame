# 响应提示锚点旧候选记录

## 当前状态

这份记录只保留为历史失败候选，不再作为 DiceThrone 响应提示的当前规范来源。

- 当前有效合同见 [`../card-timing-terms.md`](../card-timing-terms.md) 的“响应提示空间合同”。
- 当前回归裁定：响应提示恢复历史固定 HUD 槽位，锚点为视口，位置为手牌抬起区上方。
- “读取卡牌视觉矩形 / 跟随手牌 hover / 悬浮避让”的旧方案已被当前回归裁定作废；除非用户明确要求新设计，不得再用它修复回归问题。

## 作废原因

- 用户指出这是回归问题：弹窗位置以前是正确的，现在不对。
- 回归修复的默认动作是恢复最后正常行为，不是把新测量锚点、新布局或新 E2E 断言写成合同。
- 原记录中的 `PASS` 只说明当时那套候选实现曾经通过过局部截图断言；它不能覆盖用户当前对回归处理方式的裁定。

## 历史候选摘要

- 旧候选曾尝试让响应提示读取卡牌视觉矩形，并在手牌 hover 时跟随避让。
- 该候选现在不得作为实现、测试或验收依据；相关测试应断言 `data-anchor="viewport"` 与 `data-placement="fixed-hand-lift-slot"`。
