# DiceThrone 玩家面板与提示卡术语边界用户故事

## 用户原始要求

2026-10-11，用户指出：本轮要验证的是 DiceThrone 的**提示卡**放大镜，不是玩家面板；此前把两者放在同一张截图和同一个测试语义里，不能作为提示卡证据。用户同时要求检查同类问题并确认规范是否需要补齐。

## 名词解释与对象合同

- 用户本轮说的“提示卡”就是右侧承载英雄规则、Token / 状态说明和骰面需求的那张规则提示图；它不是玩家面板，也不是玩家面板上的技能槽。
- “提示板”只作为旧资料、旧教程文案和运行时兼容命名出现；本轮用户可见的测试名、截图名、evidence 和汇报统一写“提示卡”。

- **玩家面板**（`player-board`）：玩家角色的面板素材与交互区域。当前运行时识别点为 `player-board-surface`、`player-board-image`、`player-board-magnify-button`。
- **提示卡**（`tip-card`）：玩家查看规则提示的独立卡片区域。当前运行时为兼容既有 `tip-board` 命名，识别点为 `data-tutorial-id="tip-board"`、`tip-board-surface`、`tip-board-image`、`tip-board-magnify-button`。
- 玩家面板与提示卡是不同素材、不同 DOM 区域、不同放大入口、不同截图验收对象。
- `tip-board` 只保留为运行时兼容 ID；面向用户的测试名、截图名、evidence 和汇报统一使用“提示卡”。旧文档中的“提示板”不再作为本轮用户可见证据的目标名称。

## 验收标准

1. 用户点名提示卡时，测试和截图必须明确锚定 `tip-board-surface` 及其 `tip-board-magnify-button`，不能用玩家面板替代。
2. 玩家面板和提示卡必须分别断言对象本体、放大按钮归属和图标可读尺寸。
3. 混合全屏图只能作为上下文；玩家面板和提示卡必须分别生成各自目标状态的完整视口截图作为主证据。局部裁图只有在用户明确要求放大细节，或整屏无法读清按钮时，才可作为辅助证据，不能替代完整视口截图。
4. 测试名、截图名、证据索引和用户汇报不得把“玩家面板”写成“提示卡”，也不得用“玩家面板与提示卡”这一混合名称冒充单一目标证据。
5. 本用户故事只约束术语、对象层级和证据归属，不要求为证据方便而重命名现有运行时 testid。

## 不覆盖范围

- 不改变 DiceThrone 规则、卡牌效果或素材真相源。
- 不把其它游戏的玩家板 / 提示区域自动归入 DiceThrone 术语；其它游戏需按各自对象合同记录。
