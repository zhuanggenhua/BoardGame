# DiceThrone 共享攻击结算不变量

## 触发条件
- 修改 `src/games/dicethrone/domain/flowHooks.ts`
- 修改 `PendingAttack` 相关状态字段
- 修改 `targetingRoll / preDefense / withDamage / postDamage / ATTACK_RESOLVED`
- 新增会在攻击中途再弹玩家选择的 DiceThrone 技能

## 核心不变量

### 1. 同一笔攻击的主伤害只能落地一次
- “主伤害”指这次攻击本体对当前防守目标造成的那次主要 `DAMAGE_DEALT`。
- 它必须只有一个正式落地入口。
- 攻击后续选择、奖励骰、Token 响应、阶段重入，都不得让同一笔主攻击再落第二次主伤害。

### 2. 攻击后续选择只能推进阶段，不能重放主攻击
- `withDamage` / `postDamage` 里挂起的玩家选择，只能做两类事：
  - 落该选择自己的副作用
  - 把当前攻击推进到下一个显式结算阶段
- 除非规则文本明确写着“额外造成 X 点伤害”，否则后续选择不得再触发一次主攻击伤害。

### 3. 奖励骰结算与攻击后续选择不是一回事
- `bonusDiceResolved` 只能表达奖励骰收口。
- “主伤害已落地，但还在等后续选择”必须由独立语义承载。
- 禁止继续借用奖励骰字段去表达攻击后续选择完成。

### 4. autoContinue 必须服从权威阶段
- autoContinue 能不能继续，只能看：
  - 当前显式结算阶段
  - 当前是否仍有阻塞交互 / 响应窗口 / 待 reduce 结果
  - 当前攻击是否已经进入可收口阶段
- 禁止依赖某个英雄、某个技能 ID、某个历史布尔位组合来“猜现在应该继续还是停下”。

### 5. 只有本次攻击伤害可以推进攻击结算
- `pendingAttack.resolvedDamage` 和 `settlementStage` 只能消费本次攻击本体的 `DAMAGE_DEALT`。
- 同一攻击窗口内出现的直接伤害、状态爆炸伤害、维持伤害、反击附属伤害或其它副作用伤害，可以正常扣血，但不得累计为本次主攻击伤害，也不得把攻击推进到 `postDamagePending` / `readyToResolve`。
- 判断本次攻击伤害至少要同时满足：伤害类型是攻击伤害、来源玩家是当前攻击者、目标是当前防守方。只满足“目标是防守方”不够。
- 典型风险：咒缚海盗“死亡吐息”先给已有火药桶目标施加新火药桶，旧火药桶爆炸造成 3 点直接伤害；这 3 点不能顶替后续 7 点主攻击伤害。

## 禁止行为
- 禁止为修单个英雄问题，把 `PendingAttack` 的旧布尔位再塞新语义。
- 禁止在 `postDamage` / `withDamage` 的选择响应后，允许流程重新回到主伤害入口。
- 禁止只看 UI 或共血显示就把重复伤害解释成“展示问题”。
- 禁止把任意 `DAMAGE_DEALT` 只按目标玩家归入当前攻击；必须按伤害类型和来源归属分账。

## 最低验证门禁
- 至少有一条测试直接断言：同一笔攻击的主伤害事件最多 1 条。
- 至少覆盖一条 4 人 / 2v2 `targetingRoll` + 攻击后续选择链路。
- 若攻击的 preDefense / withDamage / postDamage 会附带直接伤害或状态爆炸伤害，必须补一条“副伤害先发生，但主攻击伤害仍继续落地”的行为测试。
- 若改动会影响奖励骰或 Token 响应，必须补相邻链路测试，证明没有把它们误收口成攻击后续选择。
