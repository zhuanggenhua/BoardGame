# DiceThrone 卡牌时机与术语裁定

> 适用：处理 DiceThrone 卡牌、阶段、骰子修改、响应窗口、手牌可用性相关 bug 或回归时。

## 强制拆分

DiceThrone 反馈里不能把“颜色”“类型”“使用时机”“效果目标”混成一个概念。动手前至少拆清：

- `卡牌颜色`：例如红色卡。
- `技能/伤害图面颜色`：例如能力框、伤害图标、伤害类型颜色或规则书颜色提示；这些是规则信号，必须进入录入合同，不能只看代码里的 `damage` 事件。
- `卡牌类型/使用窗口`：例如即时牌、阶段牌、响应窗口可用牌。
- `效果目标`：例如修改自己的骰子、修改对方的骰子、强制重掷、调整点数。
- `阶段归属`：进攻掷骰、防御掷骰、伤害结算前后、玩家主阶段等。
- `现实操作者`：当前回合玩家、当前掷骰者、防御者、响应者。

## 红色即时牌口径

- 红色即时牌默认按“即时牌 / 可在任意时机打出”理解，不得把红色即时牌称为“防御阶段牌”。
- “防御阶段能用来改骰子的牌”只描述效果发生的阶段和目标，不代表该牌本身的颜色或类型是防御阶段牌。
- 如果一张牌的描述限定“只能在其防御投掷阶段”或类似语义，默认按黄色防御阶段牌处理；必须同时满足：当前确实在防御掷骰阶段，并且操作者就是正在掷自己防御骰的人。
- 反过来，不能因为对方回合就一刀切禁用所有可用手牌；也不能因为当前是防御阶段就放开非当前防御掷骰者打防御骰牌。

## 官方伤害类型口径

- Rulepop 伤害表列的是伤害类型属性，不是给本地实现另造“大招特殊处理”规则。当前 bug 裁定只需要区分：`Undefendable Damage` 是否仍可被卡牌/状态效果响应，以及非攻击来源伤害是否能吃攻击修正。
- `Undefendable Damage` 官方口径：不可防御，但仍是 `Avoidable`；`Avoidable` 的官方定义包括被卡牌或状态效果降低、防止、闪避或打断。实现上不能把“不可防御”扩展成“不能用 Token 减伤/防止/闪避”。
- Rulepop 也列有 `Ultimate Damage` 条目：这是终极招式造成的一类特殊不可防御伤害，伤害表里标为不可 `Avoidable`。这只用于解释终极招式结算后的不可避免口径，不得反向扩大到普通不可防御伤害。
- 进攻骰确认并选中终极招式后，仍必须先开放正常的改骰、重掷响应窗口；对手可以通过合法卡牌改变骰面，使终极骰型不再成立。发动前任何骰面变化都必须取消当前终极招式选择并要求重新选择技能。
- 图面颜色、伤害类型和文字描述必须共同决定“是否进入防御投”。`DAMAGE_DEALT` 或 custom action `categories: ['damage']` 只能说明会造成伤害事件，不能单独证明这是可防御攻击伤害。像附属伤害、目标选择后直接伤害、非攻击来源伤害，必须在录入合同里显式写成“不触发防御投”或“需要防御投”，再由实现消费该合同。

## 不可防御伤害与可避免边界

- 官方 Rulepop / Dice Throne 规则索引口径：普通 `Undefendable Damage` 是不可防御但仍可被卡牌或状态效果响应。
- `不可防御` 在实现里只表示不能使用防御技能，不等于不能用受伤前卡牌、状态 Token 或其他合法避免效果减伤、免伤、闪避或打断。像忍者 `九字切` 这种普通不可防御直伤，应允许防御方用 `太极` 这类状态 Token 减伤。
- 非攻击来源伤害不属于攻击伤害：不能开放攻击方攻击修正或攻击加伤 Token，也不能使用防御技能；但只要不是终极伤害，仍可被防御方卡牌或状态效果避免。
- 终极招式的不可避免只按官方终极条目处理；不要把它扩展到普通不可防御伤害。

## 回归验收门禁

修改 DiceThrone 卡牌时机、手牌可用性、视角自动切换、响应窗口或改骰牌逻辑时，不能只用截图或单条正向链路收口。至少补并跑通以下自动化断言：

- 用户点名卡牌正向：必须锁定用户点名的中文牌名、卡牌 ID 和普通触发入口；不能用另一张相似颜色或相似类型的牌替代。若用户点名“这玩意儿真棒！”，回归测试就必须覆盖 `card-artificer-perfectly-calibrated` 本体。
- 红色即时牌正向：非当前回合玩家在普通对方回合能打出红色即时牌，卡牌离开手牌、进入弃牌堆，并结算对应效果；测试必须经过真实出牌命令校验，不能只直调效果结算函数。
- 防御阶段牌负向：描述限定防御投掷阶段的牌，例如“就这？”，在非防御掷骰阶段不能打出；在防御掷骰阶段也只能由当前防御掷骰者打出。
- UI 入口正向：自己的手牌不应因为自动切到对手视角或不是当前回合玩家，就被整体禁止拖动打牌；真正能不能打由卡牌规则校验决定。
- UI 入口负向：观察者仍不能操作手牌；卖牌、弃牌等只属于当前回合或弃牌阶段的动作不得被红色即时牌规则顺手放开。
- 技能/卡牌使用时状态：如果效果会打开选择窗口、响应窗口、奖励骰面板或其他中间交互，必须验证使用时玩家能看见对应中间状态，不能只断言底层命令成功。
- 技能/卡牌使用后状态：必须至少验证一个用户能看见的最终变化，例如血量、资源、状态标记、Token、弃牌堆、阶段推进或交互关闭；截图只能作为可见性证据，不能替代最终状态断言。
- 多步改骰/重掷交互：凡是“选择至多 N 颗骰子”“修改 N 颗骰子”“复制一颗骰子的骰面到另一颗骰子”这类牌，必须同时验证正向、少选、超限和重复选择。`俺也一样！` 这类复制牌必须证明源骰和目标骰是两个独立步骤，重复点击同一颗源骰不能提前完成；`我又行了！`、`就这？`、`不愧是我！` 这类“至多 N 颗”重掷牌必须证明少选后可以手动确认，继续多选会被上限挡住；`意不意外？！` 这类多骰改面牌必须证明能一次修改多颗不同骰子，且不能用重复点击同一颗骰子冒充多步完成。
- 防御阶段改对方骰子：若用户原问题是“防御阶段改别人的骰子”，验收必须在 `defensiveRoll`、防御骰确认后的响应窗口、出牌者选择对方骰子的真实 UI 上完成。截图至少覆盖出牌后选择提示、目标骰被选中、结算后对方骰结算状态；不得用普通进攻投掷、自己骰子或只看最终骰面变化替代。骰子显示样式必须按用户当前开关分别验收：默认样式走旧右侧骰盘，3D 骰子开启时走 3D 骰台选择命中层，不得为了方便把其中一种样式强制切回另一种。3D 开启态的截图必须能肉眼看见操作提示、目标骰子本体或等价投影、选中态，以及完整的加减/确认控件；只证明透明命中层、测试属性或底层物理源存在不算通过。重掷牌的验收要以真实重掷事件和动画入口为准，不能要求骰面必然变化；即使随机出相同骰面，也必须产生重掷事件并播放重掷动画。
- 3D 改骰提示口径：3D 骰台提示必须复用默认骰盘的现实语义，不能为 3D 另造一套相反文案。复制骰面类牌必须分清“选择要复制的源骰子”和“选择要设为源骰面的目标骰子”；设置指定点数类牌才允许写“选择要设为 N 的骰子”。提示条属于整局 HUD / 阶段提示，默认放在整体视线中心上方、敌人信息区下方附近；不得塞进单颗骰子、局部骰台或透明命中区内部。截图验收必须覆盖复制源骰、复制目标骰、任意改面加减、重掷选择这几类不同提示，防止把 `俺也一样！`、`再来一次`、`意不意外？！` 等牌混成同一个交互。
- 3D 改骰骰面可读性：3D 开启态必须保留真实物理骰子作为主体。若骰面角度导致读数不清，只能加轻量徽标、高亮或描边辅助读数；不得用黑色假骰子、黑色方块或大面积覆盖层替代/压住真实骰子本体。截图里只要玩家第一眼看到的是覆盖物而不是真实骰子，就按视觉失败处理。
- 改骰/重掷响应时机：进攻骰确认后，若规则要求先选定攻击，测试夹具也必须走“确认骰面 → 选择攻击 → 响应窗口打牌”的真实链路；旧测试不能停在“只确认骰面”后直接打攻击修正牌。终极招式同理，发动前仍走普通改骰响应窗口，进入 `Ultimate Damage` 结算后才适用不可避免边界。
- 奖励骰 E2E 控制：技能或卡牌额外投出的奖励骰必须用奖励骰骰面 helper（`setDiceThroneBonusDiceValues(page, [1-6...])`）控制；底层 `random.setQueue` / `setDiceThroneRandomQueue` 接收的是 0-1 原始随机数，不是骰面值。不要用普通攻防骰池 helper（`setDiceThroneDiceValues`）伪造奖励骰，也不要把 `[4, 5]` 直接传给 `random.setQueue`；否则会把奖励骰回归遮住，出现“截图像走了流程但实际随机值不受控”的假证明。
- 链路截图最终帧：如果对外声称“造成伤害、获得资源、获得/移除 Token、弃牌成功”等结果，最终截图里必须让对应可见数字或标记入镜、已经更新且无遮挡可读；例如声称对手掉血 5 点时，截图里的对手血量必须清楚显示最终值 45，不能仍显示冻结前的 50，也不能被“-5”飘字、爆字、弹层或特效遮住。
- 动画冻结等待：如果存在飞行动画、受击动画、飘字特效或血量冻结缓冲，E2E 必须等用户可见 UI 解除冻结、遮挡层消失并显示最终值后再截图。内部状态断言只能证明结算逻辑，不能替代图面验收；图面看不到变化或变化被遮住时，不得向用户声称链路截图已证明变化落地。

## 汇报要求

向用户解释时必须使用清楚口径，例如：

- 正确：`“就这？”是黄色防御阶段牌，只能在自己防御掷骰阶段由当前防御掷骰者使用。`
- 正确：`红色即时牌是任意时机牌，不等于防御阶段牌。`
- 正确：`这次修的是“这玩意儿真棒！”本体的红色即时牌回归，不是用另一张红牌证明同类牌大体可用。`
- 错误：`防御阶段红卡可以用。`
- 错误：`红卡是防御牌。`
- 错误：`用“老大真慷慨”通过了，所以“这玩意儿真棒！”也修好了。`

如果涉及代码证据，先说现实含义，再写符号。例如：“当前掷骰者是防御方，代码里的 `rollerId` 等于该玩家”。
