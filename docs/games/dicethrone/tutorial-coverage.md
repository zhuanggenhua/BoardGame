# Dice Throne 交互式教程内容总账

本文件是单游戏作者覆盖矩阵，不是通用执行规范。通用判断来自 [tutorial-design](../../../.spec/knowledge/standards/tutorial-design.md)。

## 目标与范围

用户原话：“我的核心是交互式教程，是代替视频、文本规则，所以要全面，并且响应这类新增的功能也需要解释到”。目标不是增加说明字数，而是让玩家理解规则、亲手决策、操作正式入口并看到后果。

用户已明确本轮先完整覆盖双人通用规则与操作；其它英雄专属机制及多人、团战不纳入本轮。教程集合由 [tutorial.ts](../../../src/games/dicethrone/tutorial.ts) 注册，独立机制步骤由 [tutorialPractices.ts](../../../src/games/dicethrone/tutorialPractices.ts) 承载，中英文正文位于两份 `game-dicethrone.json` 的 `tutorial`。目前有主线及七个机制练习，共八条命名教程路由；不增加专用规则命令或状态。

开局同源：双人僧侣，50 体力、2 CP、4 张手牌、先手首回合跳过收入，首个决策在主要阶段 1。仅固定合法牌序和随机结果；未预造弃牌超限、攻击、Token 或响应状态。对手由正式命令执行；自己的首次防御和响应交还玩家。

## 治理裁定

- 保留：通用标准已有的因果链、首次教学、正式权限、单焦点与截图规则，属于已有要求待执行。
- 补充：完整替代教学的范围口径、未触发机制的真实练习落点、新增正式交互后的同步检查，唯一正文位于通用 `tutorial-design.md`，作用于全项目多游戏。
- 本文件仅记录 Dice Throne 的来源、处置与缺口，不复制执行正文。旧的首次攻击及自动批次证据不作为本轮完整教学证据。
- 本轮以矩阵声明的双人通用规则与操作为验收范围；独立机制按真实入口与结果承接，信息参考与范围外内容保留明确边界。最终逐图结论见本轮验收报告，不外推为全部英雄和人数模式已完成。

## 交互族链路与界面复用

| 交互族 | 入口 → 候选 / 选择 → 提交 | 可见后果 / 下一入口 | 证据职责 |
| --- | --- | --- | --- |
| 只读检视 | 提示板放大镜 / 手牌本体 → 完整详情 → 关闭 | 回到原牌桌，手牌与 CP 不变 | 浏览器分别点选与真实触屏长按，领域不伪造只读事件 |
| 手牌动作 | 卡面字段 → 指定牌 → 点选或拖到弃牌堆 | 手牌、CP、弃牌、Token 或技能等级变动 | 领域证明数值，浏览器证明正式对象可操作 |
| 骰面决策 | 正式骰盘 → 锁定 / 重掷 / 改骰 → 普通或交互确认 | 最终骰面与合法技能集合 | 所有结果截图等待骰子动画和变换结束 |
| 进攻与防御 | 合法技能槽 → 选定 → 结算 → 对方防御 | 公开防御结果、双方资源 → 主要 2 | 自动他人动作后保留结果；首次自己防御亲手执行 |
| 响应 | 正式窗口 → 可用红橙牌或 Token → 目标骰 / 数量 → 确认或放弃 | 重新确认技能 / 最终扣血 → 下一可操作状态 | 介入与合法不介入都继续，不以跳过代替介入 |
| 条件支付 | 击倒 → 点状态 → 付费确认；或直接推进不支付 | CP 消耗并保留进攻；或移除击倒并跳过进攻 | 两种分支独立从相同代表态回放 |
| 主动不发动 | 投骰并确认 → 保持技能未选 → 结束确认 | 没有攻击，直接进入主要 2 | 正式弹窗与两方体力不变，不借用击倒惩罚冒充主动放弃 |

截图过渡由各真实回放目录的 `chain.json` 按步骤逐项登记；最终中文索引将每张图绑定自己的主线或代表态链、前中后态、来源运行和实际输入。独立练习之间不串连续编号来暗示同一局自然后果。

## 独立机制入口合同

以下均为 `representative-state`，不属于主线的连续后果。预设仅在第一张可见卡之前通过现有初始化与状态设置入口建立；之后只走正式命令。

| 教程 | 规则位置 / 首个决策 | 预设差异 |
| --- | --- | --- |
| dicethrone-response | 对手主要阶段；玩家决定使用红牌 | 对手回合、玩家 2 CP，持有对应红牌与橙牌；对手之后投出五莲花 |
| dicethrone-hand-limit | 弃牌阶段；玩家决定出售哪张牌 | 7 张合法手牌、14 CP、空牌库，余牌在弃牌堆 |
| dicethrone-ultimate | 玩家主要阶段；进入进攻 | 对手剩 5 体力，双方无响应牌，骰面策略提供五莲花 |
| dicethrone-damage | 玩家主要阶段；进入进攻 | 上回合留下的 3 个太极、对手 1 个闪避；四莲花触发不可防御攻击 |
| dicethrone-upgrade | 玩家主要阶段；决定打出升级卡 | 6 CP、手持清修 II / III；实际支付 2 和差价 1，最后持有 3 CP |
| dicethrone-straight | 玩家主要阶段；进入进攻 | 无手牌与 Token；固定五骰 1、2、3、4、5，大小顺子均合法，分别结算命中奖励 |
| dicethrone-knockdown | 玩家主要阶段；决定如何处理击倒 | 2 CP、击倒 1；允许支付 2 CP 或不支付并跳过进攻，无净化替代这两个分支 |

规则源消歧：§4.4 原有“最终确认并锁定骰面前”的括注会把电子版骰盘确认误作终极正式启动，已用同文件术语表已有的“改变骰面结果取消启动”表述替换。电子响应时序仍以已有 `card-timing-terms.md` 为源，不改变响应权限。

## 运行时与证据边界

- 学习者固定为座位 0；对手回合不切成座位 1。共享教程宿主只在 manifest 声明 `playerId` 时固定视角，未声明的现有教程继续沿用原热座行为。
- 独立伤害练习的对手闪避通过正式本地传输执行。严格候选合同仅允许传输层定义的 `_noSnapshot: true` 元数据，不放宽伤害编号、Token 数量或未知参数。对应回归同时覆盖合法命令与非法参数拒绝。
- 行为验证去重后覆盖 8 文件、116 项：最终五文件 33 项通过，结合未改动的响应合同、骰盘策略与随机上下文三文件 83 项。类型检查和规范检查通过。桌面、原生触屏、放弃响应及九条机制分支共十二条教学路径，另加两个视口的选课目录，十四条最终回放全部通过；逐图账本与索引见本轮最终验收文件。

- 主线教程进度版本为 4，终极练习为 3；沿用既有版本判定直接作废旧进度，从头开始，不迁移旧步骤索引。
