## 墙体机制门禁

墙体牌已经属于当前标准起始法术书范围，不能再说“范围外”。当前公共墙体机制已完成代表实现：边界目标、墙体状态、领域视线阻挡和通行伤害均有代码路径；`25700` 荆棘之墙已有正式页面局部 E2E 和截图证据，覆盖墙前 / 墙后浏览器视线阻挡对照与穿墙通行伤害。`2500`、`25700` 的正式 runtime atlas/frame 已接入本地资源链，结构化字段按当前数据录入基线使用；只有 Wiki、玩家反馈、用户指定新主真相源或清晰规则图与当前录入冲突时，才退回录入层复审。它们仍不能进入主黄金链或 stable 完成宣告，因为主链整合和服务器真实资源发布尚未闭合；`2500` 不需要默认补完整浏览器链，除非出现独有规则、入口差异、证据冲突或用户点名要求。

## 验收口径

- 标准起始法术书组成可以按 `composition-locked` 使用：规则书第 40 页、TypeScript 源和配置包测试需要保持一致。
- `2500`、`25700` 不再按“完全缺墙体运行机制”或“缺正式卡面接线”处理；当前配置使用 `requiresCodeSupport=false` 表示公共墙体机制已承接，正式 atlas/frame 已由配置包引用。
- 现有两派系候选链只能证明兽王 / 女祭司当前已实现代表机制；墙体局部链只能证明公共墙体机制代表，不表示 Mage Wars 主黄金端到端已完成。
