## 墙体机制门禁

墙体牌已经属于当前标准起始法术书范围，不能再说“范围外”。当前公共墙体机制已完成代表实现：边界目标、墙体状态、领域视线阻挡和通行伤害均有代码路径；`25700` 荆棘之墙已有正式页面局部 E2E 和截图证据。它们仍不能进入主黄金链或 stable 完成宣告，因为正式 runtime atlas、精确牌面审计、浏览器视线阻挡前后对照和主链整合尚未闭合。

| 必要能力 | 当前状态 | 阻塞后果 | 最小补齐动作 |
| --- | --- | --- | --- |
| 正式 runtime atlas | `2500`、`25700` 缺正式 atlas frame | 浏览器不能以正式卡面展示标准书墙体牌。 | 补正式 atlas/frame、manifest 和配置引用。 |
| 墙体对象状态 | 公共机制已实现 | 仍缺正式 atlas 与精确牌面审计，不能宣称逐牌完整。 | 用正式素材和精确牌面字段补齐 `2500`、`25700` 的最终合同。 |
| 边界目标 UI | 代表链已覆盖 | 只证明 A3-B3 代表边界和荆棘之墙正式页面链，不等于全部墙体逐边逐牌完成。 | 将已打绿边界选择 helper 复用进后续主链，并补必要负向分支。 |

| 通行伤害 / 穿墙惩罚 | 正式页面局部 E2E 已覆盖 | 当前只证明荆棘之墙代表链，不证明所有墙体数值精确。 | 用精确牌面审计校准 `2500`、`25700` 的通行伤害参数。 |

## 验收口径

- 标准起始法术书组成可以按 `composition-locked` 使用：规则书第 40 页、TypeScript 源和配置包测试需要保持一致。
- `2500`、`25700` 不再按“完全缺墙体运行机制”处理；当前配置里保留 `requiresCodeSupport=true` 是为了继续暴露正式素材和精确牌面审计缺口，不等于公共墙体代码没有实现。
- 现有两派系候选链只能证明兽王 / 女祭司当前已实现代表机制；墙体局部链只能证明公共墙体机制代表，不表示 Mage Wars 主黄金端到端已完成。
