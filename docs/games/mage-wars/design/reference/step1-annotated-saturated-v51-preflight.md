## 设计理论总结

- **开放式设计**：不是“不要边框”这么窄，而是让棋盘、卡牌、token、骰子等真实对象直接成为动作承接面；UI 只做贴附反馈、短状态和必要边缘入口。
- **场地 / 对象直选优先**：如果当前目标在棋盘上可见，玩家应直接点目标本体；目标摘要、按钮、编号、问号和代理列表只在本体不可见、数量过多需检索、无障碍入口或规则确有确认时才允许出现。
- **当前选择只高亮能做的事**：选中已计划 `火球术` 后，画面应高亮合法目标 `B2 / 西锁骑士` 本体，并让非法对象降噪；不再新增第二张目标卡或解释性路径。
- **公开归档不等于给人常驻看**：弃牌堆可以随时检视，但当前阶段不从中选择、回收、复活或结算，所以只保留所属玩家边缘小入口、数量和卡背 / 堆叠轮廓。
- **空白必须有职责**：右下或底部空白只能承担分页、展开、结算浮层或主交互让位；不能用空白放问号、目标摘要或无职责装饰。
- **删 UI 也要过账**：删除目标摘要、大箭头、弃牌正面图后，必须证明来源、目标、归档和分页仍能被玩家找到，且不会误以为对象不存在。
