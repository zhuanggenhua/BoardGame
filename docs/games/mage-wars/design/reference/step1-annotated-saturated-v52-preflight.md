## v51 失败归因

| 失败项 | 现实问题 | v52 修正 |
| --- | --- | --- |
| 保护整张底图 | 中央石砖纹理空着，但玩家的法术书和已计划法术挤到底部 / 右边缘 | 把竞技场底图拉成最低层，允许牌区浏览器和计划槽轻压底图低权重区域 |
| 边缘拥挤 | 右下已计划、弃牌和回合命令过密，底部法术书与分页像挂件 | 将法术书浏览器和己方已计划槽移入主舞台下层 overlay，保持卡面可读 |
| 误判遮挡对象 | 之前只看有没有压地图，没有区分压的是石砖纹理还是规则对象 | v52 建立保护对象表：只要不遮挡区域标签、场上卡、目标高亮、骰子 / token 和可读牌面，低权重底纹可以被覆盖 |
| 几何通过误判玩家通过 | v51 没有 bbox 冲突，但玩家仍看到边缘堆 UI | v52 审计必须同时看空间预算和玩家第一眼路径 |

## 规则到画面结论

| 规则 / 设计结论 | 影响主体 | v52 设计决策 |
| --- | --- | --- |
| 学徒模式使用 `2x3` 区域竞技场 | 中央竞技场 | 继续使用正式 `standard-arena.jpg`；6 个区域与场上卡保留唯一 `zoneId` |
| `火球术` 是己方已计划法术中的当前来源 | 己方已计划槽 | 保留唯一实体卡，放大到可读；不复制成“已选法术”或目标摘要 |
| 目标选择应由场上对象本体承接 | B2 `西锁骑士` | B2 卡牌本体高亮并可点；不加目标摘要、大箭头、问号代理区 |
| 骰子、伤害 token、燃烧 token 是用户点名物理件 | B2 目标附近结算层 | 保留攻击骰、效果骰、伤害 / 燃烧 token，作为当前结算 overlay 高于棋盘但不挡目标核心读数 |
| 法术书是大型私有库 / 浏览器 | 下方开放 overlay | 法术书浏览器可覆盖竞技场底部低权重石砖区域，保留分类、5 张候选和贴边分页 |
| 已计划法术是当前可执行来源集合 | 下方偏右开放 overlay | 已计划槽靠近法术书和 B2 目标路径，不再贴屏幕最右边 |
| 弃牌堆是公开归档 | 己方计划附近的小入口 | 只显示小卡背堆叠 + 数量，不显示正面顶牌，不进入中央主舞台 |
| 对手已计划法术是隐藏信息 | 左上镜像槽 | 只显示卡背、数量和控制归属，不公开正面或卡名 |

## 层级 / 可遮挡 / 保护对象表

| 层级 | 对象 | 可遮挡对象 | 不可遮挡对象 |
| --- | --- | --- | --- |
| 底图层 | 桌面暗场、竞技场石砖、未用低权重纹理 | 可被法术书、已计划、归档入口、短状态、分页、结算 overlay 覆盖 | 无；底图本身不是前景保护对象 |
| 规则空间层 | `A1/B1/A2/B2/A3/B3` 区域线和标签 | 非当前区域可轻微降噪 | 区域归属、区域标签、当前合法目标区域 |
| 实体对象层 | 法师牌、场上卡、计划卡、卡背、token | 非当前对象可降噪但不消失 | 当前来源卡、B2 `西锁骑士`、场上卡所属区域、对手隐藏卡背 |
| 主交互 overlay | 法术书浏览器、已计划槽、分页、弃牌入口 | 低权重底图 / 桌面纹理 / 非交互空地 | 当前可点目标、当前来源卡主体、骰子 / token |
| 结算 overlay | 攻击骰、效果骰、伤害 / 燃烧 token、目标短状态 | 底图纹理、目标周边非关键空地 | 目标卡主体、目标高亮、仍需点击的区域 / 对象 |
| 辅助 HUD | 法师状态、行动标记、回合结束 | 桌面边角背景 | 法师牌、生命 / 法力 / 聚魔读数、行动 / 快速施法 token |

## 空间预算

| 区域 | v52 占用 | 最小可读 / 可点 | 让位顺序 |
| --- | --- | --- | --- |
| 主竞技场 | `2x3` 半场、4 张场上卡、B2 高亮、骰子和 token | 场上卡约 `130x184`；区域标签持续可见 | 法术书 / 计划 overlay 不得压场上卡；必要时先缩短标签 |
| 法术书浏览器 | 下方开放 overlay，覆盖低权重底图 / 桌面 | 5 张候选卡约 `96x136`，分类与分页可点 | 先减少候选张数，不压缩当前来源卡 |
| 己方已计划槽 | 下方偏右，靠近 B2 与法术书 | 当前 `火球术` 约 `130x183`；第二张计划低权重 | 弃牌入口和回合结束先贴边，计划卡不缩成小点 |
| 弃牌入口 | 己方计划附近小卡背堆 | 小入口 + 数量，点击后后续展开 | 不进入中央，不显示正面 |
| 双方法师 HUD | 左下 / 右上 | 法师牌和三条运行态读数可读 | 不抢中央，不引入状态板整图 |
