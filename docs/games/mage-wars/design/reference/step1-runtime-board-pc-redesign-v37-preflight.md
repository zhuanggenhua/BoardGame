| 用户反馈 | v37 设计要求 |

| 卡牌自己有费用，不需要 UI 复写 | 火球术大卡保留为读卡主体；不再显示费用、射程、目标栏、骰数或效果的 UI chip |

## 规则到画面裁决

| 规则结论 | 画面主体 | v37 决策 |
| --- | --- | --- |
| 卡面费用、行动图标、射程、目标、骰数和效果是法术牌字段 | 火球术大卡 | 大卡足够可读，不再在旁边复写字段 |
| 施法支付前可取消，支付后进入反制 / 结算 | 动作工作台 | 确认施放 / 取消只存在于目标确认态；确认后退场 |
| 计划法术最多 2 张，法术书不是手牌 | 法术书 / 已计划法术 / 弃牌堆 | 当前已计划为主，另一张已计划和法术书 / 弃牌堆为入口 |
| 攻击骰 / 效果骰属于结算层 | 目标附近结算浮层 | 本稿不展示骰子；避免确认态和结算态混在一起 |

## 前置硬失败禁止清单

- 不得出现手牌 / hand / opponent-hand。
- 不得把卡面已有费用、射程、目标栏、骰数或效果正文复写成 UI chip。
- 不得把确认态和结算态混在同一单态设计稿。
- 不得把确认 / 取消放到远离来源卡和已选目标的位置。
- 不得让底部成为不可读小牌墙。
- 用户批准前不得进入真实 Board/UI、真实页面 E2E 或移动端。
