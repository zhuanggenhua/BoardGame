# Mage Wars v57 卡牌比例前置回执

> 状态：`preflight-ready / open-design-artifact-only / media-generate-forbidden / human-review-not-allowed-until-ai-pass`。本文件只服务 v57 Open Design artifact 设计稿，不是项目规范更新，不批准真实 Board/UI 实现，也不允许移动端适配先行。

## 本轮问题本质

v56 的正确部分是删除卡外可见卡名、费用、射程、目标等字段复写；失败部分是把“读卡”理解成“常驻大卡”。`260x366` 的法术书焦点卡和已计划来源卡虽然可读，但它们属于临时检视层尺寸，不应常驻在主牌桌层。下一稿必须把读卡拆成两层：

- **常驻牌桌层**：让玩家辨认当前对象、切换候选、直选目标和看结算；卡牌不追求完整正文阅读。
- **临时检视层**：hover / focus / inspect 时短暂放大，用于读完整卡面；检视层可以大，但不得常驻抢主棋盘。

## 外部比例不变量

| 来源不变量 | 本稿决策 | 禁止项 |
| --- | --- | --- |
| BGA 要求核心游戏在 `100%` 缩放下可玩，工具提示用于补充而不是复制同一张可见卡 | 竞技场必须重新占第一视觉；常驻牌桌本身要可玩，不依赖全局 zoom 挽救 | 把“看不清”交给整体页面缩放，或用重复卡图 tooltip 证明布局成立 |
| BGA 要求不要用动作栏替代桌面组件动作，合法选项应在桌面上高亮 | B2 目标、骰子和 token 是当前动作中心；目标选择仍由场上对象本体承接 | 法术书焦点卡或来源卡比场上目标更像主角 |
| Magic Online 文档说明各区域卡可 hover zoom，官方更新也把 hover zoom / large zoom 作为读卡机制 | 完整读卡进入 inspect / spotlight；常驻卡只做到可辨认和可切换 | 把 zoom 尺寸常驻进牌桌层 |
| Forge 明确 XLHQ 卡图只在 zoom view 使用，battlefield 仍使用普通卡图 | 高质量大图只属于临时检视层；常规战场维持普通牌桌尺度 | 为读正文把单张卡扩到接近法师面板或棋盘主视觉 |
| Unity 卡牌 UI 模板把 hover / zoom 做成卡牌被悬停后的变化，并提供卡间距、旋转、hover 尺寸等参数 | 法术书候选、已计划来源和 inspect 层必须有尺寸梯度 | 常驻候选、常驻来源、临时检视同尺寸 |
| 黄金比例是比例系统参考，不是单一硬公式；如果与可用性和可读性冲突，应优先实际 UI/UX 需求 | v57 用稳定梯度约束：主舞台 > 当前来源 > 焦点候选 > 普通候选 / 归档 | 为了追求“数学好看”牺牲可操作对象、目标高亮或卡牌可辨认 |

## v57 空间预算

1920x1080 PC 饱和主态以“目标选择 / 结算预备”为截图状态。核心预算如下：

| 层级 | 对象 | 预算 / 上限 | 说明 |
| --- | --- | --- | --- |
| 主舞台 | 学徒 2x3 竞技场 | 约 `1440x850`，第一视觉；不得因牌区缩到弱背景 | 棋盘和场上卡是规则判断位置 |
| 场上实体 | 生物 / 魔物 / 目标卡 | `118-138px` 宽 | 保持区域归属和 token 贴附；不和法术书焦点争主视觉 |
| 当前来源 | 已计划火球术 | 常驻宽度 `176-198px`，不超过场上卡约 `1.5x` | 来源要明显，但不进入完整读卡尺寸 |
| 次计划牌 | 第二张已计划法术 | `112-126px` 宽 | 只表达计划槽位，可切换 / inspect |
| 法术书候选 | 当前页候选 | 常规 `112-128px` 宽；焦点 `148-170px` 宽 | 焦点只表示当前浏览位置，不承担读完整正文 |
| 临时检视层 | hover / focus / inspect 卡 | `300-360px` 宽，可接近屏宽 `16-19%` | 仅在检视态出现；v57 常驻截图不得把它展开成主视觉 |
| 结算层 | 攻击骰 / 效果骰 / 伤害 token / 燃烧 token | 锚在 B2 目标附近，允许覆盖低权重底图 | 当前结果属于主舞台上层，不能挪到边栏 |
| 归档入口 | 弃牌堆 | `36-48px` 卡背堆 + 数量 | 公开可检视但非当前选择来源，默认低权重 |
| 玩家 HUD | 法师牌、生命、法力、聚魔、行动 token | 贴近座位边缘，低于主舞台权重 | 法师牌和条形读数可见，但不抢法术选择链 |

## v57 读卡策略

| 场景 | 常驻表现 | 临时表现 |
| --- | --- | --- |
| 浏览法术书 | 当前页显示 4-5 张小卡，当前焦点略大，页角分页可见 | hover / focus 打开右下或近源 spotlight，读完整卡面 |
| 已计划法术 | 两张计划牌常驻可见，来源牌略大并贴“施法来源”短状态 | hover 来源牌进入 inspect；不额外写费用 / 射程 / 目标 |
| 选择目标 | 真实 B2 目标高亮，骰子和 token 在目标附近 | inspect 不得遮挡目标点击；若打开，属于临时覆盖态 |
| 弃牌堆 | 卡背堆 + 数量 | 点击后才展开公开归档，不在主态展示顶牌正面 |

## v57 出图硬禁止

- 禁止可见文字 `手牌`。
- 禁止卡外重复显示卡名、费用、射程、目标、类型、等级或正文。
- 禁止常驻 `260x366` 或更大的法术书焦点卡 / 已计划来源卡。
- 禁止把 inspect / spotlight 与常驻主态同时铺满画面。
- 禁止删除骰子、效果骰、伤害 token、燃烧 token、守卫 token、行动 / 快速施法 token、法术书、已计划法术、弃牌堆和对手已计划卡背。
- 禁止为了完整露出底图，把仍需持续比较 / 切换 / 使用的法术书和计划牌挤到不可读。
- 禁止让法术书、已计划法术、弃牌堆或分页控件遮挡 B2 目标、A3/B3 场上卡、骰子、token 或区域归属。

## v57 AI 核验门

- v57 必须先导出 PNG，再按玩家视角核验。
- PASS 条件不是“没有重叠”，而是：棋盘第一视觉成立、常驻卡牌比例有梯度、读卡有临时检视策略、当前目标与结算主体不被抢焦点、用户点名物理件不缺失。
- 只有 v57 PNG 通过 AI 图面核验后，才允许打开给用户人工验收。
