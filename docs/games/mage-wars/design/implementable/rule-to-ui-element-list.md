## 规则到布局结论

| 规则结论 | 布局影响 | 禁止项 |
| --- | --- | --- |
| 竞技场区域是移动、范围、目标和归属单位 | 中央主舞台先画 `2x3` 当前半场；底图是最低层，允许法术书 / 计划 / 结算 overlay 覆盖低权重纹理，但不能遮挡区域语义、场上实体和当前目标。 | 把整张地图当不可覆盖矩形；把卡牌放在两个区域中间；为了露出底图牺牲法术书和计划牌可读性。 |
| 法师既是玩家身份又是战场生物 | 当前 v80 基线：玩家 HUD 放密集文字法师规则 / 提示卡，用于玩家归属和能力参考；竞技场格内放人物 / 肖像法师本体作为战场实体；详情层只放大引用规则提示卡。后续重做可换落位，但必须解释替代承载如何保持职责分离。 | 把提示 / 参考对象和战场实体混成一个对象；只修其中一边就判通过；把详情放大卡画成第二个可操作实体。 |
| 法术书是当前可支配候选集合 | 己方法术书常驻为可浏览工作台，一页 6 张，分类标签靠左，分页贴近牌列；卡面本身承担名称、费用和规则字段。 | 写成“手牌”；卡外复写费用 / 目标 / 射程；缩成看不清的小牌墙；页码占据大底栏。 |
| 已计划法术是当前可施放来源 | 己方最多 2 张已计划法术与法术书牌同尺寸，放在回合结束 / 行动推进附近；选中态引用该实体，不再复制一张“已选法术”。 | 已计划和已选重复成两个实体；计划牌缩成角落挂件；计划牌与法术书抢位。 |
| 对手已计划法术是隐藏信息 | 左上镜像己方计划位置，只显示卡背、数量和所属关系。 | 显示对手计划正面 / 卡名；称为对手手牌。 |
| 弃牌堆是公开归档 | 低权重边缘入口，显示所属、数量、紧凑顶牌正面 / 半露正面；点击后可展开检视。 | 用卡背伪装成未知信息；把弃牌堆放中央或与当前来源同权；完全不显示。 |
| 生物 / 魔物是场上实体 | 正式卡面放入唯一所属区域；token 和高亮贴附宿主；同格多对象用堆叠锚点。 | 圆点、头像、文字 count 替代卡面；对象骑线；token 漂离宿主。 |
| 结界是附属且可能隐藏 | 己方隐性结界可用卡背贴附宿主并可检视；对手隐性结界只露卡背 / 附属关系，不泄露内容；显性后露正面。 | 把隐藏结界画成公开正面；用纯文字状态替代结界卡；把所有结界放成独立边栏主对象。 |
| 攻击 / 效果骰是当前结算主体 | 骰子、伤害和状态结果应在主舞台上层，靠近来源 / 目标 / 当前动作链；伤害沿用 Summoner Wars 样式：红色受伤遮罩贴对象本体，剩余 / 总生命读数默认 hover / 聚焦显示，眼睛按钮切换全场常显。 | 放进右侧日志、边栏或角落作为主承载；省略骰子、状态或伤害结果；用普通蓝圆、右下角数字气泡或永久压牌面数字替代伤害读数。 |
| 守卫改变近战目标选择 | 守卫 token 必须贴在守卫生物 / 法师本体中下方；守卫动作入口也用同一真实 token 贴选中宿主中下方触发；近战目标高亮要先体现守卫优先级。其它单位能力入口进入屏幕中下统一动作 dock，不挂在守卫附近、不锚到格子角落、不进入顶部描述横幅，也不是场上卡牌实体。 | 守卫只做 HUD 文本；守卫 token 放离宿主、压住区域归属、做成右上角按钮堆或小卡片壳；其它能力卡按钮出现在守卫正下方、格子角落或顶部横幅；用牌面缩略图 / 小卡片壳冒充单位能力入口。 |
| 没有规则授权的常驻确认不成立 | 默认流程是选来源对象 -> 高亮合法目标本体 -> 点目标本体 -> 结算；需要可撤销、支付分支或响应窗口时才出现临时确认。 | 常驻“确认使用 / 确认施放 / 取消”占位；用代理摘要面板替代真实对象直选。 |

## 分层模型

| 层 | 承载对象 | 设计要求 |
| --- | --- | --- |
| 背景层 | 正式竞技场、未使用半场退场纹理、桌面材质 | 最低层；只保护规则热区，不保护低权重纹理。 |
| 区域语义层 | `A1/B1/A2/B2/A3/B3` 区域线、可移动格、可选目标格 | 区域边界必须一眼可读；高亮贴格子本体。 |
| 战场实体层 | 法师战场实体、生物、魔物、显性结界 / 装备附件 | 每个实体有唯一锚点；选中、来源和目标只贴状态，不改变布局尺寸。 |
| Token / 状态层 | 行动 / 快速施法、守卫、燃烧、腐化、眩晕、昏迷、沉睡；伤害状态用现代本体受伤遮罩 + 贴宿主生命读数 | 离散 token 贴附宿主；守卫固定中下方且不得和能力入口堆叠；单位能力入口不是 token 或场上卡，不能用牌面缩略图造成小牌误读；能力一级动作进入屏幕中下统一动作 dock，顶部横幅 / 阶段条只做描述提示，来源和目标仍由棋盘 / 单位本体表达。伤害读数默认 hover / 聚焦显示，眼睛按钮可常显。允许轻微覆盖卡角，但不能遮住卡牌归属或关键图面；伤害不强制使用物理 token 图，也不得改成右下角圆形数字球或通用爱心 / 护盾图标。 |
| 当前动作层 | 来源短状态、合法目标高亮、移动路径、当前阶段短标签 | 服务下一次点击，不写规则解释正文。 |
| 结算层 | 攻击骰、效果骰、伤害结果、状态结果、法术释放 FX | 属于主舞台 overlay，锚定来源 / 目标；结算后退场或折叠。 |
| 玩家 HUD 层 | 当前 v80 基线：双方法师规则提示卡、生命、法力、聚魔、伤害、状态短读数 | 贴玩家归属，不替代战场实体；血条 / 蓝条可程序化，但必须贴近法师对象语义。 |
| 法术书层 | 己方法术书 6 张、分类标签、分页按钮、己方已计划 2 张、公开弃牌堆入口 | 可覆盖低权重地图纹理；必须可读、可点、可恢复；不得被地图挤到底边。 |
| 详情 / 检视层 | 法师牌详情、完整卡面 inspect、弃牌堆展开、规则回看 | 临时层，不占常驻布局；打开时不遮挡仍需点击的目标。 |

## UI 元素清单

| UI 元素 | 规则对象 | 默认可见性 | 布局锚点 | 交互 | 表达方式 | 禁止替代 |
| --- | --- | --- | --- | --- | --- | --- |
| 学徒竞技场半场 | 2x3 区域竞技场 | 常驻 | 中央主舞台 | 区域直选、移动 / 目标高亮 | 正式竞技场底图 + 2x3 语义 overlay | 纯 CSS 网格替代正式棋盘 |
| 未使用半场 | 学徒模式忽略另一半 | 低权重 / 可裁掉 | 背景层 | 不可点击 | 退场暗化或裁切 | 看起来仍可摆卡 |
| 法师战场实体 / 法师本体 | 法师本人作为生物 | 常驻 | 所属区域内 | 可作为来源 / 目标 / token 宿主 | 人物 / 肖像 frame 裁成战场实体，或后续正式 mini / standee；行动标记 / 快速施法标记贴附其上或紧邻其卡角 | 密集文字法师规则 / 提示卡、纯文字、圆点或无材质占位 |
| 玩家 / 法师规则提示卡 | 玩家归属、法师能力参考、当前操作归属 | 常驻 | 当前 v80 基线：玩家 HUD 昵称 / 状态旁 | 提示当前玩家 / 行动归属；点击可打开详情 | 当前 v80 基线：密集文字法师规则 / 提示卡，HUD 尺寸和层级 | 把它和竞技场本体混成同一对象；用纯头像导致规则提示职责消失 |

## 设计前置检查

下一版 UI 设计、Open Design artifact 或真实 Board 实现开始前，必须逐项回答：

1. 当前画面处于哪个规则阶段：计划、优先快速施法、生物行动、攻击结算、维持，还是回合结束。
2. 当前玩家下一次点击的真实对象是什么：法术书卡、已计划法术、场上生物、法师、区域、目标卡、分页按钮，还是回合结束。
3. 每个可见规则对象是否只有一个实体锚点；若出现详情、目标摘要或选中态，是否只是引用层。
4. 法术书、已计划、公开弃牌堆和对手已计划是否使用规则术语；画面、class、aria 和审计文本不得出现“手牌 / opponent hand”。
5. 公开归档、隐藏信息和当前候选是否已区分：公开弃牌堆正面半露，对手计划 / 隐性结界卡背。
6. 攻击骰、效果骰、伤害状态 / 伤害数值、燃烧 token、守卫 token、行动 token 是否在饱和态出现；不得为了干净减少用户点名规则信息。伤害默认用现代 UI 表达，不强制出现物理伤害 token 图，但必须是贴宿主的 Summoner Wars 式受伤遮罩 / 生命读数，且有眼睛按钮控制全场常显；不得是孤立角落数字球、永久压牌面数字或通用 icon。守卫状态和守卫动作入口都必须是贴宿主中下方的真实守卫 token，不得进入右上角按钮堆或与能力入口堆在一起；单位能力动作入口不得用牌面缩略图小卡片冒充场上实体，也不得锚到格子角落或顶部横幅，应进入屏幕中下统一动作 dock。
7. 地图是否被当成最低层：法术书 / 已计划 / 结算层可以覆盖低权重纹理，但不能遮住区域归属和当前目标。
8. 是否存在规则未授权的常驻确认 / 取消；若存在，必须写出确认前能改什么、确认后发生什么，否则删除。
9. 删除、缩小、移动任何 UI 区域后，释放空间是否重新分配给真实对象；无职责空白直接 `REVISE`。
10. AI 自审只能说明能不能送人工看，不等于用户批准；设计稿未获用户明确批准前不得进入实现。
11. 法师对象 v80 基线复核：当前已定稿是场地格子用人物 / 肖像法师本体，玩家 HUD 用密集文字规则提示卡；新稿若不沿用该落位，必须先说明替代方案如何保持“战场实体 / 规则提示 / 详情”职责分离并获得用户重新认可。
