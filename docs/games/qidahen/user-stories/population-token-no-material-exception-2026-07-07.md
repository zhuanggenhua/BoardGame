# 七大恨人口不生成地图指示物例外

## 现实裁定

用户已明确裁定：七大恨地图上的人口已经有底图数字，不应再生成额外人口指示物。

这是一条只针对“人口数量状态”的专项例外，不是七大恨全局素材规则的放宽，也不是其他对象可以跳过素材或隐藏对象的通用依据。

## 适用对象

- 七大恨地图区域里的“人口数量”。
- 运行时地图 token 同步逻辑中是否生成额外人口 token。

## 规则解释

人口在当前七大恨实现里表示一个地区的数量状态。它不是玩家手牌、兵牌、控制标记、地区牌、人物、骰子，也不是需要单独查看正反面或被玩家直接操控的实体对象。

因此，人口应使用底图已有数字作为显示来源。实现层不得再额外生成一个人口 token，也不得用“生成后不渲染/隐藏”的方式处理；隐藏问题是禁止的。

## 实现要求

- `syncQidahenMapTokensFromRegions` 不得为人口生成 `type: 'population'` 的地图 token。
- `QidahenMapToken` 类型不应包含 `population`。
- 不得通过“生成后隐藏/不渲染”解决人口显示问题。
- 不得新增 `populationMarkerImageSrc`、人口图片字段或人口专用素材配置来满足这类显示。

## 验收标准

- 地图上人口仍由底图数字表达。
- 运行态 `mapTokens` 中不存在人口 token，也不存在 `*-pop` 人口指示物。
- 代码或测试里能明确拦住“人口 token 重新生成”的回归。
- 本例外不会被解释成“所有七大恨对象都可以不用素材”。

## 不覆盖范围

- 兵牌、手牌、控制标记、地区、人物、骰子仍必须优先使用正式素材或已有正式组件。
- 兵牌仍需要遵守正反面展示规则，不能借用人口例外跳过素材。
- 控制标记仍可以使用素材和数值角标，不能借用人口例外退化成纯数字。
- 骰子不属于本例外。掷骰核心必须真实产生对应面数的结果；展示层只有在已有组件或素材能正确表达该面数时才能接入，不得用不支持多面骰的组件伪装支持。
