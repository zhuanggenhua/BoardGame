# 七大恨教程分层避让修复

用户原话：“避开所有保护对象是代码还是规范问题，有问题就修了重构啊，说了ui分层判断避让的时候好好反思是不是在一个层”。失败原图是轮盘介绍在左上、说明卡在右下，玩家不能顺着画面建立文字与对象的联系；用户否定R144该定位与验收结论。

## 治理与范围锁定

| 对象 | 角色与处置 | 依据 |
| --- | --- | --- |
| `ui-ux`、`ui-responsive-layout`、`ui-change-gates` | canonical-source，保留 | 已明确层级先于几何、界面锚点不因低层实体漂移、当前目标与必要输入保留。不是缺少一条“所有对象禁止重叠”规则。 |
| `tutorial-design` | canonical-source，补直接引用 | 定位段落原先只引到槽位门禁；明确指向已有界面/场景层级主源，不复制另一套正文。 |
| `ui-audit-loop`保护槽位句 | adapter，删除脱层绝对判据并合并为主源引用 | 原“新UI不得抢占token、状态、资源…”未限定层级，紧接可读性清单可能绕过前面的层级前提；其有效的当前槽位保护已由ui-change-gates覆盖，跨层覆盖由ui-ux唯一裁定。本处只记对象、所属层、当前任务和原图结论。 |
| 七大恨PROTECTED_UI与E2E | 实现/校验，修正 | 无条件所有军队、明控制、明人口把低层背景变成硬障碍，测试固化错误要求。按同层界面与当前任务分别取现有正式对象。 |
| 原视觉PASS | evidence，历史失败 | “零交叠”不能证明提示和教学对象清楚关联；规则数值和已执行操作仍是各自事实，不能给当前视觉放行。 |

目标环境为当前本地PC正式教程入口。允许改动教程保护对象分类及直接错误断言；复用已有HUD/地图焦点、候选、交战和维修上下文元数据。共享定位器继续只消费调用方给出的实际矩形，不新增自动z-index推断、全局实体扫描、影子布局状态或规则权限。课程、文案、费用、实体、随机、阶段与进度版本不变；不移动常驻HUD去躲地图，不隐藏合法候选换通过，不开始移动端。

2. 仅改父锚点后，1362尺寸仍选择远端候选：同层手牌比顶部玩家栏先被枚举，旧定位器选第一个零交叠滑移位置，忽略更近的合法位置。公开布局单测直接复现{x:422,y:431}而应{x:422,y:65}，再最小修改共享默认PC排序：保护区与目标交叠优先级不变，在侧序之前比较超出原padding+保护间距的脱离距离。正常贴附候选该距离为0，保留原侧序；不能再把远端滑移误认作完美相邻而跳过近处自由候选。

共享修改只在原默认PC分支，compact、center和targetless路径、API、输入、规则、导航与几何缓存保持原职责；首次复杂求解成本仍存在。新增断言留在既有布局行为测试，不建立第二套定位owner。两种PC宽度的真实回归最终均通过，并验证实际拖图及推荐绿色扇区，不以像素距离替代独立图审。
