# 七大恨手牌与出兵交互重构

用户要求：“手牌露出一半，悬浮才完整抬起”“统一用放大镜组件”；第08图没有展示如何选择出兵，战前弹窗需要按成熟战略游戏参考重做。范围是本游戏手牌、检视、战前出兵与对应教程，不改地图地理、战斗数值或其它游戏。

## 依据与实现边界

- 规则源仍为正式PDF Ver1.3及已有战斗合同；出兵数量消费现有正式参战上限和命令，不能把河流战场宽度2误当成只允许出2支部队。骑兵劫掠属于另一种合法战斗选择，不能为简化面板删除。
- 真正选兵入口是地图源地区兵牌，当前已选数量由正式战前读模型承接。旧E2E先点第4支兵，再拍第08图，缺少选择前的教学与可选反馈证据；新流程须先识别选兵对象，再实际选择，最后执行战斗。
- 手牌常态露半张是用户本轮明确的布局决定；悬停及键盘聚焦时完整抬起，选牌继续保持选中反馈。检视入口复用共享`CardInspectButton`与已有`MagnifyOverlay`，不再复制一排“看”按钮。
- 代码职责：扩展现有手牌组件的显示状态；战前决策信息由独立窄组件承接，Board只接现有读模型和回调；正式选兵、支付及结算仍归原owner。

首先通过Game UI Database站内检索并打开[《全面战争：特洛伊》界面集](https://www.gameuidatabase.com/gameData.php?id=1234)。搜索工具被robots拒绝后，内置浏览器成功读取同一站点，不据此报告任务阻塞。

子代理实际读取《全面战争：特洛伊》9张整屏截图（`test-results/r85-reference/review.json`）：省份驻军按地点分组，军队卡组与容量同区，首次操作任务把必要输入与目标分层。没有真正战前双方比较截图，不能据此声称借鉴了战力预测或战斗确认。

另由子代理实际读取[《文明VI》10张整屏截图](https://www.gameuidatabase.com/gameData.php?id=639)（`test-results/r85-reference/civ/review.json`）：Found A City与Select Research教程箭头指向真实可点控件；地图对象、同名详情和必要资源读数相互对应。本轮采用“真实地图兵牌承担选择输入、教程锚定第4支部队、紧邻详情区承接已选数量与河流宽度”的职责关系。没有从截图推断动态悬停，也没有实际游玩这两个商业游戏；本轮半露/悬停行为来自用户明确要求并由真实浏览器另验。不复制商业素材、皮肤或规则。

## 实现与逐图退回后的修正

- 手牌只在悬停、键盘可见焦点或选中时完整抬起；检视使用共享放大镜，删除平行“看”按钮排。
- 突袭准备保持未选出兵状态，玩家实际点源地兵牌后才可开战；已选兵牌用金色主边界与勾记区分可选绿边，教程蓝框只表达推荐目标。
- 战前只承接来源目标、出兵数量、真实战场宽度与已生效战术；教程活动时不再重复一般选兵指令。骑兵劫掠保留规则名称及合法入口。
- 私有诊断的三张原图全部退回后，按具体问题修正：战术标记补实际骰子等级加成；结果教学指向面板标题，避免整块高面板被自动居中裁切；战斗阶段及损伤说明移到实际结果出现后。
- 触屏验收使用露出牌面的实际可见中心长按；不能用自动滚动把整牌抬入屏幕，再冒充半露状态的真实输入。手机常态半露、选中抬起与检视完整卡面分别验证。
