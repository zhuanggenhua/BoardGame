## 已证实的具体问题与修正

1. **错误区域中心**：辽东、辽西的旧保存中心落入相邻运行时区域。此前已修正这两处中心；人口布局继续消费正式像素归属，检查完整占位、邻近军队 / 控制标记，并为窄区使用指回区内的短引线。
2. **八张支付手牌的首张不可完整到达**：真实浏览器的代表态记录显示，滚动窗从 `x=206` 开始，首牌却从 `x=176.8` 开始。超宽牌列居中后左侧产生不可滚回的负溢出。两层手牌容器改为起点对齐，内层保留自动外边距，使少牌继续居中、溢出牌列从首牌开始滚动。
3. **宽屏 PC 存在第二次字号变化**：全局根字号在 1921px 以上变为 18px，而棋盘壳已经缩放一次。壳内继承字号及 Tailwind 的间距单位随之变化。本次在七大恨设计舞台内固定设计字号、行高和直接使用的间距 / 小字 / 圆角变量，保持 PC 1920 基线与统一比例。
4. **支付时空行动区仍截获地图输入**：保留教程任务的修正：支付托盘出现时，空行动区退场，由正式托盘承接支付。
5. **地图聚焦遗漏朝鲜牌区**：保留教程任务将朝鲜牌区加入聚焦避障的修正，不改地图区域和规则目标。
6. **触摸点选地区后无法稳定读取说明**：真实浏览补测已通过地图平移和地区命中，但现有说明框随触摸的离开事件立即失去悬停状态。触摸点选改为保留同一说明状态，鼠标仍按原悬停退出；点地图空白或拖动地图会清除说明。复用现有地区说明框，不增加替代入口。

## 对相关 skill 的判断

- 七大恨专项已明确地图与 HUD 分离、轮盘本体承接操作、底部只保留必要动作，以及手牌行动和轮盘行动的层级。原材料建议的若干“新原则”实际已在当前正文中，不能据其源码粗读结论认定专项设计失效。
- 移动规范区分固定构图与开放场景。七大恨同时包含自由地图和固定操作构图，选择哪条布局合同必须先落实当前产品裁定；本次用户已经明确选定手机继承桌面等比，不能继续以开放场景条款推导另一套手机 HUD。
- 代码设计规范要求按职责归属处理复杂度，没有“文件达到某行数便必须全部拆散”的单一结论。支付投影、图层布局与状态接线各自归位有实际收益；仅移动常量和文件不会自动改善玩家画面。
- 视觉验收必须同时核对本轮产品要求、同状态桌面 / 手机图面以及真实输入。此前移动专版能点击或局部不重叠，仍不符合用户要求，旧通过结论已作废。现在保留真实几何、压力态、触摸点选和独立逐图记录。
- 本轮执行当前规范并记录适用边界，未改写规范或 skill 正文；若后续要治理入口歧义，应另按项目规范治理流程处理，不能把这次证据记录变成第二份响应式执行规则。

## 图面事实与不能扩大解释的结果

- 首轮当前源码的常态 / 支付图中，没有直接证据证明两个人口方块互相重叠。
- 图中存在地图标记与手牌 / 支付区跨层覆盖。地图可以平移缩放；这与人口算法把两个方块放在同一点不是同一问题。当前必须操作的目标若被覆盖且不可恢复查看，才构成该动作的可达性失败，需要直接动作证据。
- 左上轮盘与右侧势力按钮大小不同，不单独证明层级错误；轮盘是正式主动作对象，右侧按钮是部分势力行动，不能当作四个并列主动作。
- 手机等比后细字较小是需要保留的可读性观察；不能据此擅自改回手机专版。卡牌检视和当前决策的真实触摸应单独验证。
- 首轮截图包含开发调试扳手。源码证明它仅在开发 / 显式 E2E 调试时显示，生产默认不显示。后续证据采用已有 `__BG_HIDE_DEBUG_PANEL__` 开关模拟生产页面；不以隐藏正式 UI 的方式修复问题。
