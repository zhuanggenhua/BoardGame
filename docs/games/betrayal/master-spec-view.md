# 山屋惊魂主 spec 视角与当前缺口

> 2026-07-29 接续裁定：本文件是整游戏主视角和历史 change 汇总，不是发现牌整牌库 S0 主合同。正文中关于 `12 张物品 / 23 张事件 / 发现池已完成第一层收口` 的口径属于旧阶段现场或随机化/首剧本范围，不能覆盖当前整牌库主合同 `evidence/betrayal/full-audit/full-deck-data-intake-contract.md`。当前发现牌数量层以 `43 张事件 / 22 张物品 / 9 张预兆` 为准；配置和 atlas 数量对齐仍不等于逐卡机制、UI、E2E 或截图完成。

> 用途：把 `betrayal` 从“多条阶段 change + 多份专项文档”收成一个整体视角。
> 这份文档不替代各条 change 的 proposal / tasks / design，也不替代专项 evidence；它只回答三件事：
> 1. `betrayal` 这个游戏整体现在做到哪了；
> 2. 现有各条 change 分别属于整体的哪一部分；
> 3. 当前哪些缺口阻止它被说成“正式完成游戏”。

## 0. 当前本地核心文档真相源

这份主视角不是只基于当前实现倒推，当前直接依赖的正式真相源至少包括：

- 基础规则书：
  - `docs/games/betrayal/sources/official/betrayal-3e-rulebook-en.md`
  - 其中 `HOW TO PLAY — BEFORE THE HAUNT` 明确了恶兆前的主循环：移动、探索、交易、使用特殊动作；
  - 其中恶兆段落明确了 `haunt roll` 依赖“所有玩家当前持有的恶兆总数”，不是历史探索次数。
- 英雄剧本书：
  - `docs/games/betrayal/sources/official/betrayal-3e-secrets-of-survival-en.md`
  - 其中 `Stacked Like Cordwood 2: Crimson Jack Returns` 明确了英雄侧目标、`Study the Exorcism`、`Exorcise Jack's Spirit`、`Knowledge of Jack` 等首剧本规则。
- 叛徒剧本书：
  - `docs/games/betrayal/sources/official/betrayal-3e-traitors-tome-en.md`
  - 其中同名剧本条目明确了叛徒身份、回满属性、`Stalk the Prey`、死亡后 `Jack's Spirit` 接管等规则。

当前这份主视角的首轮范围，只覆盖本地可读到的 `base game + 当前点名的第一剧本 + 对应玩家提示/参考文档`；扩展、变体、更多剧本与可选规则，默认仍属于后续可选实施任务，除非用户明确把它们纳入当前范围。

因此下文里的整体判断，既参考当前实现与 E2E，也明确受这些相关文档真相源约束；不是只看现在代码“能跑到哪”。

## 2. `betrayal` 的整体目标

从主 spec 视角看，`betrayal` 不是“做几张页面”或“跑通一条代表链”，而是至少包含以下整体层：

1. 资源与对象真相
   - 角色、怪物、房间、牌堆、标记、参考卡、背面资源、图集与 token 真相
2. pre-haunt 正式运行态
   - 起始拓扑、移动、探索、交易、使用、结束回合
3. haunt / 剧本运行态
   - 真实触发、真实剧本动作、真实胜负收口
4. 教程
   - 建立在正式玩法之上的首轮教学链，而不是 tutorial-only 假页面
5. 后续多剧本扩展能力
   - scenario/setup/source-of-truth 分层

当前 `betrayal` 的真实状态是：第 1-4 层都已有部分落地，但第 1、2、5 层仍存在正式规则真相缺口。

## 5. 当前阻止“正式完成游戏”的核心缺口

以下缺口不是 polish，而是会阻止 `betrayal` 被说成“正式完成游戏”的主视角缺口。

### 5.1 正式随机真相与发现池已完成第一层收口

本节标题里的“收口”只指随机化和当时发现池入口从固定数组升级为局内结果态，不等于官方 74 张发现牌机制 / UI / 验证完成。涉及发现牌整牌库时，必须回到 2026-07-29 主合同。

当前代码已经从“探索时临时按固定数组取值”改成“setup 时生成当前局发现池顺序，运行时消费当前局结果态”：

- `BetrayalCore.drawOrder` 保存本局牌堆类型顺序
- `BetrayalCore.roomDiscoveryOrderByFloor` 保存本局各楼层房间发现顺序
- `BetrayalCore.possessionOrderByKind` 保存本局物品 / 预兆抽取顺序
- `BetrayalCore.eventOrder` 保存本局事件抽取顺序

同时，当前正式发现池已经不再停留在最小代表池：

- 房间发现池：一层 18 间、上层 14 间、地下 10 间，合计 42 间；阁楼因当前房间正面图集没有独立图面，已从运行时发现池移除；
- 牌池：物品 12 张、预兆 9 张、官方事件 23 张；
- 单测已经约束发现池规模、房间门位非空、物品 / 预兆 id 不重复，以及发现池房间都能映射到可渲染图集。

这说明：

- 正式局内已经不再依赖 `exploreIndex` 直接套固定数组来决定下一张牌或下一间房；
- 测试仍可通过固定 `RandomFn.shuffle` 稳定复现，但正式逻辑本体已经具备当前局发现池状态；
- 后续缺口不再是“随机系统还是固定序列”或“是否还只有最小代表池”；发现池 / 效果审计当前发布口径已收口，剩余边界转为更多作祟剧本、房间背面 / 楼层板资源合同和未来新增对象的独立审计。事件牌当前锁定 23 张官方事件合同，正式运行事件牌堆接入 23 张；`大宅饿了` 对应作祟 12，当前已接入官方 setup、奇异护符控制权、巨魔手初始放置、偷牌替代伤害、Board 组件里的巨魔手移动 / 结束怪物回合、巨魔手合击入口和合击后伤害分配代表链，且已补真实入口移动 / 结束 / 合击 / 护符换手 / 无护符跳过代表截图；旧运行时邪教徒 / 仪式房 / 裂隙链已判定错挂且不再作为 12 的正向验收。当前正式可触发作祟代表链承认 1「赤红杰克」、3「灰尘」、12「大宅饿了 / 援手」、33「魔法相机」；其中 12 的完整自然怪物回合全排列和完整终局仍未完成。背面和未来新增事件不得用旧占位凑数。

### 5.2 空间系统仍未完全证明为正式数据驱动

虽然起始拓扑、开放门位、可探索槽位已经补了一轮真相，但当前仍缺更高置信度的整体收口：

- 每张房间真实门位 / 朝向 / 可连接边 是否已经完整录成正式数据；
- 是否仍存在部分 UI / 逻辑对房间连接关系的手工补丁；
- 房间背面 / 楼层背面资源合同是否已完整进入正式运行态资源链。

当前状态更准确地说是：

- 已从“单一下一槽位”升级为“有开放门位语义”，并能消费 42 间当前可确认房间；
- 真实牌桌里的“点击探索 -> 选择未知门位 -> 翻开新房间”已经补到 E2E 证据链；
- 但还没到“整套空间真相已完整录入并穷尽验证”的程度。

### 5.3 对象真相仍未完全收口

仍需继续核对：

- 玩家 token / 怪物 token / 房间背面 / 楼层板 / 更多怪物与标记素材是否已完整进入正式目录；
- 当前正式运行态是否还混有占位对象、错素材对象或低保真承接物；
- 某些对象是否只是“足够支撑第一剧本”，而不是正式完整对象集。

### 5.4 第一剧本仍是“最小闭环”，不是“完整验收”

当前文档已经明确：

- 第一剧本双主线最小闭环成立；
- 未知房间探索、交易、调查杰克、研究法阵、英雄攻击叛徒、尸体搜刮与二次限制的真实 UI 证据已补齐，但更多复杂分支和全量规则边界仍未穷尽；
- 教程已覆盖英雄线和叛徒视角最小收尾，不覆盖更多复杂分支。

所以当前正确口径只能是：

- `第一剧本最小可玩闭环成立`
- 不能写成 `第一剧本完整验收通过`

### 5.5 多剧本 / 更多 haunt 扩展能力仍需继续扩展

`refactor-betrayal-scenario-setup-model` 已经把 owner 和 setup/source-of-truth 问题抬出来了；当前新增剧本 3/12/33 已经沿正式作祟入口落地代表链，但仍不能外推为全部剧本完成。后续还需要证明：

- 更多剧本能继续沿同一条正式配置通道落地；
- 剧本书 / haunt 书的更多对象进入正式数据层；
- 当前 1/3/12/33 之外的正式玩法成立。

- `betrayal` 已具备首轮基础教程

1. 继续补更多作祟剧本

4. 补第一剧本残余边界证据

5. 再进入更多剧本 / 更多教程

## 8. 当前主视角结论

`betrayal` 现在的正确整体判断是：

- 它已经超出 skeleton；
- 已具备第一剧本与首轮教程的真实最小闭环；
- 随机和正式发现池 / 效果审计已按当前发布口径收口；
- 但正式局内的更多作祟剧本、背面 / 楼层板资源合同和未来新增对象仍未完全收口；
- 因此它当前属于：

`局部流程已验证，正式游戏仍未完成`
