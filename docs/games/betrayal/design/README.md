# 山屋惊魂设计索引

本目录只做 `betrayal` 设计入口：告诉后续 agent 当前该沿哪张稿继续、哪些历史稿不能再当候选、实现验收回到哪里。过程点评不放在入口里堆长文。

## 当前有效合同

- 当前路线：停止继续生图，按运行时 `v4`、角色选择 `character-select-style-b`、终局 `endgame-style-b` 的结构裁定进入首剧本实现线；这些是当前基线名，不是当前仓内可打开的生成稿证据路径。
- 设计主约束：[design-system/games/betrayal.md](../../../../design-system/games/betrayal.md)。
- 首剧本实现目标：跑通 `角色选择 -> 恶兆前运行时 -> 终局`，并用真实页面截图验收。
- 当前截图只能证明基本流程和第一剧本分段可跑通；角色选择、运行时、终局尚未达到高保真最终验收。

## 设计门禁

1. Step 1：规则提炼 / 运行时结构稿。
2. Step 2：布局收敛，只保留 1 张默认继续母版。
3. Step 3：在已选布局上统一风格。
4. Step 4：在已选风格下分界面出稿。

继续设计或实现时必须同时满足：

- 默认沿 `v4` 版式纪律单线推进；除非用户明确要求，不再开多版布局或风格分叉。
- 当前风格优先 2D 印刷桌游 UI，不回到 3D 实体渲染概念图。
- 素材语法优先：探索者板、五角属性、牌框、槽位、徽记和牌背先复用原素材，不先替换成泛化 HUD。
- 继续生成或改布局前先回答：持有物最多放多少、玩家当前能做什么、玩家第一眼看哪里。
- 实现验收必须回到真实页面截图；HTML mock、静态图、E2E 过程截图都不能冒充最终设计验收图。

## 当前基线

- 运行时 `v4` 的有效结构：中央房间板块网络是主视区，左侧探索者板承接角色，右侧三堆牌承接资源，底部 5 个主动作承接前兆前行动。
- 角色选择和终局分别沿 `character-select-style-b`、`endgame-style-b` 的结构裁定；它们是实现基线名，不是过程探索稿，也不是当前可独立验收的图片证据。
- 运行时实现已接入角色选择、运行时、终局三屏；首剧本已经有分段合同和截图证据。
- 后续增加房间或替换房间图时，继续从原始房间 atlas / 原始单图建立裁剪合同，不得回退到 `contact-*` 或低清索引图裁片。

## 历史稿处理

- `v5-v12` 和其它继续稿统一降级为失败 / 过程参考；它们没有守住 `v4` 的版式纪律，不再是默认候选。
- `step2-imagegen-*`、`style-a / b / c` 只保留历史档案价值；若要重启，必须重新过当前设计门禁和用户批准。
- `step2-layout-*` 是手工拼贴失败反例：可保留布局意图，不能作为正式生图设计稿。
- “foundation 资源壳层 / 录入界面”不是本游戏 UI 设计目标；不得用资源壳层截图替代对局 UI。
