# 山屋惊魂牌桌 UI：属性轨、预兆状态与开局过场合同

> 状态：`locked-for-runtime-ui`
> 日期：2026-07-31
> 角色：`canonical-source`，用于记录用户对山屋惊魂牌桌 UI 的专项裁定；上层规范只引用，不复制本文件正文。

## 用户原始要求

用户明确指出：属性不能再显示成一对小方块，必须像实体角色卡计量表一样用连续轨道和指针表示当前位置；骷髅是死亡端点，不是数值 `1`；预兆本来是进度条，不是常驻规则说明墙；卡图或正式素材已经有的内容，运行 UI 不要重新写一遍；作祟 setup 不要常驻在主 HUD；点击开始剧本后必须有开局过场承接，而不是中途冒出“开局承接”这类工程化提示。

## 覆盖对象

| 对象 | 裁定 |
| --- | --- |
| 属性轨 | 用连续轨道 + 指针 / 夹子指示当前位置；刻度只能辅助读数，不能成为一格格主视觉。 |
| 骷髅端点 | 骷髅表示死亡端点；不得显示或解释成数值 `1`。重复数值按轨道位置区分。 |
| 属性轨刻度 | 按实体角色板的均匀格位显示，重复数值仍是不同格位；不得因为数值相同就合并刻度或让指针跳格。 |
| 投骰承接 | 物理骰使用透明虚拟骰盘，不得再套深色大背景、骰盅式托盘或封闭面板。 |
| 投骰透明边界 | “透明”必须落实到实际可见层：外层容器、内层 tray surface、canvas 承载层都不得再叠背景图、径向渐变、黑盒、厚边框或遮罩式托盘。 |
| 投骰必要信息 | 骰面合计、加值、总点数属于当前结算状态，必须可见；这不属于“卡图已有正文不要复写”的禁止范围。卡面标题 / 规则正文可以隐藏复写，但投骰计算不能隐藏。 |
| 预兆状态 | 常驻 UI 用实体分段进度条和短状态承载，例如 `预兆 3`、`再抽即作祟`、`作祟已开始`。 |
| 预兆进度条刻度 | 当前素材与运行牌库锁定为 `0-9` 等距分段槽；当前格必须直接高亮，非当前格只保留实体槽位和分隔，不得把已经过格子画成填充进度；不能用独立指针、连续填充条、概率百分比条或“作祟风险”概率条冒充预兆进度。若未来换成其它实体素材，必须先补素材证据再改刻度。 |
| 作祟检定规则 | “按已发现预兆数掷骰，5+ 作祟；最后预兆自动触发”只进入 tooltip / title / aria / 规则页，不常驻铺在牌桌上。 |
| 作祟 setup | setup 队列和确认命令可以留在领域逻辑里，但牌桌右侧 rail / 主 HUD 不常驻显示 setup 文本墙或 setup 确认卡。 |
| 作祟触发剧本承接 | 作祟从未开始变为已开始、剧本卡切换或阵营阅读对象变化时，必须有一次剧本书 / 剧本阅读承接；稳定作祟牌桌、重进页面、关闭剧本后回牌桌，不得只因为领域状态仍是作祟就反复弹出剧本书。作祟横幅本身不再显示“阅读开局 / 可以打开剧本 / 英雄和叛徒分别阅读”这类动作或规则流程提示，重开入口只保留右侧短按钮 `剧本`。 |
| 开始剧本后过场 | 从角色选择进入恶兆前牌桌时，必须先显示一次全屏开局电影字幕；直接注入恶兆前状态的测试夹具不强制弹出。 |
| 正式素材已有信息 | 卡图、剧本页、参考卡、token 或实体组件已经表达的信息，运行 UI 只补交互、状态归属和无障碍信息，不再可见复写同一套标题 / 规则正文。 |
| 业务逻辑与 UI 分离 | 官方规则和领域逻辑必须先提炼成玩家可用 UI：常驻主 UI 只显示对象名、当前值、短状态和动作入口；规则流程、系统决策、测试结论、setup 队列、阵营阅读说明、素材来源、原文可信度、OCR / 转写状态、正式翻译状态不得原句上屏。剧本开场 / 终局朗读的标题下不得出现“本地规则源正文”“正式中文转写”“官方 If You Win 原文”“非原文摘要”等开发来源小字。 |
| 剧情幕可见文字 | 开局电影字幕、作祟剧本阅读承接和终局朗读里，玩家可见文字最低 `12px`；眉标、章标、页脚 `序章 / 终幕`、按钮副文案和装饰性短字都按可见文字处理。若只是氛围装饰，必须改成非文字装饰或删除，不得缩成 8-11px 小字。 |

## 防回归门禁

- 改属性轨、投骰、预兆 / 作祟状态、剧本阅读或开局过场前，必须先回到本文件、官方规则源和对应正式素材 / 运行牌库；缺少证据时只能补证据，不能凭印象重画 UI。
- 牌桌常驻 UI 不得从概率、推测风险、工程状态、业务流程、测试结论或测试夹具名派生玩家可见文案；只显示玩家此刻必须持续读取的对象名、数值、短状态和动作入口。
- 投骰承接态必须同时验收“无深色大背景 / 无托盘”和“骰面合计、加值、总点数可见”；不能用“卡图已有内容不复写”隐藏投骰计算；不能只给外层写透明标记，内层实际渲染层也必须无背景图 / 无渐变 / 无托盘面。
- 属性轨和预兆状态都必须按实体位置显示；重复数值、相同刻度或相同结果不得被合并成一个格位。
- 预兆状态必须表现为分段格槽，只有当前格直接高亮；非当前格不得显示已走过填充，不得退回单独指针、连续填充条或概率条。
- 作祟触发、剧本阅读和开局过场属于流程承接，不属于右侧 HUD 常驻说明；测试若固化了相反行为，先翻正测试合同，再改实现。
- 作祟揭示横幅只能显示短状态、触发来源和关闭动作；不得额外挂“阅读开局 / 打开剧本 / 可以查阅 / 英雄和叛徒分别阅读”按钮或句子。剧本承接只在作祟/剧本变化发生时打开一次，后续重开由牌桌固定短入口 `剧本` 承接。
- 剧情幕 / 剧本阅读承接 / 终局朗读里的所有玩家可见文字都必须 >= `12px`；截图里只要出现标题上下、页脚或按钮附近的 8-11px 可读小字，直接判为 UI 回归。

## 验收标准

- 属性轨截图里第一眼看到的是连续轨道和当前位置指针，不是离散小方块；重复数值不会让指针落错位置。
- 属性轨刻度按位置均匀分布；重复数值只作为辅助读数，不得被合并成单格。
- 骷髅端点在图面和无障碍说明里都表达为死亡端点，不把骷髅计为数值 `1`。
- 投骰截图里骰子直接浮在开放式桌面上，不出现深色托盘 / 大背景框；骰面合计、加值、总点数同时可见。
- 投骰 DOM / 截图验收必须能证明骰盘真实承载层透明，不得只检查外层 `data-dice-tray-style`。
- 预兆进度条显示 `0..9` 等距分段槽，当前预兆所在格直接高亮，非当前格不显示已走过填充；不得出现独立指针、连续填充条或概率百分比式“作祟风险”进度。
- 预兆状态常驻区域不出现 `下次掷 X 颗`、`5+ 作祟`、`再抽预兆时检定` 这类完整规则说明；这些信息只在 tooltip / title / aria 或规则阅读层可追溯。
- 作祟 setup 不在主 HUD 或右侧 rail 常驻；玩家牌桌只保留当前可操作目标、剧本入口和必要短状态。
- 作祟揭示横幅不出现 `阅读开局`、`打开剧本`、`可以查阅`、`英雄和叛徒分别阅读` 这类动作提示或规则流程说明；变化发生时的剧本承接结束后，重开入口只显示为右侧 rail 的短按钮 `剧本`。
- 作祟触发这种状态变化发生时，剧本阅读承接至少打开一次；稳定作祟状态、初次渲染已作祟 core、关闭后回牌桌都不得反复弹出剧本书。
- 从真实角色选择流程点击 `开始剧本` 后，必须先看到 `木乃伊横行` 开局电影字幕和规则源状态，再点击继续进入牌桌。
- 开局电影字幕、作祟剧本阅读承接和终局朗读截图中，标题上方、标题下方、页脚和按钮周边不得出现小于 `12px` 的可读文字；`序章 / 终幕` 这类短字如果保留，也必须按可读文字尺寸显示。
- 完整截图链必须包含：投骰承接态、属性轨当前态、属性轨详情态、预兆进度条普通态、最后预兆态、作祟触发后剧本阅读承接、作祟开始态、开始剧本后开局过场、过场关闭后牌桌。
