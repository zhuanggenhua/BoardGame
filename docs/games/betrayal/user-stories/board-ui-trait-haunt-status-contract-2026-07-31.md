# 山屋惊魂牌桌 UI：属性轨、预兆状态与开局过场合同

> 状态：`locked-for-runtime-ui`
> 日期：2026-07-31
> 角色：`canonical-source`，用于记录用户对山屋惊魂牌桌 UI 的专项裁定；上层规范只引用，不复制本文件正文。

## 用户原始要求

用户明确指出：属性不能再显示成一对小方块，必须像实体角色卡计量表一样用连续轨道和指针表示当前位置；骷髅是死亡端点，不是数值 `1`；预兆本来是进度条，不是常驻规则说明墙；卡图或正式素材已经有的内容，运行 UI 不要重新写一遍；作祟 setup 不要常驻在主 HUD；点击开始剧本后必须有开局过场承接，而不是中途冒出“开局承接”这类工程化提示。

## 覆盖对象

| 对象 | 裁定 |
| --- | --- |
| 属性轨 | 用连续轨道 + 指针 / 夹子指示当前位置；连续指同一条实体轨道容器，不代表把相同数字合并成同一段。 |
| 骷髅端点 | 骷髅表示死亡端点；不得显示或解释成数值 `1`。重复数值按轨道位置区分。 |
| 属性轨刻度 | 按实体角色板的均匀格位显示，重复数值仍是不同格位；相邻重复数字必须有可见分隔，不得因为数值相同就合并刻度、合并视觉格或让指针跳格。这里的“不得合并”以玩家截图肉眼判断为准，不是只看 DOM 里有几个节点。 |
| 属性轨当前值 | 当前值只能由轨道内当前格的整格高亮 / 夹子承载；不得在轨道右侧、角色头像板或相邻 HUD 再放一枚独立数字方块、数字贴片或第二个当前值实体。角色头像板若需要标记属性位置，只能用无数字夹子 / 指针锚定，不能复写数值。 |
| 属性轨视觉语义 | 属性轨颜色必须来自规则书、实体角色卡 / 正式素材或本合同已批准语义；绿色起始值是规则与角色板来源语义，必须保留并能和当前格高亮区分。用户追问颜色含义时，先解释当前格、起始格、临界格、死亡端点等现实含义，不得把追问自动改写成“去掉绿色 / 换成别的颜色”的需求。角色卡上的属性锚点若需要实体夹子，优先使用空白数字标记 / 无字实体夹子，避免把 `Trait` 字牌、数字牌或额外正文贴回角色卡。 |
| 属性轨实体对齐 | 角色卡上的属性夹子必须沿实体角色板轨道端点和格位中心对齐；不得为了做外部 HUD 效果把夹子漂到轨道外、偏离轨道线或遮成另一套状态贴片。截图验收必须看图确认基本对齐，不能只看 DOM 属性。 |
| 玩家卡点击语义 | 队友 / 其他玩家卡的主点击不是详情弹窗，而是切换本地观察视角，左侧角色板随之显示被观察探索者；行动按钮、当前玩家、领域 `currentPlayer` 不因此改变。详情弹窗只能由棋盘探索者 token、专门详情入口或其它 inspect 语义触发。 |
| 玩家卡普通状态色 | 队友 / 其他玩家卡的状态色必须能说明现实含义，例如当前观察、同房、可交易、可攻击、可拍照等；用户追问某个颜色代表什么时，先回答含义和证据，不得直接把颜色改掉。只有攻击、交易、拍照等明确可操作候选才使用目标提示色；当前观察态不得与目标候选混色。 |
| 投骰承接 | 物理骰使用透明虚拟骰盘，不得再套深色大背景、骰盅式托盘或封闭面板。 |
| 投骰透明边界 | “透明”必须落实到实际可见层：外层容器、内层 tray surface、canvas 承载层都不得再叠背景图、径向渐变、黑盒、厚边框或遮罩式托盘。 |
| 投骰必要信息 | 骰面合计、加值、总点数属于当前结算状态，必须可见；这不属于“卡图已有正文不要复写”的禁止范围。卡面标题 / 规则正文可以隐藏复写，但投骰计算不能隐藏。 |
| 预兆状态 | 常驻 UI 用实体分段进度条和短状态承载，例如 `预兆 3`、`再抽即作祟`、`作祟已开始`。 |
| 预兆进度条刻度 | 当前素材与运行牌库锁定为正式 `trait-track-0-9` 等距分段槽；图面必须以正式实体素材为底，是一条闭合长条里的大格槽位，当前格只做轻量覆盖 / 整格高亮，非当前格只保留实体槽位和分隔，不得把已经过格子画成填充进度；不得用小竖线、小刻度、断开的细格、独立指针、连续填充条、概率百分比条、手绘红框或“作祟风险”概率条冒充预兆进度。若未来换成其它实体素材，必须先补素材证据再改刻度。 |
| 草稿 / 标注图 | 用户草稿只说明设计意图，例如分段关系、当前位置表达和哪些信息该退场；不得把草稿线宽、颜色、粗糙边框、手绘红框或标注排版当成正式运行 UI。 |
| 作祟检定规则 | “按已发现预兆数掷骰，5+ 作祟；最后预兆自动触发”只进入 tooltip / title / aria / 规则页，不常驻铺在牌桌上。 |
| 作祟 setup | setup 队列和确认命令可以留在领域逻辑里，但牌桌右侧 rail / 主 HUD 不常驻显示 setup 文本墙或 setup 确认卡。 |
| 作祟触发剧本承接 | 作祟从未开始变为已开始、剧本卡切换或阵营阅读对象变化时，必须有一次剧本书 / 剧本阅读承接；稳定作祟牌桌、重进页面、关闭剧本后回牌桌，不得只因为领域状态仍是作祟就反复弹出剧本书。作祟横幅本身不再显示“阅读开局 / 可以打开剧本 / 英雄和叛徒分别阅读”这类动作或规则流程提示，重开入口只保留右侧短按钮 `剧本`。 |
| 开始剧本后过场 | 从角色选择进入恶兆前牌桌时，必须先显示一次全屏开局电影字幕；直接注入恶兆前状态的测试夹具不强制弹出。 |
| 正式素材已有信息 | 卡图、剧本页、参考卡、token 或实体组件已经表达的信息，运行 UI 只补交互、状态归属和无障碍信息，不再可见复写同一套标题 / 规则正文。 |
| 事件结果承接去重 | 探索事件、房间效果、预兆入手或物品入手的结果已经由卡图、投骰区、属性轨、持有区、主结果文本或短确认按钮承接时，确认队列不得再可见复写同一段结果正文；确认队列只能承担内部追踪、无障碍补充或按钮进度，不作为第二个玩家可见结果区。 |
| 业务逻辑与 UI 分离 | 官方规则和领域逻辑必须先提炼成玩家可用 UI：常驻主 UI 只显示对象名、当前值、短状态和动作入口；规则流程、系统决策、测试结论、setup 队列、阵营阅读说明、素材来源、原文可信度、OCR / 转写状态、正式翻译状态不得原句上屏。剧本开场 / 终局朗读的标题下不得出现“本地规则源正文”“正式中文转写”“官方 If You Win 原文”“非原文摘要”等开发来源小字。 |
| 剧情幕可见文字 | 开局电影字幕、作祟剧本阅读承接和终局朗读里，玩家可见文字最低 `12px`；眉标、章标、页脚 `序章 / 终幕`、按钮副文案和装饰性短字都按可见文字处理。若只是氛围装饰，必须改成非文字装饰或删除，不得缩成 8-11px 小字。 |

## 防回归门禁

- 改属性轨、投骰、预兆 / 作祟状态、剧本阅读或开局过场前，必须先回到本文件、官方规则源和对应正式素材 / 运行牌库；缺少证据时只能补证据，不能凭印象重画 UI。
- 牌桌常驻 UI 不得从概率、推测风险、工程状态、业务流程、测试结论或测试夹具名派生玩家可见文案；只显示玩家此刻必须持续读取的对象名、数值、短状态和动作入口。
- 投骰承接态必须同时验收“无深色大背景 / 无托盘”和“骰面合计、加值、总点数可见”；不能用“卡图已有内容不复写”隐藏投骰计算；不能只给外层写透明标记，内层实际渲染层也必须无背景图 / 无渐变 / 无托盘面。
- 发现结果面板不得同时出现两个玩家可见的结果正文承接点；如果结果已经在卡图、骰盘、属性轨、持有区或主结果文本中可见，确认步骤列表必须隐藏或退成非可见追踪。
- 属性轨和预兆状态都必须按实体位置显示；重复数值、相同刻度或相同结果不得被合并成一个格位，且重复数字相邻时必须在截图里看得出两个独立物理格。当前格、初始格、临界格、死亡格或相邻同色格叠在一起时，也必须保留清楚格间缝和单格边界；截图看起来连成一整段即判失败。
- 属性轨截图夹具、测试注入和验收状态不得用短数组、压缩轨道或缺失物理格来制造“重复数值不合并”的假证据；验收图必须使用与实体角色卡一致的完整物理格位，再检查重复数字是否逐格显示。
- 属性轨当前值只能出现一次：轨道内当前格整格高亮 / 夹子即为当前位置；轨道外不得再复写当前数值，角色头像板也不得再叠数字方块贴片。
- 属性轨当前指示和起始格都必须有实体计量表语义来源；当前格使用已批准的物理格高亮，绿色起始格必须保留为起点语义。不得用没有规则 / 素材 / 合同来源的临时色块、CSS 自绘小方块或业务状态色冒充属性夹子；也不得以“去掉无语义颜色”为理由删除有来源的绿色。角色卡如需夹子，优先使用正式空白数字标记 / 无字夹子并对齐对应格位中心，不能漂出轨道、遮成第二套数值或把 `Trait` 字牌重复贴上卡面。
- 属性轨验收必须实际看截图确认夹子沿实体轨道基本对齐；若图面上夹子漂移、偏出轨道或像外部贴片，即使 DOM 上位置字段正确也判失败。
- 队友 / 其他玩家卡普通点击必须切换观察视角；若测试或实现把普通点击写成打开详情弹窗，先翻正测试合同。只有棋盘 token inspect、放大镜或专门详情入口可以打开探索者详情。
- 队友 / 其他玩家卡使用绿色、淡绿、暖金或其它状态色时，必须能回到明确现实含义；若当前实现解释不出含义，只能先补证据、补短状态或请用户裁定，不得默认删色或换色。
- 预兆状态必须表现为正式 `trait-track-0-9` 素材承载的闭合长条内分段大格槽，只有当前格轻量覆盖 / 整块高亮；非当前格不得显示已走过填充，不得退回小刻度线、断开细格、单独指针、连续填充条、概率条或草稿红框。
- 用户草稿、标注截图和口头示意必须先抽取不变量，再回到正式素材和本合同实现；禁止把草稿本身当成像素级目标稿。
- 作祟触发、剧本阅读和开局过场属于流程承接，不属于右侧 HUD 常驻说明；测试若固化了相反行为，先翻正测试合同，再改实现。
- 作祟揭示横幅只能显示短状态、触发来源和关闭动作；不得额外挂“阅读开局 / 打开剧本 / 可以查阅 / 英雄和叛徒分别阅读”按钮或句子。剧本承接只在作祟/剧本变化发生时打开一次，后续重开由牌桌固定短入口 `剧本` 承接。
- 剧情幕 / 剧本阅读承接 / 终局朗读里的所有玩家可见文字都必须 >= `12px`；截图里只要出现标题上下、页脚或按钮附近的 8-11px 可读小字，直接判为 UI 回归。

## 验收标准

- 属性轨截图里第一眼看到的是连续轨道和当前位置指针，不是离散小方块；重复数值不会让指针落错位置。
- 属性轨刻度按位置均匀分布；重复数值只作为辅助读数，不得被合并成单格。截图里每个物理格的边界必须肉眼可辨；相同数字、相同颜色、初始格底线或当前高亮不得把两个相邻格视觉连成一块。
- 属性轨截图里不得出现轨道右侧当前值、角色头像板数字贴片或其它第二套当前值实体；若头像板需要显示当前位置，只能显示无数字夹子。
- 属性轨当前格、绿色起始格、临界格和骷髅死亡端点必须在截图和 DOM 中各自可区分；当前格由轨道内物理格直接高亮，起始格保留绿色起点语义，角色卡锚点使用无字实体夹子并与当前物理位置对齐。
- 点击其它玩家卡后，左侧角色板必须切到对应玩家并显示观察状态；同一动作不得弹出探索者详情弹窗，棋盘探索者 token inspect 仍可打开详情。
- 普通队友卡上的状态色必须能解释其现实含义；观察中只显示观察态，不把同房、详情或候选状态混在一起。用户只问“这个颜色是什么意思”时，不得把提问当成改色授权。
- 骷髅端点在图面和无障碍说明里都表达为死亡端点，不把骷髅计为数值 `1`。
- 投骰截图里骰子直接浮在开放式桌面上，不出现深色托盘 / 大背景框；骰面合计、加值、总点数同时可见。
- 投骰 DOM / 截图验收必须能证明骰盘真实承载层透明，不得只检查外层 `data-dice-tray-style`。
- 预兆进度条显示正式 `trait-track-0-9` 素材上的 `0..9` 等距分段大格槽，槽位属于同一条闭合长条，当前预兆所在格轻量覆盖 / 整块高亮，非当前格不显示已走过填充；不得出现小竖线/小刻度、断开细格、独立指针、连续填充条、草稿红框或概率百分比式“作祟风险”进度。
- 预兆状态常驻区域不出现 `下次掷 X 颗`、`5+ 作祟`、`再抽预兆时检定` 这类完整规则说明；这些信息只在 tooltip / title / aria 或规则阅读层可追溯。
- 事件 / 房间 / 物品 / 预兆发现结果截图里，玩家可见层不得同时出现“结果标签 + 完整结果正文”的重复确认列表；确认按钮只显示 `确认` 或必要的 `确认 X/Y` 进度。
- 作祟 setup 不在主 HUD 或右侧 rail 常驻；玩家牌桌只保留当前可操作目标、剧本入口和必要短状态。
- 作祟揭示横幅不出现 `阅读开局`、`打开剧本`、`可以查阅`、`英雄和叛徒分别阅读` 这类动作提示或规则流程说明；变化发生时的剧本承接结束后，重开入口只显示为右侧 rail 的短按钮 `剧本`。
- 作祟触发这种状态变化发生时，剧本阅读承接至少打开一次；稳定作祟状态、初次渲染已作祟 core、关闭后回牌桌都不得反复弹出剧本书。
- 从真实角色选择流程点击 `开始剧本` 后，必须先看到 `木乃伊横行` 开局电影字幕和规则源状态，再点击继续进入牌桌。
- 开局电影字幕、作祟剧本阅读承接和终局朗读截图中，标题上方、标题下方、页脚和按钮周边不得出现小于 `12px` 的可读文字；`序章 / 终幕` 这类短字如果保留，也必须按可读文字尺寸显示。
- 完整截图链必须包含：投骰承接态、属性轨当前态、属性轨详情态、预兆进度条普通态、最后预兆态、作祟触发后剧本阅读承接、作祟开始态、开始剧本后开局过场、过场关闭后牌桌。
