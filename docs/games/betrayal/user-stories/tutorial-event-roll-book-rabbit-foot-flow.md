# 山屋惊魂教程：事件骰、书本与兔脚自然流程

> 状态：`locked-for-current-tutorial`
> 日期：2026-08-31
> 角色：`canonical-source`，记录本次山屋惊魂教程事件骰流程的产品裁定；跨游戏的教程判断以 `.spec/knowledge/standards/tutorial-design.md` 为唯一规范正文。

## 用户原始裁定

事件先触发，再由触发者点击“投掷事件”。书本只在事件骰已经出现时教学：先查看书本牌面，确认它能介入这次非战斗检定；关闭牌面后再使用书本本体，点击后立即扣除神志并改用知识投骰，不需要第二次确认。玩家已经经历公开可见的事件骰、书本改骰和兔脚重掷过程后，不需要每位玩家再确认事件结果，游戏应自动进入伤害分配。

基础教程按自然玩家流程合并教学；不能因为测试、截图或机制数量拆章节。只有叛徒视角或其它真实私密信息边界才单独成章。

主线合并的含义是把同一条玩家因果链放进一个可见教程容器，不是把多个中段测试快照首尾拼接。当前普通玩家主线只收口到作祟前基础回合、交易、探索、事件骰、书本、兔脚和伤害分配；作祟后目标、驱逐、怪物行动和终局只能作为隐藏代表态或叛徒视角补充。若以后要把作祟后目标并入普通玩家主线，必须先让玩家从作祟前通过真实探索获得预兆、完成作祟检定并看到作祟触发，之后才进入作祟目标教学。

探索新房间必须按规则先翻出匹配区域房间、选择朝向让至少一个走廊连接当前未探索走廊、确认放置，之后才结算房间文字和符号。教程可以把这段放在同一主线章节里，但必须单独教学“查看房间牌面 / 旋转朝向 / 确认放置”，不能从探索目标房间直接跳到事件牌。

本裁定已回查规则源 [`山屋惊魂小黑屋第三版规则汉化整理.md`](../../../../src/games/betrayal/rule/山屋惊魂小黑屋第三版规则汉化整理.md)：第 12 节把探索新房间写成翻开匹配区域房间、让走廊相连、放置后结算房间文字和符号；第 13 节才按房间符号抽取事件 / 物品 / 预兆。房间文字效果和“触发哪类发现牌”都属于确认放置后的连续自动后果，可以在同一个教学时刻说明；旋转朝向是确认前的玩家选择，必须有独立 UI、操作和截图证据。

## 覆盖对象

| 对象 | 本轮裁定 |
| --- | --- |
| 同房间交易 | 保留在基础教程主线中，发生在移动到队友同房间之后、探索新房间之前；使用急救包交换地图，书本和兔脚不得被交易走，因为后续事件骰要继续教学这两张牌。 |
| 房间放置朝向 | 探索未知门位后，先显示新房间牌面、连接走廊和旋转按钮；玩家旋转选择朝向后，再确认放置。 |
| 三类发现牌 | 房间符号必须先教“事件 / 物品 / 预兆”三类映射；本轮主线真实触发事件牌，物品牌和预兆牌作为同一映射的可读信息保留在教程说明或分支教学中，不能无声消失。 |
| 事件投掷 | 事件牌翻出后保留“投掷事件”作为真实入口，触发者主动开始投掷。 |
| 书本 | 事件骰显示且书本可用时先高亮查看牌面入口；玩家读完牌面后再点击书本本体即刻生效，扣除 1 点神志并把本次非战斗检定改为知识。 |
| 兔脚 | 书本改骰后由玩家选择一颗骰子并确认使用兔脚，随后展示重掷后的结果。 |
| 事件结算 | 兔脚重掷后的事件骰不存在 `确认 1/3` 或等价的多人确认入口；没有后续玩家选择时自动进入伤害分配。 |
| 确认按钮 | 需要确认的物品命令和事件命令使用同一确认按钮组件与样式；是否出现确认由当前流程是否仍有玩家决策或共同等待理由决定。 |
| 教程目录 | 普通玩家主线合并为自然因果链；叛徒视角因私密信息另列章节。 |

## 教程内容总账

| 教学内容 | 落点 | 不允许的退化 |
| --- | --- | --- |
| 作祟前目标、属性轨、移动力、房间网格、观察队友、帮助入口 | 主线自然教学，发生在第一次移动前 | 只教按钮，不教这些读数如何影响首局判断。 |
| 同房间交易 | 主线自然教学，移动到门厅后立刻走完整请求 / 等待 / 同意 / 结果链 | 因为要保留书本和兔脚而删掉交易，或把交易拆成只有按钮和最终结果的独立快照。 |
| 房间放置与三类发现牌 | 主线自然教学，探索后先查看新房间牌面并旋转朝向，确认放置后再看房间符号和事件牌；物品 / 预兆作为同一映射被点名 | 截图直接从探索目标跳到某张牌，吞掉朝向选择，或只剩事件 / 预兆两类。 |
| 事件骰、书本、兔脚 | 主线自然教学，事件触发后按“投掷事件 -> 查看书本牌面 -> 使用书本 -> 选择兔脚重掷 -> 伤害分配”推进 | 先用书本再投事件，或把兔脚 / 书本写成提前解释而没有牌面查看和使用过程。 |
| 预兆确认和作祟风险 | 隐藏回归专题，证明预兆牌的获得和一次确认语义 | 冒充主线已经自然触发作祟，或把预兆确认重新夹回当前事件主线。 |
| 作祟后英雄目标、驱逐木乃伊、攻击、木乃伊怪物行动 | 隐藏代表态专题；只有叛徒视角对玩家目录可见 | 用已作祟 / 已找真名快照接在基础教程后面，伪装成同一条自然流程。 |

## 教程 UI 职责总账

| 交互族 | 唯一承接 | 验收点 |
| --- | --- | --- |
| 确认 / 提交 | 复用同一游戏的方形确认按钮样式；确认只表示已完成选择、共同观看、响应或授权 | 样式统一不能新增确认步骤；触发者主动投掷后的事件骰若没有额外选择，应自动进入下一真实决策。 |
| 交易 | 持有物牌面、地图上的同房间队友、对方持有物候选、交易横幅和同意 / 拒绝面板 | 每一步都有真实对象、选中态、等待态和结算后持有物变化，不用“跳过 / 不拿取”假按钮占候选位。 |
| 房间放置 | 房间放置面板、房间牌预览、旋转按钮、连接走廊标记和确认放置按钮 | 先证明玩家能改变朝向，再证明确认按钮提交已选朝向；确认按钮样式复用同一游戏确认组件。 |
| 投骰 / 重掷 | 事件牌阅读区和骰盘；兔脚选择直接贴到骰子本体 | 候选骰子只用底部短描边，选中后升级为贴合骰面的高亮边界，不能用大圆圈盖住骰子。 |
| 物品 / 预兆使用 | 持有区卡牌本体和放大镜入口 | 书本先查看牌面再使用；兔脚使用后必须展示可选骰子和确认使用结果。 |
| 房间 / 发现牌 | 房间牌本体、房间符号、发现牌牌面和牌堆类型 | 截图相邻编号必须有“玩家看到符号 -> 玩家触发探索 / 投掷 -> 对应牌出现”的过渡。 |

## 标准回代

- 通用教程标准的唯一正文是 [`.spec/knowledge/standards/tutorial-design.md`](../../../../.spec/knowledge/standards/tutorial-design.md)：后续教程重构必须先做内容总账、交互族链路账、UI 元素职责账和截图过渡账，不能继续按单个截图或单个按钮逐点补丁。
- 通用游戏 UI 门禁的唯一正文是 [`.spec/knowledge/standards/ui-change-gates.md`](../../../../.spec/knowledge/standards/ui-change-gates.md)：确认、候选、选中、结果和等待状态必须先按同游戏交互族统一裁定，组件复用不能改变确认语义。
- 本文只记录山屋惊魂本轮产品裁定和覆盖对象；若本文与通用标准冲突，先回通用标准修正或收窄，再更新本文的专项落点。

## 验收标准

- 教程 E2E 从探索未知门位开始证明房间翻出、旋转朝向、确认放置、房间符号翻出事件牌，再进入“投掷事件”按钮；不用测试夹具的即时投骰链代替。
- 截图链至少包含事件骰出现后的书本“可查看时机”、书本牌面查看、关闭牌面后使用书本、以及点击书本后的生效结果。
- 点击书本后验证神志减少 1、检定属性改为知识、书本已使用且事件骰仍在结算中。
- 兔脚重掷后验证事件确认按钮不存在，并且不模拟其它玩家操作即可进入伤害分配。
- 教程连续文案只讲当前新增信息，不复读前一步的完整机制说明。

## 不覆盖

- 仍需要其它玩家选择、响应或授权的发现 / 卡牌窗口，继续保留相应的共同确认。
- 不改变其他事件、预兆、房间效果或联机响应窗口的确认语义；它们必须按各自的公开展示和决策需要裁定。
- 不把本次教程事件链外推成所有随机结果一律自动结算。
