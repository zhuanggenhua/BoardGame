# 斗地主 UGC 预览需求记录

本记录保留一次 UGC 预览用例的用户需求和平台能力缺口。它不是 UGC 框架规范；通用规则仍看 [`../../../ugc/ugc-overview.md`](../../../ugc/ugc-overview.md)。

## 原始目标

- 用户要制作一个斗地主原型。
- 平台目标是验证“需求 -> 提示词 -> 外部 AI -> 粘贴导入 -> 预览/运行”链路。
- 实现层不得为斗地主硬编码专属系统；可复用能力进入 UGC 框架。

## 需求摘录

| 区域 | 需求 |
| --- | --- |
| 规则 | 3 人；每人 17 张牌；出完手牌即获胜；阵营胜负按地主 / 农民判断 |
| 首家 | 暂定房主先手 |
| 手牌区 | 顺序展开；选中时抬高；按斗地主点数排序，含大小王 |
| 操作 | 仅当前玩家可操作；开局可叫分 / 抢地主；允许跳过不出 |
| 出牌 | 规则层校验牌型合法性，并要求大过上一手 |
| 玩家信息 | 显示玩家名称与必要状态 |
| 对手手牌 | 复用手牌区配置，但支持背面渲染 |
| 出牌区 | 只展示出牌结果，不触发手牌出牌钩子 |
| 数据生成 | 根据需求生成完整 54 张扑克牌数据 |
| 预览层 | 预览应贴近真实运行环境，可用内联窗口形态 |
| 玩家数 | 由玩家信息组件数量加自己推导 |

## 抽出的通用能力

- 保存和导入 / 导出 requirements。
- 预览层复用运行态链路，避免预览能力和真实运行能力分叉。
- 区域组件支持动作钩子，并能限制为当前玩家。
- 区域级 `allowActionHooks=false` 可禁用动作钩子。
- 区域级正面 / 背面渲染策略。
- 根据玩家信息组件推导玩家数量。
- 根据自然语言需求生成牌库数据。
- DomainCore 规则执行框架提供规则管线、基础组件和动作钩子，但不内置牌型或胜负逻辑。

## 边界

- 斗地主牌型、排序、比较和叫地主细节只属于本预览用例。
- UGC 框架只能沉淀通用机制；不得把本记录里的游戏规则搬进模板、引擎或通用文档。
