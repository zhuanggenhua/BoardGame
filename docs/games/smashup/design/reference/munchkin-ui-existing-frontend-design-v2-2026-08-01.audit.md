## 2026-08-01 用户反馈降级

- 反馈结论：v2 把怪物牌贴在基地上缘，但当前大杀四方基地上缘已经承载泰坦和基地持续行动；随从区还存在附着行动浮层。这个设计会和已有 UI 抢位，不能通过人工验收。
- 追加反馈：v2 对怪物 / 宝藏牌使用 `怪物 / 战力 / 奖励`、`宝藏` 等常驻 chip，但这些信息本来就应由卡面承担；重复显示会制造噪音，也会误导实现阶段去做多余字段壳。
- 用户布局裁定：怪物默认应排在基地下方一排，位于基地卡与玩家随从列之间；多张怪物允许在怪物行内部横向重叠 / 扇形排布。
- 规范结论：后续 Munchkin UI 必须先列出基地内外保护槽位，再决定怪物 / 宝藏入口；不得只看新机制本身能不能显示。
- 推荐改法：怪物作为“基地公共附属对象”应进入基地下方公共怪物行；公共牌堆 rail 只负责怪物 / 宝藏牌堆入口或折叠补充，不替代基地上的怪物归属。怪物行不能占用泰坦 / 持续行动所在的基地上缘，也不能盖住玩家随从列。怪物和宝藏的名称、类别、战力、奖励值默认只读卡面；UI 只补 `可击败`、`已控制`、`已选`、动态门槛修正或多张牌聚合值这类卡面没有的信息。

## 规则 / 素材到画面映射

| 规则 / 素材结论 | v2 画面决策 |
| --- | --- |
| 怪物是基地上的公共对象，不归属玩家 | v2 错误地把怪物牌贴在基地上缘，且用 chip 复写卡面字段。v3 必须改为基地下方公共怪物行，位于基地卡与玩家随从列之间；多张怪物允许横向重叠 / 扇形排布；怪物个体信息默认只显示卡面 |
| 宝藏是奖励资源，可进入持有 / 使用 / 附着语义 | v2 用金色边和 `宝藏` chip 区分宝藏；若卡面已清楚显示宝藏身份，v3 应去掉常驻复写，只保留运行时状态或选择反馈 |
| 怪物牌堆和宝藏牌堆是公共特殊牌堆 | 参考疯狂牌供应做轻量角标 / 小牌堆，不新建厚右栏，也不改变底部手牌主槽位 |
| 怪物会提高基地破坏门槛，不给任何玩家加力量 | 允许在焦点基地显示聚合结果：玩家总力、基础破坏点、怪物门槛合计、最终破坏点；不得逐张复写怪物卡面上的战力 / 奖励字段 |
| 已有正式 Munchkin 裁片可作为设计输入 | 基地、怪物、宝藏、玩家卡牌全部使用 `temp/smashup-munchkin-ui-imagegen/input-pack/*.png` 的正式裁片 |

## 后续使用边界

- 前端必须守住：现有牌桌大构图、顶部 HUD 家族、中央基地主舞台、底部手牌槽位、底部牌堆 rail、怪物属于基地下方公共怪物行、宝藏持有 / 附着。
- 可在实现时降级：木纹明暗、纸张颗粒、阴影强度、卡牌轻微旋转角度、便签微裁边。
- 不得按图新增：常驻规则说明、厚右侧后台栏、完整日志列、第二套主操作面板、占用泰坦 / 持续行动 / 附着行动槽位的怪物贴片、复写卡面名称 / 类别 / 战力 / 奖励的常驻 chip。
- 进入实现前仍需单独裁定 Munchkin 玩法数据和交互链：怪物如何进基地、怪物力量如何参与破基地、宝藏如何进入玩家持有区、宝藏牌的使用时机与普通牌关系。
