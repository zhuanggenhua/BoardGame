# SmashUp 控制权变更不转移拥有权用户故事

## 用户原始要求

2026-06-06，用户明确要求：

- 通过卡牌把其他玩家牌组中的牌加入自己手中后，这只是控制权变更，不是拥有权变更。
- 该牌后续离场时，不应该进入当前控制者的墓地/弃牌堆，而应进入真实拥有者的对应区域。
- 这条口径不只适用于维京人，而适用于 SmashUp 中所有“获取控制权 / 借用 / 临时持有 / 代为打出他人拥有牌”的实现。

## 覆盖对象

- 游戏：`smashup`
- 覆盖语义：
  - 获取控制权但未显式转移拥有权
  - 从其他玩家区域拿牌到自己手中、场上或待结算区
  - 借来的随从、行动、持续牌、泰坦或其他可离场对象
  - 由当前玩家代为打出、代为持有、代为结算，但真实拥有者仍是他人的对象

## 覆盖原因

- 既有实现中，部分链路把“当前控制者/当前持有者”误当成“真实拥有者”，导致对象离场时进入错误玩家的弃牌堆、墓地、牌库、手牌或其他拥有者区域。
- 用户明确要求：这类对象的真实拥有权必须单独保留；后续去向按真实拥有者结算，而不是按当前控制者结算。

## 实现口径

- 只要规则效果描述的是“获取控制权”“拿到手中”“代为打出”“临时借用”或其他等价语义，而没有明确写“转移拥有权”，就视为：
  - 当前可操作者可以变化；
  - 当前持有位置可以变化；
  - 真实拥有权不变化。
- 这类对象后续进入弃牌堆、回手、回牌库、移出游戏区或其他默认归属区域时，必须按真实拥有者归区。
- 若某条实现链路在对象离开原区域后已经无法从活体状态反推出真实拥有者，则必须在转移/打出/控制变更时显式保留这份 provenance。

## 验收标准

- 玩家 A 通过效果取得原本属于玩家 B 的牌，并把它放入自己的手中或打出后：
  - 玩家 A 可以在允许的时机使用/控制该牌；
  - 该牌的真实拥有者仍视为玩家 B。
- 上述牌后续因消灭、弃置、结算完成、回收、洗回牌库、返回手牌或移出游戏而离开当前区域时：
  - 必须进入玩家 B 的对应拥有者区域；
  - 不能进入玩家 A 的对应拥有者区域。
- 当来源区对象已不可见、只剩转移事件或中间态记录时：
  - 系统仍能根据保留的真实拥有者信息把对象送入正确区域。

## 不覆盖范围

- 若某张牌、某条规则或后续明确裁定写明“转移拥有权”或等价语义，则不受本文约束，应按该显式规则实现。
- 本文不直接改写其他游戏的规则口径；如其他游戏存在相同需求，应在对应游戏目录或项目级用户故事另行留档。
