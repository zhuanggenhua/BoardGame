# 数据录入规范

> **触发条件**：根据图片、规则书、Wiki、官方 PDF、用户提供截图等来源录入业务数据时必须阅读。

## 核心原则

- **先建契约，后写代码**：数据录入必须先产出 Markdown 核对契约，再录入运行时代码。
- **单一权威来源**：同一条数据只能有一个当前权威来源；若存在多个来源，必须显式写出优先级和冲突处理结论。
- **零猜测**：任何文字、数字、关键词、索引、限定词，只要有一点看不清或不确定，必须停止录入并说明不确定点。
- **描述与实现分离**：先把“卡面/规则原文”抄准，再做结构化字段映射，禁止边猜原文边设计字段。
- **先文档后实现**：涉及规则或机制的数据录入，必须先更新 `rule/*.md` 或对应规范文档，再开始实现。

## 权威来源优先级

默认优先级如下：

1. 官方勘误 / 官方规则书 / 官方 PDF
2. 官方授权页面或官方数据库
3. 项目要求的专用抓取源
4. 用户提供的清晰原图 / 截图
5. 项目内已有规则文档

补充约束：

- 若用户明确指定“以这张图为准”，则该图在本任务内可以作为卡面中文的权威来源，但仍需记录是否与官方英文规则存在潜在冲突。
- 大杀四方查 Wiki 时，必须使用仓库爬虫，不得凭记忆补数据。

## 标准流程

### 1. 锁定来源

必须先记录：

- 来源类型：规则书 / Wiki / 图片 / 截图 / 用户口述
- 来源路径或链接
- 获取时间
- 适用范围：名称 / 卡面描述 / 数值 / 图片索引 / 机制通则

### 2. 建立 Markdown 核对契约

录入前必须先写表格，至少覆盖以下字段：

| 字段 | 含义 |
| --- | --- |
| 实体标识 | `defId` / `id` / 变体 ID |
| 来源定位 | 图片路径、裁图路径、PDF 页码、Wiki 链接 |
| 原始名称 | 原图/原文中的名称 |
| 原始描述 | 原图/原文中的完整效果文本 |
| 结构化字段 | faction、type、cost、power、tags、索引等 |
| 不确定项 | 任何看不清、待确认、存在冲突的字段 |
| 结论状态 | `已确认` / `待确认` / `冲突待裁决` |

强制要求：

- 表格必须按逻辑顺序或素材顺序排列，不能随手插入。
- 原始文本与结构化字段必须并排出现，禁止只保留结构化结果。
- 若同一张卡有“图片文案”和“官方英文规则”两个来源，必须在表格中显式列出冲突点。

### 3. 全口径核对

录入时必须逐项核对：

- 名称
- 数值
- 关键词
- 限定词
- 作用对象
- 作用范围
- 时机
- 次数限制
- 例外条件
- 图片索引 / 图集索引 / 资源路径

### 4. 结构化映射

把原始描述拆成结构化字段时，必须显式说明：

- 哪些内容进入静态数据层
- 哪些内容进入 i18n 文案
- 哪些内容进入规则文档
- 哪些内容需要后续能力实现

禁止把“暂时不会实现”的描述直接丢掉。

### 5. 文档同步

录入会影响玩法、机制、描述或资源展示时，必须同步更新：

- 游戏规则文档 `src/games/<gameId>/rule/*.md`
- 对应 i18n 文案
- 必要时的开发规范文档

### 6. 再进入代码实现

只有在以下内容都完成后，才允许开始实现：

- 来源已锁定
- Markdown 核对契约已写
- 不确定项已清零或显式挂起
- 规则文档已同步

## 图片文字辨识零猜测原则

以下任一情况都必须停下：

- 名称有字看不清
- 数值模糊
- “可/必须/直到/改为/额外/其他/另一个”等限定词不确定
- 图片索引、图集位置、裁片对应关系不确定

禁止行为：

- 根据英文原版猜中文
- 根据上下文补完整句子
- 根据相邻卡牌推断索引
- 先录进去，等以后再核对

## 图片/卡牌索引录入规范

当素材涉及 atlas/index/crop 时，必须额外记录：

- 原始大图路径
- 裁片路径
- 裁片顺序依据（从上到下、从左到右，或官方编号）
- 最终运行时索引字段

如果图片索引尚未确认：

- 可以先录 `defId` 和文案
- 但必须把 `previewRef` 标记为未完成
- 不得伪造索引占位成正式值

## 大杀四方附加规则

当录入大杀四方数据时，必须额外遵守：

1. Wiki 数据使用 `scripts/scrape-wiki-with-descriptions.mjs` 抓取。
2. 如需比对代码与 Wiki，使用 `scripts/final-wiki-code-comparison.mjs`。
3. 泰坦、POD、勘误版卡牌必须在核对契约中显式标记来源和适用范围。
4. 若中文图与 Wiki/官方英文存在差异，必须把差异写入规则文档，不得静默择一。

## 最低交付物

一次完整的数据录入任务，最低应交付：

1. 权威来源记录
2. Markdown 核对契约表
3. 同步后的规则/说明文档
4. 结构化数据录入
5. 必要的验证测试或校验结果

如果只完成了第 4 步，没有前 1-3 步，则视为录入不完整。
