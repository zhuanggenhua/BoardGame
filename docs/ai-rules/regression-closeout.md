# 回归收口与漏审复盘

> 适用：用户反馈“以前好的现在坏了 / 审计漏了 / 为什么回归 / 这怎么又回来了”，或本轮修复后需要解释为什么旧测试、旧审计、旧规范没有拦住问题。

## 落点

- 本文档属于 BoardGame 项目通用层，只写跨游戏回归处理和漏审复盘方法。
- 单游戏事故细节、具体卡牌结论、单次截图或规则裁定，不写入本文档；应下沉到该游戏 evidence、用户故事、专项 bug 文档或 `docs/games/<gameId>/...`。
- 全面审计仍走 `docs/ai-rules/testing-audit.md`；本文档只管“修完后如何证明回归已收口、漏审原因已回代”。

## 回归处理顺序

1. **锁原始症状**：用用户原话拆成可验证断言，避免把外围问题替换成本轮目标。
2. **找最后正常证据**：优先找历史测试、evidence、截图、提交 diff 或用户故事；不能只凭印象说“以前是好的”。
3. **找首次变坏范围**：定位引入提交、改动批次、共享 helper、录入合同变化或测试断言变化。
4. **判根因类型**：至少在 `数据/录入缺陷`、`单点实现缺陷`、`共享抽象缺陷`、`架构/时序/系统边界缺陷` 中选一类。
5. **最小修复**：默认恢复最后正常行为或修掉直接根因；禁止自创一套新逻辑冒充回归还原。
6. **补回归验证**：验证必须回到用户原始失败位点，不能只证明辅助现象变好了。
7. **同类扩审**：按根因关键词、事件、状态字段、共享 helper、生命周期和同族对象横向搜索。
8. **规范回代**：复盘为什么旧测试、旧审计或旧规范没拦住；若是方法失守，补通用门禁；若是单游戏规则答案，回写单游戏文档。

## 漏审归因默认口径

漏审不能默认归因于“测试不够多”。先按下面顺序判断：

1. **真相源没锁**：录入合同缺失、冲突、状态错误，或实现拿旧文案当规则。
2. **审计对象没建全集**：只看了用户点名对象，没列基础版、升级版、变体、同名分支、共享 helper。
3. **证据停在中间态**：只看到了 prompt、候选、pending、按钮、日志，没有验证最终血量、资源、token、区域归属或阶段收口。
4. **测试断言过窄**：只测 happy path、只测单状态、没测已有状态叠加、并存来源、低伤害/低资源等边界。
5. **旧测试已经失效**：测试仍在断言旧规则、旧文案或旧错误语义。
6. **共享抽象没扩审**：根因在共享消费、清理、时序、队列或状态字段，却只修了单个对象。
7. **规范落点错误**：把单游戏答案写成通用规则，或把通用判断方法留在一次性对话里。

## 同类扩审最低要求

修复 bug 后必须说明横向搜了什么，而不是只说“已检查”：

- 同游戏同族对象：基础版、升级版、同名变体、相同骰型/图标/触发条件。
- 同游戏共享实现：reducer、handler、hook、selector、validator、UI 消费点。
- 引擎共享层：同一事件类型、状态字段、helper、生命周期钩子。
- 测试和证据：旧测试断言、evidence 表格、截图描述、文案合同。

若扩审未完成，最终口径只能写“当前点位已修复，仍有残余扩审范围”，不得写“已收口”。

## 回归收口输出模板

最终汇报或 evidence 至少包含：

- 用户原始症状。
- 是否判定为回归，以及最后正常证据。
- 引入范围或疑似根因范围。
- 根因类型与为什么不是其它类型。
- 修复策略是否恢复最后正常行为；若不是，依据是什么。
- 验证命令、截图或状态断言。
- 同类扩审范围、命中结果和未完成范围。
- 漏审复盘：旧测试/旧审计/旧规范为什么没挡住。
- 规范回代：新增或更新到哪里；若不需要更新，说明原因。
