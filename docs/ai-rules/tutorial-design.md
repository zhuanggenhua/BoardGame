# 教程与新手引导设计规范

> 适用于 `tutorial / onboarding / 新手引导 / 教学步骤`。本文件约束“教什么”，不是只约束“怎么点”。

## 适用边界

- 当本轮在做教程、重做教程、审核教程质量、补教程 E2E、或用户明确指出“教程看不懂/只是在教按钮”时，必须阅读本文。
- 本文和 `docs/ai-rules/e2e-verification.md`、`.codex/skill/game-audit-workflow/SKILL.md` 配合使用：
  - `tutorial-design.md` 约束教学目标与内容结构
  - `e2e-verification.md` 约束截图与真实流程证据
  - `game-audit-workflow` 约束教程交互必须和真实游玩一致

## 核心不变量

1. **教程先教“为什么赢”，再教“怎么按”**
   - 玩家必须先知道这局游戏的目标是什么，例如比总分、抢基地、击倒对手、占区得分。
   - 如果教程结束后，玩家仍说不出“我到底在追求什么结果”，该教程直接判不合格。

2. **教程必须解释“为什么做这个动作有好处”**
   - 不允许把教程退化成“点这里 -> 再点那里 -> 下一步”。
   - 每个正式行动至少要说明它解决什么现实问题，例如补组合、抢公开资源、压缩损失、推进结算。

3. **教程必须用真实局面教一个最小得分/收益案例**
   - 至少有一个真实案例能让玩家看到：做出正确选择后，分数、战力、控制权、伤害或其它核心收益发生了清晰提升。
   - 这个案例必须来自真实牌桌/真实棋盘状态，不能只靠口头描述“理论上会更强”。

4. **教程必须覆盖“结果反馈”**
   - 玩家不只要知道动作执行了，还要知道动作带来了什么结果。
   - 至少要覆盖以下其一：
     - 分数提升
     - 伤害/控制权变化
     - 资源曲线改善
     - 组合成立后的明显收益

5. **计分制游戏默认必须看到计分因果**
   - 如果游戏胜负核心是分数，教程默认至少要让玩家看到一次真实计分、准计分，或清晰的分数差案例。
   - 禁止只讲“终局会计分”，却不让玩家看到“哪张牌为什么加分/减分”。

6. **教程交互必须与正式游玩一致**
   - 正式游玩点按钮，教程就点按钮。
   - 正式游玩点卡牌，教程就点卡牌。
   - 不得为了教学顺手改成交互壳层、说明壳、替代入口。

7. **教程不能用长段台词替玩家做判断**
   - 教程文案可以点出“当前该看什么”，但不应把整套推理替玩家说完，更不能形成“老师命令你现在该丢哪张、该拿哪张”的口吻。
   - 更好的做法是：先把真实局面布到足够清楚，再用 1 到 2 句短提示提醒玩家去看“哪张在补线、哪张只是在占位、哪张会拖后腿”。
   - 如果离开长段解释后，玩家就看不出为什么这张更好，优先判定为案例设计不合格，而不是继续往文案里加说明。

8. **判断提示和操作提示必须拆开**
   - `infoStep` 的职责是提醒玩家“这一步该看哪里、为什么值得看”，不应顺手把按钮操作和标准答案一起说完。
   - `requireAction` 的职责是教真实点击对象和最小动作，例如“点击摸牌按钮”“点击中央这张牌”“点击手牌弃掉”，而不是在动作步里再次长篇解释整套推理。
   - 如果一个步骤同时承担“替玩家做判断”和“告诉玩家怎么点”，默认先拆成前一说明步 + 后一操作步，再决定文案是否还需要保留。

9. **教程开场第一句默认只讲“目标 + 一个最基本操作”**
   - 开场第一句默认只负责让玩家立刻知道：这游戏要赢什么、自己每回合最基本在做什么。
   - 不要一上来把全部规则、例外、术语、细节一起塞进第一句。
   - 更好的开场是：`目标 + 轮到你时最基本的回合动作 + 结束条件/胜负条件`，而且必须短。

10. **脚本化教程可以直接点名当前对象与动作**
   - 当教程已经把牌桌固定到真实预设局面时，文案可以直接说出当前牌名、组合对象和该执行的动作，例如“中央有钟塔，和你手里的蜡烛可以加分，现在选中钟塔来获取”。
   - 这种直接点名只在“当前真实局面就是这一手示范题”时成立，禁止脱离当前牌面空讲策略。
   - 优先使用“这张能加分 / 这张现在没用 / 选中这张牌”这类短句，不要再绕成抽象术语或长段分析。

11. **默认只教常规对局，不教变体或扩展**
   - 如果用户没有明确要求教程覆盖双人变体、扩展规则、额外模式或特殊结算，基础教程默认只讲常规对局。
   - 禁止一边用常规口吻讲目标，一边在动作步骤里偷偷塞变体规则，例如“双人局会多摸 1 张”“这个模式结束条件不同”。

12. **已经讲过的规则不得在后续步骤复读**
   - 开场已经交代过的基本回合结构、胜负条件、结束条件，后续步骤默认不再重复。
   - 后续文案只负责当前这一步的判断、动作或结果，不再回头重讲规则书。

13. **禁止空提示句和无信息量过渡句**
   - 像“先看当前手牌”“下面看另一种情况”“现在总分更高了”这类没有新增信息、没有局面判断、没有交互价值的句子，默认不合格。
   - 每一步文案必须至少承担一项职责：讲当前目标、指出当前收益、点名当前对象、或说明当前结果。

14. **能合并的判断和动作就直接合并**
   - 如果同一句话已经足够自然地同时说明“为什么这么做”与“现在点哪里”，就不要机械拆成一个说明步加一个重复动作步。
   - 只有当拆开后能明显降低理解负担，才允许分成 `infoStep` 和 `requireAction` 两步。

15. **教程必须覆盖真实隐性交互**
   - 除了显式规则，教程还应覆盖玩家第一次上手时不一定会自己发现、但真实游玩中会频繁用到的关键交互。
   - 例如：点击或悬浮查看单张牌得分、查看战力来源、查看奖励说明、确认当前控制权、读懂等待归属。

16. **计分制教程必须出现一次清晰的计分因果**
   - 不能只说“最后比总分”，也不能只展示一个结果数字。
   - 至少要让玩家看到一次：哪张牌的基础分是什么、哪两张或哪几张牌如何互相加分、最后总分在哪里看。

17. **结语必须短，并且只负责收口鼓励**
   - 结语默认只做两件事：宣布基础流程讲完了；鼓励玩家进入正式对局。
   - 禁止在结语里再讲一遍完整规则、再总结一遍操作顺序、再复述一遍案例推理。

## 默认结构

一个合格的基础教程，默认至少包含以下四段：

1. **目标段**
   - 讲清楚赢法、核心爽点、玩家这局在追求什么。

2. **决策段**
   - 讲清楚本回合/本轮有哪些正式行动，以及它们分别在什么情况下更划算。

3. **案例段**
   - 给出一个真实局面，让玩家做出一次“有理由的选择”，并看到收益变化。

4. **结果段**
   - 用计分、结算、伤害、控制权或其它核心反馈收口，让玩家知道自己刚刚“做成了什么”。

## 禁止行为

- 禁止把“教程能走通”当成“教程合格”。
- 禁止只用抽象概念替代真实案例，例如只说“注意组合”“尽量协同”，却不给可见的收益结果。
- 禁止只教界面部件名称，不教它们和赢法的关系。
- 禁止为了让截图更顺而把教程写成特判壳、假按钮链、伪结算态。
- 禁止只讲失败门禁或按钮顺序，不讲玩家为什么要这么做。
- 禁止用 3 句以上的说明文去替玩家完成本应由牌面、棋盘、数值变化自己表达的判断。

## 最低验收口径

教程收口前，至少要能用玩家听得懂的话回答以下问题：

1. 这游戏要怎么赢？
2. 这一回合我为什么选这个动作，不选另一个？
3. 我刚刚这步具体赚到了什么？
4. 哪张牌/哪个对象让结果变好了？
5. 如果这是计分游戏，我有没有真正看到一次分数因果？

五个问题有任意一个答不出来，教程不得收口。
