> 现在移动端设计也出来，看下你计划怎么适配
> 可以出移动端的了

## 覆盖范围

- Open Design 平台首页 `artifacts/home-platform-v3-neo-brutalist/` 在 `375×812` 竖屏上的承载去向。
- 顶栏、底栏、收藏库、发现、详情/创建/销毁/作者弹窗、个人中心、对局条、上传页。

## 项目级裁定

- 这是 L1/L2 平台页，不是游戏 Board。不另做第二套页面，不走 `MobileBoardShell` 等比缩放。
- PC `1920×1080` 仍是视觉基线。先把 `html/body` 从 1920 画布改成 `width=device-width` 流体布局，1920 画面保持原样，再加 `max-width: 1023px` 条件覆盖 375。
- 顶栏留下品牌和头像；搜索、操作指南、语言进抽屉。发现 / 收藏库 / 上传改底栏，命中区至少 44。
- 收藏库默认直接展示三列紧凑封面，搜索和排序直接可见。游戏单次点按进入，详情有明确返回收藏库入口，返回保留搜索、排序与浏览位置。新情报移到游戏后方默认折叠。主按钮独占一行，教程 / 收藏 / 配置两列紧凑排列，间距 12；房间和好友仍按自然高度进入页面滚动。
- 发现改两列封面。电脑悬停介绍改成点按通栏展开，其他卡片补齐网格空位；再点一次进入详情。
- 详情全屏 sheet。简介通栏，主按钮独立；教程 / 收藏 / 配置三个辅助入口同排并留出至少 16 间隔，作者以轻量署名放在主按钮右侧。人数采用现有 UI 的只读数字格并突出推荐值，时长为资料信息。叉号仍在右上，页签可横滑。收紧头部留白，大厅占据超过半幅并独立滚动，默认当前四房完整可见；短屏保留最少列表高度，整层必要时可滚动。创建 / 销毁 / 作者弹窗宽度 `100% - 32`，确认仍底部居中，触控至少 44。
- 个人中心身份、统计栏、最新动态纵向叠放。资料背景改成顶图，内容井通栏。排行和分数仍只出现在游戏动态行。
- 对局条贴底栏上方通栏，继续叠在内容上，不为对局条让位。
- 上传改单列。人数仍两个下拉。游戏链接下方常驻检测结果。
- 不实现 `src/`。整页仍待用户批准。

## 验收标准

1. 同一份 HTML 在 `1920×1080` 仍是顶栏三导航、左侧列表、六列发现、个人页左右留背景。
2. `375×812` 收藏库首屏完整显示当前八款游戏的封面与名称，中心可点，搜索和排序直接可见；保留底栏三导航、工坊列表抽屉、两列发现、个人页纵向叠放和顶图背景。
3. 点按能展开发现封面介绍；详情、创建、销毁仍是右上叉加底部居中确认。
4. 对局条在底栏上方，不把底栏顶走。
5. 触控主按钮、底栏、列表行的命中高度至少 44。
6. 收藏、发现、房间、好友、上传提交和个人动态的末项可滚动到对局条上方；创建弹窗展开电脑设置后，创建按钮仍可滚动到视口内并命中。
7. 收藏搜索有结果、无结果和清除恢复都保留查找入口；单次点击进入游戏，返回保持条件与浏览位置；情报默认不挤占游戏主区域。
8. 详情主辅操作有清楚间距和视觉层级；辅助按钮悬停不跳出同一行。作者以轻量署名放在按钮右侧；人数沿用现有 UI 的只读数字格并突出推荐值，不绑定人数选择。教程、配置、收藏和作者入口在重排后仍能触发原有 artifact 行为。
9. 详情不能为分组按钮留下无职责空白而挤占房间列表；桌面操作复用封面右侧资料空间，手机保持完整简介与触控尺寸。两端默认四房完整显示，短屏能在列表内滚动至末房并命中操作。

## 本轮纠正

2026-10-16，用户先指出「移动端收藏库游戏都看不见了」并要求继续重构；收藏库据此改为游戏优先、搜索排序直接可见、单击进入与明确返回。随后用户指出「按钮挤在一坨呢」并再次授权重构，本轮将详情主操作独立、三个辅助入口同排留距、作者署名化及人数只读化，同时取消辅助按钮悬停位移。保持桌面结构、底栏、两列发现和叠底对局条。当前 [逐图账本](../../../artifacts/home-platform-v3-neo-brutalist/exports/.visual-review.json) 与 [E2E 索引](../../../artifacts/home-platform-v3-neo-brutalist/exports/.e2e-image-index.json) 覆盖 16 张桌面、27 张移动截图，其中本轮重拍审查 11 张，另 32 张未改写并核对摘要后沿用。`375×540` 只验证既有短视口填写布局，不代表真机键盘验收；整稿仍待用户设计验收。
