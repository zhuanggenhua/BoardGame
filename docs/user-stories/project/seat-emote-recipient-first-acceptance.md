# 座位表情验收以接收方视角为准

## 用户原始要求

- 用户要求测试“我被别人发表情时的视角”。
- 用户明确指出：测试目标不是聊天窗口本身，也不是自己发送时看到什么。
- 用户明确指出：自己发送时，本来就在对话窗口里有本地显示；真正要验证的是别人发来后，我这一侧是否在发送者座位位置看到表情弹出。

## 覆盖范围

- 所有游戏的 seat emote / match emote / 对局内座位表情 E2E 验收口径。
- 包含发送方与接收方都在联机房间内的真实链路。

## 验收标准

1. 当需求表述为“看我被别人发表情的视角”“看接收方能不能看到”“主要验证别人发来后的表现”时，E2E 主断言必须以接收方页面为中心。
2. 主证据截图必须优先提供接收方页面，且截图中要能直接看到：
   - 发送者座位锚点；
   - 该座位附近的表情弹出；
   - 表情没有跑到错误玩家、错误位置或聊天面板本体里。
3. 发送方侧的聊天窗口、表情选择器、发送按钮，只能作为触发步骤，不得当作“本轮问题已修好”的主要证据。
4. 若产品口径要求“自己发送时不出现座位弹出，只在聊天窗口保留本地显示”，该项只能作为次级断言，不能替代接收方视角验证。

## 不覆盖范围

- 不定义表情资源风格、表情库来源或透明底处理流程。
- 不改变表情入口当前是否位于聊天窗口内；这里只定义验收视角优先级。
